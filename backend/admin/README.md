# Admin

Final Project의 Admin은 **LUMIA를 제작·운영하는 팀이 게임 운영을 위해 사용하는 별도 관리자 콘솔**입니다. 일반 사용자용 기록 조회 화면이 아니며, 운영자가 로그인해 회원·플레이 기록과 집계 통계를 확인하고 일부 전역 밸런스 값을 조정합니다.

> 구현 상태 (2026-10-18): FastAPI Phase 10에 관리자 Custom Claim 권한 검사, 로그인 감사로그, UID/이메일 사용자 조회, `activityDays → analyticsDays` 일/주/월 집계, 전역 `rewardMultiplier` 조회·변경과 balance audit가 구현되어 있으며 오프라인 회귀 테스트를 작성했다. **로컬 pytest 재검증, 실제 Firebase Custom Claim/Firestore, 관리자 웹 콘솔 통합 검증은 아직 완료되지 않았다.** 사용자별 데이터 수정, 콘텐츠 CRUD, Gemini Key 관리 UI는 아래 확정 범위대로 구현하지 않는다.

## 1. 관리자 정의와 접근

- 관리자는 LUMIA 제작·운영팀의 승인된 운영 계정입니다.
- 관리자 계정은 최대 **3개**까지 운영합니다.
- 일반 사용자가 관리자 권한을 신청하거나 획득하는 UI는 제공하지 않습니다.
- 관리자 콘솔은 게임 서비스와 **다른 주소**로 배포합니다. 실제 배포 URL은 배포 단계에서 확정하되 `admin.<service-domain>` 또는 별도 Vercel 프로젝트처럼 일반 게임 URL과 분리합니다.
- 인증은 Firebase Authentication을 재사용할 수 있지만, FastAPI는 Firebase ID Token 검증 후 서버에서 부여한 `admin` 권한을 추가 확인합니다.
- 관리자 권한은 클라이언트 요청만으로 부여·변경할 수 없습니다. Firebase Custom Claims 또는 서버가 관리하는 승인 UID 목록처럼 서버 측 기준으로만 판정합니다.
- 관리자 API는 `/admin/*`처럼 일반 게임 API와 경로를 분리하고, 관리자 권한이 없는 정상 로그인 사용자도 접근할 수 없게 합니다.

## 2. 관리자 기능

### 2.1 관리자 로그인

- 승인된 관리자 계정으로 로그인합니다.
- 로그인 성공 후 관리자 권한을 확인한 뒤 콘솔에 진입합니다.
- 일반 게임 계정이 관리자 URL에 로그인하더라도 관리자 권한이 없으면 접근을 거부합니다.
- 로그인 성공·실패 시도는 감사로그에 남깁니다.

### 2.2 회원·플레이 기록 조회

관리자는 로그인한 사용자들의 계정·게임 기록을 조회할 수 있습니다.

- 사용자 목록 및 검색: 이메일, UID 기준
- 가입 시각, 마지막 플레이 시각
- 세이브 슬롯별 상태·플레이 캐릭터·현재 주차
- 회차 완료 횟수
- 현재 회차의 보이는 성장 스탯
- 수업·모험·미니게임·NPC 조우 등 주요 누적 플레이 기록
- 캐릭터·펫·배지·마이룸 배경 등 해금 현황
- 확인한 직업 엔딩 목록
- 완료 회차에 저장된 엔딩 편지

운영상 필요하지 않은 비밀번호, Firebase 토큰, 서비스 계정 자격 증명은 조회하지 않습니다. 보이지 않는 스탯의 원시 수치와 전체 대화 원문은 기본 관리자 화면에 노출하지 않습니다.

Final Project 범위에서는 관리자에게 사용자 스탯·해금·세이브 값을 직접 수정하는 기능은 제공하지 않습니다. 사용자별 데이터를 고치는 기능보다 전역 밸런스 설정을 조정하는 구조를 우선합니다.

### 2.3 운영 통계

관리자 대시보드는 저장된 게임 기록을 기반으로 최소한 다음 집계를 제공합니다.

#### 회원 통계

- 전체 가입 사용자 수
- 실제 플레이 기록이 있는 사용자 수
- 최근 7일 / 30일 플레이 사용자 수
- 52주 회차를 1회 이상 완료한 사용자 수

#### 기간 필터

- 통계는 최소 `일 / 주 / 월` 단위로 조회할 수 있습니다.
- **월별 통계는 필수**이며, 월 단위로 회원·플레이·완료 회차·미니게임 결과·엔딩 분포를 비교할 수 있어야 합니다.
- 기본 월 집계 기준은 KST 달력 월(`1일 00:00 ~ 말일 23:59:59`)로 사용합니다.

#### 플레이 통계

- 전체 완료 회차 수
- 사용자당 평균 완료 회차 수
- 수업 / 모험 / 휴식 / 특수 활동 누적 횟수
- 미니게임별 `FAIL / SUCCESS / GREAT` 횟수와 성공 비율
- NPC Story / Location Story 주요 진행 건수

#### 밸런스·콘텐츠 통계

- 완료 회차의 성장 스탯별 평균 최종값
- 성장 스탯별 `300 이상`, `500 도달` 회차 비율
- 직업 엔딩별 노출 횟수
- 캐릭터·펫·배지·마이룸 배경 해금 현황 집계

통계 화면은 전체 경향 파악을 목적으로 하며 이메일 같은 개인 식별 정보를 집계 결과에 섞지 않습니다. 개별 사용자 상세 조회와 전체 통계 화면을 분리합니다.

## 3. 전역 밸런스·난이도 설정

게임의 퍼즐 규칙이나 스테이지 구조를 관리자 화면에서 임의 편집하지 않습니다. Final Project의 운영 난이도 조절은 **반복 플레이에서 획득하는 보이는 성장 스탯의 획득량 배율**을 낮추는 방식으로 제한합니다.

관리 대상은 다음 5개 성장 스탯입니다.

- `knowledge` 지식
- `expression` 표현력
- `skill` 솜씨
- `exploration` 탐험
- `magic` 마법

각 스탯은 `rewardMultiplier`를 가집니다.

- 기본값: `1.0` (100%)
- 허용 범위: `0.5 ~ 1.0`
- 변경 단위: `0.1`
- 관리자는 스탯별로 서로 다른 값을 설정할 수 있습니다.
- `1.0`보다 크게 올려 기본 기획보다 보상을 증가시키는 기능은 이번 범위에서 제공하지 않습니다.

적용 대상은 수업·미니게임과 모험처럼 **반복 가능한 성장 콘텐츠의 보이는 스탯 보상**입니다. 일회성 메인/NPC/Location Story에서 기획자가 명시한 스탯 변화와 보이지 않는 스탯은 이 전역 배율의 영향을 받지 않습니다.

성장량 계산은 다음 계약을 사용합니다.

```text
baseGrowth
= 결과·rewardDifficulty로 계산한 원래 성장량

staminaMultiplier
= 저체력 상태면 0.5, 아니면 1.0

finalGrowth
= floor(baseGrowth × rewardMultiplier[targetStat] × staminaMultiplier)
```

- 계산 결과는 기존 `0~500` 상한을 그대로 적용합니다.
- 설정 변경 이전에 이미 저장된 성장 스탯은 소급 변경하지 않습니다.
- 설정 변경 이후 확정되는 활동 보상부터 새 배율을 적용합니다.
- 현재 설정에는 `version / updatedAt / updatedBy`를 기록해 어떤 밸런스가 적용 중인지 식별합니다.
- 값 변경은 감사로그에 이전값과 변경값을 남깁니다.

상세한 수업·장소 난이도 기획은 WBS 8.2.2와 `document/content/02_STATS_EVENTS_ENDINGS/01_STATS_SYSTEM.md`를 함께 기준으로 합니다.

## 4. 감사로그

Final Project에서는 관리자 운영 추적에 필요한 최소 감사로그만 저장합니다.

관리자 기간 통계용 요약·집계, 전역 보상 배율, 감사로그는 중앙 Firestore에 저장합니다. 관리자 콘솔은 플레이어 기기의 로컬 SQLite에 접근하지 않습니다. 상세 문서 목록과 저장 경계는 [DB 저장 설계](../database/STORAGE_DESIGN.md)를 따릅니다.

### 반드시 기록

1. **관리자 로그인 시도**
   - 시각
   - 성공 / 실패
   - 성공 시 관리자 UID
   - 실패 시도 식별자(이메일은 필요하면 마스킹 또는 해시 처리)
   - 요청 IP와 User-Agent는 운영 환경에서 확보 가능한 범위에서 기록
   - 실패 사유는 `INVALID_CREDENTIAL / NOT_ADMIN / TOKEN_INVALID`처럼 비밀정보가 없는 코드로 기록

2. **운영 값 변경**
   - 시각
   - 관리자 UID
   - 변경 대상 key
   - 이전값
   - 변경값
   - 설정 version

비밀번호, Firebase ID Token, Gemini API Key, Firebase Admin 자격 증명은 감사로그에 기록하지 않습니다. 단순 사용자 기록 조회를 모두 영구 감사로그로 쌓는 기능은 Final Project 필수 범위로 두지 않습니다.

## 5. AI 키 관리 제외

관리자 콘솔에서 Gemini API Key를 등록·조회·교체하는 기능은 만들지 않습니다.

- `GEMINI_API_KEY`는 Render 서버 환경변수로만 관리합니다.
- 키 원문을 Firestore나 Git 저장소에 저장하지 않습니다.
- 관리자 웹 화면이나 API 응답으로 키를 노출하지 않습니다.
- 키 교체가 필요하면 배포 환경의 비밀 환경변수를 운영자가 직접 교체합니다.

따라서 기존 WBS 8.1.3 `AI 키 관리 기능`은 본편 관리자 콘솔 기능에서 **스펙 아웃**합니다.

## 6. 범위 밖

- 일반 사용자의 관리자 권한 신청
- 사용자 비밀번호 조회
- 사용자별 스탯·세이브·해금 직접 수정
- 스토리/콘텐츠 원고 CRUD
- Gemini API Key 관리 UI
- Firebase 서비스 계정 관리 UI
- 실시간 플레이 화면 감시

핵심 이미지 등록·교체 기능은 Final Project 제출 범위에서 **스펙 아웃**합니다. 장소 게임의 세부 규칙을 관리자에서 직접 편집하는 기능도 제공하지 않으며, 제출 버전의 밸런스 관리는 위 `rewardMultiplier` 방식으로 한정합니다.

## 7. 제출 후 관리자 확장

Final Project 제출 이후에는 운영 편의성을 높이기 위해 다음 기능을 확장할 수 있습니다.

- asset 자원 등록·교체·채택본 관리
- 스토리/대화 내용 수정
- 캐릭터 추가·수정
- 펫 추가·수정
- 콘텐츠 버전 관리와 필요 시 이전 자원 복원

이 기능들은 현재 관리자 콘솔의 필수 기능이 아니며, 제출판 구현 일정에는 포함하지 않습니다.

상세 기능·비기능 요구사항과 시스템 구조는 `document/12_REQUIREMENTS_ARCHITECTURE.md`를 기준으로 합니다.
