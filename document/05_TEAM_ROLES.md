# 팀원 역할과 협업 경계

이 문서는 LUMIA 팀의 **R&R(Role & Responsibility)** 과 주 작업 영역을 정의합니다. 역할별 실명 담당자는 아래와 같이 확정합니다. 브랜치 표기는 책임 영역의 참고 정보이며 AI가 임의로 생성·전환하지 않습니다.

| 담당자 | 역할 | 주 작업 영역 | 참고 브랜치·관리 | 주요 책임 |
|---|---|---|---|---|
| **이대선** | 엔진 · 게임 UI | [engine/](../engine/) | `dev-ds` | 게임 엔진 구조와 플레이 시스템 구현, 게임 화면/UI 구현, 입력·상호작용, 실행·통합·기술 검증 |
| **최현서** | 스토리 | [story/](../story/) | `dev-hs` | 메인·NPC·장소·서브·엔딩 시나리오 작성 및 스토리 콘텐츠 검토 |
| **최주원** | 디자인 | [asset/](../asset/) | `dev-jw` | 캐릭터·배경·아이템·UI 그래픽 등 시각 자원 제작, 자원 정리 및 시각 검수 |
| **박순몽** | 백엔드 · 콘텐츠 기획 · PM | [backend/](../backend/), [document/](../document/) 및 공통 기획 | 별도 담당 브랜치 미기재 | API·DB·저장/운영 구조, 콘텐츠 시스템·규칙·밸런스 기획, 일정·이슈·통합 조율 및 프로젝트 관리 |

[prototype/](../prototype/)은 기존 완성 기준물을 보존하는 영역이며, [lumia/](../lumia/)는 최종 통합 결과물 영역입니다. 둘 다 일반 개인 작업 폴더로 배정하지 않습니다. 최종 통합 시에는 각 담당자가 자신의 산출물을 검수하고, PM이 전체 일정과 영역 간 연결을 조율합니다.

## 역할 경계

- **게임 UI 구현**은 이대선이 담당합니다. 화면 레이아웃의 실제 코드, 입력, 상태 전환, 게임 화면 연결이 여기에 포함됩니다.
- **UI 시각 디자인**은 최주원이 담당합니다. 버튼·패널·아이콘·배경 등 화면에 사용되는 그래픽 자원과 시각 품질이 여기에 포함됩니다.
- **스토리 내용**은 최현서가 담당하고, 스토리가 들어갈 시점·발생 규칙·해금 조건 등 **콘텐츠 시스템 기획**은 박순몽이 담당합니다. 두 영역이 맞물리는 경우 시나리오와 시스템 규칙을 분리해 검토합니다.
- **백엔드와 콘텐츠 기획의 데이터 연결**은 박순몽이 담당합니다. 캐릭터·배지·펫·이벤트·세이브처럼 기획 규칙이 API/DB 계약으로 이어지는 항목을 일관되게 관리합니다.

## 변경 시 인계 규칙

1. 각 담당자는 자신의 디렉터리를 중심으로 수정합니다. 다른 영역의 변경이 필요하면 직접 수정하기 전에 사용자 또는 담당자에게 알립니다.
2. 공통 문서 변경은 최소화합니다. 세계관·캐릭터·콘텐츠 기준이 바뀌면 관련 `document/` 문서와 [AI 요약](../document_for_ai/00_READ_FIRST.md)을 함께 확인합니다.
3. 이미지 추가·삭제·교체 시 해당 `asset/` 하위 README의 파일 목록·설명·미리보기를 함께 갱신합니다.
4. 엔진 실행 방식이 바뀌면 [실행방법](실행방법.md)을 갱신합니다.
5. 역할별 세부 작업이 다른 영역에 영향을 주면 해당 담당자와 조율합니다. PM은 일정과 통합을 조율하지만, 각 전문 영역의 산출물은 해당 담당자가 검수합니다.
