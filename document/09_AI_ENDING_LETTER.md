# AI 핵심 기능 — 개인화 엔딩 편지

## 1. 기능 정의

LUMIA의 생성형 AI 핵심 기능은 **52주 플레이가 끝난 뒤, 게임 시스템이 확정한 미래 직업 엔딩과 실제 플레이 기록을 바탕으로 플레이어 개인에게 맞는 엔딩 편지를 생성하는 것**입니다.

AI는 직업 엔딩 자체를 임의로 결정하지 않습니다. 직업 엔딩 판정은 재현 가능한 게임 규칙으로 처리하고, AI는 그 결과와 플레이 기록을 자연어로 해석해 개인화된 편지로 전달합니다.

핵심 원칙은 다음과 같습니다.

> **게임 시스템이 “어떤 미래인가”를 결정하고, AI는 “그 미래가 이번 플레이어의 52주와 어떻게 이어지는가”를 편지로 표현한다.**

## 2. 전체 처리 흐름

```text
52주 플레이 완료
→ 엔딩 조건 판정
→ 10종 이상 직업 엔딩 중 1개 확정
→ 이번 회차의 대표 플레이 기록 추출
→ AI 편지 입력 데이터 구성
→ 생성형 AI가 개인화 엔딩 편지 생성
→ 형식·금지 표현·필수 항목 검증
→ 엔딩 화면에 편지 노출
→ 엔딩 결과 및 필요한 메타 기록 저장
```

엔딩 후보 산출과 복수 후보 우선순위는 [엔딩 시스템](content/02_STATS_EVENTS_ENDINGS/03_ENDINGS.md)의 규칙을 따릅니다.

## 3. AI가 받는 입력

AI에는 원시 게임 데이터 전체를 그대로 전달하지 않고, 편지 생성에 필요한 **정리된 엔딩 컨텍스트**만 제공합니다.

| 입력 | 내용 |
|---|---|
| 캐릭터 | 현재 회차의 플레이 캐릭터 이름·ID |
| 확정 직업 엔딩 | 규칙 엔진이 이미 확정한 직업 ID·직업명 |
| 보이는 스탯 요약 | 수치 자체보다 두드러진 성장 방향과 직업 관련 능력 |
| 보이지 않는 스탯 요약 | 공감·책임·호기심·용기·협력·독립성·신중함·솔직함 중 이번 회차에서 의미 있는 경향 |
| 대표 플레이 기록 | 수업·모험·NPC 만남·발견·미니게임 등 실제 플레이 기록 중 직업과 관련성이 높은 4~6개 |
| 대표 사건·선택 | 이번 회차에서 실제 경험한 주요 사건·발견·선택 중 편지에서 회고할 내용 |
| 표현 규칙 | 대상 연령, 문체, 금지 표현, 길이, 필수 섹션 |

실제 API의 필드명과 저장 형식은 백엔드 데이터 계약 단계에서 확정합니다.

## 4. AI가 생성하는 편지

엔딩 편지는 최소 다음 세 부분을 포함합니다.

1. **이번 이야기에서의 미래 직업** — 규칙 엔진이 확정한 직업을 알려 줍니다. AI가 다른 직업으로 변경하지 않습니다.
2. **52주 플레이 기록 회고** — 실제로 발생한 활동·선택·사건 중 직업과 관련성이 높은 기록을 사용합니다. 존재하지 않은 일을 만들어 내지 않습니다.
3. **미래 모습과 응원** — 이번 회차의 성장 방향과 플레이 방식을 바탕으로, 해당 직업에서 어떤 방식으로 행동할지 긍정적인 가능성을 상상하고 응원 메시지로 마무리합니다.

같은 직업 엔딩이라도 플레이 경향이 다르면 편지의 미래 모습도 달라질 수 있습니다.

| 플레이 경향 | 편지에서 그릴 수 있는 미래 모습 |
|---|---|
| 솜씨·용기·독립성이 두드러짐 | 상황을 빠르게 파악하고 먼저 행동하는 모습 |
| 책임·협력·신중함이 두드러짐 | 동료와 역할을 나누고 모두의 안전을 확인하는 모습 |
| 공감·표현력·책임이 두드러짐 | 상대를 안심시키고 주변 사람과 침착하게 소통하는 모습 |

이 차이는 직업의 우열이나 성격 평가가 아니라 **이번 플레이에서 보여 준 서로 다른 방식**을 반영합니다.

## 5. 게임 규칙과 AI의 책임 경계

| 처리 | 담당 |
|---|---|
| 엔딩 후보 조건 계산 | 게임 규칙 / 백엔드 |
| 미노출 우선·적합도·동률 판정 | 게임 규칙 / 백엔드 |
| 최종 직업 엔딩 확정 | 게임 규칙 / 백엔드 |
| 대표 플레이 기록 선별 | 백엔드 규칙을 우선하며 AI 입력용으로 가공 |
| 플레이 기록의 자연어 해석 | 생성형 AI |
| 미래 직업에서의 모습 상상 | 생성형 AI |
| 응원 메시지 작성 | 생성형 AI |
| 편지의 필수 항목·금지 표현 검증 | 백엔드 |

이 구조를 사용하면 같은 플레이 데이터에 대한 직업 판정은 재현 가능하게 유지하면서, 편지 표현은 개인화할 수 있습니다.

## 6. 어린이 대상 표현 원칙

주 대상이 9~11세이므로 AI 편지는 게임 기록을 어린이의 실제 성격·심리·진로에 대한 진단처럼 표현하지 않습니다.

- `너는 원래 이런 사람이야`처럼 실제 성격을 단정하지 않습니다.
- `책임감이 부족하다`, `용기가 낮다` 같은 부정적 성격 평가를 하지 않습니다.
- 내부 스탯 점수와 순위를 직접 보여 주며 평가하지 않습니다.
- 미래 직업을 실제 진로 예측이나 운명처럼 단정하지 않습니다.
- 플레이하지 않은 사건·행동·관계를 사실처럼 만들어 내지 않습니다.
- 플레이어를 다른 사람과 비교하지 않습니다.
- 불필요한 개인정보를 AI 입력에 포함하지 않습니다.

권장 표현은 `아르카디아에서 보여 준 모습을 보면...`, `이번 이야기에서 너는 ...하는 모습을 자주 보여 줬어.`, `이번 이야기에서 그려진 미래는 ...이야.`처럼 **게임 안의 경험**임을 명확하게 합니다.

## 7. 실패·오류 대응

AI 호출 실패 때문에 52주 엔딩 자체가 막히면 안 됩니다.

1. 직업 엔딩은 AI 호출 전에 확정·저장할 수 있어야 합니다.
2. AI 응답이 실패하거나 검증을 통과하지 못하면 재시도 정책을 적용합니다.
3. 재시도 후에도 생성할 수 없으면 직업별 안전한 기본 편지 템플릿을 사용합니다.
4. AI 실패가 엔딩·해금·다음 회차 데이터의 정합성에 영향을 주지 않게 합니다.

세부 재시도 횟수와 timeout은 API 구현 단계에서 결정합니다.

## 8. Final Project의 AI 핵심 기능으로서의 의미

생성형 AI는 단순 장식 문구를 무작위로 만드는 데 사용하지 않습니다. 플레이어가 52주 동안 축적한 서로 다른 행동·선택·성장 기록을 **개인화된 서사적 보상**으로 변환하는 마지막 단계에 사용합니다.

비AI 방식이라면 직업별 고정 편지 몇 종류를 미리 작성해야 하므로, 같은 직업을 얻은 플레이어들은 거의 같은 결과를 보게 됩니다. AI를 사용하면 동일한 직업 엔딩 안에서도 실제 플레이 기록과 성장 방향에 따라 서로 다른 회고와 미래 모습을 제공할 수 있습니다.

핵심 사용자 가치는 다음과 같습니다.

> **“내가 52주 동안 어떻게 플레이했는지 기억하고, 그 기록을 나만의 미래 이야기로 돌려받는 경험.”**

## 9. Final Project 기술 요소와의 연결

현재 설계는 과제의 기술 요소 중 다음 항목과 연결할 수 있습니다. 최종 제출에서 기술 요소로 인정받기 위해서는 실제 구현 코드와 테스트 증거가 필요합니다.

### Long-term Memory 후보

- 여러 주차·세션에 걸쳐 누적되는 플레이 기록을 계정에 저장합니다.
- 52주 종료 시 장기 기록을 다시 불러와 개인화 편지 생성에 사용합니다.
- 실제 구현에서 어떤 데이터를 얼마나 장기간 보존하고 불러오는지 증명해야 합니다.

### 자동화 워크플로우 후보

```text
52주 종료
→ 엔딩 판정
→ 대표 기록 추출
→ AI 입력 생성
→ 생성형 AI 호출
→ 응답 검증
→ 편지 저장/노출
→ 회차 완료·메타 반영
```

이 파이프라인이 코드로 자동 연결되고 오류 처리가 검증되면 자동화 워크플로우의 구현 근거로 사용할 수 있습니다.

두 항목을 Final Project의 최종 `기술 요소 2종`으로 확정할지는 구현·검증 단계에서 최종 확인합니다.

## 10. 아직 구현 단계에서 결정할 항목

- 생성형 AI 제공자는 **Gemini API**로 확정합니다.
- 기본 모델은 **`gemini-3.8-flash`**로 두고 `GEMINI_MODEL` 환경변수로 변경할 수 있게 합니다. 사용자 테스트에서 품질 차이가 작고 비용·속도 최적화가 필요하면 `gemini-3.5-flash-lite` 같은 경량 모델을 비교할 수 있습니다.
- 초기 `GEMINI_THINKING_LEVEL`은 `low`로 두고 엔딩 편지 품질 테스트에 따라 조정합니다.
- 프롬프트 및 구조화 출력 형식
- AI 편지의 목표 길이와 최대 토큰
- 응답 검증 방식
- 금지 표현 필터와 fallback 템플릿
- 호출 timeout·재시도 정책
- 생성된 편지를 영구 저장할지, 필요할 때 다시 생성할지
- AI API 비용 제한과 호출 횟수 정책
- Final Project 기술 요소 2종의 최종 인정 범위와 구현 증거
