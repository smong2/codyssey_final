# 01. 폴더 정렬·번호 부여 규칙

2026-10-05 · 작업 브랜치: **dev-jw**. 기존 main 이력을 재작성하거나 파일을 제거하지 않았다. dev-jw의 초기 이력에 지금까지 main에 저장한 제작 이력을 합친 뒤 이 브랜치에서 정리했다.

1. 최상위 제작 카테고리는 01~12, 정리·검증은 13이다. 모든 제작물은 document/03_characters 아래에 저장한다.
2. 각 폴더의 관리 문서·실행 파일·하위 폴더는 **하나의 번호 묶음**을 사용한다. 01부터 연속된 두 자리 번호로 정렬하며 같은 폴더에서 번호를 중복 사용하지 않는다. 번호는 해당 폴더에서만 유효하다.
3. 폴더 목차는 00_README.md로 고정한다. 제작 루트의 README.md와 00_manifest.json은 고정 진입점·전체 에셋 명세이므로 예외다.
4. CH01·NPC03·IT01·BG01·UI01·ENV01·OBJ01·SD03·PZ·SC01·MAP01·FLOW01 등은 관리 번호가 아닌 **고유 에셋 ID**다. 이름·방향·상태·버전 접미사를 유지한다. 프롬프트와 이미지의 ID를 일치시키고 같은 ID의 버전은 삭제하지 않는다. COMMON_LOCKS.txt도 공통 프롬프트 진입점으로 유지한다.
5. source_documents의 제공 문서 사본은 원래 파일명과 본문을 보존한다. 저장소 원본 README.md 및 document/01_project_overview.md~04_tech_stack.md, 프로젝트 sources/는 수정·이동하지 않는다.
6. 새 관리 항목은 해당 폴더의 마지막 번호+1을 사용한다. 00은 예약하며 빈 번호나 기존 번호를 재사용하지 않는다. 중간 삽입을 위해 임의로 다시 번호를 바꾸지 않는다. 99를 초과하기 전 하위 카테고리를 나눈다.
7. 새 에셋은 ID·상태·규격을 먼저 기록하고 기존 파일과 대조한다. 정리만을 위해 이미지를 재생성하거나 새 복사본을 GitHub에 중복 등록하지 않는다.
8. 이동 시 경로표·문서 링크·HTML/CSS/JS 경로·JSON 목록·폴더 목차를 함께 갱신한다. 폴더 번호, 기존 파일 보존, 이미지 SHA256, 제공 원본, 시안 이미지 로딩을 확인한 뒤 dev-jw에 저장한다.
