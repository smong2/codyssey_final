# Final Project 요구사항

> 코디세이 Final Project 미션에서 제공된 요구사항을 읽기 쉽게 재구성한 문서입니다. **필수 조건**, **학습·발표 목표**, **참고 예시**를 구별합니다. 아래의 LUMIA 점검 항목은 적용을 위한 분석이며, 새로운 요구사항이나 확정된 설계 결정이 아닙니다.

## 한눈에 보는 필수 조건

- 생성형 AI 또는 AI Agent가 서비스의 **핵심 기능**이어야 합니다. 단순한 API 호출만으로 미션 취지를 충족했다고 보지 않습니다.
- 아래 [기술 요소](#5-필수-기술-요소) 다섯 가지 중 **두 가지 이상**을 포함해야 합니다.
- 서비스를 외부에서 접근할 수 있게 **배포**해야 합니다.
- **실제 사용자 최소 5명**에게 서비스를 제공하고 피드백을 수집·반영해야 합니다.
- 모든 소스 코드와 문서를 GitHub에서 관리하고 버전 관리 기록을 남겨야 합니다.
- AI 생성 콘텐츠임을 사용자에게 알리고, 개인정보를 수집한다면 동의를 받아 안전하게 관리해야 합니다.

## 1. 미션 소개

Final Project는 5개월간의 코디세이 AI 네이티브 학습을 하나의 서비스로 증명하는 최종 캡스톤 프로젝트입니다. AI 도구 학습, Python 기반 AI 활용, AI Agent 개발에서 쌓은 역량을 활용해 **실제 사용자에게 가치를 제공하는 AI 기반 서비스**를 자율 주제로 기획하고 구현합니다. 소개 문구에는 팀 또는 개인 수행이 언급되며, 팀 수행 조건은 아래 [팀 구성](#6-팀-구성과-프로젝트-수행)에 따로 정리했습니다.

아이디어나 시연에서 끝나지 않습니다. `문제 정의 → 서비스 설계 → AI Agent/워크플로우 구축 → 프론트엔드 연동 → 배포 → 사용자 피드백 반영`까지 서비스 개발 전 주기를 수행하고, AI 도구를 활용해 문제를 해결한 역량을 포트폴리오로 설명해야 합니다.

## 3. 과제 목표: 팀이 설명할 수 있어야 하는 것

- 실제 사용자의 문제를 어떻게 정의하고 AI 기반 해결 방식을 설계했는가?
- 생성형 AI API 또는 AI Agent를 서비스에 어떻게 효과적으로 통합했는가?
- 프롬프트 엔지니어링, RAG, 메모리 관리 등 적용한 AI 기법을 왜 선택했는가?
- 노코드 자동화 도구와 Python을 조합하여 서비스를 구축한 경험을 어떻게 설명할 수 있는가?
- 사용자 피드백을 어떻게 수집하고 서비스에 어떤 개선을 반영했는가?
- 각 팀원의 역할·실질적 기여와 협업 과정은 무엇인가?

이 항목은 **성과를 설명하는 목표**입니다. 아래 필수 기술 요소와 개발 환경 선택 규칙을 대신하지 않습니다.

## 4. 기능·서비스 요구사항

- 주제는 자율적으로 정하되, 생성형 AI 또는 AI Agent를 서비스의 핵심 기능으로 포함합니다.
- 해결할 실제 사용자 문제와 대상 사용자를 명확히 정의합니다.
- 실제 사용자 **최소 5명**에게 서비스를 제공하고, 피드백을 수집·반영합니다.
- 서비스 아키텍처와 AI 활용 방식(프롬프트, Agent 구조, RAG 등)을 설계·문서화합니다.
- 프로젝트 진행 과정과 기술적 의사결정 근거를 기록합니다.

## 5. 필수 기술 요소

다음 **다섯 가지 중 두 가지 이상**을 서비스에 포함해야 합니다. 오른쪽 열은 예시이며 특정 구현을 요구하지 않습니다.

| 기술 요소 | 의미 | 원문 예시 |
|---|---|---|
| AI Agent | 사용자 의도를 파악하고 도구를 활용해 목표를 달성 | 일정 관리·정보 검색·업무 자동화 Agent |
| RAG(검색 증강 생성) | 외부 지식을 검색해 LLM 응답에 활용 | 문서 기반 Q&A, 지식 베이스 챗봇 |
| 멀티모달 AI | 텍스트·이미지·음성 등 다양한 입출력 형식 처리 | 이미지 분석 서비스, 음성 인터페이스 |
| 자동화 워크플로우 | 여러 서비스를 연동한 자동화 파이프라인 | 콘텐츠 자동 생성, 알림 자동화 |
| Long-term Memory | 사용자별 대화 기록·선호도를 저장하고 활용 | 개인화 추천, 맥락 유지 대화 |

## 6. 팀 구성과 프로젝트 수행

- 팀으로 수행할 경우 인원은 **3~6명**이며, 역할을 명확히 나누고 모든 팀원이 실질적으로 기여해야 합니다.
- Git을 사용해 체계적으로 버전을 관리하고, 모든 소스 코드와 문서를 GitHub에 올립니다.
- README에 프로젝트 개요, 팀원 역할, 기술 스택, 실행 방법, 결과를 정리합니다.
- 서비스를 외부 접근 가능하게 배포하고 실사용자 테스트와 피드백 반영까지 수행합니다.

## 7. 개발 환경과 제약

- 프로그래밍 언어, 프레임워크, AI 서비스는 자유롭게 선택할 수 있습니다. 선택한 기술 스택의 **선정 이유를 문서화**합니다.
- AI 생성 콘텐츠임을 사용자에게 명시합니다.
- 개인정보를 수집한다면 동의를 받고 안전하게 관리합니다.

## 8. LUMIA에 적용할 때 확인할 사항

아래는 현재 프로젝트 문서와 이 미션 요구사항을 대조한 **점검 목록**입니다. 미정 사항의 답을 이 문서에서 임의로 정하지 않습니다.

| 확인할 사항 | 필요한 결정·증거 |
|---|---|
| 사용자 문제와 AI 핵심 기능 | LUMIA가 어떤 사용자 문제를 해결하고, 생성형 AI 또는 AI Agent가 게임 경험의 어느 핵심 기능에 쓰이는지 정의 |
| 기술 요소 두 가지 이상 | 위 다섯 요소 중 실제로 구현·검증할 요소를 선택하고 설계 근거 기록 |
| 팀 역할과 기여 | 팀 인원, 담당자, 각자의 실질적 기여를 확정·기록 |
| 산출물 | 기획서, 요구 명세서·아키텍처, AI 활용 설계, README, 발표 자료의 작성·관리 방식 결정 |
| 배포와 사용자 피드백 | 외부 접근 가능한 배포 방법, 최소 5명 테스트 방법, 피드백 및 개선 기록 마련 |
| AI 윤리·개인정보 | AI 생성물 안내 방식과 개인정보 수집 여부·동의·보관 방식 결정 |

현재 [프로젝트 개요](01_PROJECT_OVERVIEW.md)에는 게임 방향이 정리되어 있으나 기술 스택과 배포 플랫폼은 확정되어 있지 않습니다. 이 점검 목록의 항목을 **이미 구현·검증·승인한 것으로 간주하지 마세요.**

원문 표현에는 확인이 필요한 부분도 있습니다. 미션 소개는 “생성형 AI와 AI Agent”, 필수 기능·제약 사항은 “생성형 AI 또는 AI Agent”라고 적고 있습니다. 또한 소개에는 개인 수행 가능성이 언급되지만 팀 구성 항목은 3~6명으로 제시됩니다. LUMIA의 구체적인 준수 범위를 최종 판단할 때는 이 표현 차이를 확인해야 합니다.

### README.md 예시

#### AI 기반 개인화 학습 코치 서비스

##### 프로젝트 소개

사용자의 학습 목표와 진행 상황을 파악하여 맞춤형 학습 계획을 수립하고, 일일 학습 리마인더와 진도 체크를 제공하는 AI 학습 코치 서비스입니다. RAG를 통해 학습 자료를 검색하고, Long-term Memory로 사용자별 학습 이력을 관리합니다.

- **AI**: OpenAI API, LangChain, Pinecone (Vector DB)
- **Backend**: FastAPI, Render
- **Frontend**: HTML, CSS, Javascript
- **Infra**: Vercel, Supabase, GitHub Actions
- **자동화**: n8n (일일 리마인더 발송)

##### 시스템 아키텍처

(아키텍처 다이어그램 이미지)

##### 핵심 AI 활용

###### 1. AI Agent 구조

- Planning Agent: 사용자 목표 분석 → 학습 계획 수립
- Coaching Agent: 일일 진도 체크 → 피드백 생성

###### 2. RAG 파이프라인

- 학습 자료 임베딩 → Pinecone 저장
- 사용자 질문 → 관련 자료 검색 → 맥락 기반 답변

###### 3. Long-term Memory

- 사용자별 학습 이력, 선호도, 강점/약점 저장
- 대화 시 이전 맥락 자동 로드
