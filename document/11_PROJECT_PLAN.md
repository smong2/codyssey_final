# Final Project 기획서 요약

이 문서는 WBS 10.1.1의 제출용 기획서 역할을 합니다. 세부 게임 규칙은 `document/content/`, 기술 구현 기준은 `document/10_TECH_STACK.md`, 역할 경계는 `document/05_TEAM_ROLES.md`를 우선합니다.

## 1. 프로젝트 문제 정의

LUMIA가 해결하려는 문제는 **어린이의 선택과 성장 경험을 정답·오답이나 단순 점수로 평가하지 않으면서도, 긴 플레이의 결과가 플레이어 자신의 이야기로 돌아오게 만드는 것**입니다.

일반적인 고정 엔딩만으로는 52주 동안의 수업·모험·NPC 만남·선택·발견 차이를 충분히 반영하기 어렵습니다. LUMIA는 게임 규칙으로 재현 가능한 미래 직업 엔딩을 먼저 확정하고, 실제 플레이 기록을 생성형 AI가 회고 편지로 표현하여 같은 직업 엔딩에서도 플레이 과정이 다른 사용자가 서로 다른 결과를 받게 합니다.

## 2. 대상 사용자와 제공 가치

- 주 대상: 약 **9~11세 어린이**
- 플레이 맥락: 웹에서 52주 동안 수업·모험·휴식, 사건·NPC 교류, 수집·해금을 반복하는 판타지 생활 어드벤처
- 핵심 가치: 선택을 도덕 점수로 평가하기보다 세계와 인물의 반응으로 보여 주고, 마지막에는 실제 52주 기록을 개인화된 미래 이야기로 돌려줌
- 운영 맥락: LUMIA 제작·운영팀은 일반 게임과 다른 관리자 주소에서 승인된 운영자 계정으로 로그인해 회원·플레이 기록과 집계 통계를 확인하고, 제한된 전역 성장 보상 배율을 조정합니다. 사용자별 저장값 직접 수정이나 실시간 감시 기능은 제공하지 않습니다.

## 3. AI 활용 방식

LUMIA의 핵심 AI 기능은 **개인화 엔딩 편지**입니다.

```text
52주 플레이 기록
→ 규칙 엔진의 직업 엔딩 판정
→ 대표 기록·사건 추출
→ Gemini 입력 컨텍스트 구성
→ 개인화 편지 생성
→ 형식·금지 표현 검증
→ 실패 시 fallback 편지
→ 엔딩 화면 표시·저장
```

AI는 직업을 결정하거나 플레이어의 성격을 진단하지 않습니다. 게임 시스템이 확정한 직업과 실제 플레이 기록을 자연어로 해석하는 역할만 담당합니다. 작가의 고정 질문 `무엇을 지켰니?`에도 AI가 하나의 정답을 대신 제시하지 않습니다.

Final Project의 기술 요소 두 가지는 **Long-term Memory**와 **자동화 워크플로우**를 사용합니다.

- Long-term Memory: 단순 세이브가 아니라 **여러 주차·세션에 걸쳐 누적한 현재 회차의 플레이 기억을 52주 종료 시 다시 불러와 실제 Gemini 입력에 사용하는 Long-term Play Memory**로 구현
- 자동화 워크플로우: `엔딩 판정 → 장기 기억 로드 → 기록 선별 → AI 입력 생성 → Gemini 호출 → 검증 → fallback → 저장/표시 → 메타 반영`을 하나의 서버 처리 흐름으로 연결

Long-term Play Memory는 플레이 도중 활동 결과·중요 선택을 안정 저장 경계마다 누적하고, 로그아웃·재접속 후에도 유지합니다. 52주 종료 시 현재 회차의 기억을 다시 읽어 대표 기록 4~6개와 중요 선택 최대 2개를 AI Memory Context로 구성하고 Gemini 편지 생성에 사용합니다. 최종 편지와 사용한 대표 기억은 회차별 Ending Record에 보관하며, 다음 회차 편지에는 이전 회차 기억을 섞지 않습니다.

별도 AI Agent는 제출 버전에 넣지 않습니다. 엔딩의 처리 순서는 규칙으로 고정할 수 있으므로 자율적인 도구 선택보다 자동화 워크플로우가 재현성·안전성·검증 측면에서 적합합니다. Agent는 제출 후 부모/보호자 피드백을 고도화할 때 여러 회차·통계 조회 도구를 선택하는 기능으로 검토할 수 있습니다.

실제 구현·화면·실패 테스트를 통한 증명은 WBS 10.1.4에서 게임 구현 후 수행합니다.

## 4. 기술적 접근

| 영역 | 기술 | 역할 |
|---|---|---|
| 게임 클라이언트 | Phaser 3 + JavaScript/Node.js/Vite | 게임 UI·입력·미니게임·탐험 |
| 프론트 배포 | Vercel | 사용자 접속 웹 게임 |
| API | Python + FastAPI | 저장·해금·엔딩 판정·AI 호출 |
| API 배포 | Render | FastAPI 운영 |
| 인증 | Firebase Authentication | Email/Password + 이메일 인증 |
| 데이터 | Cloud Firestore | 세이브 슬롯·Global Meta·플레이 기록·엔딩 기록 |
| 생성형 AI | Gemini API | 개인화 엔딩 편지 |
| 관리자 콘솔 | 별도 웹 Admin + Firebase 관리자 권한 + FastAPI | 회원·플레이 조회, 운영 통계, 전역 성장 보상 배율 조정, 감사로그 |
| 협업 | GitHub / Git | 코드·문서·WBS·변경 이력 |

클라이언트가 신뢰해야 하는 게임 상태를 직접 임의 변경하지 않도록 주요 저장·판정은 FastAPI를 통과시키는 구조를 기본으로 합니다. 관리자 콘솔도 별도 주소와 관리자 권한 검증을 거쳐 `/admin/*` API를 사용합니다. Gemini API 키와 Firebase Admin 자격 증명은 서버 환경변수에만 두며 관리자 UI에서 관리하지 않습니다.

### 4.1 Final Project 제출 범위 고정

WBS 1.1.2의 제출 범위는 **Must / Should / Post-Submission**으로 고정합니다. 세부 기능의 단일 기준은 `document/12_REQUIREMENTS_ARCHITECTURE.md`이며, 이 표는 제출 시 무엇을 우선 완성하고 무엇을 일정 위험 시 뒤로 미룰지 판단하는 범위표입니다.

| 구분 | 제출 범위 | 판단 기준 |
|---|---|---|
| **Must** | Email/Password + 이메일 인증, 5개 세이브 슬롯과 Global Meta, 52주 주간 루프, 수업·모험·휴식·강제휴식, 6개 미니게임 + 1개 특수 활동, 메인/NPC/Location Story, 수집·해금·직업 엔딩, Gemini 개인화 엔딩 편지, Long-term Play Memory, 자동화 AI Workflow, 검증·fallback, 운영 관리자 인증·회원/플레이 조회·일/주/월 통계·전역 성장 보상 배율·감사로그, 외부 배포, 실제 사용자 5명 이상 테스트·피드백 반영, 필수 제출 문서·GitHub·발표 근거 | Final Project 제출 완료 전에 구현·검증 근거가 필요하며 일정 부족을 이유로 제출 후로 넘기지 않음 |
| **Should** | 현재 기기를 유지한 다른 기기 인증 세션 폐기, 해금 펫 활성화와 임시 성장 스탯 보정 | Must가 안정된 뒤 구현·검증을 마무리하는 우선 기능. 일정 충돌 시 Must 안정성과 제출 증거를 우선함 |
| **Post-Submission** | asset/콘텐츠 CMS, 대화·캐릭터·펫 관리 고도화, 고품질 UI 전면 개선, 상황별 BGM/SFX 세분화, 여러 회차를 비교하는 부모/보호자 피드백과 자율 AI Agent | Final Project 완료 조건에 포함하지 않으며 제출판 구현·검증 일정에서 제외 |

범위 변경이 필요하면 새 기능을 암묵적으로 Must에 추가하지 않고 이 표와 요구 명세의 우선순위를 함께 수정합니다. 특히 별도 AI Agent, 이미지 등록·교체 관리자 기능, 스토리/콘텐츠 CRUD는 **제출판 미완료가 아니라 의도적으로 제출 후 범위로 이동한 항목**입니다.

### 4.2 Final Project 제출 후 확장

다음 항목은 현재 제출판의 핵심 동작을 완성한 뒤 확장합니다.

1. **관리자 기능 강화** — asset 자원 등록·교체, 대화 내용 변경, 캐릭터·펫 추가/관리 등 콘텐츠 CMS 기능
2. **UI 개선** — 기능 중심 UI를 고품질 디자인 버튼·창·인터랙션으로 교체
3. **사운드 개선** — 장소·상황·이벤트·성공/실패 결과에 맞춘 BGM/SFX 세분화
4. **부모/보호자 피드백 개선** — 현재의 결과 조회 수준에서 여러 회차·활동 경향을 이해하기 쉬운 피드백으로 확장

이 항목들은 Final Project 제출 완료 조건을 위해 구현하지 않으며, 제출 버전의 구현·검증 일정에 포함하지 않습니다.
