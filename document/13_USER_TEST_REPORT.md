# LUMIA 사용자 테스트·피드백 보고서

> **문서 상태:** 1차 사용자 테스트 결과 및 피드백 반영 정리 / 개선 후 별도 사용자 재테스트는 수행하지 않음  
> **목적:** 실제 사용자 최소 5명의 핵심 플레이 경험을 확인하고, 발견된 문제·우선순위와 실제 개선 반영 내용을 함께 기록한다.
> **관련 WBS:** #191, #192, #193, #206

## 1. 테스트 목적

LUMIA의 외부 웹 환경에서 사용자가 별도의 개발자 설명 없이 핵심 흐름을 이해하고 진행할 수 있는지 확인한다.

이번 1차 테스트에서는 다음을 중점적으로 관찰했다.

- 회원가입과 로그인 가능 여부
- 새 게임 시작과 캐릭터 선택의 이해도
- 주간 일정 등록 방식의 직관성
- 수업과 모험 콘텐츠의 조작성·게임성
- Story 선택 UI의 가독성과 진행 이해도
- 저장·이어하기의 안정성과 정보 전달
- 캐릭터·펫·비주얼·사운드·스토리·수집 요소에 대한 전반적인 인상

이 문서는 **1차 관찰 결과와 사용자 의견, 그에 따른 개선 반영 내용까지 기록한 상태**다. 개선 후 동일 사용자 또는 대표 사용자를 대상으로 한 별도 재테스트는 이번 제출 범위에서 수행하지 않았다.

## 2. 테스트 참가자

개인 식별 정보는 기록하지 않고 `T01~T05` 익명 ID로 관리한다.

| ID | 연령대 | 게임 경험 | 사용 기기 | 브라우저 |
|---|---|---|---|---|
| T01 | 10대 | 많음 | 태블릿 | Chrome |
| T02 | 30대 | 많음 | 태블릿 | Safari |
| T03 | 40대 | 적음 | PC | Chrome |
| T04 | 50대 | 보통 | PC | Chrome |
| T05 | 20대 | 많음 | 태블릿 | Safari |

참가자는 연령대와 게임 경험이 서로 다르고 PC·태블릿 환경을 모두 포함한다. 다만 이번 표본은 제품의 핵심 대상인 9~11세 사용자만으로 구성한 테스트는 아니므로, **기본 사용성 검증 결과와 핵심 연령층 적합성 검증은 구분해서 해석**한다.

## 3. 테스트 수행 결과

개별 참가자별 세부 성공/실패 로그가 따로 기록되지 않은 항목은 임의로 T01~T05에 배분하지 않고, 실제 관찰된 전체 경향으로 기록한다.

| 테스트 항목 | 결과 | 관찰 요약 |
|---|---|---|
| 회원가입 / 로그인 | **모두 성공** | 기능 자체는 정상 동작했으나 10대 참가자의 이메일 사용 환경에서 보호자 도움이 필요했다. |
| 게임 시작 / 진행 속도 | **모두 성공** | 진입과 진행은 가능했지만 활동 전환과 저장 과정에서 대기 시간이 길게 느껴진다는 의견이 있었다. |
| 캐릭터 선택 | **모두 성공** | 선택 기능은 정상적으로 이해하고 진행했다. |
| 일정 등록 | **대부분 혼란** | 날짜와 콘텐츠 선택 순서가 직관적이지 않아 핵심 주간 루프 진입에서 혼란이 컸다. |
| 수업 | **성공** | 기능은 정상 동작했으나 게임성과 조작 가이드가 부족하다는 의견이 있었다. |
| 모험 | **일부 혼란** | 목표와 탐색 방식이 명확하지 않고 탐험의 재미가 약하다는 의견이 있었다. |
| Story 선택 | **부분 혼란** | 선택 구조 자체는 대체로 이해했지만 버튼 크기와 텍스트 넘침 때문에 읽기 불편했다. |
| 저장 / 이어하기 | **부분 혼란** | 대체로 동작했으나 불러오기 실패 사례가 있었고 슬롯 정보가 부족하다는 의견이 있었다. |

## 4. 관찰된 문제와 사용자 의견

### UT-01. 로그인 방식과 어린 사용자 접근성

**관찰**

- 로그인 기능 자체는 모든 참가자가 성공했다.
- 10대 참가자의 경우 평소 이메일을 직접 사용하지 않아 보호자의 도움을 받아야 했다.

**사용자 의견**

- 향후 Google 등 SNS/소셜 로그인 방식을 지원하면 어린 사용자의 진입 장벽을 낮출 수 있겠다는 의견이 있었다.

**해석**

- 현재 Email/Password 인증은 기능적으로 동작하지만 핵심 대상 연령층의 실제 계정 사용 습관과는 차이가 있을 수 있다.
- 소셜 로그인 도입은 인증 구조에 영향을 주는 확장 기능이므로 제출판 즉시 수정과 제출 후 개선을 구분해 판단해야 한다.

### UT-02. 게임 진행 속도

**관찰**

- 게임 시작과 플레이는 모두 가능했지만 활동 전환과 저장이 반복되는 구간에서 게임 진행이 다소 느리게 느껴진다는 의견이 있었다.

**사용자 의견**

- 게임 중간중간 발생하는 저장·전환 대기 시간을 줄이면 좋겠다는 의견이 있었다.

**해석**

- 저장 요청 처리 방식과 서버 통신 경로를 함께 점검해 체감 속도를 개선할 필요가 있다고 판단했다.

### UT-03. 주간 일정 등록 방식

**관찰**

- 일정 등록에서 대부분의 참가자가 혼란을 보였다.
- 현재는 콘텐츠를 누르면 일정이 바로 채워지는 방식이 아니라, **달력의 날짜를 선택한 뒤 콘텐츠를 선택해야 등록되는 흐름**이라 사용자가 다음 행동을 직관적으로 예상하기 어려웠다.

**사용자 의견**

- 콘텐츠를 누르면 월요일부터 빈 일정 칸에 순서대로 자동 배치되는 방식이 더 이해하기 쉽겠다는 의견이 있었다.

**해석**

- 주간 일정은 LUMIA의 핵심 반복 루프 진입점이므로 단순한 편의 문제가 아니라 핵심 UX 문제로 본다.

### UT-04. 수업 미니게임의 게임성과 가이드

**관찰**

- 수업 기능은 정상적으로 동작했다.
- 다만 미니게임의 재미와 몰입도가 낮고, 처음 플레이할 때 무엇을 해야 하는지 알려 주는 가이드가 부족하다는 의견이 있었다.

**사용자 의견**

- 조작 방법이나 목표를 짧게 안내하는 가이드가 필요하다.
- 단순히 기능이 동작하는 수준을 넘어 반복해서 플레이하고 싶은 게임성이 필요하다.

### UT-05. 모험의 목표 전달과 탐색 재미

**관찰**

- 무엇을 해야 하는지 바로 이해하기 어렵다는 반응이 있었다.
- 화면에 놓인 아이템을 찾아가 눌렀을 때 빠르게 종료되어 `모험`이라는 이름에 비해 탐색 과정의 의미가 약하게 느껴졌다.

**사용자 의견**

- 단순히 보이는 물건을 클릭하는 방식보다 **처음에는 보이지 않거나 바로 알 수 없는 대상을 단서로 찾아가는 과정**이 필요하다는 의견이 있었다.

**해석**

- 현재 기획된 방향 단서·숨은 목표 탐색 구조가 실제 플레이 화면에서 충분히 전달되는지 다시 검증할 필요가 있다.

### UT-06. Story 선택 UI 가독성

**관찰**

- Story의 선택 방식 자체는 대체로 긍정적으로 받아들여졌다.
- 선택지가 노출될 때 버튼이 작아 긴 텍스트가 버튼 영역을 넘치거나 읽기 불편한 사례가 있었다.

**사용자 의견**

- 선택 버튼 크기를 늘리고 텍스트가 버튼 내부에서 정상적으로 줄바꿈되어 표시되면 좋겠다는 의견이 있었다.

### UT-07. 저장·이어하기 안정성과 슬롯 정보

**관찰**

- 저장과 이어하기는 대체로 동작했다.
- 일부 불러오기 실패 사례가 있었다.
- 세이브 슬롯만 보고 어떤 진행 상태인지 판단하기 어렵다는 의견이 있었다.

**사용자 의견**

- 슬롯에 최소한의 진행 정보를 표시하면 어떤 저장을 이어야 할지 판단하기 쉬울 것이라는 의견이 있었다.

**표시 후보 정보**

- 플레이 캐릭터
- 현재 주차
- 최근 저장 시각
- 회차 상태

### UT-08. 캐릭터별 대사 차별화 부족

**관찰**

- 선택할 수 있는 캐릭터 수는 많지만 실제 플레이 중 대사가 동일하게 느껴져 캐릭터를 바꾸는 재미가 약하다는 의견이 있었다.

**사용자 의견**

- 캐릭터의 성격과 말투에 맞게 대사와 선택 문구가 달라지면 캐릭터 선택의 의미가 커질 것이라는 의견이 있었다.

**해석**

- LUMIA는 다수의 플레이 캐릭터를 제공하는 것이 주요 특징이므로 캐릭터 수 자체뿐 아니라 실제 대화 경험의 차별화가 중요하다.

## 5. 긍정적인 결과

1차 테스트에서 다음 요소는 긍정적으로 평가되었거나 기능적으로 안정적인 결과를 보였다.

| 항목 | 결과 |
|---|---|
| 로그인 | 5명 모두 성공 |
| 캐릭터 선택 | 5명 모두 성공 |
| 캐릭터 다양성 | 여러 캐릭터를 선택할 수 있다는 점이 긍정적으로 받아들여짐 |
| 펫 다양성 | 다양한 펫 수집·선택 요소에 긍정적 반응 |
| 비주얼과 사운드 | 게임의 시각·청각적 분위기에 긍정적 반응 |
| 스토리 다양성 | 단일 반복 플레이보다 여러 Story가 존재한다는 점에 긍정적 반응 |
| 수집 시스템 | 캐릭터·펫·배지·마이룸 등 다양한 수집 목표가 장기 동기로 작용할 가능성을 확인 |

기능적으로는 **회원가입/로그인 → 게임 시작 → 캐릭터 선택 → 수업 실행**까지 5명 모두 핵심 진입 흐름을 완료할 수 있었다.

## 6. 전체 결과 요약

1차 사용자 테스트에서는 모든 참가자가 회원가입·로그인, 게임 시작, 캐릭터 선택을 완료했고 수업 콘텐츠도 정상 실행할 수 있었다. 따라서 서비스의 기본 진입 경로와 주요 기능이 사용 불가능한 상태는 아니었다.

반면 실제 사용성에서는 **주간 일정 등록**이 가장 넓게 혼란을 일으켰다. 일정은 게임의 핵심 반복 루프인데도 날짜를 먼저 선택하고 콘텐츠를 다시 선택해야 하는 현재 조작 방식이 직관적으로 이해되지 않았다. 이 문제는 단순한 UI 취향보다 첫 플레이 진행을 방해하는 핵심 UX 문제로 판단한다.

모험과 수업은 기능적으로 실행되지만 `무엇을 해야 하는지`, `왜 반복해서 해야 하는지`가 충분히 전달되지 않아 게임성 개선이 필요했다. 특히 모험은 화면에 보이는 대상을 찾고 선택하는 것만으로 끝난다는 인상이 강해, 숨겨진 목표와 단서를 추적하는 탐험 경험을 실제 플레이에서 더 명확하게 구현할 필요가 있다.

Story 선택은 전반적인 방식 자체보다 **UI 가독성**이 주요 문제였다. 긴 선택 문장이 작은 버튼 안에서 정상적으로 표시되지 않는 문제는 바로 수정 가능한 영역이다. 저장·이어하기는 대체로 동작했지만 실제 불러오기 실패 사례가 있었으므로 데이터 손실·진행 차단 위험을 먼저 확인해야 한다.

또한 다수의 캐릭터와 펫, 비주얼·사운드, 스토리 및 수집 요소는 프로젝트의 긍정적인 차별점으로 평가되었다. 다만 캐릭터가 많음에도 실제 대사가 동일하게 느껴진다는 피드백은 캐릭터 선택의 장기적인 매력을 떨어뜨릴 수 있어 후속 품질 개선 대상으로 본다.

## 7. 피드백 우선순위

### 7.1 우선순위 기준

| 등급 | 기준 |
|---|---|
| **P0** | 진행 실패, 저장 데이터 위험, 핵심 기능 사용 불가처럼 제출 전에 반드시 확인·수정해야 하는 문제 |
| **P1** | 게임은 진행되지만 핵심 루프 이해·조작·가독성·몰입을 크게 저해하는 문제 |
| **P2** | 플레이는 가능하지만 완성도·재미·접근성을 낮추는 품질 문제 |
| **P3** | 현재 제출을 막지는 않으며 구조 변경이나 추가 개발이 필요한 후속 확장 |

### 7.2 발견 당시 우선순위

| ID | 피드백 | 우선순위 | 판단 이유 |
|---|---|:---:|---|
| UT-07 | 저장/이어하기 불러오기 실패 사례 | **P0** | 플레이 기록 접근 실패는 진행 차단과 데이터 신뢰 문제로 이어질 수 있어 가장 먼저 재현·수정해야 함 |
| UT-03 | 주간 일정 등록이 직관적이지 않음 | **P1** | 대부분의 참가자가 혼란을 느꼈고 52주 핵심 반복 루프 진입에 직접 영향을 줌 |
| UT-06 | Story 선택 버튼 텍스트 넘침·가독성 | **P1** | Story 선택은 핵심 상호작용이며 수정 범위가 명확하고 즉시 체감되는 문제 |
| UT-05 | 모험의 목표·탐색 재미 부족 | **P1** | 핵심 활동 중 하나가 무엇을 해야 하는지 전달하지 못하고 콘텐츠 의미가 약하게 느껴짐 |
| UT-02 | 게임 진행 속도 | **P1** | 반복 저장·화면 전환의 대기 시간이 전체 플레이 흐름에 영향을 주어 최적화가 필요함 |

## 9. 피드백 반영 결과 요약

테스트에서 제기된 8개 주요 피드백 중 저장 안정성, 일정 등록, Story 선택 UI, 모험 구조, 게임 진행 속도, 캐릭터별 대사 차별화는 제출판에 직접 반영했다. 수업은 가이드와 게임 종류 재구성까지 우선 반영하고, 세부 게임성 고도화는 제출 후 개선으로 남겼다. 소셜 로그인은 현재 인증 방식을 대체해야 할 필수 문제라기보다 핵심 연령층의 접근성을 높일 수 있는 후속 확장 항목으로 분류했다.

가장 큰 변화는 **사용자가 실제로 혼란을 느낀 핵심 흐름을 직접 수정했다는 점**이다. 일정은 콘텐츠 선택만으로 순차 등록되도록 바뀌었고, 모험은 보이는 아이템을 단순 클릭하는 구조에서 단서·조사·숨은 목표·시간 제한을 사용하는 탐색 콘텐츠로 확장됐다. 저장 화면은 현재 진행 상태를 식별할 수 있게 되었고, 대화와 캐릭터 표현도 실제 플레이 가독성과 캐릭터 차별화를 중심으로 개선했다.

이 섹션은 **피드백이 실제 제품 변경에 어떻게 연결됐는지**를 기록한다. 개선 후 별도의 사용자 재테스트는 수행하지 않았으므로, 아래 반영 내용은 구현 반영 결과이며 `후속 사용자 재검증 완료`를 의미하지 않는다.

## 10. 향후 작업

이 문서의 `향후 작업`은 이번 사용자 테스트에서 즉시 해결하지 못한 버그 목록이 아니라, **Final Project 제출판 이후 제품을 발전시킬 방향**을 의미한다. 세부 기준은 `document/11_PROJECT_PLAN.md`의 `Final Project 제출 후 확장`을 따른다.

1. **관리자 기능 강화** — asset 등록·교체, 대화 내용 변경, 캐릭터·펫 추가/관리 등 콘텐츠 CMS 기능을 확장한다.
2. **UI 개선** — 현재 기능 중심으로 구성된 UI를 보다 완성도 높은 버튼·창·인터랙션으로 개선한다. 이번 사용자 테스트의 Story 버튼·일정 UI 개선 경험도 후속 UI 품질 기준으로 사용한다.
3. **사운드 개선** — 장소·상황·이벤트·성공/실패 결과에 따라 BGM과 SFX를 더 세분화한다.
4. **부모/보호자와의 대화 연결** — 여러 회차의 플레이 경향과 선택을 아이의 성격으로 단정하지 않는 범위에서 정리해 부모·자녀 대화의 단서로 활용하는 방향을 검토한다.
5. **미니게임 품질 개선** — 이번 테스트에서 지적된 게임성 문제를 장기 과제로 이어 받아 조작감·연출·피드백·재미를 고도화하고 게임 전체의 세계관과 톤앤매너에 맞춘다.
6. **앱 전환 검토** — 현재 웹 기반 게임을 향후 앱으로 확장하거나 전환할 수 있는지 검토한다.
7. **인물·공간 확장** — 등장인물과 공간을 추가하고 주인공에 따라 만나는 관계와 사건의 차이를 늘려 회차별 경험을 다양화한다.

이번 사용자 테스트에서 추가로 확인된 접근성 개선 과제로 **소셜 로그인 지원**을 검토한다. 이는 현재 Final Project 제출 범위를 변경하는 필수 기능이 아니라, 어린 사용자의 실제 계정 사용 환경을 고려한 후속 인증 UX 개선 항목이다.
