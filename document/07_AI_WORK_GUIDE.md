# 팀원용 AI 작업 시작 안내

이 문서는 팀원이 각자의 AI로 LUMIA 작업을 시작할 때 사용하는 안내입니다. **새 대화에서 한 번만 프로젝트 기준과 담당 영역을 확인한 뒤, 같은 대화에서는 평소처럼 작업을 지시**하세요. AI에게 “꼭 기억해”라고만 말해도 다른 대화까지 내용이 유지되는 것은 아닙니다. 새 대화마다 아래 첫 프롬프트를 사용하고, 개별 작업에 필요한 원문과 실제 파일은 그때 다시 확인하게 하세요.

## 시작 전에

- AI가 이 저장소의 파일을 읽을 수 있는 환경에서 대화를 시작하세요. 파일 접근이 없다면 [AI 시작 문서](../document_for_ai/00_READ_FIRST.md)와 연결된 01~06 문서를 실제로 전달해야 합니다. 파일 경로만 적는 것으로는 내용을 읽을 수 없습니다.
- 담당 영역을 정하세요: 엔진 `engine/`, 스토리 `story/`, 디자인 `asset/`, 백엔드 `backend/`. 참고 브랜치와 작업 경계는 [팀 역할](05_TEAM_ROLES.md)과 [AI 협업 규칙](../document_for_ai/06_WORKSPACE_RULES.md)을 확인하세요. 브랜치 정보만 보고 AI가 임의로 전환하게 하지 마세요.
- Codex는 저장소의 `AGENTS.md`를 작업 지침으로 읽습니다. 다른 AI 도구에서도 자동으로 읽힌다고 가정하지 말고 첫 프롬프트에서 명시하세요. 이후 팀원은 **하고 싶은 작업**을 말하면 됩니다. 필요한 파일 범위와 확인 방법은 AI가 판단합니다.

## 1단계: 새 대화의 첫 프롬프트

아래를 복사한 뒤 `[담당 영역]`을 자신의 영역으로 바꿔 보내세요. 이 단계에서는 **수정을 요청하지 않습니다.**

```text
LUMIA 프로젝트 작업을 시작합니다. 지금은 파일을 수정하지 말고 프로젝트 기준부터 확인해 주세요.

1. document_for_ai/00_READ_FIRST.md와 그 문서가 안내하는 01~06 문서를
   순서대로 읽으세요. 저장소에 접근할 수 있다면 AGENTS.md와 README.md도 읽으세요.
   접근할 수 없는 파일은 읽었다고 말하지 말고 알려 주세요.
2. 내 담당 영역은 [engine / story / asset / backend]입니다.
   접근 가능하다면 해당 영역의 README.md와 관련 팀 문서·실제 파일을 확인하세요.
3. 저장소 전체에 접근할 수 있다면 git status와
   node document_for_ai/check_sources.mjs의 결과를 확인하세요.
   CHANGED가 나오면 관련 원문과 안내된 AI 문서를 다시 읽으세요.
   UNTRACKED, ASSET README, MANIFEST가 나오면 새 관리 문서 등록, 자원 README 불일치,
   manifest 자체 문제 중 무엇인지 구분해 보고하세요.
   지금은 --record를 실행하지 마세요.
4. 현재 사용자의 명시적 결정과 최신 팀 문서·실제 파일을 AI 요약보다 우선하세요.
   기획, 제작된 자원, 구현·검수 완료, 미정을 구별하고 확인하지 못한 내용은 추정하지 마세요.
5. 읽은 자료, 담당 범위, 확인된 현재 상태, 문서 간 충돌·미정 사항,
   작업 전에 내 결정이 필요한 사항을 간단히 보고하세요.
   이 단계에서는 코드·문서·이미지를 변경하거나 브랜치를 전환하지 마세요.
6. 이후 같은 대화에서 내가 작업을 요청하면, 내 담당 영역과 저장소 규칙을
   기준으로 필요한 파일·수정 범위·검증 방법을 스스로 판단해 진행하세요.
   매 작업에 관련된 최신 문서와 실제 파일을 확인하고 결과를 검증하세요.
   내가 파일 목록이나 완료 기준을 따로 지정하지 않아도 진행하세요.
   다만 담당 영역 밖의 변경, prototype/·lumia/ 수정, 기존 데이터의 삭제·대규모
   이동, 근거 없는 설정·기술·자원 최종 선택이 필요하면 먼저 이유를 설명하고
   내 결정을 요청하세요. 완료 후에는 변경 내용, 검증 결과, 남은 미정 사항을
   간단히 보고하세요.
```

AI의 보고를 보고 **담당 영역과 자료 접근 여부가 맞는지** 확인하세요. 파일을 읽지 못했다면 요약을 사실로 받아들이지 말고 자료를 제공한 뒤 다시 확인받으세요. `check_sources.mjs`의 `CHANGED`는 원문 재검토 신호, `UNTRACKED`는 새 관리 문서의 manifest 등록 필요, `ASSET README`는 실제 자원과 README 불일치, `MANIFEST`는 manifest 자체 오류를 뜻합니다. route가 이미 명확한 새 문서는 검토 후 `--add-untracked`로 등록할 수 있지만, AI 요약까지 자동으로 수정되는 것은 아닙니다.

## 이후에는 평소처럼 작업 요청

첫 답변에서 **담당 영역과 자료 접근 여부가 맞는지** 확인했다면, 같은 대화에서 별도의 2단계 양식 없이 작업을 말하세요. 예: “시온과 대화하는 새 에피소드를 만들어 줘”, “아이템 이미지 목록에서 누락된 설명을 채워 줘”, “현재 엔진 구조에서 대화 선택 기능을 구현해 줘”. 필요한 수정 파일과 적절한 검증은 AI가 현재 자료를 확인해 결정합니다. 팀원은 특정 파일이나 결과 조건이 **정말 중요할 때만** 추가로 알려 주면 됩니다.

새 AI 대화를 열었거나 다른 AI 도구로 옮겼다면 첫 프롬프트부터 다시 사용하세요. 이전 대화에서 읽은 문서나 결정이 자동으로 전달되었다고 가정하지 마세요.

## 작업 중·완료 후 확인

- AI가 문서와 실제 파일이 충돌한다고 보고하면, 원문을 확인하고 팀의 결정을 명시하세요. AI에게 확정되지 않은 설정을 채우게 하지 마세요.
- 이미지 변경 시 카테고리 README의 파일 목록·설명·미리보기를 함께 확인하세요. 팀 문서를 바꿨다면 관련 AI 요약도 검토해야 합니다. 자세한 기준은 [AI 협업 규칙](../document_for_ai/06_WORKSPACE_RULES.md)에 있습니다.
- 결과를 받을 때 변경 파일과 검증 결과를 확인하세요. AI가 보고한 “완료”와 팀의 최종 승인·통합은 별개입니다.
