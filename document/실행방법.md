# LUMIA 실행·배포 방법

최종 사용자는 별도 설치 없이 [Vercel LUMIA 웹 주소](https://lumia-web-six.vercel.app/)로 접속합니다. 게임 클라이언트는 Vercel에서 제공하고, 백엔드 API는 Render의 FastAPI Web Service로 운영할 예정입니다. 현재 프론트 배포는 성공했지만 API 연결과 운영 E2E는 진행 중입니다.

## 실행에 필요한 환경

최종 사용자에게 별도 실행 환경은 필요하지 않습니다. Chrome, Edge, Safari 등 현대적인 웹 브라우저에서 Vercel 주소로 접속합니다.

개발 환경은 게임 클라이언트 빌드에 Node.js와 npm, 백엔드에 Python 3.13이 필요합니다. Firebase Emulator 검증에는 Firebase CLI와 JDK 21 이상도 필요합니다.

## 설치 방법

최종 사용자는 설치하지 않습니다. 개발자는 저장소 루트에서 `npm ci`와 `python3.13 -m venv backend/api/.venv`, `backend/api/.venv/bin/pip install -r backend/api/requirements-dev.txt`를 실행합니다. 배포 환경 설정 순서는 [Phase 12 배포 안내](../backend/api/deploy/README.md)에 기록했습니다.

## 실행 명령

운영 서비스는 Vercel URL 접속으로 실행합니다. 별도 서버 명령을 사용자가 실행하지 않습니다.

독립 미니게임 데모는 저장소 루트에서 `node engine/minigame-demo/server.mjs`로 계속 실행할 수 있지만, 이는 최종 LUMIA 실행 방법이 아닙니다.

## 개발 서버

### 현재 엔진 UI 개발판

저장소 루트에서 `node engine/server.mjs`를 실행하고 `http://127.0.0.1:4173/`로 접속합니다. 현재 개발판은 추가 패키지 설치 없이 동봉된 Phaser 배포본을 사용합니다. Firebase/Auth·API 연동은 `npm run build:web`으로 생성하는 별도 웹 빌드에 연결하며 Firebase Web App·Render URL 설정이 필요합니다. 이 빌드의 운영 배포는 아직 검증 전입니다.

시작하기/새로 시작하기 → 첫 빈 슬롯 자동 배정 → 캐릭터 선택 → 초대장·입학 이야기 시안 → 마이룸 → 주간 일정으로 확인합니다. 마이룸의 가방 → 펫 탭에서는 해금된 펫 선택과 현재 펫·임시 스탯 보정 표시를 확인할 수 있습니다. 본편에 미등록된 대사·자동 해금·AI·엔딩은 개발판 프레임 또는 명시된 시안 상태입니다.

소스 변경은 브라우저 새로고침으로 확인하고 서버 종료는 실행 터미널의 `Ctrl+C`입니다. 주중 진행과 일정 초안은 주말 저장 전까지 유지되지 않으므로 저장 경계를 마친 뒤 새로고침하세요. 포트/주소마다 로컬 저장 공간이 달라집니다. 상세 제약·검증 명령은 [엔진 README](../engine/README.md)를 확인합니다.

### 운영 배포 주소 (생성 후 기록)

운영 프론트: [https://lumia-web-six.vercel.app/](https://lumia-web-six.vercel.app/) — `main` 커밋 `a0e8b67`의 로그인 화면 로드를 확인했습니다. API 의존 흐름은 아직 운영 검증 전입니다.

운영 API: `https://<render-service>.onrender.com` 형태의 주소를 사용하며 게임 클라이언트 내부에서 호출합니다. 일반 사용자가 API 주소를 직접 사용할 필요는 없습니다.

## 검증

최종 사용자 실행 안내에 별도 테스트 명령은 두지 않습니다. 개발 검증은 저장소 루트에서 `node --test engine/tests/*.test.mjs engine/minigame-demo/tests/*.test.mjs`와 `backend/api/.venv/bin/python -m pytest backend/api/tests -q`로 실행합니다. Firebase Emulator 전용 테스트와 운영 브라우저 E2E는 [Phase 12 배포 안내](../backend/api/deploy/README.md)를 따릅니다. 독립 미니게임 데모만 검증할 때는 `cd engine/minigame-demo && npm test`를 사용합니다.

## 환경 변수

운영 환경변수의 기준 목록은 [기술 스택](10_TECH_STACK.md)을 따릅니다.

- Vercel: `LUMIA_API_BASE_URL=https://lumia-api-pcxd.onrender.com` (운영 Config, 기존 `VITE_API_BASE_URL`보다 우선), `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` (공개 Web App 설정)
- Render: `CORS_ORIGINS`, Firebase Admin 자격 증명, `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_THINKING_LEVEL`

API 키·서비스 계정 같은 비밀값은 Git에 커밋하지 않습니다.

## 포트

운영 서비스의 외부 포트는 Vercel/Render가 관리합니다. Render FastAPI는 배포 시 플랫폼이 제공하는 `$PORT`를 사용합니다. 현재 엔진 개발판은 로컬 `4173`(`LUMIA_ENGINE_PORT`로 변경), 독립 미니게임 데모는 로컬 `4174`(`LUMIA_MINIGAME_PORT`로 변경)를 사용합니다.

## 종료 방법

웹 게임은 브라우저 탭을 닫아 종료합니다. Render/Vercel 운영 서비스의 시작·종료는 배포 플랫폼에서 관리합니다.

## 갱신 규칙

Render 서비스가 생성되면 API URL을 이 문서와 루트 README에 기록합니다. Phase 12는 Emulator·로컬 브라우저 검증과 Vercel 프론트 배포까지만 확인했고 운영 Firebase/Render/Vercel E2E는 미완료입니다. 엔진 또는 백엔드의 로컬 실행 방식이 바뀌면 실제 설정 파일과 검증 결과를 기준으로 갱신합니다.
