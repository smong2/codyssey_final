# 기능·비기능 요구 명세와 시스템 아키텍처

이 문서는 WBS 10.1.2의 기준 문서입니다. Final Project 제출에서 요구하는 기능 요구사항, 비기능 요구사항, 시스템 구조, 기술 선택 경계를 LUMIA 기준으로 정리합니다.

## 1. 시스템 범위

LUMIA의 제출 범위는 다음 네 영역으로 구분합니다.

1. **게임 클라이언트** — 52주 플레이, 수업·모험·휴식, 이벤트, 수집·해금, 엔딩 UI
2. **계정·저장 API** — Firebase 인증, 5개 세이브 슬롯, Global Meta, 플레이 기록
3. **AI 엔딩** — 규칙 기반 직업 판정 후 Gemini 개인화 편지 생성
4. **운영 관리자 콘솔** — LUMIA 제작·운영팀이 별도 주소로 로그인하여 회원·플레이 기록과 운영 통계를 조회하고, 제한된 전역 밸런스 값을 조정하는 관리 화면

관리자 콘솔은 일반 게임 사용자 화면과 분리합니다. 운영자는 승인된 관리자 계정만 사용하며, 일반 사용자가 관리자 권한을 획득하는 기능은 제공하지 않습니다. 사용자별 세이브·스탯·해금을 직접 수정하는 CMS나 스토리 원고 CRUD는 Final Project 범위에서 제외합니다.

## 3. 운영 관리자 콘솔

관리자 콘솔은 **LUMIA 제작·운영팀을 위한 운영 화면**입니다. 일반 사용자 게임과 다른 주소로 배포하며, 실제 URL은 배포 단계에서 확정합니다.

### 3.1 인증·권한

- Firebase Authentication으로 관리자 계정을 인증할 수 있습니다.
- 승인된 관리자 계정은 최대 **3개**까지 운영합니다.
- 일반 사용자 계정과 인증 시스템을 공유하더라도 서버 측 Firebase Custom Claim 또는 승인 UID 기준으로 `admin` 권한을 별도 확인합니다.
- 관리자 권한은 클라이언트에서 자기 자신에게 부여할 수 없습니다.
- 관리자 API는 `/admin/*`처럼 일반 게임 API와 경로를 분리합니다.
- 로그인 성공·실패는 감사로그 대상입니다.

### 3.2 개별 사용자 조회

- 이메일 / UID
- 가입 시각 / 마지막 플레이 시각
- 세이브 슬롯 상태 / 플레이 캐릭터 / 현재 주차
- 회차 완료 횟수
- 현재 회차의 보이는 성장 스탯
- 수업·모험·미니게임·NPC 조우 등 주요 누적 기록
- 캐릭터·펫·배지·마이룸 배경 해금 현황
- 확인한 직업 엔딩과 저장된 엔딩 편지

비밀번호, Firebase Token, 서비스 계정 자격 증명은 표시하지 않습니다. 보이지 않는 스탯의 원시 수치와 전체 대화 원문은 기본 관리자 화면에 노출하지 않습니다.

### 3.3 운영 통계

최소 통계 범위는 다음과 같습니다.

- 전체 가입 사용자 / 플레이 기록 보유 사용자 / 최근 7일·30일 활동 사용자
- 52주 회차 1회 이상 완료 사용자와 전체 완료 회차 수
- 수업 / 모험 / 휴식 / 특수 활동 횟수
- 미니게임별 `FAIL / SUCCESS / GREAT` 및 성공 비율
- NPC Story / Location Story 주요 진행 건수
- 완료 회차의 성장 스탯별 평균 최종값과 `300 이상 / 500 도달` 비율
- 직업 엔딩별 노출 횟수
- 캐릭터·펫·배지·마이룸 배경 해금 집계

통계는 최소 `일 / 주 / 월` 기간 필터를 제공하며, **월별 집계는 필수**입니다. 월별 화면에서는 가입 사용자, 활동 사용자, 완료 회차, 활동·미니게임 결과, 엔딩 분포 등 주요 지표를 월 단위로 비교할 수 있어야 합니다. 월 경계는 KST 달력 월을 기준으로 합니다.

통계 화면은 집계값 위주로 표시하고 이메일 같은 개인 식별 정보를 통계 결과에 섞지 않습니다.

### 3.4 전역 성장 보상 조절

관리자가 직접 퍼즐 규칙이나 사용자별 저장값을 수정하지 않고, 반복 가능한 수업·미니게임·모험에서 얻는 보이는 성장 스탯의 획득량만 전역 배율로 조정합니다.

- 대상: `지식 / 표현력 / 솜씨 / 탐험 / 마법`
- 스탯별 `rewardMultiplier` 기본값 `1.0`
- 허용 범위 `0.5~1.0`, 변경 단위 `0.1`
- 설정 변경 이전의 저장 스탯에는 소급 적용하지 않음
- 변경 이후 완료되는 활동 보상부터 적용
- Main/NPC/Location Story의 명시적 일회성 스탯 변화와 보이지 않는 스탯에는 적용하지 않음
- 설정에는 `version / updatedAt / updatedBy`를 기록

구체적인 성장량 계산 계약은 `document/content/02_STATS_EVENTS_ENDINGS/01_STATS_SYSTEM.md`를 따릅니다.

### 3.5 감사로그

Final Project의 필수 감사로그는 다음 두 범위로 제한합니다.

- 관리자 로그인 성공/실패: 시각, 성공 여부, 관리자 UID 또는 마스킹된 시도 식별자, 비밀정보가 없는 실패 코드
- 운영 값 변경: 시각, 관리자 UID, 변경 key, 이전값, 변경값, 설정 version

운영 환경에서 확보 가능한 경우 IP와 User-Agent도 함께 기록할 수 있습니다. 비밀번호, Firebase ID Token, Gemini API Key, Firebase Admin 자격 증명은 로그에 남기지 않습니다.

| NFR-013 | AI Memory 경계 | Long-term Memory는 일반 세이브와 구분해 현재 회차의 장기 플레이 기억을 AI 개인화에 실제 사용하며, 이전 회차 기억은 다음 회차 엔딩 편지에 자동 혼합하지 않는다. |

정량적인 응답 시간·가용성 SLA는 학교 Final Project 프로토타입에 근거 없는 숫자를 만들지 않고, 실제 배포·사용자 테스트 결과가 나온 뒤 측정값으로 기록합니다.

```text
├─ 누적 플레이 기록
├─ 엔딩 기록·편지
├─ 관리자 기간 통계용 활동 요약·집계
├─ 운영 밸런스 설정
└─ 관리자 감사로그

운영자 브라우저
└─ 관리자 콘솔 (별도 Admin URL)
        ↓ Firebase Authentication + admin 권한
FastAPI / Render `/admin/*`
├─ 회원·플레이 조회
├─ 운영 통계 집계
└─ 전역 밸런스 설정 변경
```

게임 클라이언트의 로컬 SQLite는 마스터·화면 조회와 미확정 상태에 사용합니다. 확정 세이브·보상·엔딩은 FastAPI가 검증해 Firestore에 저장합니다. 관리자 콘솔은 플레이어 기기의 SQLite에 접근하지 않고 중앙 Firestore의 사용자 기록·기간 집계·설정·감사로그를 권한 검증 후 조회합니다. [저장 경계·테이블 목록](../backend/database/STORAGE_DESIGN.md)을 상세 기준으로 사용합니다.

## 6. 기술 선택 이유

세부 선정 이유는 `document/10_TECH_STACK.md`를 기준으로 합니다. 요약하면 Phaser 3는 기존 웹 게임/미니게임 자산을 이어 쓰기 위해, FastAPI는 서버 규칙·Firebase Admin·Gemini 연동을 분리하기 위해, Firebase Auth/Firestore는 계정 인증과 계정별 문서형 상태·관리자 중앙 조회를 위해 사용합니다. 플레이어 로컬 SQLite는 반복 조회와 임시 상태를 기기에서 처리해 불필요한 서버 요청을 줄이기 위해 사용합니다. Vercel과 Render는 프론트/API 배포 책임을 분리하며, Gemini는 52주 실제 기록을 고정 문구가 아닌 개인화된 서사 보상으로 표현하기 위해 사용합니다.
