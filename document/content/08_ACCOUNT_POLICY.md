# 계정·인증·탈퇴 정책

이 문서는 WBS 2.6의 기준 문서입니다. LUMIA Final Project의 계정 범위를 **Email/Password + 이메일 인증**으로 단순화하고, 최소 개인정보 수집과 탈퇴 시 데이터 삭제 범위를 정의합니다.

## 1. 기본 원칙

- 게스트 플레이는 Final Project 범위에서 제공하지 않습니다.
- 게임을 시작하려면 **이메일, 비밀번호, 이메일 인증** 절차를 먼저 완료해야 합니다.
- 인증은 Firebase Authentication을 사용하고 비밀번호는 LUMIA 서버·Firestore에 저장하지 않습니다.
- 회원가입 과정에서 이름, 생년월일, 성별, 전화번호, 주소, 프로필 사진, 보호자 정보는 수집하지 않습니다.
- 게임 데이터의 사용자 기준 키는 Firebase Authentication의 `uid`입니다.
- 이메일은 로그인·인증·비밀번호 재설정을 위한 최소 계정 정보로만 사용합니다.

게스트로 먼저 시작한 뒤 저장 시점에 이메일 계정으로 전환하는 방식은 사용자 진입 장벽은 낮지만, 익명 계정과 정식 계정의 연결·인증 전환·세이브 소유권·복구 예외를 추가로 처리해야 합니다. 구현 일정 단축을 위해 이번 Final Project에서는 사용하지 않습니다.

## 2. 회원가입

### 입력 항목

회원가입 화면은 다음 항목만 받습니다.

1. 이메일
2. 비밀번호
3. 비밀번호 확인
4. `[필수] 개인정보 수집·이용 동의`

비밀번호는 클라이언트에서 최소 8자 이상인지 확인하고, 비밀번호 확인 값이 일치해야 가입 요청을 보냅니다. 실제 인증 계정 생성과 비밀번호 정책 검증은 Firebase Authentication을 사용합니다.

### 개인정보 동의 안내

가입 화면에서 별도의 긴 가입 설문은 만들지 않고 다음 최소 내용을 확인할 수 있게 합니다.

```text
수집 항목: 이메일 주소
이용 목적: 계정 인증, 로그인, 비밀번호 재설정, 게임 저장 데이터 연결
보관 기간: 회원 탈퇴 시까지
```

동의하지 않으면 회원가입을 진행하지 않습니다. 동의한 시각과 동의 문구 버전은 서버에 기록할 수 있도록 `privacyConsentAt`, `privacyConsentVersion`을 계정 메타에 저장합니다.

> 이 정책은 Final Project 프로토타입의 최소 개인정보 처리 기준입니다. 9~11세 아동을 실제 공개 서비스의 이용자로 운영할 때 필요한 법정대리인 동의 등 법적 요건을 충족한다고 단정하지 않으며, 실제 상용·공개 운영 전에는 별도 법률·정책 검토가 필요합니다.

## 3. 이메일 인증

```text
회원가입
→ Firebase 계정 생성
→ 인증 메일 발송
→ 인증 대기 화면
→ 사용자가 이메일 링크에서 인증
→ 인증 완료 확인
→ 현재 인증 세션 갱신
→ 인트로/타이틀 진입
```

- 이메일 인증을 완료하지 않은 계정은 게임 본편에 진입할 수 없습니다.
- 인증 대기 화면에는 `인증 메일 다시 보내기`와 `인증 완료 확인`을 제공합니다.
- 인증 완료 전에는 세이브 슬롯·Global Meta 같은 본편 게임 데이터를 생성하지 않는 것을 기본으로 합니다.
- 회원가입 직후 이미 Firebase 인증 세션이 있는 사용자는 `인증 완료 확인`이 성공하면 이메일/비밀번호를 다시 입력시키지 않고 그대로 게임 진입 흐름으로 이동합니다.
- 로그인 페이지 영역은 `로그인 / 회원가입 / 이메일 인증 대기·확인 / 비밀번호 분실 복구 진입`까지 담당하며, 인증 완료 전에는 인트로·타이틀을 노출하지 않습니다.

## 4. 로그인·재접속

로그인 화면은 `이메일 / 비밀번호 / 로그인 / 비밀번호 재설정 / 회원가입`만 제공합니다.

- 이메일 인증이 완료된 계정만 게임에 진입합니다.
- 브라우저 로그인 상태는 유지하며, 사용자가 명시적으로 로그아웃하기 전까지 다음 접속에서 자동으로 인증 상태를 복원합니다.
- 별도의 `로그인 유지` 체크박스는 두지 않습니다.
- 로그인 후 FastAPI 보호 API 요청에는 Firebase ID Token을 보내며 서버는 토큰 유효성과 `email_verified`를 검사합니다.
- 자동 복원된 계정이 이메일 미인증 상태라면 게임으로 이동하지 않고 인증 대기 화면을 다시 표시합니다.

### 로그인 오류 문구

기술 오류 코드를 그대로 보여 주지 않고 다음 정도로 단순화합니다.

| 상황 | 사용자 안내 |
|---|---|
| 계정 없음 또는 비밀번호 불일치 | `이메일 또는 비밀번호를 확인해주세요.` |
| 이메일 미인증 | `이메일 인증이 필요합니다.` |
| 올바르지 않은 이메일 형식 | `이메일 형식을 확인해주세요.` |
| 네트워크·일시적 서버 오류 | `잠시 후 다시 시도해주세요.` |

회원가입에서 이미 사용 중인 이메일은 `이미 사용 중인 이메일입니다.`로 안내합니다.

## 5. 비밀번호 변경·분실 복구

### 로그인 상태에서 비밀번호를 알고 있는 경우

아이들이 계정 관리 중 게임 밖으로 이동하는 흐름을 최소화하기 위해 **게임 내부 계정 화면에서 비밀번호를 직접 변경**합니다.

```text
비밀번호 변경
→ 현재 비밀번호 입력
→ 새 비밀번호 입력
→ 새 비밀번호 확인
→ 현재 계정 재인증
→ 새 비밀번호 적용
→ 게임 내부에서 변경 완료 안내
```

- 새 비밀번호는 가입과 동일하게 최소 8자 이상을 기본 클라이언트 검증으로 사용하고 실제 정책 검증은 Firebase Authentication에 맡깁니다.
- 현재 비밀번호가 틀리면 `현재 비밀번호를 확인해주세요.`로 안내합니다.
- 새 비밀번호와 확인 값이 다르면 Firebase 요청 전에 화면에서 안내합니다.
- 게임 서버와 Firestore에는 현재 비밀번호나 새 비밀번호를 저장하지 않습니다.

### 현재 비밀번호를 잊은 경우

- 현재 비밀번호를 모르면 게임 내부 재인증으로 변경할 수 없으므로 **예외적으로 이메일 기반 비밀번호 재설정 흐름**을 사용합니다.
- 로그인 화면의 `비밀번호를 잊으셨나요?` 또는 게임 내부 비밀번호 변경 화면의 `현재 비밀번호를 잊으셨나요?`에서 등록 이메일로 재설정 메일을 요청할 수 있습니다.
- 사용자가 이메일의 보안 링크에서 본인 확인과 새 비밀번호 설정을 완료하는 외부 흐름은 계정 복구 상황에만 허용합니다.
- 정상적인 로그인 상태의 비밀번호 변경에는 외부 이메일 화면을 요구하지 않습니다.

## 6. 계정 관리 범위

Final Project에서는 별도의 빈 `환경설정 → 계정` 2단계 구조를 만들지 않습니다. 현재 별도 설정 카테고리가 계정밖에 없으므로 **게임 내 메뉴에 `계정`을 1뎁스로 직접 노출**합니다. 이후 사운드·접근성 등 실제 설정 영역이 여러 개 생기면 그때 `환경설정` 상위 메뉴로 재구성할 수 있습니다.

계정 화면은 다음 정보를 보여 줍니다.

- 연결된 이메일 — 읽기 전용
- 최초 가입 일자 — 읽기 전용
- `비밀번호 변경`
- `다른 기기에서 모두 로그아웃`
- `이 기기에서 로그아웃`
- `계정 탈퇴`

최초 가입 일자는 서버 사용자 루트의 `createdAt`을 기준으로 날짜 단위로 표시합니다. 로그인 이메일은 기존 정책대로 Firebase Authentication 사용자 정보에서 읽고 Firestore에 중복 저장하지 않습니다.

다음 기능은 구현하지 않습니다.

- 이메일 주소 변경
- 닉네임·이름·프로필 사진 변경
- 소셜 로그인 연결
- 보호자 계정과 자녀 계정 연결
- 다른 사용자 검색·관리
- 게임 데이터 전체 초기화 버튼

이메일을 바꾸고 싶은 경우 이번 Final Project에서는 새 계정을 만드는 방식만 지원합니다. 계정 간 게임 데이터 이전 기능은 제공하지 않습니다.

### 다른 기기에서 모두 로그아웃

`다른 기기에서 모두 로그아웃`은 지속 설정이 아니라 **한 번 실행하는 계정 보안 명령**이므로 체크박스가 아니라 버튼으로 제공합니다.

```text
[다른 기기에서 모두 로그아웃]
→ 현재 비밀번호 입력
→ 현재 계정 재인증
→ 기존 원격 세션 무효화
→ 현재 기기 세션만 새 인증 상태로 갱신
→ 완료 안내
```

- 목적은 **현재 기기는 로그인 상태를 유지하면서 다른 기기의 기존 로그인 세션을 해제**하는 것입니다.
- 실제 구현에서는 Firebase Admin의 사용자 세션/refresh token 폐기 기능과 현재 기기의 재인증을 조합합니다.
- 보호 API는 세션 폐기 이후의 오래된 인증 상태를 허용하지 않도록 토큰 유효성뿐 아니라 폐기 여부를 검증해야 합니다.
- 다른 기기가 즉시 화면을 닫는 것을 보장하는 실시간 원격 제어 기능은 범위에 포함하지 않습니다. 해당 기기가 보호 API를 다시 사용하거나 인증을 갱신할 때 재로그인이 필요하도록 처리합니다.

## 7. 로그아웃

- `이 기기에서 로그아웃`은 현재 브라우저의 Firebase 인증 세션만 종료합니다.
- Firestore의 세이브 슬롯, Global Meta, 엔딩 기록은 삭제하지 않습니다.
- 다시 같은 계정으로 로그인하면 기존 서버 저장 데이터를 그대로 사용합니다.
- 일반 로그아웃에는 데이터 삭제 확인창을 사용하지 않고 로그인 페이지로 이동합니다.

## 8. 계정 탈퇴

계정 탈퇴는 슬롯 삭제보다 강한 파괴적 기능이므로 명시적 확인을 사용합니다.

```text
계정을 탈퇴하면 모든 게임 기록과 엔딩 편지가 영구 삭제됩니다.
삭제한 데이터는 복구할 수 없습니다.

[취소] [계정 탈퇴]
```

탈퇴 처리 전에 Firebase가 최근 로그인을 요구하는 경우 사용자에게 비밀번호 재입력 등 재인증 절차를 안내합니다.

### 삭제 대상

탈퇴가 확정되면 해당 `uid`에 연결된 다음 데이터를 모두 삭제합니다.

- 사용자 계정 메타 `users/{uid}`
- Account Settings
- Global Meta Progress
- Global Statistics
- Unlock State
- 세이브 슬롯 5개와 진행 중 Active Run
- 모든 Ending Record와 저장된 AI 엔딩 편지
- 기타 해당 UID 아래에서 생성된 사용자 전용 게임 데이터
- Firebase Authentication 계정

슬롯 삭제와 달리 **계정 탈퇴에서는 Global Meta도 유지하지 않습니다.**

### 삭제·복구 정책

- Final Project에서는 별도 탈퇴 유예 기간이나 휴지통을 만들지 않습니다.
- 탈퇴 완료 후 복구 기능을 제공하지 않습니다.
- 같은 이메일로 나중에 다시 가입하더라도 이전 게임 데이터를 복원하지 않습니다.
- 계정 탈퇴 API는 사용자 본인의 유효한 Firebase ID Token을 요구합니다.

## 9. 개인정보 최소화

Firestore에는 로그인 이메일을 중복 저장하지 않는 것을 기본으로 합니다. 이메일 확인이 필요한 화면은 Firebase Authentication의 현재 사용자 정보에서 읽습니다.

AI 엔딩 편지 입력에는 다음 정보를 보내지 않습니다.

- 이메일
- 비밀번호
- Firebase ID Token
- 개인정보 동의 시각
- Firebase UID처럼 편지 내용에 불필요한 계정 식별 정보

AI에는 확정 직업, 게임 캐릭터, 실제 52주 플레이 기록과 필요한 중요 선택 등 게임 안에서 생성된 최소 데이터만 전달합니다. 대표 사건 목록은 별도로 전달하지 않습니다.

## 10. WBS 완료 기준

### 2.6.1 가입·로그인 요구사항

- Email/Password 입력 범위 확정
- 이메일 인증 완료 전 게임 이용 차단
- 인증 메일 재발송·인증 확인 흐름 확정
- 로그인 유지·로그아웃 동작 확정
- 간단한 오류 문구 확정
- 로그인 상태의 게임 내부 비밀번호 변경 방식 확정
- 비밀번호 분실 시 이메일 복구 방식 확정
- 최소 개인정보 수집·동의 범위 확정
- 게스트 플레이 제외 확정

### 2.6.2 이용자 계정 관리·탈퇴 정책

- 계정 관리 최소 기능 확정
- 연결 이메일·최초 가입 일자 표시 확정
- 다른 기기 모두 로그아웃 정책 확정
- 이메일 변경 등 범위 밖 기능 확정
- 로그아웃 시 데이터 유지 범위 확정
- 슬롯 삭제와 계정 탈퇴 차이 확정
- 탈퇴 시 Auth + 해당 UID 게임 데이터 전체 삭제 확정
- 탈퇴 후 복구·데이터 이전 없음 확정
