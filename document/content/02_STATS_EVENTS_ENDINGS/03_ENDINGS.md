# 엔딩 시스템

## 1. 엔딩 구조

12월 24일의 최종 메인 이벤트를 해결하고 52주차 마지막 자유 플레이까지 완료하면, 12월 31일에 플레이 기록을 종합해 **미래 직업 엔딩**을 노출합니다.

엔딩은 **정규 직업 엔딩 10종 + 조건 미충족 시 사용하는 별도 fallback 엔딩 1종**으로 구성합니다.

정규 직업 엔딩은 다음의 단순한 공통 계약을 사용합니다.

```text
필수 조건
→ 해당 직업의 대표 보이는 스탯 >= 300

선택 조건 3개
→ 보조 보이는 스탯 >= 200
→ 직업과 관련된 보이지 않는 스탯 >= 40
→ 직업과 관련된 실제 플레이 기록 기준 달성
```

필수 조건은 후보 진입 여부를 결정하고, 선택 조건은 여러 후보가 동시에 생겼을 때의 **적합도 0~3**을 결정합니다. 이 방식의 목적은 단일 숫자 하나로 모든 것을 판정하지 않으면서도 구현 가능한 수준으로 엔딩 규칙을 단순하게 유지하는 것입니다.

### 정규 직업 엔딩 10종

정규 직업의 **직업명·부제·직업의 의미·미래 장면 방향은 작가 문서 `story/ending/ENDING_STORY.md`를 원본으로 채택**합니다. 시스템 문서는 작가의 직업을 새로 작명하지 않고, 그 10종에 우리가 확정한 수치 판정 규칙을 연결합니다.

모든 정규 직업 엔딩은 **대표 보이는 스탯 300 이상**을 필수 조건으로 사용합니다. 필수 조건을 만족한 엔딩만 후보가 되며, 각 엔딩의 선택 조건 3개는 후보 사이의 적합도를 계산하는 데 사용합니다.

대표 스탯은 5종 각각 2개의 직업이 대응하도록 배치했습니다. 작가 문서의 서사 방향과 현재 게임에서 실제로 저장 가능한 수치 기록을 함께 고려한 시스템 매핑이며, **작가 문서의 특정 사건·선택 하나를 필수 게이트로 만들지는 않습니다.** 따라서 작가가 강조한 경험은 편지·미래 장면에 반영하되, 선택적 콘텐츠를 놓쳤다는 이유만으로 해당 직업이 봉쇄되지 않습니다.

정규 엔딩마다 선택 조건은 정확히 3개이며 **적합도 = 충족한 선택 조건 개수(0~3)** 로 계산합니다. 필수 조건을 만족했다면 선택 조건이 0개여도 정규 후보가 될 수 있습니다.

### 조건 미충족 fallback 엔딩 — `별길 개척자`

정규 직업 엔딩 10종의 필수 조건을 **하나도 만족하지 못한 경우**, 준비된 직업 중 하나를 억지로 보여 주지 않습니다. 대신 별도 엔딩을 사용합니다.

| 항목 | 값 |
|---|---|
| ID | `ENDING_STARPATH_PIONEER` |
| 플레이어 표시 직업 | **별길 개척자** |
| 유형 | `FALLBACK` |
| 의미 | 아직 하나의 전문 길로 자신을 묶지 않고 여러 가능성을 탐색하는 아르카디아의 자유로운 개척자 |

`별길 개척자`는 플레이어에게 실패나 꽝으로 표현하지 않습니다. 편지에서도 `조건을 만족하지 못했다`, `능력이 부족하다` 같은 표현을 사용하지 않고 **여러 분야를 경험했기 때문에 앞으로 선택할 수 있는 길이 많다**는 방향으로 설명합니다.

이 엔딩은 정규 직업 엔딩 10종과 별개이므로 `서로 다른 직업 엔딩 3개/10개` 같은 해금·배지 조건의 정규 엔딩 수에는 포함하지 않습니다. 다만 실제로 몇 번 보았는지는 계정의 `endingViewCounts[ENDING_STARPATH_PIONEER]`에 누적합니다.

## 2. 여러 엔딩 조건을 동시에 만족했을 때

한 회차에서 여러 직업 엔딩의 조건을 동시에 만족하는 것은 정상적인 상황으로 처리합니다. 플레이어에게 엔딩을 직접 선택하게 하지 않고, 이번 회차의 조건과 기존 엔딩 노출 기록을 이용해 하나를 결정합니다.

### 결정 순서

1. 이번 회차에서 조건을 만족한 직업 엔딩 후보를 모두 찾습니다.
2. 후보를 **아직 노출되지 않은 엔딩**과 **이미 노출된 엔딩**으로 구분합니다.
3. 아직 노출되지 않은 엔딩이 하나라도 있으면 이미 본 엔딩은 이번 판정에서 우선순위를 낮추고, **미노출 엔딩 후보만 대상으로 결정**합니다.
4. 미노출 후보가 여러 개라면 각 직업의 **선택 조건 충족 개수(적합도 0~3)** 를 비교합니다.
5. 적합도가 같다면 위 직업표의 **동률 대표 기록**을 비교합니다.
6. 대표 기록까지 같다면 해당 직업의 **대표 보이는 스탯**을 비교합니다.
7. 위 비교까지 모두 같다면 후보 중 하나를 무작위로 선택합니다.
8. 이번 회차에서 만족한 엔딩이 **모두 이미 노출된 엔딩**이라면 후보 전체에서 무작위로 하나를 선택합니다.
9. 정규 후보가 하나도 없다면 `ENDING_STARPATH_PIONEER`를 확정합니다.

핵심 원칙은 다음과 같습니다.

`정규 필수 조건 확인 → 미노출 엔딩 우선 → 적합도 → 대표 기록 → 대표 스탯 → 랜덤 → 정규 후보 0개면 별길 개척자`

미노출 엔딩을 우선한다고 해서 이번 회차에서 조건을 만족하지 않은 엔딩을 강제로 보여주지는 않습니다.

### 판정 테스트 사례

| 사례 | 후보 상태 | 결과 |
|---|---|---|
| A | 미노출 후보 2개, 적합도 `3 vs 2` | 적합도 3인 엔딩 |
| B | 미노출 후보 2개, 적합도 동일 | 각 엔딩의 동률 대표 기록이 높은 쪽 |
| C | 적합도·대표 기록 동일 | 대표 보이는 스탯이 높은 쪽 |
| D | 위 값까지 모두 동일 | 해당 미노출 후보 중 랜덤 |
| E | 만족한 후보가 모두 이미 본 엔딩 | 만족한 정규 후보 전체 중 랜덤 |
| F | 정규 직업 필수 조건을 하나도 만족하지 못함 | `별길 개척자` |

## 3. 고정 엔딩 문구 — `무엇을 지켰니?`

12월 31일 마지막 주간 요약 뒤에는 작가 원문의 질문 **`무엇을 지켰니?`** 를 엔딩 진입의 고정 문구로 사용합니다.

이 문구는 플레이어에게 정답을 요구하는 퀴즈가 아니며, 게임 시스템이나 생성형 AI가 `네가 지킨 것은 우정이다`처럼 하나의 답을 대신 판정하지 않습니다. 이후 직업 엔딩과 편지가 이번 52주의 실제 행동·선택·NPC 교류와 사건을 되돌려 보여 주고, 플레이어가 스스로 질문의 의미를 느끼게 하는 구조를 사용합니다.

엔딩 표시 흐름은 다음과 같습니다.

```text
12월 31일 마지막 주간 요약
→ 고정 문구 `무엇을 지켰니?`
→ 규칙 엔진이 확정한 미래 직업 공개
→ 개인화 엔딩 편지
→ 필요한 엔딩·메타 기록 저장
```

별도의 `올해의 기억` 화면·섹션은 만들지 않습니다. **대표 사건 데이터는 엔딩 편지 입력에서 사용하지 않습니다.** 실제 횟수형 기록 4~6개와, 필요한 경우 엔딩과 관련성이 높은 중요 선택 최대 2개만 개인화에 사용합니다.

## 4. 엔딩 편지

엔딩은 단순 결과표보다 **아르카디아에서 보낸 52주를 돌아보는 편지** 형태로 전달합니다.

엔딩 직업은 이 문서의 규칙에 따라 게임 시스템이 먼저 확정하고, 최종 편지의 개인화 문장은 생성형 AI가 작성합니다. AI는 직업 엔딩을 다시 판정하거나 다른 직업으로 변경하지 않습니다. AI 입력·출력·안전·fallback의 상세 기준은 [AI 핵심 기능 — 개인화 엔딩 편지](../../09_AI_ENDING_LETTER.md)를 따릅니다.

편지에는 최소한 다음 내용을 포함합니다.

| 항목 | 내용 |
|---|---|
| 미래 직업 | 이번 회차에서 결정된 정규 직업 또는 `별길 개척자` |
| 직업 부제 | 정규 직업이면 작가 원문의 부제를 직업명과 함께 표시. fallback은 별도 부제 없이 사용 가능 |
| 스탯 기반 메시지 | 높은 보이는 스탯과 성장 방향을 자연어로 해석한 문장 |
| 플레이 기록 | 백엔드가 선별한 실제 횟수형 기록 4~6개. UI가 수치를 직접 표시 |
| 중요 선택 | 존재하는 경우 최대 2개의 실제 중요 선택을 AI 회고에 사용 |

편지에서는 `지식 342`처럼 수치를 그대로 나열하기보다, 스탯 수치를 바탕으로 **어떤 능력이 두드러졌는지 자연어로 설명**하는 것을 기본으로 합니다.

반면 플레이 기록은 실제 횟수를 보여줄 수 있습니다.

예시:

```text
아르카디아에서의 기록
- 수업에 참여한 횟수: 74회
- 모험을 떠난 횟수: 41회
- 새로운 장소를 발견한 횟수: 12회
- NPC와 만난 횟수: 86회
- 중요한 이야기를 완료한 횟수: 9회
```

모든 기록을 고정적으로 나열하기보다 **공통 기록과 해당 직업에 의미 있는 기록을 합쳐 4~6개** 보여 줍니다. 수치와 라벨은 AI 문장으로 만들지 않고 UI가 선별 데이터에서 직접 렌더링합니다.

예를 들어 탐험 계열 직업이라면 `모험 횟수 / 숨겨진 장소 발견 / 특별한 아이템 발견`을 강조하고, 관계·대화 계열 직업이라면 `NPC 만남 / NPC 스토리 완료 / 함께 해결한 사건`을 강조할 수 있습니다.

같은 직업 엔딩을 다시 보더라도 이번 회차의 플레이 기록·성장 방향·중요 선택이 다르면 생성형 AI가 이를 반영하므로 **편지 내용은 달라질 수 있습니다.**

## 5. 편지 기본 템플릿

```text
무엇을 지켰니?

[캐릭터 이름]에게

아르카디아에서 보낸 52주 동안 너는 많은 것을 배우고,
직접 선택하며 너만의 길을 만들어 왔구나.

너의 미래는 「[직업명]」이야.
[정규 직업이면 작가 부제]

[주요 보이는 스탯에 기반한 성장 메시지]
[필요하면 보이지 않는 스탯과 플레이 성향에 기반한 메시지]

아르카디아에서의 기록
- [플레이 기록 1]: [횟수]
- [플레이 기록 2]: [횟수]
- [플레이 기록 3]: [횟수]
- [플레이 기록 4]: [횟수]

[중요 선택이 있는 경우 그 선택을 짧게 돌아보는 문장]

[직업과 성장 방향을 연결하는 미래 메시지]

— 아르카디아 아카데미
```

`무엇을 지켰니?`는 AI가 생성하는 편지 본문이 아니라 엔딩 화면의 고정 작가 문구입니다. 직업명과 `careerAnchor`, `아르카디아에서의 기록`의 라벨·수치는 게임 데이터가 고정하며, AI는 그 데이터를 바꾸지 않고 개인화 회고와 미래 응원 문장만 생성합니다.
