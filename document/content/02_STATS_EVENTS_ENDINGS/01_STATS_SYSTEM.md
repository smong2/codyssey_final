# 스탯 시스템

## 1. 보이는 스탯

플레이어가 직접 확인하고 육성 계획에 사용하는 능력입니다.

| 스탯 | 시작값 | 최소 | 최대 | 의미 |
|---|---:|---:|---:|---|
| 체력 | 100 | 0 | 100 | 일정을 수행할 수 있는 현재 행동 자원 |
| 지식 | 50 | 0 | 500 | 학문, 이론, 문제 이해 능력 |
| 표현력 | 50 | 0 | 500 | 언어, 대화, 발표, 의사 전달 능력 |
| 솜씨 | 50 | 0 | 500 | 신체 활동, 도구 활용, 손재주와 실기 능력 |
| 탐험 | 50 | 0 | 500 | 조사, 발견, 관찰, 탐험 능력 |
| 마법 | 50 | 0 | 500 | 룬 마법과 마법적 현상을 이해·활용하는 능력 |

`체력`은 소모·회복되는 현재 자원입니다. 나머지 5개는 한 회차 동안 성장하는 육성 스탯이며, 이후 캐릭터별 초기 보정을 적용합니다.

## 2. 보이지 않는 스탯

플레이어에게 숫자로 직접 노출하지 않고 플레이 행동과 선택을 기록하는 내부 스탯입니다.

보이지 않는 스탯은 모두 `0~300`, 시작값 `0`으로 사용합니다. 수업처럼 반복해서 오르는 능력치가 아니라 **실제 선택 성향을 민감하게 기록하는 신호**이므로 적용 빈도는 낮게 유지하되, Story choice에서는 `+5/+8`처럼 선택 의미가 충분히 남는 가중치를 사용합니다. 8종에 분산되고 한 choiceNode에서는 하나의 보기만 적용되므로, 단순히 모든 선택의 최대 합을 한 스탯에 더하는 방식으로 상한을 계산하지 않습니다.

| 스탯 | 시작값 | 최소 | 최대 | 의미 |
|---|---:|---:|---:|---|
| 공감 | 0 | 0 | 300 | 다른 사람의 상황과 감정을 이해하려는 경향 |
| 책임 | 0 | 0 | 300 | 맡은 일과 약속을 끝까지 수행하려는 경향 |
| 호기심 | 0 | 0 | 300 | 새로운 장소·정보·현상을 알아보려는 경향 |
| 용기 | 0 | 0 | 300 | 부담이나 위험이 있어도 행동하려는 경향 |
| 협력 | 0 | 0 | 300 | 다른 사람과 함께 해결하려는 경향 |
| 독립성 | 0 | 0 | 300 | 스스로 판단하고 해결하려는 경향 |
| 신중함 | 0 | 0 | 300 | 충분히 살피고 생각한 뒤 결정하려는 경향 |
| 솔직함 | 0 | 0 | 300 | 자신의 생각과 사실을 숨기지 않고 표현하려는 경향 |

보이지 않는 스탯은 도덕적 선악을 판정하는 점수가 아니라 **플레이 스타일을 기록하는 내부 값**입니다. 서로 반대처럼 보이는 항목도 반드시 `+/-` 한 쌍으로 움직일 필요는 없습니다.

보이지 않는 스탯은 감점하지 않습니다. 예를 들어 협력적인 선택을 했을 때 `협력 +3`을 주더라도 `독립성 -3`을 자동으로 적용하지 않습니다.

### 보이지 않는 스탯 증가 기준

보이지 않는 스탯의 주된 성장 수단은 **대화·이벤트에서 플레이어가 실제로 고른 선택**입니다. 수업·미니게임의 성공은 성격이나 태도와 직접 연결하기 어렵기 때문에, 해당 게임 행동이 특정 내부 스탯과 명확히 연결되어 있다고 콘텐츠 데이터에 표시된 경우에만 약한 신호로 반영합니다.

| 발생 원인 | 기본 증가량 | 적용 기준 |
|---|---:|---|
| 관련 수업·미니게임 성공 | `+1` | 해당 게임에 명시적인 내부 스탯 태그가 있을 때만 적용 |
| 일반 짧은 대화 선택 | `+3` | Story가 아닌 일반 조우에서 선택 의미가 성향과 직접 연결될 때 |
| NPC·Location Story Primary Hidden | `+5` | 일반 교류·장소 Story의 핵심 선택 성향 |
| Main Story Primary Hidden | `+8` | 회차의 주요 사건에서 가장 강하게 드러나는 선택 성향 |
| NPC·Location Story Secondary Hidden | `+2` | 같은 선택에서 부가적으로 분명히 드러나는 성향이 있을 때만 |
| Main Story Secondary Hidden | `+3` | 핵심 사건에서 부가 성향이 명확할 때만 |
| 실패·무관한 행동 | `+0` | 내부 스탯을 억지로 연결하지 않음 |

하나의 선택에는 최대 2개의 보이지 않는 스탯 태그를 부여할 수 있습니다. 복수 태그를 사용할 때는 선택의 핵심 의미를 **Primary Hidden**, 부가적으로 드러난 성향을 **Secondary Hidden**으로 둡니다. 같은 `choiceNode` 안에서는 Secondary Hidden의 **유무와 총 증가량을 동일하게** 맞춰 어느 선택도 성장 효율의 정답이 되지 않게 합니다. 어떤 경우에도 반대 성향을 자동으로 감소시키지 않습니다.

### 현재 스토리 제작본의 선택 보상 기본값

현재 `story/main/MAIN_STORY_PRODUCTION.md`, `story/npc/NPC_STORY_PRODUCTION.md`, `story/location/LOCATION_STORY_PRODUCTION.md`에서 실제 제작하는 선택지는 **보이는 성장 스탯과 보이지 않는 스탯을 함께 변화**시킵니다.

| 스토리 구분 | 선택 1회당 보이는 성장 스탯 | Primary Hidden | Secondary Hidden | 비고 |
|---|---:|---:|---:|---|
| Main Story | 관련 성장 스탯 `+2` | `+8` | 필요한 선택만 `+3` | 핵심 사건 선택 |
| NPC Story | 관련 성장 스탯 `+1` | `+5` | 필요한 선택만 `+2` | 일반 교류 선택 |
| Location Story | 관련 성장 스탯 `+1` | `+5` | 필요한 선택만 `+2` | 일반 장소 선택 |

- 한 선택에서 보이는 성장 스탯은 기본적으로 **1종만** 올립니다.
- 현재 제작본은 모든 Story 선택에 **Primary Hidden 1종**을 반드시 두고, 의미가 충분히 강한 일부 choiceNode에만 Secondary Hidden 1종을 추가합니다.
- 선택지별 정확한 대상 스탯은 각 `*_PRODUCTION.md`의 `choiceId` 표를 원본으로 합니다.
- 서로 다른 선택이 같은 스탯 결과를 가져도 됩니다. 예를 들어 `누구에게 먼저 인사할지`처럼 캐릭터 선호 자체가 성장 효율의 정답이 되어서는 안 되는 선택은 항목별 수치를 동일하게 둡니다.
- 이 스토리 보상은 일회성 명시 보상이므로 아래 관리자 `rewardMultiplier`를 적용하지 않습니다.
- Story 대화 선택은 체력을 소비하는 수행 행동이 아니므로 **저체력 성장량 `-50%`도 적용하지 않습니다.** 따라서 Main의 `+2`, NPC·Location의 `+1`은 선택 보상 자체의 고정 기본값으로 처리하고, 상한 clamp만 적용합니다.

### Story 선택 결과 공개 규칙

선택 버튼에는 어떤 스탯이 오르는지 표시하지 않습니다. 대화가 끝나기 전까지 개별 선택의 `VISIBLE_STAT / HIDDEN_STAT` 효과는 플레이어에게 공개하지 않습니다.

```text
CHOICE 선택
→ 서버는 choiceId만 기록
→ 장면 END
→ 모든 선택 효과를 서버에서 합산
→ Firestore에 Visible + Hidden을 한 번에 저장
→ 저장 성공
→ 실제 적용된 Visible 증가량만 이벤트 결과 화면에 합산 표시
```

- 결과 화면은 `지식 +4 / 표현력 +2`처럼 **이벤트 전체에서 실제 적용된 보이는 스탯 총합**만 표시합니다.
- 어떤 선택이 어느 스탯을 올렸는지 선택별 상세 내역은 표시하지 않습니다.
- 보이지 않는 스탯의 종류·증가량·현재값은 결과 화면과 Dialogue API payload에 포함하지 않습니다.
- 보이는 스탯은 `0~500`, 보이지 않는 스탯은 `0~300`으로 clamp한 뒤 **실제 저장값이 증가한 양**을 결과 화면의 증가량으로 사용합니다. 예를 들어 `499 + nominal 4 → 500`이면 화면에는 `+1`만 표시합니다.
- 모든 보이는 스탯이 이미 상한이라 실제 증가량이 0이면 허위 `+N`을 표시하지 않습니다.
- `completionMode=SKIP`은 Story 진행만 완료하고 Visible/Hidden 선택 보상은 모두 `0`입니다.
- 보이지 않는 스탯은 서버 권위 데이터로 유지하며, 클라이언트가 선택 보상을 역산할 수 있는 형태로 노출하지 않습니다.

## 3. 스탯 증감 원칙

| 변화 유형 | 처리 원칙 |
|---|---|
| 일반 성공 | 관련 스탯 증가 |
| 일반 실패 | 원칙적으로 스탯을 깎지 않고 증가량 감소 또는 0으로 처리 |
| 선택의 대가 | 한 스탯이 오르는 대신 다른 스탯 또는 체력이 감소할 수 있음 |
| 스토리 결과 | 메인·NPC·공간 스토리의 중요한 결과에 따라 증가·감소 가능 |
| 과로·저체력 | 성장 스탯 자체를 영구 감소시키지 않고 일시적 효율 감소로 처리 |

스탯 감소는 실패에 대한 벌점보다는 **플레이어가 선택한 행동의 대가 또는 트레이드오프**로 사용하는 것을 기본 원칙으로 합니다.

### 수업·미니게임 성장량

수업·미니게임의 성공·실패·대성공 판정 자체는 각 게임 콘텐츠에서 결정합니다. 스탯 시스템은 현재 저장 성장 스탯에 따라 난이도 단계를 정하고, 전달받은 결과에 따라 아래 값만 적용합니다.

| 현재 `run.stats` | 난이도 | 실패 | 성공 | 대성공 |
|---:|---|---:|---:|---:|
| `0~100` | 쉬움 | `+0` | `+5` | `+10` |
| `101~200` | 보통 | `+1` | `+6` | `+10` |
| `201~350` | 어려움 | `+2` | `+7` | `+10` |
| `351~500` | 매우 어려움 | `+3` | `+8` | `+10` |

- 난이도 단계는 해당 성장 스탯의 **저장값 `run.stats`** 으로 판정합니다. 펫 임시 보정과 저체력 유효값 감소 때문에 난이도 단계가 바뀌지 않습니다.
- 대성공은 난이도와 관계없이 `+10`으로 통일합니다.
- 실패는 성장 스탯을 차감하지 않고 난이도에 따라 `+0~+3`만 적용합니다.
- 적용 후 저장 성장 스탯은 항상 `0~500` 범위로 제한합니다.
- 밸런스 목표는 한 회차에서 모든 스탯을 쉽게 500으로 만드는 것이 아니라, 한두 개의 주력 스탯에 집중했을 때 **12월 시작 무렵 500에 도달할 수 있는 정도**입니다.

#### 관리자 전역 성장 보상 배율

운영팀은 관리자 콘솔에서 반복 가능한 성장 콘텐츠의 보이는 성장 스탯 획득량을 스탯별로 낮출 수 있습니다. 이 설정은 사용자별 보정이 아니라 **게임 전체에 적용되는 전역 밸런스 설정**입니다.

| 대상 스탯 | 설정 key | 기본값 | 허용 범위 |
|---|---|---:|---:|
| 지식 | `knowledge` | `1.0` | `0.5~1.0` |
| 표현력 | `expression` | `1.0` | `0.5~1.0` |
| 솜씨 | `skill` | `1.0` | `0.5~1.0` |
| 탐험 | `exploration` | `1.0` | `0.5~1.0` |
| 마법 | `magic` | `1.0` | `0.5~1.0` |

- 변경 단위는 `0.1`입니다.
- `1.0`보다 높게 올려 기본 기획보다 보상을 증가시키는 운영 기능은 사용하지 않습니다.
- 수업·미니게임과 모험처럼 반복 가능한 콘텐츠의 보이는 스탯 보상에만 적용합니다.
- Main/NPC/Location Story의 일회성 명시 스탯 변화와 보이지 않는 스탯은 이 배율의 영향을 받지 않습니다.
- 이미 저장된 `run.stats`에는 소급 적용하지 않고, 설정 변경 이후 결과가 확정되는 활동부터 새 값을 사용합니다.

성장량 적용 순서는 다음과 같이 통일합니다.

```text
baseGrowth
= outcome + rewardDifficulty로 계산한 원래 성장량

staminaMultiplier
= 저체력 상태면 0.5, 아니면 1.0

finalGrowth
= floor(baseGrowth × adminRewardMultiplier[targetStat] × staminaMultiplier)

run.stats += finalGrowth
→ 0~500 clamp
```

관리 설정은 `version / updatedAt / updatedBy`를 함께 저장하고, 변경 시 관리자 감사로그에 이전값과 변경값을 기록합니다.

### 모험에서 탐험 스탯 사용

모험은 `탐험` 스탯을 **미션 난이도, 제한시간, 결과 성장량**에 사용합니다. 상세 플레이 계약은 [공통 엔진 프레임·마이룸·모험 흐름](../10_COMMON_ENGINE_FRAME.md)을 따릅니다.

- 모험 난이도는 미니게임과 동일하게 **저장값 `run.stats.exploration`** 의 `0~100 / 101~200 / 201~350 / 351~500` 구간으로 `쉬움 / 보통 / 어려움 / 매우 어려움`을 정합니다.
- 난이도에 따른 숨은 목표 아이템 수는 `1 / 2 / 3~4 / 5개`입니다.
- 제한시간 계산에는 `run.stats.exploration + 활성 펫의 탐험 보정`을 `500` 상한으로 사용합니다. 저체력 유효 스탯 `-30%`는 제한시간을 다시 줄이지 않습니다.
- 탐험 수치 `50 이하`는 `120초`, `50~500`은 `120~240초` 선형 증가, `500 이상`은 `240초`입니다.
- `MISSION_COMPLETE`의 탐험 성장량에는 기존 저체력 성장 효율 `-50%`를 적용합니다.
- `TIMEOUT`에서 목표를 하나 이상 발견했다면 아래 부분 성장 공식을 사용합니다. 목표 아이템 자체는 획득하지 않습니다.

```text
effectiveSuccessGrowth
= 저체력 보정까지 반영한 해당 모험의 정상 성공 탐험 성장량

발견 수 = 0
→ partialGrowth = 0

발견 수 > 0
→ partialGrowth
  = max(1, floor(effectiveSuccessGrowth × (발견 수 / 목표 수) × 0.5))
```

따라서 실패해도 실제로 하나 이상 발견했다면 탐색 경험으로 탐험 `+1` 이상을 남기되, 모든 목표를 찾은 정상 성공보다 성장량이 작습니다. 비정상 종료 `INTERRUPTED`는 발견 진행도와 관계없이 탐험 성장 `0`으로 처리합니다.

## 4. 스탯 변화가 발생하는 주요 콘텐츠

| 콘텐츠 | 보이는 스탯 변화 | 보이지 않는 스탯 변화 | 비고 |
|---|---|---|---|
| NPC 대화·선택 | 가능 | 주요 반영 | 대화 내용과 선택에 따라 결정 |
| 수업·미니게임 | 주요 성장 수단 | 가능 | 수업별 대표 성장 스탯과 미니게임을 연결 |
| 모험 | 가능 | 가능 | 발견·미발견·조사 결과에 따라 차등 |
| 메인 스토리 | 가능 | 주요 반영 | 중요한 선택과 결과에 사용 |
| 지역·공간 스토리 | 가능 | 주요 반영 | 장소 대화·선택과 연계 |
| 체력 부족·과로 | 유효 성장 스탯 `-30%`, 획득 성장량 `-50%` | 보이지 않는 스탯에는 배율 미적용 | 회복하면 원래 적용값으로 복구 |

수업·장소 연결과 5개 현행 미니게임의 실제 판정은 [수업·미니게임 시스템](../06_CLASSES_MINIGAMES.md)과 [7개 공간 콘텐츠 상세 규칙](../06_01_LOCATION_ACTIVITIES.md)을 따릅니다. 표현력은 시계탑 광장의 `아르카디아 야외무대 → 별빛 무대`, 마법은 `마도 공방 → 룬 회로`, 탐험은 `별빛 천문대 → 거울 마법`을 대표 성장 경로로 사용합니다. 게임 결과를 성장량으로 바꾸는 규칙은 이 문서의 공통 표를 사용합니다.

연속 실패 보정으로 실제 플레이 난이도가 낮아져도 성장량 계산에 사용하는 난이도는 해당 `run.stats`로 정한 원래 난이도를 유지합니다. 즉 `rewardDifficulty`와 `playDifficulty`를 분리합니다.

## 5. 체력과 과로

- 체력 범위는 `0~100`, 시작값은 `100`입니다.
- 수업 1회는 체력 `10`, 모험 1회는 체력 `15`를 소비하며 **활동 시작 시점에 먼저 차감**합니다. 시작한 활동이 성공·실패·중단으로 끝나더라도 이미 소비한 체력은 반환하지 않습니다.
- 휴식은 마이룸에서 방법을 먼저 고릅니다. `집에서 쉰다`는 체력 `+60/+70/+80`, `친구와 논다`는 체력 `+40/+50/+60`과 무작위 성장 스탯 1종 `+1`, `취미활동을 한다`는 체력 `+30/+40/+50`과 무작위 성장 스탯 1종 `+2` 중 서버가 결과를 정합니다. 체력을 제외한 여러 성장 스탯을 한 번에 올리지 않습니다.
- 토요일과 일요일은 일정 선택 없이 자동으로 지나가지만 **체력을 자동 회복하지 않습니다.**
- 체력이 `10~30`이면 저체력 상태입니다. 이때 체력을 제외한 5개 보이는 성장 스탯의 최종 유효값을 `70%`로 사용하고, 새로 획득하는 성장량은 `50%`만 적용합니다.
- 저체력 성장량은 관리자 전역 성장 보상 배율까지 포함해 `floor(기본 획득량 × adminRewardMultiplier × 0.5)`로 계산합니다. 저체력이 아니면 마지막 배율은 `1.0`입니다.
- 보이지 않는 스탯은 플레이 선택 기록이므로 저체력 `-50%` 성장 효율을 적용하지 않습니다.
- 하루가 시작될 때 체력이 `0~9`이면 그날부터 강제 휴식 상태에 진입합니다. 수업·모험의 시작 비용으로 활동 도중 `0~9`가 된 경우에는 이미 시작된 당일 활동을 종료한 뒤 다음 행동 가능한 평일부터 강제휴식을 시작합니다.
- 강제휴식은 **평일 3일**이며 3일이 끝나면 체력을 `100`으로 회복합니다. 토·일은 강제 휴식 3일에 포함하지 않습니다. 같은 주에 이어지는 강제휴식일은 첫 안내 뒤 한 번에 확정하고, 주 경계를 넘는 잔여일만 다음 주에 이어서 처리합니다.
- 강제휴식에 해당하는 기존 일정은 잠긴 `강제휴식`으로 교체하며 플레이어가 수정할 수 없습니다. 강제휴식은 주 경계를 넘어 다음 주 평일까지 이어질 수 있습니다.
- 정상적인 콘텐츠 중단 결과는 스탯 변화를 `0`으로 처리합니다. 비정상 종료의 복구 여부는 저장 시스템의 마지막 안정 저장 경계를 따릅니다.
- 과로에 따른 감소는 성장 스탯 원본값을 깎지 않습니다.

### 보정 적용 순서와 상한

새 회차의 저장 성장 스탯은 다음 순서로 만듭니다.

```text
기본 성장 스탯 50
+ 캐릭터 초기 보정
+ 수집 시스템에서 전달받은 영구 보너스
= 회차 시작 run.stats
```

배지 수집 영구 보너스는 성장 스탯별 최대 `+15`입니다. 체력 영구 보너스는 사용하지 않습니다. 스탯 시스템은 계정에 저장된 값을 **새 회차 생성 시** 시작값에 반영하며 이미 진행 중인 회차의 `run.stats`를 소급 변경하지 않습니다.

플레이 중 성장과 펫 보정은 다음처럼 처리합니다.

```text
run.stats + 이번 행동의 성장량
→ 0~500 clamp

clamp(run.stats + petModifier, 0, 500)
= 보정 후 성장 스탯

저체력 상태라면
floor(보정 후 성장 스탯 × 0.70)
= 최종 유효 성장 스탯
```

따라서 어떤 캐릭터·수집·펫 보정을 사용해도 실제 판정에 사용하는 성장 스탯의 최대값은 `500`입니다. 저체력 `-30%`는 이 상한 처리 이후 마지막 단계에서만 적용하며 저장 원본을 변경하지 않습니다.

## 6. 이벤트 결과 처리 기준

하나의 중요한 행동이나 선택은 필요에 따라 다음 결과를 동시에 가질 수 있습니다.

`보이는 스탯 변화 + 보이지 않는 스탯 변화 + NPC 조우/스토리 진행 + 이벤트/선택 플래그`

숫자형 NPC 친밀도·호감도는 사용하지 않습니다. NPC와의 교류는 만남 횟수, 마지막 만남 주차, NPC 스토리 진행 단계와 필요한 선택 플래그로 기록합니다. 이 구조를 통해 같은 사건에서도 선택에 따라 서로 다른 성장·이야기 기록을 만들고 이후 이벤트와 엔딩 조건에 활용합니다.
