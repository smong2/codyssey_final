# 이벤트 시스템

## 0. 주간 일정과 이벤트의 관계

메인·서브·NPC·지역 이벤트는 **평일 일정 슬롯을 소비하지 않습니다.** 이벤트가 발생한 주에도 월~금의 일반 일정 5회는 그대로 유지합니다.

- 발생 날짜가 자유로운 이벤트는 토·일을 우선적인 표시 구간으로 활용합니다.
- 시나리오에서 날짜가 고정된 메인 이벤트는 임의로 주말로 옮기지 않습니다.
- 이야기상 평일에 이벤트가 발생하더라도 그날의 예정 수업·모험·휴식을 대체하거나 소모하지 않습니다.
- 주말 이벤트에서 발생한 스탯·관계·플래그 변화는 해당 주 결과에 포함한 뒤 주간 저장과 다음 월요일의 주간 요약에 반영합니다.

## 1. NPC 이벤트 발생 규칙

모험 맵에는 기본적으로 NPC를 **무작위 1~2명** 배치할 수 있습니다. 단순 균등 랜덤 대신 **가중 랜덤**을 사용합니다. LUMIA는 NPC 친밀도·호감도 같은 숫자형 관계 수치를 사용하지 않으며, NPC 출현과 이야기 진행에는 `만남 횟수 / 마지막 만남 주차 / NPC 이야기 진행 단계 / 이벤트 플래그`를 사용합니다.

### 1.1 기본 노출 조건

- 일반 NPC 조우는 MS01 입학·온보딩이 끝난 **1주차부터** 사용할 수 있습니다.
- NPC 개별 스토리는 기본적으로 해당 NPC를 **최소 1회 이상 만난 뒤** 후보가 됩니다. 메인 스토리 등 명시적으로 지정된 콘텐츠만 예외로 바로 시작할 수 있습니다.
- NPC가 현재 플레이 캐릭터와 동일하면 해당 NPC는 조우 후보에서 제외하고, 콘텐츠에 대체 캐릭터가 지정되어 있으면 대체 캐릭터를 사용합니다.
- 장소·주차·선행 스토리 단계·필수 플래그를 만족하지 않은 NPC 이벤트는 후보에 넣지 않습니다.

### 1.2 NPC 출현 가중치

조건을 통과한 NPC 후보는 아래 기본 점수를 사용합니다.

| 조건 | 가중치 |
|---|---:|
| 기본 출현 가중치 | `+100` |
| 현재 장소가 NPC의 선호·생활 장소와 일치 | `+50` |
| 해당 NPC의 개별 스토리가 진행 중 | `+80` |
| 현재 메인 진행과 직접 연관 | `+40` |
| 최근 미등장 보정 | 미등장 1주당 `+10`, 최대 `+60` |

최근 미등장 보정은 `lastEncounterWeek`를 기준으로 계산합니다. 숫자형 친밀도·호감도는 가중치에 사용하지 않습니다. 콘텐츠별 특별한 이유가 없다면 NPC별 기본값은 모두 `100`으로 시작합니다.

동일 NPC의 **개별 스토리 단계가 직전 주에 이미 진행됐다면**, 고정 이벤트가 아닌 이상 다음 주의 랜덤 개별 스토리 후보에서는 한 번 제외합니다. 일반적인 NPC 조우·인사 자체는 계속 가능합니다. 이를 통해 특정 NPC 스토리만 연속해서 몰리는 것을 줄입니다.

### 1.3 이벤트 순서와 주간 제한

- 메인 이벤트는 고정 일정으로 처리하며 아래 랜덤 이벤트 제한에 포함하지 않습니다.
- NPC·서브·공간 스토리 이벤트는 합쳐서 **주당 최대 2회** 발생합니다.
- 스토리 결과나 선택을 가지는 이벤트는 **하루 최대 1회**만 발생합니다.
- 동일 NPC의 개별 스토리는 **한 주에 최대 1단계**만 진행합니다.
- 일반 NPC 만남, 짧은 인사, 배경 반응은 위 `주당 2회` 제한에 포함하지 않습니다.
- 날짜가 자유로운 이벤트는 주말을 우선 사용하되, 특정 장소·수업·모험 안에서 발생해야 자연스러운 이벤트는 해당 활동 직후에 표시할 수 있습니다.

### 1.4 중복 방지와 반복 이벤트

- 일회성 이벤트는 `eventFlags` 또는 `storyProgress`의 완료 상태를 확인하여 같은 회차에서 다시 발생시키지 않습니다.
- 연속 스토리는 이전 단계가 완료된 뒤에만 다음 단계가 후보가 됩니다.
- 미확인 일회성 이벤트와 반복 가능한 이벤트가 동시에 있다면 **미확인 일회성 이벤트를 우선**합니다.
- 반복 이벤트는 마스터 데이터에서 명시적으로 `repeatable`인 경우에만 다시 사용할 수 있습니다.
- 같은 반복 이벤트 ID는 한 주에 두 번 발생시키지 않습니다.
- 후보가 없거나 주간 제한에 도달했다면 억지로 이벤트를 만들지 않고 일반 대화·일상 반응으로 끝냅니다.

NPC를 실제로 한 번 조우하면 `encounterCount`를 1 증가시키고 `lastEncounterWeek`를 현재 주차로 갱신합니다. 이 값은 친밀도가 아니라 **조우 이력과 출현 제어를 위한 기록**입니다.

## 2. 공간 이벤트

수업·모험·장소 방문을 진행할 때 조건에 따라 **장소·공간 기반 스토리**가 발생할 수 있습니다. 공간 이벤트는 별도의 고정 퍼센트 확률을 두지 않고, 현재 장소에서 조건을 만족한 이벤트 후보 중 아직 보지 않은 이벤트를 우선 선택합니다. 후보 선정은 위의 주간·일일 제한과 중복 방지 규칙을 공통으로 사용합니다.

공간 이벤트의 조건 예시는 다음과 같습니다.

- 특정 수업 또는 장소
- 특정 주차 이후
- 필요한 보이는 스탯
- 특정 NPC 스토리 진행 여부
- 이전 선택 또는 발견 기록

공간 이벤트는 수업에만 영구적으로 제한하지 않습니다. 향후 모험·마이룸·특수 활동에서도 장소 중심 이벤트를 사용할 수 있습니다.

장소 이벤트는 기본 `startWeek = 1`로 두고, 이야기상 더 늦게 열려야 하는 콘텐츠만 마스터 데이터에서 시작 주차를 별도로 지정합니다. 연속 장소 이야기는 `storyProgress`의 단계 순서대로 노출합니다.

## 3. 선택 이후 대화 연결 규칙

NPC 대화에서 플레이어가 어떤 선택을 하더라도 다음 대사가 앞선 선택과 모순되지 않아야 합니다. 이를 위해 선택지가 있는 대화는 기본적으로 **`선택 직후의 짧은 개별 반응 → 중립적인 공통 대화 합류`** 구조를 사용합니다.

```text
NPC 질문
→ 긍정 / 부정 / 다른 관점 선택
→ 선택별 1~2개 반응 문장
→ 공통 대화 노드
→ 다음 장면
```

- 부정적인 답을 선택했는데 공통 대화가 `역시 넌 내 생각을 좋아하는구나`처럼 긍정을 전제로 이어지는 문장은 금지합니다.
- 공통 합류 문장은 앞선 선택의 태도를 특정하지 않는 중립 문장으로 작성합니다.
- 이후 다른 장면에서 과거 선택을 직접 언급해야 한다면 공통 대화로 뭉개지 않고 해당 선택을 `eventFlag`로 저장해 조건부 대사를 사용합니다.
- 선택에 정답/오답을 두지 않으며, 어떤 응답을 골라도 NPC 교류 자체가 막히지 않습니다.
- NPC 스토리 단계는 기본적으로 **장면을 정상 완료했는지**로 진행합니다. 긍정 답변이나 특정 정답을 골라야 다음 단계가 열리는 구조는 만들지 않습니다.

## 4. 선택 결과·기록 반영 계약

숫자형 NPC 관계도는 저장하지 않습니다. 하나의 선택은 필요한 경우 아래 결과를 가질 수 있습니다.

| 결과 | 처리 |
|---|---|
| 보이는 스탯 변화 | 이벤트가 명시적으로 요구할 때만 적용 |
| 보이지 않는 스탯 변화 | 일반 `+3`, 중요 `+5`, 메인·핵심 `+8` 기준 사용 |
| NPC 만남 기록 | NPC 조우 시 `encounterCount`, `lastEncounterWeek` 갱신 |
| 스토리 진행 | 해당 `storyId`의 `step/status` 갱신 |
| 이후 분기 필요 선택 | `eventFlags`에 최소한의 선택 플래그 저장 |
| 엔딩 편지용 중요 선택 | `representativeChoices` 후보로 저장 |
| 엔딩 편지용 중요 사건 | `representativeEventIds` 후보로 저장 |

모든 선택의 원문과 모든 대화를 장기 저장하지 않습니다.

```text
일반 선택
→ 결과만 적용
→ 별도 상세 선택 기록 없음

향후 대사·이벤트 조건에 필요한 선택
→ eventFlags 저장

엔딩 편지에서 회고할 만큼 중요한 선택
→ eventFlags(필요한 경우)
+ representativeChoices 저장
```

`representativeChoices`는 실제 선택이 있었음을 증명할 수 있는 `eventId / choiceId / week` 중심의 최소 레퍼런스를 저장하고, 표시 문구는 마스터 데이터에서 조회하는 것을 기본으로 합니다.

## 5. 스탯 연계

이벤트 결과는 [스탯 시스템](01_STATS_SYSTEM.md)의 원칙을 따릅니다.

- 일반 실패를 이유로 성장 스탯을 기계적으로 감소시키지 않습니다.
- 중요한 선택에는 스탯 간 트레이드오프를 사용할 수 있습니다.
- 보이는 스탯과 보이지 않는 스탯을 같은 이벤트에서 함께 변화시킬 수 있습니다.
- NPC 친밀도·호감도 수치는 사용하지 않습니다.
- 정확한 보이는 스탯 증감이 필요한 개별 이벤트는 해당 콘텐츠에서 정의하고, 보이지 않는 스탯은 공통 증가 기준을 사용합니다.
