# 저장과 회차 계승

## 1. 저장 시스템

플레이어는 진행 중 **언제든 저장하고 다시 이어서 플레이**할 수 있어야 합니다.

- 여러 개의 세이브 슬롯을 제공합니다.
- 각 슬롯에서는 현재 주차, 요일, 일정, 캐릭터 상태, 스탯, NPC 관계, 이야기 진행, 수집 상태 등 게임 진행에 필요한 정보를 저장합니다.
- 수동 저장을 기본으로 하되, 데이터 유실 방지를 위한 자동 저장 추가를 권장합니다. 자동 저장 시점과 슬롯 수는 **미정**입니다.

이벤트·미니게임 진행 중의 정확한 저장 가능 시점은 구현 안정성을 고려해 정할 수 있지만, 플레이어 경험상 "언제든 이어할 수 있다"는 원칙을 유지합니다.

## 2. 한 회차 종료 후 계승

52주와 엔딩을 완료한 뒤 같은 진행 계보로 다음 회차를 시작할 경우 다음 항목을 계승합니다.

### 계승

- 획득한 수집 배지
- 해금한 플레이 가능 캐릭터
- 해금한 펫
- 해금한 마이룸 배경
- 확인한 엔딩 기록
- 카테고리 완성으로 얻은 최대 체력·스탯 영구 보너스

### 새 회차에서 초기화

- 해당 회차에서 성장한 일반 스탯
- 현재 체력 상태
- NPC 관계·개별 스토리 진행도
- 메인·서브·공간 이벤트의 현재 진행도
- 현재 주차와 일정

새 회차의 기본 스탯은 캐릭터의 시작값에 **계승된 영구 보너스**를 더한 상태로 시작하는 구조를 사용합니다.

## 3. 새로하기와 엔딩 후 이어하기

다음 두 흐름 모두 계승 플레이를 지원하는 방향입니다.

1. 엔딩을 본 세이브 슬롯에서 다음 회차 이어하기
2. 새로하기를 통해 새로운 회차 시작하기

다만 `새로하기`에서 **어느 세이브의 계승 데이터를 기준으로 삼을지**, 여러 세이브 슬롯 사이에서 해금·수집·영구 보너스를 공유할지는 아직 결정하지 않았습니다.

## 4. 세이브 슬롯 간 메타 데이터 — 미정

아래 두 방식 중 어느 쪽을 사용할지 후속 결정이 필요합니다.

### 방식 A — 슬롯별 독립 계승

각 세이브 슬롯이 독립적인 수집·캐릭터·펫·엔딩 기록을 가집니다.

- 장점: 각 슬롯을 완전히 다른 플레이 기록으로 유지 가능
- 단점: 다른 슬롯에서 얻은 캐릭터나 배지를 다시 획득해야 함

### 방식 B — 프로필 공통 메타 진행

개별 회차 진행은 세이브 슬롯에 저장하지만, 배지·캐릭터·펫·배경·엔딩·영구 보너스는 플레이어 프로필에서 공유합니다.

- 장점: 32명 캐릭터와 200개 수집을 여러 슬롯에서 자연스럽게 이어갈 수 있음
- 단점: 완전히 처음부터 다시 플레이하고 싶은 경우 별도의 초기화 기능이 필요함

현재 게임이 다회차 수집과 캐릭터 해금을 중요하게 사용하므로 **방식 B가 장기 플레이에는 더 적합할 가능성이 높지만 아직 확정하지 않습니다.**

## 5. 저장 데이터에서 반드시 구분할 상태

향후 구현에서는 최소한 다음 개념을 구분하는 것이 좋습니다.

- `Run State`: 현재 52주 회차의 진행 상태
- `Slot State`: 해당 세이브 슬롯의 기록
- `Meta Progress`: 회차를 넘어 유지되는 해금·수집·영구 보너스

`Meta Progress`를 슬롯별로 둘지 프로필 공통으로 둘지는 위 결정에 따라 달라집니다.
