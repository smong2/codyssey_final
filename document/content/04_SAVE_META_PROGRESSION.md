# 저장과 회차 계승

## 1. 기본 구조

LUMIA는 ID/Password로 로그인하는 **계정 단위 게임**을 전제로 합니다. 저장 시스템은 **계정 전역 메타 진행 + 세이브 슬롯 + 현재 회차**를 분리합니다.

```text
Account
├─ Global Meta Progress
│  ├─ 캐릭터 해금
│  ├─ 플레이 완료 캐릭터
│  ├─ 펫 해금
│  ├─ 배지
│  ├─ 마이룸 배경·퍼즐 조각
│  ├─ 확인한 엔딩
│  ├─ 영구 보너스
│  └─ 누적 플레이 기록
│
└─ Save Slots (5개)
   ├─ Slot 1
   ├─ Slot 2
   ├─ Slot 3
   ├─ Slot 4
   └─ Slot 5
```

기존처럼 슬롯마다 메타 데이터를 따로 소유하지 않습니다. **로그인한 계정 하나가 하나의 Global Meta Progress를 가지며 5개 슬롯이 이를 공유**합니다.

현재 선택한 펫은 슬롯별 진행 데이터가 아니라 **계정 환경설정의 `activePetId`**로 관리합니다. 해금된 펫 목록은 Global Meta Progress에 저장하며 모든 슬롯이 공유합니다. 펫의 스탯 보정값 자체는 세이브에 복사하지 않고 [펫 시스템](03_COLLECTION_UNLOCKS/05_PET_SYSTEM.md)의 마스터 데이터를 조회합니다.

```text
Global Meta Progress
├─ 캐릭터 해금
├─ 플레이 완료 캐릭터
├─ 펫 해금
├─ 배지
├─ 마이룸 배경·퍼즐 조각
├─ 확인한 엔딩
├─ 영구 보너스
└─ 누적 플레이 기록
```

핵심 원칙은 다음과 같습니다.

- 세이브 슬롯은 총 **5개**를 제공합니다.
- 한 슬롯은 52주 한 회차만 저장하는 파일이 아니라 **여러 회차를 계속 이어가는 장기 플레이 컨테이너**입니다.
- `새로 시작하기`로 다른 슬롯에서 새 게임을 시작해도 전역 누적 데이터는 유지합니다.
- 같은 슬롯에서 `2회차 시작`, `3회차 시작`을 해도 전역 누적 데이터는 유지합니다.
- 현재 캐릭터의 일반 성장 스탯, 체력, NPC 관계, 스토리 진행은 회차마다 초기화합니다.
- 팝업은 최소화하고, 파괴적 행동인 **세이브 슬롯 삭제 확인**에만 우선 사용합니다.
- 게임 내부에 **전체 플레이 데이터 초기화 기능은 제공하지 않습니다.** 계정 삭제가 필요하다면 저장 시스템이 아니라 계정 관리 기능으로 처리합니다.

## 2. 세이브 슬롯 5개

### 타이틀과 슬롯 선택 화면

저장된 슬롯이 모두 `EMPTY`이면 타이틀에 `시작하기`만 표시합니다. `PLAYING` 또는 `RUN_COMPLETE` 슬롯이 하나 이상 있으면 `새로 시작하기 / 이어서 하기`를 표시합니다. 공용 메타 보유 여부가 아니라 슬롯 상태를 기준으로 합니다.

`이어서 하기`는 타이틀 배경을 유지하는 프레임으로 열고 슬롯 1~5를 한 열로 나열합니다. 실제 마지막 저장 슬롯 정보가 있으면 같은 슬롯을 맨 위에 `최근 저장` 바로가기로 한 번 더 표시합니다. 별도 슬롯을 만들거나 방문만으로 최근 저장 정보를 갱신하지 않습니다.

타이틀의 `이어서 하기`를 선택하면 **항상 5개의 슬롯 카드**를 모두 보여 줍니다.

저장된 슬롯만 나열하지 않고 빈 슬롯도 같은 위치에 표시하여 플레이어가 최대 5개까지 사용할 수 있다는 사실을 바로 알 수 있게 합니다.

### 슬롯 상태

세이브 슬롯은 최소 다음 3개 상태를 가집니다.

| 상태 | 의미 | 주요 버튼 |
|---|---|---|
| `EMPTY` | 한 번도 사용하지 않았거나 슬롯 기록을 삭제함 | 없음 |
| `PLAYING` | 현재 회차 진행 중 | `이어서 하기` |
| `RUN_COMPLETE` | 엔딩 완료 후 다음 회차 시작 전 | `N+1회차 시작` (N은 완료 회차 수) |

### 빈 슬롯

빈 슬롯은 숨기지 않고 다음과 같이 카드로 표시합니다.

```text
슬롯 4
저장 기록 없음
```

빈 카드 자체를 이어서 하기 대상으로 사용하지 않습니다.

### 진행 중 슬롯

카드에서는 슬롯을 구분하는 데 필요한 핵심 정보만 보여 줍니다.

예:

```text
슬롯 1
아이리스
2회차 · 18주차
마지막 저장 2026.10.11

[이어서 하기]                 [삭제]
```

권장 표시 정보:

- 슬롯 번호
- 현재 회차 캐릭터
- 현재 회차 번호
- 현재 주차
- 마지막 저장 시점

필요한 경우 캐릭터 대표 이미지는 상반신 기본 이미지(`img1`, `*_base.png`)를 사용할 수 있습니다.

전체 스탯, NPC 관계, 엔딩 조건처럼 카드 선택에 불필요한 세부 정보는 기본 슬롯 카드에서 제외합니다.

## 3. 새 게임 시작

타이틀의 `시작하기`와 `새로 시작하기`는 **첫 번째 빈 슬롯을 자동 배정**하여 새 1회차를 시작하는 기능입니다. 사용자가 빈 슬롯을 고르는 화면은 표시하지 않고 기존 슬롯을 덮어쓰지 않습니다.

### 빈 슬롯이 있을 때

```text
시작하기 / 새로 시작하기
  ↓
첫 빈 슬롯 자동 배정 (슬롯 선택 화면 없음)
  ↓
캐릭터 선택
  ↓
1회차 시작
```

캐릭터 선택을 확정하고 `시작하기`를 누를 때 회차를 생성·저장합니다. 그 전에 뒤로가면 타이틀로 돌아가며 슬롯을 소비하지 않습니다. 완료 슬롯의 다음 회차 선택에서 뒤로가면 이어서 하기 프레임으로 돌아갑니다.

새 게임이라도 `Global Meta Progress`는 초기화하지 않습니다. 따라서 기존 플레이에서 해금한 캐릭터·펫·배지·배경·엔딩·누적 플레이 기록은 그대로 유지합니다.

### 5개 슬롯이 모두 사용 중일 때

5개 슬롯이 모두 `PLAYING` 또는 `RUN_COMPLETE` 상태이면 `새로 시작하기`를 눌러도 새 회차를 생성하지 않고 슬롯이 가득 찼다는 안내를 표시합니다. `이어서 하기`는 사용 가능합니다.

팝업을 띄우지 않고 버튼 주변에 이유를 직접 표시합니다.

```text
저장 슬롯 5 / 5

[ 새로 시작하기 ]
[ 이어서 하기 ]
저장 슬롯이 가득 찼습니다.
새 게임을 시작하려면 기존 저장 기록 하나를 삭제해주세요.
```

일반 안내는 하단에서 잠시 표시한 뒤 사라집니다. 저장 실패와 재시도 안내는 일반 알림과 구분하여 유지합니다.

## 4. 엔딩 이후 같은 슬롯에서 다음 회차 시작

예를 들어 `슬롯 1`에서 카엘로 1회차 엔딩을 봤다고 가정합니다.

엔딩이 끝나면 현재 회차를 완료 기록으로 확정하고 슬롯을 삭제하거나 비우지 않습니다.

```text
Slot 1
1회차 / 카엘 / 52주 완료
  ↓
엔딩 판정 및 엔딩 편지
  ↓
1회차 기록 확정
  ↓
전역 메타 진행 반영
  ↓
Slot 1 = RUN_COMPLETE
  ↓
타이틀
```

엔딩 직후 별도의 다음 회차 확인 팝업은 만들지 않습니다. 기본 흐름은 엔딩을 마치고 타이틀로 돌아가는 것입니다.

이후 `이어서 하기` 화면에서 슬롯 1은 다음처럼 표시합니다.

```text
슬롯 1
카엘
1회차 완료
엔딩: 유적 탐험가

[2회차 시작]                 [삭제]
```

`2회차 시작`을 누르면 확인 팝업 없이 바로 **캐릭터 선택 화면**으로 이동합니다.

```text
슬롯 1
1회차 완료
  ↓
[2회차 시작]
  ↓
캐릭터 선택
  ↓
새 캐릭터 선택 가능
  ↓
Slot 1 / 2회차 / 1주차 시작
```

다음 회차에서는 현재 해금되어 선택 가능한 캐릭터 중에서 주인공을 다시 선택할 수 있어야 합니다. 이전 회차와 다른 새 캐릭터를 선택할 수 있으며, 이전에 사용한 캐릭터를 다시 선택하는 것을 별도로 제한하지 않습니다.

캐릭터 해금 조건은 현재 회차 중 달성될 수 있지만 실제 해금은 회차 종료 시 확정하여 **바로 다음 회차 캐릭터 선택부터 사용 가능**하게 합니다.

## 5. 슬롯의 회차 정보는 최소한만 보관

완료한 모든 회차의 최종 스탯·NPC 관계·이벤트 플래그 등을 `runHistory[]`처럼 계속 쌓아 둘 필요는 없습니다.

LUMIA의 장기 목표는 **32명의 플레이 가능 캐릭터를 다양하게 경험하는 것**입니다. 완료한 캐릭터·엔딩·누적 성취는 계정의 `Global Meta Progress`에서 관리하고, 슬롯에는 현재 진행을 이어가기 위한 정보와 회차 표시를 위한 최소 정보만 남깁니다.

권장 슬롯 구조:

```text
Save Slot 1
├─ slotId: 1
├─ status: EMPTY | PLAYING | RUN_COMPLETE
├─ completedRunCount: 2
├─ lastCompletedCharacterId: CH01
├─ lastEndingId: ENDING_03
├─ lastSavedAt
└─ activeRun
   ├─ runNumber: 3
   ├─ characterId: CH08
   ├─ week
   ├─ stats
   ├─ stamina
   ├─ hiddenStats
   ├─ npcRelations
   ├─ storyProgress
   └─ flags
```

엔딩 직후에는 `activeRun = null`로 두고 `completedRunCount + 1`을 다음 회차 번호로 사용할 수 있습니다.

예:

```text
completedRunCount = 1
activeRun = null
→ 버튼: 2회차 시작
```

캐릭터별로 과거 한 회차 전체 데이터를 영구 저장하지 않습니다. 대신 계정 전역에는 다음 정도만 남깁니다.

- `playedCharacterIds`: 한 번 이상 엔딩까지 플레이한 캐릭터
- 필요 시 `characterPlayCounts`: 캐릭터별 완료 횟수
- `seenEndings`: 확인한 엔딩 목록
- 각 해금 조건에 필요한 누적 플레이 기록

32명의 캐릭터를 모두 플레이해 보는 것을 장기 목표로 삼을 수 있습니다. 동일 캐릭터를 다시 선택하는 것을 현재 단계에서 강제로 막지는 않으며, 캐릭터 선택 화면에서 `플레이 완료` 여부를 표시해 새로운 캐릭터 선택을 자연스럽게 유도합니다.

## 6. 전역으로 유지하는 데이터

다음 데이터는 **슬롯과 회차를 넘어 플레이어 전체에서 공유**합니다.

### 수집·해금

- 획득한 수집 배지
- 해금한 플레이 가능 캐릭터
- 엔딩까지 플레이 완료한 캐릭터 목록
- 해금한 펫
- 획득한 마이룸 퍼즐 조각
- 해금한 마이룸 배경
- 확인한 엔딩
- 카테고리 완성 등으로 획득한 영구 보너스

### 누적 플레이 기록

- 미니게임 총 플레이·클리어 기록
- 서로 다른 미니게임 클리어 기록
- 모험 누적 횟수
- NPC 누적 만남 기록
- NPC 스토리 완료 누적 기록
- 계열별 수업 누적 기록
- 배지·캐릭터·펫·배경 해금 조건에 사용하는 기타 장기 기록

이 문서에서 `누적 스탯` 또는 `누적 기록`은 위와 같은 **장기 플레이 카운터와 메타 진행도**를 의미합니다. 현재 캐릭터의 `지식 / 표현력 / 솜씨 / 탐험 / 마법` 성장 수치를 그대로 다음 인생으로 넘긴다는 의미가 아닙니다.

따라서 다음 두 경우 모두 전역 누적 데이터는 유지됩니다.

```text
새로 시작하기 → 다른 빈 슬롯에서 1회차 시작
2회차 시작하기 → 같은 슬롯에서 다음 회차 시작
```

## 7. 새 회차에서 초기화하는 데이터

새로운 회차에서 다음 항목은 초기화합니다.

- 해당 회차에서 성장한 일반 스탯
- 현재 체력
- 보이지 않는 스탯의 현재 회차 값
- NPC 관계
- NPC 개별 스토리의 현재 회차 진행
- 메인·서브·공간 이벤트 진행
- 현재 주차와 일정
- 현재 회차에서만 사용하는 선택·플래그
- 현재 회차용 행동 기록

새 회차의 성장 스탯은 선택한 캐릭터의 시작값을 기준으로 다시 생성합니다.

```text
캐릭터 기본 시작값
+ 캐릭터별 초기 보정
+ 전역에서 획득한 영구 보너스
= 새 회차 시작값
```

영구 보너스의 정확한 수치와 누적 상한은 별도 밸런싱 대상으로 둡니다.

## 8. 슬롯 삭제

각 사용 중인 세이브 슬롯 카드 오른쪽에는 `삭제` 버튼을 둡니다.

삭제는 복구하기 어려운 파괴적 행동이므로 **이 기능에는 확인 팝업을 사용합니다.**

예:

```text
이 저장 기록을 정말 삭제할까요?
슬롯 1의 진행 중인 회차와 회차 기록이 삭제됩니다.
삭제한 슬롯 기록은 복구할 수 없습니다.

[취소]    [삭제]
```

삭제 후 해당 슬롯은 즉시 다음 상태가 됩니다.

```text
슬롯 1
저장 기록 없음
```

### 삭제 범위

슬롯 삭제로 제거하는 것:

- 해당 슬롯의 현재 회차
- 해당 슬롯의 완료 회차 수·직전 완료 캐릭터·직전 엔딩 요약
- 슬롯 자체의 마지막 저장 정보

슬롯 삭제로 제거하지 않는 것:

- 전역 해금 캐릭터
- 전역 해금 펫
- 전역 배지
- 전역 퍼즐 조각·마이룸 배경
- 전역 확인 엔딩
- 전역 누적 미니게임·모험·NPC·수업 기록
- 전역 영구 보너스

즉 슬롯을 삭제하더라도 지금까지 플레이어가 LUMIA 전체에서 쌓은 메타 진행은 유지합니다.

게임 내부에서 전역 메타 진행을 초기화하는 기능은 제공하지 않습니다. 계정 자체의 삭제가 필요한 경우에는 계정 관리 정책에 따라 해당 계정의 서버 저장 데이터를 함께 처리합니다.

---

## 9. 팝업 최소화 원칙

화면과 구현 작업량을 줄이기 위해 이동·시작 행동에 불필요한 확인 단계를 만들지 않습니다.

| 행동 | 처리 |
|---|---|
| 이어서 하기 | 바로 해당 회차 로드 |
| 다음 회차 시작 | 바로 캐릭터 선택으로 이동 |
| 빈 슬롯에서 새 게임 시작 | 첫 빈 슬롯 자동 배정 후 캐릭터 선택으로 이동 |
| 캐릭터 선택 화면에서 뒤로가기 | 새 게임은 타이틀, 다음 회차는 이어서 하기 프레임으로 복귀 |
| 슬롯 5개가 가득 참 | 새 게임을 생성하지 않고 안내 문구 표시 |
| 슬롯 삭제 | 확인 팝업 사용 |

새로운 팝업은 실제 실수 방지 가치가 있을 때만 추가합니다.

---

## 10. 자동 저장 시점

저장 로직을 복잡하게 만들지 않기 위해 미니게임·대화·이벤트 도중의 임의 시점 저장은 기본 범위에서 제외하고, **상태가 안정적으로 확정되는 경계에서 자동 저장**합니다.

자동 저장 시점은 다음 3개를 기본으로 합니다.

1. **새 회차 생성 직후**
2. **매주 일정이 모두 끝난 직후**
3. **엔딩 결과가 확정된 직후**

### 매주 종료 저장

주간 저장은 `2주마다`가 아니라 **매주 종료 시** 수행합니다.

```text
월~금 행동 완료
  ↓
주말 자동 처리 / 체력 회복
  ↓
해당 주 결과 확정
  ↓
자동 저장
  ↓
다음 주 진입
```

이 시점은 미니게임, NPC 대화, 이벤트 선택 도중이 아니어서 저장 상태를 만들기 비교적 단순합니다. 또한 2주 단위 저장보다 비정상 종료 시 잃을 수 있는 진행량을 줄일 수 있습니다.

52주 한 회차 기준으로 주간 자동 저장은 약 52회이므로 계정 서버 저장 횟수도 과도하지 않은 수준으로 봅니다.

### 저장하지 않는 중간 상태

기본 구현에서는 다음 중간 상태를 저장 대상으로 삼지 않습니다.

- 미니게임 진행 중 프레임 상태
- NPC 대화 중간 문장
- 선택지 선택 전 임시 UI 상태
- 이벤트 연출 중간 상태

이벤트나 게임이 끝나고 주간 상태에 결과가 반영된 뒤 다음 주 경계에서 저장하는 것을 기본으로 합니다.

현재 엔진 시안의 주중 일정 초안과 완료한 활동은 주말 저장 전까지 메모리에만 있습니다. 새로고침·종료 후 이어서 하기는 마지막 저장 경계로 돌아갑니다. 주말 저장된 일별 활동 기록은 달력에서 지난 일정으로, 다이어리에서 주별 묶음으로 표시합니다. 주별 표시는 저장된 원본 일별 기록을 지우거나 전체 회차를 영구 보관하는 정책 변경을 뜻하지 않습니다.

저장 요청 실패 시 재시도·복구 방식은 구현 단계에서 별도로 정합니다.

---

## 11. 구현 데이터 경계

향후 구현에서는 최소 다음 세 계층을 명확히 분리합니다.

### `Run State`

현재 52주 인생 하나의 진행 상태입니다.

- 현재 캐릭터
- 회차 번호
- 현재 주차·일정
- 체력과 성장 스탯
- 보이지 않는 스탯
- NPC 관계
- 이벤트·스토리 진행
- 현재 회차 플레이 기록

### `Slot State`

한 세이브 슬롯의 현재 진행과 최소 회차 요약입니다.

- 슬롯 ID
- 현재 상태 `EMPTY / PLAYING / RUN_COMPLETE`
- 완료 회차 수
- 직전 완료 캐릭터
- 직전 엔딩
- `activeRun`
- 마지막 저장 시점

### `Meta Progress`

로그인한 **계정 단위로 저장**되며 모든 슬롯과 모든 회차에서 공유하는 장기 진행입니다.

- 해금 캐릭터·펫·배경
- 플레이 완료 캐릭터
- 배지·퍼즐 조각
- 확인 엔딩
- 영구 보너스
- 누적 미니게임·모험·NPC·수업 기록
- 장기 해금 조건 달성 기록

`Run State`와 `Slot State`가 삭제되거나 새로 생성되어도 `Meta Progress`는 자동으로 초기화하지 않습니다.

## 13. 현재 개발판과 본편 기획의 구현 경계

`engine/`에는 같은 주소/브라우저의 로컬 저장 adapter를 사용하는 실행형 시안이 있습니다. 빈 슬롯 자동 배정, 이어서 하기 프레임, 최근 저장 바로가기, 주말 저장·재개, 손상 데이터 보존과 저장 실패 재시도는 구현되어 있습니다. 엔딩 직업·편지 표시 프레임과 사용자 승인 예시가 있지만 실제 회차 완료/저장을 처리하지 않습니다. 계정 서버 저장, 본편 펫 `activePetId`·보정, 해금 조건 판정, AI 편지 생성·검증과 엔딩 완료 저장은 후속 연결 대상입니다. 최신 펫·엔딩 기획은 유지하며 실제 구현 완료와 구분합니다. 실행과 검증 범위는 [엔진 README](../../engine/README.md)를 따릅니다.
