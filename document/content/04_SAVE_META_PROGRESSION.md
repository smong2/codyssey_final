# 저장과 회차 계승

## 1. 기본 구조

LUMIA는 **Email/Password + 이메일 인증**으로 로그인하는 계정 단위 게임을 전제로 합니다. 게스트 플레이는 Final Project 범위에 포함하지 않습니다. 저장 시스템은 **계정 전역 메타 진행 + 세이브 슬롯 + 현재 회차**를 분리합니다.

```text
Account
├─ Global Meta Progress
│  ├─ 캐릭터 해금
│  ├─ 플레이 완료 캐릭터
│  ├─ 펫 해금
│  ├─ 배지
│  ├─ 마이룸 배경·퍼즐 조각
│  ├─ 확인한 엔딩
│  ├─ 영구 보너스
│  └─ 누적 플레이 기록
│
└─ Save Slots (5개)
   ├─ Slot 1
   ├─ Slot 2
   ├─ Slot 3
   ├─ Slot 4
   └─ Slot 5
```

기존처럼 슬롯마다 메타 데이터를 따로 소유하지 않습니다. **로그인한 계정 하나가 하나의 Global Meta Progress를 가지며 5개 슬롯이 이를 공유**합니다.

현재 선택한 펫은 슬롯별 진행 데이터가 아니라 **계정 환경설정의 `activePetId`**로 관리합니다. 해금된 펫 목록은 Global Meta Progress에 저장하며 모든 슬롯이 공유합니다. 펫의 스탯 보정값 자체는 세이브에 복사하지 않고 [펫 시스템](03_COLLECTION_UNLOCKS/05_PET_SYSTEM.md)의 마스터 데이터를 조회합니다.

```text
Global Meta Progress
├─ 캐릭터 해금
├─ 플레이 완료 캐릭터
├─ 펫 해금
├─ 배지
├─ 마이룸 배경·퍼즐 조각
├─ 확인한 엔딩
├─ 영구 보너스
└─ 누적 플레이 기록
```

핵심 원칙은 다음과 같습니다.

- 세이브 슬롯은 총 **5개**를 제공합니다.
- 한 슬롯은 52주 한 회차만 저장하는 파일이 아니라 **여러 회차를 계속 이어가는 장기 플레이 컨테이너**입니다.
- `새로 시작하기`로 다른 슬롯에서 새 게임을 시작해도 전역 누적 데이터는 유지합니다.
- 같은 슬롯에서 `2회차 시작`, `3회차 시작`을 해도 전역 누적 데이터는 유지합니다.
- 현재 캐릭터의 일반 성장 스탯, 체력, NPC 조우 기록, 스토리 진행은 회차마다 초기화합니다.
- 팝업은 최소화하고, 파괴적 행동인 **세이브 슬롯 삭제 확인**에만 우선 사용합니다.
- 게임 내부에 **전체 플레이 데이터 초기화 기능은 제공하지 않습니다.** 계정 탈퇴는 [계정·인증·탈퇴 정책](08_ACCOUNT_POLICY.md)에 따라 해당 UID의 모든 게임 데이터와 Firebase Authentication 계정을 함께 삭제합니다.

## 2. 세이브 슬롯 5개

### 타이틀과 슬롯 선택 화면

저장된 슬롯이 모두 `EMPTY`이면 타이틀에 `시작하기`만 표시합니다. `PLAYING` 또는 `RUN_COMPLETE` 슬롯이 하나 이상 있으면 `새로 시작하기 / 이어서 하기`를 표시합니다. 공용 메타 보유 여부가 아니라 슬롯 상태를 기준으로 합니다.

`이어서 하기`는 타이틀 배경을 유지하는 프레임으로 열고 슬롯 1~5를 한 열로 나열합니다. 실제 마지막 저장 슬롯 정보가 있으면 같은 슬롯을 맨 위에 `최근 저장` 바로가기로 한 번 더 표시합니다. 별도 슬롯을 만들거나 방문만으로 최근 저장 정보를 갱신하지 않습니다.

타이틀의 `이어서 하기`를 선택하면 **항상 5개의 슬롯 카드**를 모두 보여 줍니다.

저장된 슬롯만 나열하지 않고 빈 슬롯도 같은 위치에 표시하여 플레이어가 최대 5개까지 사용할 수 있다는 사실을 바로 알 수 있게 합니다.

### 슬롯 상태

세이브 슬롯은 최소 다음 3개 상태를 가집니다.

| 상태 | 의미 | 주요 버튼 |
|---|---|---|
| `EMPTY` | 한 번도 사용하지 않았거나 슬롯 기록을 삭제함 | 없음 |
| `PLAYING` | 현재 회차 진행 중 | `이어서 하기` |
| `RUN_COMPLETE` | 엔딩 완료 후 다음 회차 시작 전 | `N+1회차 시작` (N은 완료 회차 수) |

서버나 네트워크 오류로 특정 슬롯을 읽지 못한 경우의 `LOAD_ERROR`는 저장되는 슬롯 상태가 아니라 **이어 하기 화면의 일시 표시 상태**입니다. 원본 슬롯의 실제 상태를 추정해서 `EMPTY`로 바꾸지 않습니다.

### 빈 슬롯

빈 슬롯은 숨기지 않고 다음과 같이 카드로 표시합니다.

```text
슬롯 4
저장 기록 없음
```

빈 카드 자체를 이어서 하기 대상으로 사용하지 않습니다.

### 진행 중 슬롯

카드에서는 슬롯을 구분하는 데 필요한 핵심 정보만 보여 줍니다.

예:

```text
슬롯 1
아이리스
2회차 · 18주차
마지막 저장 2026.10.11

[이어서 하기]                 [삭제]
```

권장 표시 정보:

- 슬롯 번호
- 현재 회차 캐릭터
- 현재 회차 번호
- 현재 주차
- 마지막 저장 시점

캐릭터 대표 이미지가 필요한 경우 전신 원본(`*0_fullbody.png`)만 사용하고 원본 비율을 유지합니다. 슬롯 카드에 맞춰 크롭할 수 있지만 상반신·표정 파일(`img1~img5`, `*_base.png` 등)은 새로 연결하지 않습니다. 마이룸 기본 프로필 UI에는 작은 얼굴 이미지를 표시하지 않습니다.

전체 스탯, NPC 조우·스토리 진행, 엔딩 조건처럼 카드 선택에 불필요한 세부 정보는 기본 슬롯 카드에서 제외합니다.

## 3. 새 게임 시작

타이틀의 `시작하기`와 `새로 시작하기`는 **첫 번째 빈 슬롯을 자동 배정**하여 새 1회차를 시작하는 기능입니다. 사용자가 빈 슬롯을 고르는 화면은 표시하지 않고 기존 슬롯을 덮어쓰지 않습니다.

### 빈 슬롯이 있을 때

```text
시작하기 / 새로 시작하기
  ↓
첫 빈 슬롯 자동 배정 (슬롯 선택 화면 없음)
  ↓
캐릭터 선택
  ↓
1회차 시작
```

캐릭터 선택을 확정하고 `시작하기`를 누르면 첫 빈 슬롯에 회차를 생성하고 **초기 자동 저장 성공을 확인한 뒤** MS01과 실제 플레이로 진입합니다. 초기 저장이 실패하면 회차 콘텐츠를 시작하지 않습니다. 그 전에 뒤로가면 타이틀로 돌아가며 슬롯을 소비하지 않습니다. 완료 슬롯의 다음 회차 선택에서 뒤로가면 이어서 하기 프레임으로 돌아갑니다.

새 게임이라도 `Global Meta Progress`는 초기화하지 않습니다. 따라서 기존 플레이에서 해금한 캐릭터·펫·배지·배경·엔딩·누적 플레이 기록은 그대로 유지합니다.

### 5개 슬롯이 모두 사용 중일 때

5개 슬롯이 모두 `PLAYING` 또는 `RUN_COMPLETE` 상태여도 `새로 시작하기`는 정상 모습·클릭 가능 상태를 유지합니다. 반투명이나 비활성 표현은 사용하지 않습니다. 클릭하면 새 회차를 만들지 않고 버튼들 아래에 프레임 안내를 약 3초 표시한 뒤 숨깁니다. 연속 클릭은 표시 시간을 갱신하며 `이어서 하기`는 계속 사용할 수 있습니다.

상시 문구나 별도 모달 팝업 대신 클릭 후에만 짧게 안내합니다.

```text
[ 새로 시작하기 ]  ← 정상 모습·클릭 가능
[ 이어서 하기 ]

클릭 후 아래 프레임에 잠시 표시:
5개 슬롯이 모두 사용 중입니다. 슬롯을 삭제하면 새로 시작할 수 있습니다.
```

일반 안내는 하단에서 잠시 표시한 뒤 사라집니다. 저장 실패와 재시도 안내는 일반 알림과 구분하여 유지합니다.

### 슬롯 로드 오류

특정 슬롯을 서버에서 읽거나 검증하지 못한 경우에는 빈 슬롯처럼 표시하지 않습니다.

```text
슬롯 2
저장 기록을 확인할 수 없습니다.

[다시 시도]    [삭제]
```

- `다시 시도`는 해당 슬롯 데이터를 다시 요청합니다.
- 재시도 성공 시 원래 슬롯 카드 상태를 표시합니다.
- 재시도 실패 상태에서도 사용자가 직접 `삭제`를 선택할 수 있지만 확인 팝업을 반드시 거칩니다.
- 삭제 확인에는 `삭제한 슬롯 기록은 복구할 수 없음 / Global Meta는 유지됨`을 함께 안내합니다.
- 로드 실패만으로 슬롯을 자동 초기화하거나 새 게임으로 덮어쓰지 않습니다.

## 4. 엔딩 이후 같은 슬롯에서 다음 회차 시작

예를 들어 `슬롯 1`에서 카엘로 1회차 엔딩을 봤다고 가정합니다.

52주 플레이 결과와 엔딩 직업·편지는 화면 표시 전에 재접속 가능한 형태로 안전하게 준비할 수 있지만, **사용자가 엔딩 전체를 확인했다는 열람 완료는 마지막 `타이틀로` 동작으로 확정**합니다. 슬롯을 삭제하거나 비우지 않습니다.

```text
Slot 1
1회차 / 카엘 / 52주 완료
  ↓
엔딩 판정 및 엔딩 편지 준비 저장
  ↓
Slot 1 = PLAYING / ending presentation phase
  ↓
무엇을 지켰니? → 직업 → 편지 → 선택적 해금 요약
  ↓
최종 [타이틀로]
  ↓
본 엔딩 기록·회차 종료 메타를 한 번만 확정
  ↓
Slot 1 = RUN_COMPLETE
  ↓
타이틀
```

엔딩 직후 별도의 다음 회차 확인 팝업은 만들지 않습니다. 기본 흐름은 엔딩을 마치고 타이틀로 돌아가는 것입니다.

실제 엔딩 화면은 `무엇을 지켰니? → 미래 직업 공개 → 개인화 편지 + 아르카디아에서의 기록` 순서로 진행합니다. 회차 완료로 신규 캐릭터·펫·배지 등 실제 새 해금이 발생한 경우에만 편지 뒤에 한 번의 해금 요약을 보여 준 다음 타이틀로 이동합니다. 엔딩 화면 자체에는 `N+1회차 시작` 버튼을 두지 않습니다.

엔딩 화면에 표시한 개인화 편지는 해당 회차의 `Ending Record`에 영구 저장하며, 같은 엔딩을 다시 보더라도 과거 회차의 편지를 덮어쓰지 않습니다. 편지에 실제 사용한 대표 플레이 기록과 대표 선택도 함께 보관해 과거 편지가 어떤 플레이 기억을 바탕으로 생성됐는지 다시 확인할 수 있게 합니다.

### 엔딩 표시 미완료 복구

엔딩 표시 도중 브라우저 종료·오류가 발생할 수 있으므로, 직업 판정과 최종 편지는 **다시 생성하지 않고 재표시할 수 있는 형태로 먼저 저장**합니다. 논리적으로는 `endingPresentationPending` 같은 표시 미완료 상태를 유지할 수 있으며 실제 필드명은 저장/API 구현 단계에서 확정할 수 있습니다.

```text
엔딩 결과/편지 준비 저장
→ 엔딩 표시 미완료
→ 무엇을 지켰니? / 직업 / 편지

중간 종료
→ 다음 접속
→ 이어 하기
→ 저장된 결과로 엔딩을 처음부터 재표시
```

엔딩 중간 화면 번호는 저장하지 않습니다. 최종 `타이틀로`가 성공하기 전에는 `N+1회차 시작`을 제공하지 않습니다.

최종 `타이틀로`에서 다음을 한 번만 확정합니다.

- 정규 엔딩의 `seenEndingIds`
- 해당 엔딩의 `endingViewCounts +1`
- 엔딩 열람/회차 종료에 의존하는 해금·메타 결과
- 엔딩 표시 미완료 상태 해제

해당 저장이 실패하면 타이틀로 이동하지 않고 재시도합니다. 같은 완료 요청이 다시 실행되어도 엔딩 횟수·해금이 중복 반영되지 않아야 합니다.

이후 `이어서 하기` 화면에서 슬롯 1은 다음처럼 표시합니다.

```text
슬롯 1
카엘
1회차 완료
엔딩: 유적 탐험가

[2회차 시작]                 [삭제]
```

`2회차 시작`을 누르면 확인 팝업 없이 바로 **캐릭터 선택 화면**으로 이동합니다.

```text
슬롯 1
1회차 완료
  ↓
[2회차 시작]
  ↓
캐릭터 선택
  ↓
새 캐릭터 선택 가능
  ↓
Slot 1 / 2회차 / 1주차 시작
```

다음 회차에서는 현재 해금되어 선택 가능한 캐릭터 중에서 주인공을 다시 선택할 수 있어야 합니다. 이전 회차와 다른 새 캐릭터를 선택할 수 있으며, 이전에 사용한 캐릭터를 다시 선택하는 것을 별도로 제한하지 않습니다.

캐릭터 해금 조건은 현재 회차 중 달성될 수 있지만 실제 해금은 회차 종료 시 확정하여 **바로 다음 회차 캐릭터 선택부터 사용 가능**하게 합니다.

## 5. 슬롯의 회차 정보는 최소한만 보관

완료한 모든 회차의 최종 스탯·NPC별 만남 상태·이벤트 플래그 등을 `runHistory[]`처럼 계속 쌓아 둘 필요는 없습니다.

LUMIA의 장기 목표는 **32명의 플레이 가능 캐릭터를 다양하게 경험하는 것**입니다. 완료한 캐릭터·엔딩·누적 성취는 계정의 `Global Meta Progress`에서 관리하고, 슬롯에는 현재 진행을 이어가기 위한 정보와 회차 표시를 위한 최소 정보만 남깁니다.

권장 슬롯 구조:

```text
Save Slot 1
├─ slotId: 1
├─ status: EMPTY | PLAYING | RUN_COMPLETE
├─ completedRunCount: 2
├─ lastCompletedCharacterId: CH01
├─ lastEndingId: ENDING_03
├─ lastSavedAt
└─ activeRun
   ├─ runNumber: 3
   ├─ characterId: CH08
   ├─ storyCast
   ├─ week
   ├─ stats
   ├─ stamina
   ├─ hiddenStats
   ├─ npcProgress
   ├─ storyProgress
   └─ flags
```

`storyCast`는 현재 회차에서 사용할 Main·NPC·Location Story의 학생 배역 맵입니다. 주인공 선택이 확정된 직후 역할별 후보와 `prior_assignment_policy`를 적용해 한 번 계산하고, **같은 회차가 끝날 때까지 고정**합니다. 재접속해도 다시 뽑지 않습니다. Main 핵심 역할은 서로 다른 학생을 우선하며, Location 온실 역할은 지정된 hard exclusion을 지킵니다. NPC의 `NPC_GUIDE_ACTOR`와 `NPC_WORK_ACTOR`는 다른 Story 역할과 중복될 수 있지만 현재 주인공 자신은 제외해 각각 `티아→로빈`, `렌→다나` 후보 순서로 정합니다. 역할별 후보·충돌 규칙은 `story/main/MAIN_STORY_PRODUCTION.md`, `story/npc/NPC_STORY_PRODUCTION.md`, `story/location/LOCATION_STORY_PRODUCTION.md`를 따릅니다.

엔딩 표시를 마지막 `타이틀로`까지 완료하기 전에는 `activeRun.phase = ENDING_PRESENTATION`처럼 **현재 회차를 유지**합니다. 최종 열람 완료 저장이 성공한 뒤 `activeRun = null`, `status = RUN_COMPLETE`로 전환하고 `completedRunCount + 1`을 다음 회차 번호로 사용할 수 있습니다.

예:

```text
completedRunCount = 1
activeRun = null
→ 버튼: 2회차 시작
```

캐릭터별로 과거 한 회차 전체 데이터를 영구 저장하지 않습니다. 대신 계정 전역에는 다음 정도만 남깁니다.

- `playedCharacterIds`: 한 번 이상 엔딩까지 플레이한 캐릭터
- 필요 시 `characterPlayCounts`: 캐릭터별 완료 횟수
- `seenEndings`: 확인한 **정규 직업 엔딩** 목록. `별길 개척자` fallback은 정규 엔딩 해금 수에 포함하지 않음
- 각 해금 조건에 필요한 누적 플레이 기록

32명의 캐릭터를 모두 플레이해 보는 것을 장기 목표로 삼을 수 있습니다. 동일 캐릭터를 다시 선택하는 것을 현재 단계에서 강제로 막지는 않으며, 캐릭터 선택 화면에서 `플레이 완료` 여부를 표시해 새로운 캐릭터 선택을 자연스럽게 유도합니다.

## 6. 전역으로 유지하는 데이터

다음 데이터는 **슬롯과 회차를 넘어 플레이어 전체에서 공유**합니다.

### 수집·해금

- 획득한 수집 배지
- 해금한 플레이 가능 캐릭터
- 엔딩까지 플레이 완료한 캐릭터 목록
- 해금한 펫
- 획득한 마이룸 퍼즐 조각
- 해금한 마이룸 배경
- 확인한 엔딩
- 카테고리 완성 등으로 획득한 영구 보너스

### 누적 플레이 기록

- 미니게임 총 플레이·클리어 기록
- 서로 다른 미니게임 클리어 기록
- 모험 누적 횟수
- NPC 누적 만남 기록
- NPC 스토리 완료 누적 기록
- 계열별 수업 누적 기록
- 배지·캐릭터·펫·배경 해금 조건에 사용하는 기타 장기 기록
- 엔딩별 확인 횟수. `별길 개척자` 횟수도 `endingViewCounts`에 누적

이 문서에서 `누적 스탯` 또는 `누적 기록`은 위와 같은 **장기 플레이 카운터와 메타 진행도**를 의미합니다. 현재 캐릭터의 `지식 / 표현력 / 솜씨 / 탐험 / 마법` 성장 수치를 그대로 다음 인생으로 넘긴다는 의미가 아닙니다.

따라서 다음 두 경우 모두 전역 누적 데이터는 유지됩니다.

```text
새로 시작하기 → 다른 빈 슬롯에서 1회차 시작
2회차 시작하기 → 같은 슬롯에서 다음 회차 시작
```

## 7. 새 회차에서 초기화하는 데이터

새로운 회차에서 다음 항목은 초기화합니다.

- 해당 회차에서 성장한 일반 스탯
- 현재 체력
- 보이지 않는 스탯의 현재 회차 값
- NPC별 만남 횟수·마지막 만남 주차
- NPC 개별 스토리의 현재 회차 진행
- 메인·NPC·공간 이벤트 진행
- 현재 주차와 일정
- 현재 회차에서만 사용하는 선택·플래그
- 현재 회차용 `storyCast` 배역 맵
- 현재 회차용 행동 기록

새 회차의 성장 스탯은 선택한 캐릭터의 시작값을 기준으로 다시 생성합니다.

새 회차에서 캐릭터를 확정할 때 `storyCast`도 새로 계산합니다. 이전 회차의 배역은 계승하지 않으며, 같은 캐릭터를 다시 플레이하더라도 현재 후보 규칙과 현재 `gameDataVersion`을 기준으로 새 회차용 배역을 저장합니다.

```text
캐릭터 기본 시작값
+ 캐릭터별 초기 보정
+ 수집 시스템에서 계산한 전역 영구 보너스
= 새 회차 시작값
```

배지 수집 영구 보너스는 `지식 / 표현력 / 솜씨 / 탐험 / 마법` 각각 최대 `+15`입니다. 최대 체력 영구 보너스는 사용하지 않습니다. 저장·스탯 시스템은 확정된 영구 보너스 값을 **새 회차 생성 시에만** 시작 성장 스탯에 반영하며, 최종 성장 스탯 상한 `500`을 넘기지 않습니다.

## 8. 슬롯 삭제

각 사용 중인 세이브 슬롯 카드 오른쪽에는 `삭제` 버튼을 둡니다.

삭제는 복구하기 어려운 파괴적 행동이므로 **이 기능에는 확인 팝업을 사용합니다.**

예:

```text
이 저장 기록을 정말 삭제할까요?
슬롯 1의 진행 중인 회차와 회차 기록이 삭제됩니다.
삭제한 슬롯 기록은 복구할 수 없습니다.

[취소]    [삭제]
```

삭제 후 해당 슬롯은 즉시 다음 상태가 됩니다.

```text
슬롯 1
저장 기록 없음
```

### 삭제 범위

슬롯 삭제로 제거하는 것:

- 해당 슬롯의 현재 회차
- 해당 슬롯의 완료 회차 수·직전 완료 캐릭터·직전 엔딩 요약
- 슬롯 자체의 마지막 저장 정보

슬롯 삭제로 제거하지 않는 것:

- 전역 해금 캐릭터
- 전역 해금 펫
- 전역 배지
- 전역 퍼즐 조각·마이룸 배경
- 전역 확인 엔딩
- 전역 누적 미니게임·모험·NPC·수업 기록
- 전역 영구 보너스

즉 슬롯을 삭제하더라도 지금까지 플레이어가 LUMIA 전체에서 쌓은 메타 진행은 유지합니다.

게임 내부에서 전역 메타 진행을 초기화하는 기능은 제공하지 않습니다. 계정 자체의 탈퇴가 확정되면 계정 관리 정책에 따라 해당 UID의 서버 저장 데이터, 엔딩 기록·편지, Firebase Authentication 계정을 모두 삭제합니다.

## 9. 팝업 최소화 원칙

화면과 구현 작업량을 줄이기 위해 이동·시작 행동에 불필요한 확인 단계를 만들지 않습니다.

| 행동 | 처리 |
|---|---|
| 이어서 하기 | 바로 해당 회차 로드 |
| 다음 회차 시작 | 바로 캐릭터 선택으로 이동 |
| 빈 슬롯에서 새 게임 시작 | 첫 빈 슬롯 자동 배정 후 캐릭터 선택으로 이동 |
| 캐릭터 선택 화면에서 뒤로가기 | 새 게임은 타이틀, 다음 회차는 이어서 하기 프레임으로 복귀 |
| 슬롯 5개가 가득 참 | 새 게임을 생성하지 않고 안내 문구 표시 |
| 슬롯 삭제 | 확인 팝업 사용 |
| 슬롯 로드 실패 | `다시 시도 / 삭제`를 표시하며 EMPTY로 추정하지 않음 |

새로운 팝업은 실제 실수 방지 가치가 있을 때만 추가합니다.

## 10. 자동 저장 시점

미니게임 프레임 단위 상태를 저장하지 않는 원칙은 유지하되, 비정상 종료 때 하루 전체나 한 주 전체를 되돌리지 않도록 **활동 단위의 안정 체크포인트**를 사용합니다.

자동 저장 시점은 다음을 기본으로 합니다.

1. **새 회차 생성 직후 — 실제 콘텐츠 진입 전**
2. **주간 일정 5칸을 확정하고 일정 시작을 누른 직후**
3. **각 평일 활동 시작 직후 — 상태를 `IN_PROGRESS`로 바꾸고 필요한 체력을 선차감한 뒤, 실제 콘텐츠 실행 전**
4. **각 평일 활동 결과 확정 직후 — 결과·스탯·통계·일정 완료 상태를 반영한 뒤**
5. **주말 이벤트를 포함해 한 주 결과가 모두 확정된 직후**
6. **엔딩 직업·편지 준비가 끝난 직후 — 재접속용 표시 미완료 상태 저장**
7. **엔딩 최종 `타이틀로` 직후 — 본 엔딩 기록·회차 종료 메타·RUN_COMPLETE를 한 번만 확정**

### 활동 시작 체크포인트

```text
오늘 예정 활동 확인
  ↓
ScheduleEntry = IN_PROGRESS
  ↓
수업/모험이면 체력 선차감
  ↓
자동 저장
  ↓
저장 성공
  ↓
Location Story 후보 판정
  ↓
있으면 Story 완료 저장 후 같은 IN_PROGRESS 활동으로 복귀
  ↓
미니게임 / 모험 / 휴식 / 특수 활동 실행
```

실제 콘텐츠는 활동 시작 체크포인트 저장이 성공한 뒤 실행합니다. 따라서 비정상 종료 후에는 **어떤 활동을 시작했고 체력을 이미 소비했는지**를 세이브에서 판별할 수 있습니다.

### 활동 완료 저장

정상 결과가 확정되면 결과를 반영하고 `ScheduleEntry = COMPLETED`로 변경한 뒤 자동 저장합니다.

- 미니게임 `FAIL / SUCCESS / GREAT`: 해당 결과와 성장량·통계를 반영
- 미니게임 `포기하기`: `FAIL`로 반영
- 모험 `MISSION_COMPLETE`: 성공한 발견 기록과 정상 탐험 성장량·통계를 반영. 숨은 목표 아이템 ID 자체는 가방/계정 영구 수집 목록에 저장하지 않음
- 모험 `TIMEOUT`: 목표 아이템은 획득 처리하지 않고 발견 비율에 따른 부분 탐험 성장량과 실패 통계를 반영
- 모험 `QUIT`: 사용자가 `중단하기`를 확정한 명시적 실패. 이미 소비한 체력은 유지하고 목표 아이템·탐험 성장·목표 보상은 지급하지 않은 채 해당 일정을 `COMPLETED`로 저장. 모험 시도 횟수 같은 누적 활동 기록은 실패한 시도도 포함
- 요정의 거래: `TRANSFERRED / SKIPPED` 반영
- Location Story는 정상 완료 뒤가 아니라 활동 시작 체크포인트 저장 직후 실제 플레이 화면 전에 판정하는 별도 이벤트이며, 일정 슬롯을 다시 소비하지 않음

Location Story는 활동 시작 체크포인트 저장 직후 실제 플레이 화면 전에 판정·실행하고, 완료 저장 뒤 같은 `IN_PROGRESS` 활동을 이어서 시작합니다. 활동 완료 저장이 성공하면 NPC Story 후보를 판정하고, 이야기가 선정되면 분리된 장면의 정상 완료 결과까지 저장한 뒤 다음 예정 평일 활동으로 자동 전환합니다. 후보가 없으면 바로 다음 활동으로 전환합니다. 월~금 연속 실행 중에는 활동마다 마이룸을 경유하지 않으며 **휴식 일정 자체가 마이룸을 사용하는 경우에만** 마이룸으로 진입합니다. 활동 또는 이야기 결과 저장 실패 시에는 다음 일정으로 넘어가지 않고 재시도 상태를 유지합니다.

### 비정상 종료 복구

최근 저장에 `IN_PROGRESS` 일정이 남아 있으면 해당 콘텐츠의 프레임·퍼즐판을 복원하지 않습니다.

```text
최근 자동저장 로드
  ↓
IN_PROGRESS 일정 발견
  ↓
resolution = INTERRUPTED
  ↓
저장된 체력 소비 유지
성장량 0
미니게임 연속 실패 횟수 변화 없음
  ↓
ScheduleEntry = COMPLETED
  ↓
복구 상태 자동 저장
  ↓
마이룸 복귀
  ↓
저장 phase 판단
  ↓
다음 예정 평일 활동 또는 스케줄 작성으로 진행
```

`INTERRUPTED`는 플레이어가 누른 `포기하기`와 구분합니다. 포기는 정상 결과 `FAIL`이고, 비정상 종료는 실패 보정·미니게임 실패 통계에 포함하지 않습니다. 모험 `INTERRUPTED` 역시 그 판에서 임시로 발견한 목표 아이템과 부분 탐험 성장을 반영하지 않습니다. **재접속 복구에서는 마이룸을 먼저 복귀 허브로 사용**하고, 그곳에서 다음 예정 일정이나 새 주 스케줄 작성 상태를 판단합니다. 정상 활동 완료 직후의 월~금 연속 진행은 여전히 마이룸을 경유하지 않습니다.

### 매주 종료 저장

주간 저장은 `2주마다`가 아니라 **매주 종료 시** 수행합니다.

```text
월~금 행동 완료
  ↓
주말 자동 처리 / 체력 추가 회복 없음
  ↓
주말 우선 이벤트 처리
  ↓
해당 주 결과 확정
  ↓
자동 저장
  ↓
다음 월요일 진입
  ↓
지난주 주간 요약 표시
  ↓
`창 닫기`
  ↓
마이룸 확인
  ↓
날짜 카드에서 새 주간 일정 등록
```

이 시점은 미니게임, NPC 대화, 이벤트 선택 도중이 아니어서 저장 상태를 만들기 비교적 단순합니다. 또한 2주 단위 저장보다 비정상 종료 시 잃을 수 있는 진행량을 줄일 수 있습니다.

52주 한 회차에서는 평일 활동이 최대 260회이므로 활동 시작·완료 체크포인트까지 포함하면 주간 저장만 사용하던 이전안보다 저장 횟수가 늘어납니다. 다만 **중간 프레임 상태를 계속 저장하는 것이 아니라 명확한 활동 경계에서만 저장**합니다. 실제 Firestore/API 구현에서는 필요한 필드만 갱신하거나 쓰기를 묶을 수 있지만, 비정상 종료 복구에 필요한 시작·완료 경계 자체는 생략하지 않습니다.

### 저장하지 않는 중간 상태

기본 구현에서는 다음 중간 상태를 저장 대상으로 삼지 않습니다.

- 미니게임 진행 중 프레임 상태
- 모험에서 현재 배치된 숨은 아이템 좌표·남은 시간·임시 발견 목록·조사 횟수
- NPC 대화 중간 문장
- 선택지 선택 전 임시 UI 상태
- 이벤트 연출 중간 상태

미니게임의 내부 보드 상태는 저장하지 않지만, 게임 시작 여부와 최종 결과는 활동 체크포인트로 저장합니다. 메인·NPC·지역 이벤트는 일반 일정 슬롯을 소비하지 않으며, 주말에 발생한 이벤트 결과까지 해당 주에 포함한 뒤 주간 종료 저장을 수행합니다. 서브스토리는 본편 저장 대상에서 제외합니다.

다음 월요일의 주간 요약은 저장이 완료된 지난주 기록을 읽어 표시합니다. 기본 표시 정보는 `보이는 스탯 변화 / 수업 진행 횟수 / 체력 소비·회복 / 주간 시작·종료 체력 / 강제휴식 일수`입니다. 요약 화면은 이미 확정된 결과를 다시 적용하거나 추가 보상을 지급하지 않습니다. `창 닫기` 후에는 곧바로 일정 화면을 강제하지 않고 마이룸을 보여 주며, 플레이어가 날짜 카드로 새 일정을 엽니다. 52주차 종료 뒤에는 12월 31일 마지막 주간 요약 후 최종 이벤트·엔딩 흐름으로 이동합니다.

새로고침·강제 종료 후 이어서 하기는 마지막으로 성공한 활동 체크포인트로 복구합니다. 미니게임에서 `포기하기`를 누른 경우에는 `FAIL`로 정상 완료하고 같은 날 다시 시작하지 않습니다. 프로세스 비정상 종료는 `INTERRUPTED`로 별도 처리합니다. 주말 저장된 일별 활동 기록은 달력에서 지난 일정으로, 다이어리에서 주별 묶음으로 표시합니다. 주별 표시는 저장된 원본 일별 기록을 지우거나 전체 회차를 영구 보관하는 정책 변경을 뜻하지 않습니다.

저장 요청 실패 시에는 다음 화면 자동 전환을 멈추고 **지속형 오류 안내와 `다시 시도` 진입점**을 유지합니다. 재시도는 같은 안정 체크포인트 스냅샷을 다시 저장하며 성공한 뒤에만 다음 일정으로 진행합니다. 네트워크 backoff·재시도 횟수 같은 세부 구현값은 개발 단계에서 정합니다.

## 11. 구현 데이터 경계

향후 구현에서는 최소 다음 세 계층을 명확히 분리합니다.

### `Run State`

현재 52주 인생 하나의 진행 상태입니다.

- 현재 캐릭터
- 회차 번호
- 현재 주차·일정
- 체력과 성장 스탯
- 보이지 않는 스탯
- NPC별 조우 진행
- 이벤트·스토리 진행
- 현재 회차 플레이 기록

#### AI `Long-term Play Memory`

Final Project에서 사용하는 Long-term Memory는 별도의 전역 세이브 컬렉션을 하나 더 만든다는 뜻이 아닙니다. **현재 회차의 `Run State` 안에서 여러 주차·여러 로그인 세션에 걸쳐 누적되고 유지되는 플레이 기록을, 52주 종료 시 AI가 다시 읽어 개인화에 사용하는 방식**입니다.

기억의 원본은 다음 데이터입니다.

- `Run State`의 현재 회차 활동 통계
- `representativeChoices`의 중요 선택 기록
- 현재 회차 최종 성장 스탯
- 현재 회차 보이지 않는 스탯 중 AI에 전달할 요약 대상

축적과 사용 시점은 다음과 같습니다.

```text
활동/중요 선택 완료
→ 현재 회차 기록 갱신
→ 활동 결과·주간 종료 등 안정 저장 경계에서 저장
→ 로그아웃/재접속 후에도 같은 Run State에서 계속 누적

52주 종료
→ 현재 회차 Run State 다시 로드
→ 대표 플레이 기록 4~6개와 중요 선택 최대 2개 선별
→ AI Memory Context 구성
→ Gemini 개인화 엔딩 편지 입력에 사용
→ 최종 편지 + 사용한 대표 기억을 Ending Record에 보존
```

계정 전체의 `Global Meta Progress`에 있는 모든 회차 누적 통계는 해금·메타 진행을 위한 별도 장기 데이터입니다. **현재 회차 엔딩 편지를 만들 때 이전 회차의 전역 누적 기록을 자동으로 섞지 않습니다.** 새 회차가 시작되면 그 회차의 Long-term Play Memory도 새 `Run State`를 기준으로 다시 누적합니다.

### `Slot State`

한 세이브 슬롯의 현재 진행과 최소 회차 요약입니다.

- 슬롯 ID
- 현재 상태 `EMPTY / PLAYING / RUN_COMPLETE`
- 완료 회차 수
- 직전 완료 캐릭터
- 직전 엔딩
- `activeRun`
- 마지막 저장 시점

### `Meta Progress`

로그인한 **계정 단위로 저장**되며 모든 슬롯과 모든 회차에서 공유하는 장기 진행입니다.

- 해금 캐릭터·펫·배경
- 플레이 완료 캐릭터
- 배지·퍼즐 조각
- 확인 엔딩
- 영구 보너스
- 누적 미니게임·모험·NPC·수업 기록
- 장기 해금 조건 달성 기록

`Run State`와 `Slot State`가 삭제되거나 새로 생성되어도 `Meta Progress`는 자동으로 초기화하지 않습니다.

## 13. 현재 개발판과 본편 기획의 구현 경계

`engine/`에는 같은 주소/브라우저의 로컬 저장 adapter를 사용하는 실행형 시안이 있습니다. 빈 슬롯 자동 배정, 이어서 하기 프레임, 최근 저장 바로가기, 주말 저장·재개, 손상 데이터 보존과 저장 실패 재시도는 구현되어 있습니다. 엔딩 직업·편지 표시 프레임과 사용자 승인 예시가 있지만 실제 회차 완료/저장을 처리하지 않습니다. 계정 서버 저장, 본편 펫 `activePetId`·보정, 해금 조건 판정, AI 편지 생성·검증과 엔딩 완료 저장은 후속 연결 대상입니다. 최신 펫·엔딩 기획은 유지하며 실제 구현 완료와 구분합니다. 실행과 검증 범위는 [엔진 README](../../engine/README.md)를 따릅니다.
