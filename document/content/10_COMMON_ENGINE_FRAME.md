# 공통 엔진 프레임·마이룸·모험 흐름

이 문서는 **WBS 4.1 공통 엔진 프레임**의 최종 기획 계약입니다. 화면 공통 HUD, 마이룸 조작, 주간 일정의 연속 실행, 모험 지도·숨은 아이템 미션, 화면 전환·로딩·저장 오류·취소 상태를 정의합니다.

실제 Phaser Scene 구현, 신규 모험맵 에셋 제작, 충돌 마스크 제작과 자동 테스트는 엔진·디자인 개발 WBS에서 별도로 검증합니다. 이 문서의 작업완료 판단은 **기획 화면·상태 계약이 확정되었다는 의미**입니다.

## 1. 공통 화면 프레임

웹사이트식 GNB 하나를 모든 화면에 고정하지 않고, 플레이 상황에 맞는 **공통 HUD/화면 프레임**을 사용합니다.

### 1.1 마이룸 HUD

마이룸은 한 주의 일정을 만들고 기록·수집·계정을 관리하는 기본 허브입니다.

```text
좌측 상단
- 캐릭터 프로필
- 현재 체력
- 날짜
- 계절
- 주차
- 현재/다음 일정 안내

우측 상단
- 다이어리
- 가방
- 메뉴

하단
- 스케줄
```

프로필은 상세 프로필 화면, 다이어리는 기록 화면, 가방은 수집·펫·마이룸 관련 화면으로 이동합니다. 현재 선택 펫을 직접 누르면 가방의 펫 탭을 엽니다.

### 1.2 활동 HUD

수업·모험·특수 활동 중에는 마이룸의 전체 메뉴를 유지하지 않습니다. 현재 활동에 필요한 최소 정보와 활동 전용 조작만 보여 줍니다.

- 수업: 수업/장소명, 미니게임 전용 상태, 필요한 경우 `포기하기`
- 모험: 장소명, 남은 시간, 단서, 목표 아이템 수, 발견 수, 조사 횟수
- 특수 활동: 장소/활동명과 해당 활동 전용 조작
- 휴식: 마이룸 배경에서 휴식 선택 UI 사용

### 1.3 스토리 HUD

메인·NPC·Location Story·엔딩 화면은 이야기 몰입을 우선하며 성장/수집 메뉴를 상시 노출하지 않습니다. `대화 기록 / 건너뛰기 / 닫기`처럼 해당 스토리에서 허용하는 보조 조작만 제공합니다.

## 2. 마이룸 최종 역할

마이룸에서 플레이어가 직접 사용하는 핵심 진입점은 다음입니다.

| 대상 | 이동/역할 |
|---|---|
| 프로필 카드 | 현재 캐릭터 상세 프로필 |
| 다이어리 | 완료한 활동·기록 확인 |
| 가방 | 아이템·배지·캐릭터·펫·마이룸 관련 수집 화면 |
| 현재 펫 | 가방의 펫 탭 |
| 스케줄 | 월~금 주간 일정 작성 |
| 메뉴 | 관계·계정·타이틀 복귀 등 보조 기능 |

중앙 플레이어 캐릭터와 배경 자체는 별도 기능을 억지로 추가하지 않습니다. 상호작용 가능한 대상은 시각적으로 의미가 분명한 진입점 중심으로 제한합니다.

### 메뉴 정리

- `오늘을 마무리하기`는 최종 메뉴에서 **삭제**합니다.
- 개발 검증용 `전체 흐름 보기`는 최종 게임 메뉴에 포함하지 않습니다.
- `방 변경·퍼즐`은 별도 중복 메뉴를 만들지 않고 **가방의 마이룸 영역**에서 관리합니다.
- `계정`은 [첫 화면·이어 하기·계정 화면 계약](09_TITLE_ACCOUNT_UI.md)에 따라 게임 메뉴의 1뎁스로 둡니다.
- `오늘 돌아보기`는 별도 콘텐츠 계약이 확정될 때 연결할 수 있으나 WBS 4.1 공통 프레임의 필수 진행 버튼으로 사용하지 않습니다.

## 3. 한 주 일정의 연속 실행

주간 일정 5개를 확정하고 `일정 시작`을 누르면 **월요일부터 금요일까지 하나의 연속 진행 흐름**으로 처리합니다.

```text
마이룸
→ 월~금 일정 5개 작성
→ 일정 시작
→ 월요일 활동
→ 결과 확정·자동 저장
→ 화요일 활동 자동 진입
→ 결과 확정·자동 저장
→ 수요일 활동 자동 진입
→ ...
→ 금요일 활동
→ 결과 확정·자동 저장
→ 주말 처리/이벤트
→ 주간 저장
→ 다음 월요일 주간 요약
→ 마이룸에서 새 주 일정 작성
```

- 한 활동이 끝날 때마다 마이룸으로 돌아가지 않습니다.
- 활동 결과 저장이 성공하면 플레이어가 별도의 `다음 일정 시작` 버튼을 누르지 않아도 다음 예정 활동으로 이동합니다.
- 다음 활동을 알 수 있도록 짧은 결과/전환 표시는 둘 수 있지만, 추가 확인 버튼을 진행 조건으로 만들지 않습니다.
- **저장 성공 전에는 다음 활동으로 넘어가지 않습니다.** 저장 실패 시 자동 진행을 멈추고 재시도를 제공합니다.

### 휴식만 마이룸을 활동 공간으로 사용

평일 일정 중 마이룸으로 진입하는 정상 활동은 **휴식**입니다.

```text
휴식 일정 도달
→ 마이룸
→ 무엇을 하며 쉴지 선택
→ 체력 회복 결과 확정
→ 자동 저장
→ 다음 예정 일정 자동 진입
```

강제휴식도 휴식 규칙에 맞는 마이룸 연출을 사용할 수 있습니다. 휴식 중 마이룸을 보여 주는 것은 주간 연속 실행을 취소하거나 일정 편집 상태로 돌아간다는 의미가 아닙니다.

### 이어 하기·재접속의 마이룸 복귀

정상 월~금 연속 실행과 달리 **재접속 또는 타이틀의 `이어 하기`는 마이룸을 기본 복귀 허브로 사용**합니다.

```text
이어 하기/재접속
→ 세이브 로드
→ 필요 시 IN_PROGRESS → INTERRUPTED 복구 저장
→ 마이룸
→ 현재 phase 확인
   ├─ 새 주/일정 미확정 → 주간 요약(필요 시) → 스케줄 작성
   ├─ 주간 진행 중 → 다음 예정 활동
   └─ 다음 일정 휴식 → 마이룸 휴식 UI
```

단, 엔딩 표시가 아직 최종 확인되지 않은 상태는 예외입니다. 이 경우 일반 마이룸 복귀보다 저장된 엔딩 재표시를 우선합니다.

## 4. 모험 장소

Final Project의 직접 모험 장소는 총 **3곳**을 사용합니다.

1. `유리 온실·약초원`
2. `대서고`
3. `별빛 천문대`

현재 엔진에는 유리 온실 이동 시안과 충돌 마스크가 존재합니다. 대서고와 별빛 천문대는 동일한 수준의 모험용 `world / foreground / collision mask` 자원이 후속 제작 대상입니다.

주간 일정 작성 단계에서 단순히 `모험`만 넣지 않고 **모험 장소까지 선택해 해당 날짜의 일정으로 확정**합니다. 따라서 주간 실행이 시작된 뒤 장소 선택 때문에 연속 진행이 다시 멈추지 않습니다.

예:

```text
월요일 · 마법 수업
화요일 · 대서고 모험
수요일 · 휴식
목요일 · 표현 수업
금요일 · 별빛 천문대 모험
```

## 5. 모험 미션의 한 가지 기본 규칙

세 모험 장소 모두 기본 미션은 동일합니다.

> **보이지 않는 목표 아이템을 단서와 조사를 이용해 제한시간 안에 모두 발견한다.**

모험마다 난이도에 따라 **1~5개의 숨겨진 목표 아이템**을 배치합니다. 화면에는 아이템 자체를 표시하지 않습니다.

### 난이도와 목표 개수

기존 성장 난이도 구간을 사용합니다.

| 탐험 저장 스탯 | 모험 난이도 | 목표 아이템 수 |
|---:|---|---:|
| `0~100` | 쉬움 | 1개 |
| `101~200` | 보통 | 2개 |
| `201~350` | 어려움 | 3~4개 |
| `351~500` | 매우 어려움 | 5개 |

`어려움`의 3개/4개 여부는 미션 마스터 데이터에서 정할 수 있습니다. 아이템 수를 1~5 사이 완전 랜덤으로 정해 같은 난이도의 요구량이 과도하게 흔들리게 만들지 않습니다.

## 6. 모험 제한시간

탐험 스탯이 높을수록 실제 맵을 돌아다닐 수 있는 시간이 길어집니다.

- 탐험 `50 이하`: **120초**
- 탐험 `50~500`: **120초 → 240초 선형 증가**
- 탐험 `500 이상`: **240초**

시간 계산식:

```text
E = clamp(시간 계산용 탐험 수치, 50, 500)

E <= 50
→ 120초

50 < E < 500
→ round(120 + ((E - 50) / 450) × 120)초

E >= 500
→ 240초
```

시간 계산용 탐험 수치는 `저장 탐험 스탯 + 활성 펫의 탐험 보정`을 `500` 상한으로 사용합니다. 저체력 상태의 유효 스탯 `-30%`는 모험 제한시간을 다시 줄이는 데 사용하지 않습니다. 저체력의 성장 효율 감소는 결과 성장량에만 적용합니다.

## 7. 숨겨진 아이템 배치

아이템은 임의의 이미지 좌표가 아니라 **플레이어가 실제로 도달 가능한 이동 영역 안**에만 배치합니다.

배치 계약:

```text
충돌 마스크의 이동 가능 영역
→ 모험 시작점에서 실제 연결된 영역만 추출
→ 캐릭터 이동/조사 판정 크기만큼 벽·장애물에서 안전 여유 확보
→ 시작점 바로 주변과 별도 금지 영역 제외
→ 아이템끼리 지나치게 겹치지 않도록 최소 간격 확보
→ 필요한 개수만큼 좌표 선택
```

- 시작점에서 도달할 수 없는 고립된 이동 가능 픽셀/영역은 후보에서 제외합니다.
- 캐릭터가 그래픽상 접근했다고 느끼는데 벽 판정 때문에 조사할 수 없는 위치를 만들지 않습니다.
- 맵별로 배치하면 안 되는 연출·출입구·오브젝트 영역은 금지 영역으로 추가할 수 있습니다.
- 구현은 충돌 마스크에서 안전 후보를 생성하거나, 검증된 후보 좌표 풀을 함께 사용할 수 있습니다. 어느 방식을 쓰더라도 **도달 가능성 검증**이 우선입니다.

## 8. 모험 시작 전 단서 화면

모험 장소에 들어왔다고 바로 타이머를 시작하지 않습니다.

```text
모험 장소 진입
→ 목표 아이템 좌표 배치
→ 이동 잠금
→ 타이머 정지
→ 모든 목표 아이템의 단서 표시
```

아이템이 N개라면 **N개의 단서를 모두 처음부터 보여 줍니다.** 플레이어는 어떤 아이템부터 찾을지 선택할 수 있습니다.

예:

```text
이번 모험에서 찾아야 할 것

○ 푸른 잎의 씨앗
  입구에서 2시 방향

● 오래된 룬 조각       ← 현재 추적
  입구에서 10시 방향

○ 작은 약초 주머니
  입구에서 5시 방향

[모험 시작]
```

최초 시계 방향 단서의 기준점은 **해당 맵의 모험 시작 위치/입구**입니다. 단서를 선택하면 현재 추적 대상으로 표시합니다. 추적은 힌트를 이해하기 위한 UI 기능이며, 선택하지 않은 다른 아이템을 우연히 정확한 위치에서 조사해도 정상 발견으로 인정합니다.

`모험 시작`을 누르면 이동을 허용하고 제한시간 카운트다운을 시작합니다.

## 9. 모험 HUD와 단서 다시 보기

모험 중 상단에는 최소 다음 정보를 표시합니다.

```text
[단서]
남은 시간 02:17
아이템 1 / 3
조사 4회
```

- 단서 아이콘을 누르면 처음과 같은 전체 단서 목록을 다시 볼 수 있습니다.
- 다시 보기 화면에서는 `모험 시작`이 아니라 `닫기`를 표시합니다.
- 단서를 읽는 동안 **타이머와 캐릭터 이동을 일시정지**합니다.
- 단서 화면에서 현재 추적 대상을 변경할 수 있습니다.

아이들이 글을 읽거나 선택하는 시간이 실제 탐색시간을 소비하지 않게 합니다.

## 10. 조사

모험 중 조사 횟수에는 별도 상한을 두지 않습니다. 제한시간 안에서는 얼마든지 다시 조사할 수 있습니다.

```text
[조사]
→ 조사 횟수 +1
→ 이동 잠금
→ 타이머 일시정지
→ `찾는 중...`
→ 1.0~2.0초 사이의 소수점 포함 랜덤 연출시간
→ 발견/미발견 판정
```

랜덤 조사시간은 연출 차이만 만들고 플레이어의 실제 제한시간을 랜덤하게 깎지 않습니다.

### 발견 판정 범위

전체 SD 이미지의 투명 여백·머리까지 포함한 사각형을 쓰지 않고, **캐릭터가 실제 이동 판정에서 차지하는 발/몸 충돌 영역에 대응하는 탐색 범위**를 사용합니다.

목표 좌표가 이 조사 범위 안에 있으면 발견합니다. 정확히 한 픽셀 위에 서야 하는 조작은 요구하지 않고, 플레이어가 해당 지점에 도달했다고 느낄 정도의 판정 여유를 둡니다.

아이템끼리는 조사 범위가 불필요하게 겹치지 않게 배치합니다.

### 발견 성공

- 발견 아이템을 이번 시도의 `foundThisAttempt`에 추가합니다.
- 발견 수를 갱신합니다.
- 추적 중인 아이템을 발견한 경우 다음 미발견 아이템으로 추적을 옮길 수 있습니다.
- 추적하지 않던 아이템을 우연히 발견해도 동일하게 발견 처리합니다.

### 발견 실패

아무 목표 아이템도 조사 범위에 없으면 실패입니다. 현재 추적 중인 미발견 아이템을 기준으로 **방향과 거리의 정성적 추가 힌트**를 제공합니다.

예:

```text
여기에는 없는 것 같아.
오른쪽을 더 찾아보자.
아직 조금 멀리 있는 것 같아.
```

방향·거리의 정확한 구간값과 문구 세트는 플레이테스트 가능한 밸런스 상수로 두며, 아이에게 정확한 좌표 숫자를 직접 노출하지 않습니다.

## 11. 타이머 일시정지 대상

제한시간은 **실제로 맵을 탐색하고 이동하는 시간**을 중심으로 사용합니다.

다음 동안에는 타이머를 정지합니다.

- 최초 단서 브리핑
- 모험 중 단서 다시 보기
- `찾는 중...` 조사 연출과 판정
- NPC 대화·Location Story처럼 읽기/선택이 필요한 장면
- 시스템 로딩 또는 게임이 입력을 받을 수 없는 상태

단서·스토리를 천천히 읽는 아이가 시간상 불이익을 받지 않게 합니다.

## 12. 모험 종료 조건

모험의 정상 결과는 두 가지입니다.

### `MISSION_COMPLETE`

제한시간 안에 목표 아이템을 모두 발견하면 즉시 성공합니다.

```text
발견 수 = 목표 수
→ MISSION_COMPLETE
→ 모험 성공 결과·발견 기록 확정
→ 정상 탐험 성장량 적용
→ 활동 결과 자동 저장
→ 다음 예정 일정 자동 진입
```

모험의 숨은 목표 아이템은 현재 모험판의 성공 조건을 위한 임시 미션 오브젝트입니다. 성공해도 개별 목표 아이템 ID를 가방 인벤토리나 계정 전역 수집 목록에 저장하지 않습니다. 기존 배지·엔딩에서 사용하는 발견 관련 횟수형 통계는 콘텐츠가 해당 발견을 기록 대상으로 지정한 경우 **플레이 기록 카운터**로만 증가할 수 있으며, 이는 아이템 보유를 뜻하지 않습니다.

### `TIMEOUT`

타이머가 `0`이 되었는데 미발견 목표가 하나 이상 남아 있으면 해당 모험판 전체를 실패로 처리합니다.

```text
시간 초과
→ TIMEOUT
→ 이번 판의 목표 아이템 획득 없음
→ 발견했던 목표 아이템도 획득 데이터에 반영하지 않음
→ 일부 탐험 성장량만 적용
→ 활동 결과 자동 저장
→ 다음 예정 일정 자동 진입
```

예를 들어 `2 / 3`을 발견했더라도 해당 미션은 실패이며, 다음에 같은 미션을 플레이하면 그 아이템들도 다시 찾아야 합니다. `foundThisAttempt`는 현재 모험판의 임시 진행도입니다. 성공 시에는 미션 성공·성장·필요한 발견 통계만 확정하고 개별 목표 아이템을 영구 소지품으로 커밋하지 않습니다.

NPC 조우·스토리처럼 미션 아이템과 별개의 이벤트 기록은 이벤트 시스템의 완료 규칙을 따르며, `TIMEOUT`이라는 이유만으로 이미 완료된 별도 이야기 결과를 임의로 되돌리지 않습니다.

## 13. 실패 시 부분 탐험 성장

모험 실패에서 목표 아이템을 일부 발견했다면 탐색 경험이 완전히 사라지지 않도록 **탐험 스탯 일부 성장**을 제공합니다. 다만 성공 보상보다 명확히 작게 유지합니다.

기본 계산:

```text
발견 수 = 0
→ 부분 성장 0

발견 수 > 0
→ floor(해당 미션의 정상 탐험 성장량 × (발견 수 / 목표 수) × 0.5)
→ 최종 최소 +1
```

- 미션을 성공한 경우 부분 성장과 성공 성장을 중복 지급하지 않고 정상 성공 성장량만 적용합니다.
- 저체력 성장 효율은 기존 공통 규칙을 반영하되, 한 개 이상 실제 발견한 `TIMEOUT` 결과는 최종 탐험 성장 최소 `+1`을 보장합니다.
- 비정상 종료 `INTERRUPTED`는 발견 수와 관계없이 성장량 `0`이며 미션 아이템도 획득하지 않습니다.
- 해당 미션의 정상 탐험 성장량 자체는 콘텐츠/밸런스 데이터에서 관리하며 WBS 4.1 화면 흐름이 특정 성장 수치를 강제하지 않습니다.

## 14. 수동 모험 중단 없음

최종 모험에는 날짜를 소비하지 않고 마이룸으로 돌아가는 `중단` 버튼을 두지 않습니다.

- 정상 성공: `MISSION_COMPLETE`
- 정상 실패: `TIMEOUT`
- 브라우저 종료·프로세스 종료 등 비정상 중단: `INTERRUPTED`

활동 시작 체크포인트가 이미 저장된 뒤 비정상 종료되면 기존 저장 정책대로 소비한 체력을 유지하고 모험 보상·부분 성장 없이 해당 일정을 `INTERRUPTED`로 완료 처리한 뒤 다음 예정 일정으로 복구합니다.

## 15. 공통 화면 상태

프레임 간 상태를 다음 원칙으로 통일합니다.

| 상태 | 처리 |
|---|---|
| `LOADING` | 필요한 데이터/자원 로드 중. 중복 입력 잠금 |
| `READY` | 정상 입력 가능 |
| `SAVING` | 결과 저장 중. 다음 화면 전환·중복 제출 잠금 |
| `ERROR_RETRYABLE` | 원본 상태를 보존하고 오류 설명 + `다시 시도` 제공 |
| `RECOVERY` | 비정상 중단을 마지막 안정 체크포인트 기준으로 정리하고 다음 정상 화면으로 복귀 |

### 저장 실패

```text
활동 결과
→ SAVING
→ 저장 실패
→ 자동 진행 중단
→ 오류 안내 + [다시 시도]
→ 저장 성공
→ 다음 일정 자동 진행
```

저장 실패 알림은 몇 초 뒤 사라지는 일반 토스트로 끝내지 않고 재시도 진입점을 유지합니다.

### 활동 자원 로드 실패

활동 시작 체크포인트 저장 이후 미니게임/모험 자원을 불러오지 못했다면 일정을 새로 소비하거나 체력을 한 번 더 차감하지 않습니다. 같은 활동 자원 로드를 재시도합니다. 브라우저 자체를 종료하면 해당 `IN_PROGRESS` 활동은 기존 `INTERRUPTED` 복구 규칙을 따릅니다.

### 대화·이야기 저장 경계

NPC·Location Story·메인 대화는 대사 한 줄이나 선택지 중간에 저장하지 않습니다. 활동 결과를 먼저 안정 저장한 뒤 이야기를 실행하고, 장면을 정상 완료했을 때 선택 결과·스토리 진행·플래그를 반영해 저장합니다. 따라서 `이어 하기`가 특정 대사 중간 위치를 복원하는 상태는 정의하지 않습니다.

## 16. 뒤로가기·취소 원칙

- 주간 일정 계획 중: 마이룸과 일정 화면 사이 이동 가능, 아직 시작하지 않은 초안 유지
- `일정 시작` 이후: 주간 일반 일정 취소·재편집 불가
- 수업 미니게임: 명시된 `포기하기`는 `FAIL`
- 모험: 날짜를 되돌리는 수동 `중단` 없음
- 휴식: 마이룸에서 휴식 선택 후 결과 확정
- 프로필·가방·다이어리 등 정보 화면: `X`로 원래 마이룸 복귀
- 스토리: 콘텐츠가 허용한 경우에만 `건너뛰기`
- 슬롯 삭제·계정 탈퇴 같은 파괴 작업: 확인 절차 사용

활동 진행 중 브라우저 이탈에는 가능한 환경에서 `현재 활동이 중단 처리될 수 있음`을 알리는 이탈 경고를 사용할 수 있습니다. 브라우저가 경고를 보장하지 못하더라도 저장 복구 규칙이 최종 안전장치입니다.

## 17. WBS 4.1 완료 판단

### 4.1.1 상단 GNB 역할·표시 상태

- 하나의 고정 GNB 대신 `마이룸 HUD / 활동 HUD / 스토리 HUD` 역할 확정
- 마이룸 프로필·체력·날짜·주차·다이어리·가방·메뉴·스케줄 역할 확정
- 모험 HUD의 단서·타이머·발견/목표·조사 횟수 확정

### 4.1.2 마이룸 조작 흐름

- 프로필·다이어리·가방·펫·스케줄·메뉴 진입점 확정
- `오늘을 마무리하기` 삭제 확정
- 개발용 `전체 흐름 보기` 최종 메뉴 제외
- 방 변경·퍼즐을 가방 마이룸 영역으로 통합
- 주간 일정 시작 후 월~금 자동 연속 진행 확정
- 정상 평일 진행에서 휴식만 마이룸을 활동 공간으로 사용

### 4.1.3 모험 지도·장소 진입 흐름

- 유리 온실·대서고·별빛 천문대 3개 직접 모험 장소 확정
- 주간 계획 단계에서 모험 장소 선택 확정
- 도달 가능한 충돌 영역 기반 숨은 아이템 1~5개 배치 확정
- 모든 단서 선공개·추적 선택·우연 발견 인정 확정
- 탐험 수치 기반 120~240초 제한시간 확정
- 조사 무제한·조사/단서/대화 중 타이머 정지 확정
- `MISSION_COMPLETE / TIMEOUT / INTERRUPTED` 결과 계약 확정
- 실패 시 목표 아이템 미획득·부분 탐험 성장 확정

### 4.1.4 화면 전환·공통 오류/취소 상태

- `LOADING / READY / SAVING / ERROR_RETRYABLE / RECOVERY` 공통 상태 확정
- 활동 결과 저장 성공 후 다음 일정 자동 이동 확정
- 저장 실패 시 자동 진행 중단·재시도 확정
- 일정 시작 후 취소 불가, 미니게임 포기와 모험 TIMEOUT/INTERRUPTED 구분 확정
- 정상 활동 완료는 다음 일정으로 직접 진행하고, 재접속/이어 하기 복구는 마이룸 허브에서 다음 상태를 판별하는 원칙 확정

위 계약으로 **WBS 4.1 기획 범위는 작업완료 판단 가능**합니다. 실제 신규 2개 모험맵 제작, 모험 검색 로직·타이머·HUD 구현, 현재 엔진의 마이룸 경유 흐름 수정과 통합 플레이테스트는 엔진·디자인 개발 WBS에서 별도로 수행합니다.
