# 7개 공간 콘텐츠 상세 규칙

이 문서는 WBS 2.4.1~2.4.9의 본편 기획 계약입니다. `engine/minigame-demo/`는 참고 구현이고, **본편에서는 아래 6개 미니게임 + 1개 특수 활동**을 사용합니다.

## 1. 전체 연결표

| 장소 | 코드 | 과목·활동 | 수업·일정 | 콘텐츠 | 결과 대상 |
|---|---|---|---|---|---|
| 별빛 천문대 | `OBS` | 천문 관측학 | 탐사 실습 | 거울 마법 | 탐험 |
| 시계탑 광장 야외무대 | `CLK` | 공연 표현학 | 표현 수업 | 별빛 무대 | 표현력 |
| 유리 온실·약초원 | `GH` | 약초 분류학 | 약초학 실습 | 정령 화분 정리 | 지식 |
| 기숙사 공용 공간 | `DRM` | 자율 활동 | 요정과 만나기 | 요정의 거래 | 성장 스탯 이전 |
| 대서고 | `LIB` | 고대 기록학 | 기록학 실습 | 봉인 서가 | 지식 |
| 마도 공방 | `WRK` | 룬 공학 | 마법훈련 | 룬 회로 | 마법 |
| 수련장 | `TRN` | 검술학 | 검술훈련 | 룬 핀 훈련 | 솜씨 |

지식은 `GH / LIB` 두 공간에서 성장할 수 있고 나머지 성장 스탯은 한 공간을 대표 경로로 사용합니다. 체력은 미니게임 성장 대상이 아닙니다.

## 2. 일정과 장소 스토리 실행 순서

수업·특수 활동은 평일 일정 슬롯 1칸을 사용합니다. 6개 수업 미니게임은 체력 `10`을 시작 시 소비하고, `요정의 거래`는 체력을 소비하지 않습니다.

```text
평일 일정 시작
→ 활동 시작 체크포인트 자동 저장
→ 미니게임 또는 요정의 거래 실행
→ 결과 확정·스탯 반영
→ 활동 완료 자동 저장
→ 해당 방문에서 Location Story 판정 가능
→ 필요한 장소 이야기가 있으면 별도 이벤트로 실행
→ 이야기 완료 결과 저장
→ 다음 예정 일정
```

- Location Story는 미니게임이나 요정의 거래를 **대체하지 않습니다.** 이벤트는 일정 슬롯을 추가로 소비하지 않습니다.
- 같은 방문에서 Location Story가 발생하더라도 먼저 예약된 공간 콘텐츠의 결과를 확정한 뒤 보여 줍니다.
- 미니게임·요정의 거래·직접 모험의 플레이 화면에는 NPC를 배치하지 않으며 NPC 대화나 이야기 화면을 겹쳐 실행하지 않습니다. NPC/Location Story는 활동 완료 저장 뒤 분리된 이야기 장면으로만 실행합니다.
- Location/NPC Story 대사·선택 중간에는 별도 자동저장을 두지 않고, 장면 정상 완료 시 결과를 한 번 저장합니다.
- 현재 방문 자체가 메인 스토리 강제 장면이면 기존 장소 스토리 규칙대로 같은 방문의 Location Story 판정을 생략할 수 있습니다.
- 미니게임 도중 비정상 종료된 방문은 복구 시 해당 활동을 `INTERRUPTED`로 끝내고 Location Story를 새로 굴리지 않습니다.

## 3. 공통 난이도와 연속 실패 보정

### 3.1 보상 난이도

스탯 시스템의 기존 4단계를 그대로 사용합니다.

| `run.stats` | `rewardDifficulty` |
|---:|---|
| `0~100` | `EASY` |
| `101~200` | `NORMAL` |
| `201~350` | `HARD` |
| `351~500` | `VERY_HARD` |

`rewardDifficulty`는 성장량 계산용이며 연속 실패 보정으로 바뀌지 않습니다.

### 3.2 실제 플레이 난이도

게임별 현재 회차 연속 실패 횟수 `consecutiveFails`를 사용합니다.

```text
0~1회 연속 FAIL → assistLevel 0
2~3회 연속 FAIL → assistLevel 1
4회 이상 연속 FAIL → assistLevel 2

playDifficulty
= rewardDifficulty를 assistLevel만큼 하향
단, EASY보다 아래로 내려가지 않음
```

- `FAIL`이면 해당 게임의 `consecutiveFails += 1`.
- `SUCCESS` 또는 `GREAT`이면 `consecutiveFails = 0`.
- `포기하기`는 `FAIL`이므로 연속 실패 횟수에 포함합니다.
- 비정상 종료로 복구된 `INTERRUPTED`는 실패 횟수에 포함하지 않습니다.
- 보정은 한 회차 안에서 같은 `gameId`에만 유지하며 새 회차에서는 초기화합니다.
- 보정 중에는 `조금 더 쉬운 연습으로 준비했어.` 정도의 안내만 보여 주고 실패 횟수 숫자를 강조하지 않습니다.

예:

```text
마법 run.stats = 240
→ rewardDifficulty = HARD

룬 회로 2회 연속 실패
→ 다음 룬 회로 playDifficulty = NORMAL
→ 성공 보상은 HARD 기준 +7
```

## 4. 공통 결과·포기 계약

6개 미니게임은 다음 형태의 결과를 반환합니다.

```js
{
  gameId: 'rune-circuit',
  locationCode: 'WRK',
  targetStat: 'magic',
  rewardDifficulty: 'HARD',
  playDifficulty: 'NORMAL',
  assistLevel: 1,
  outcome: 'SUCCESS', // FAIL | SUCCESS | GREAT
  endReason: 'COMPLETE', // COMPLETE | TIMEOUT | QUIT
  score: 78,
  durationMs: 82400,
  metrics: {}
}
```

- `outcome`만 스탯 성장량 계약에 사용합니다.
- `score`는 게임 내부 성과 비교값이며 성장량과 직접 동일하지 않습니다.
- `포기하기`를 누르면 확인 단계를 한 번 거친 뒤 `outcome=FAIL`, `endReason=QUIT`으로 종료합니다.
- 포기해도 이미 사용한 일정 슬롯과 체력 `10`은 복구하지 않습니다.
- `FAIL` 뒤 결과 화면에서 즉시 `다시 하기`를 제공하지 않습니다.
- 타임아웃은 각 게임의 완료 조건에 따라 `FAIL` 또는 이미 확보한 진행 기준으로 판정할 수 있지만, 아래 6개 규칙에서는 별도 명시가 없으면 `FAIL`입니다.

성장량은 `rewardDifficulty` 기준으로 기존 공통 표를 적용한 뒤, `document/content/02_STATS_EVENTS_ENDINGS/01_STATS_SYSTEM.md`의 관리자 전역 `rewardMultiplier[targetStat]`와 저체력 성장 효율을 함께 적용합니다. 관리자 배율은 결과 판정이나 `playDifficulty`를 바꾸지 않고 최종 획득 성장량만 낮춥니다.

## 5. 별빛 천문대 — 거울 마법

### 역할

천문대의 별빛을 거울과 프리즘으로 반사해 관측 룬을 밝히는 **빛 경로 퍼즐**입니다. 기존 데모의 거울 회전 조작을 본편에 재채택합니다.

### 조작·한 세션

- 거울을 클릭/터치하면 방향을 회전합니다.
- 빛의 현재 경로는 즉시 다시 표시합니다.
- 한 세션은 검증된 스테이지 3개, 최대 약 `120초`를 기본으로 합니다.
- 각 스테이지의 목표 관측 룬을 모두 밝히면 다음 단계로 이동합니다.

### 결과

- `GREAT`: 3개 모두 해결 + 전체 제한시간 `20초 이상` 남음.
- `SUCCESS`: 3개 중 2개 이상 해결.
- `FAIL`: 2개 미만 해결, 제한시간 종료, 또는 포기.

### 난이도

| 난이도 | 규칙 변화 |
|---|---|
| EASY | 목표 1개, 적은 거울, 장애물 없음 |
| NORMAL | 거울 증가 + 고정 장애물 |
| HARD | 반드시 통과해야 하는 별 룬 추가 |
| VERY_HARD | 프리즘 분기 + 목표 2개를 함께 점등 |

### 반복 변형

검증된 스테이지 풀과 seed를 사용해 거울 위치, 장애물, 목표 별 룬 조합을 바꿉니다. 무작위 생성은 **해답 존재 검증** 없이 사용하지 않습니다.

## 6. 시계탑 광장 — 별빛 무대

### 역할

아르카디아 야외무대에서 공연 신호에 맞춰 표현을 이어 가는 **리듬 탭 게임**입니다. `Piano Tiles` 계열의 짧은 몰입과 타이밍 조작을 판타지 공연으로 변환합니다.

### 조작·한 세션

- 기본 레인은 `표정 / 몸짓 / 마법 연출` 3종입니다.
- 신호가 판정선에 도착할 때 해당 레인을 클릭/터치합니다.
- 약 `60~90초`의 고정 길이 공연 한 곡을 진행합니다.
- 실제 음악이 없어도 일정 BPM과 효과음만으로 판정 가능하게 설계합니다.

### 결과

전체 유효 입력 대비 정확도를 계산합니다.

- `GREAT`: 정확도 `90% 이상`.
- `SUCCESS`: 정확도 `65% 이상 90% 미만`.
- `FAIL`: 정확도 `65% 미만` 또는 포기.

### 난이도

| 난이도 | 규칙 변화 |
|---|---|
| EASY | 2레인, 느린 BPM, 단일 탭 위주 |
| NORMAL | 3레인, 기본 속도 |
| HARD | 홀드 신호와 짧은 연속 입력 추가 |
| VERY_HARD | 속도 변화 + 동시 또는 교차 신호 일부 추가 |

### 반복 변형

동일한 조작 규칙 아래 공연 장면, BPM, 신호 패턴 세트를 여러 개 둡니다. 패턴은 완전 랜덤보다 검증된 pattern set을 섞어 사용합니다.

## 7. 유리 온실·약초원 — 정령 화분 정리

### 역할

`Water Sort Puzzle`의 핵심 규칙을 **정령 화분 안에 쌓인 꽃빛·씨앗 룬을 같은 종류끼리 정리하는 퍼즐**로 재해석합니다. 물병 이미지는 사용하지 않습니다.

### 조작·한 세션

- 한 화분의 맨 위에 연속해 있는 같은 색 꽃빛 묶음을 다른 화분으로 옮깁니다.
- 빈 화분 또는 맨 위 색이 같은 화분에만 옮길 수 있습니다.
- 화분별 최대 수용량을 넘길 수 없습니다.
- 모든 화분이 한 종류의 꽃빛만 가지거나 비어 있으면 완료합니다.
- 한 세션은 퍼즐 1개, 목표 `60~120초`입니다.

### 결과

각 스테이지 마스터 데이터에 `greatMoveLimit`을 둡니다.

- `GREAT`: 완성 + 이동 횟수 `<= greatMoveLimit`.
- `SUCCESS`: 제한시간 안에 완성.
- `FAIL`: 제한시간 안에 완성하지 못함 또는 포기.

### 난이도

| 난이도 | 규칙 변화 |
|---|---|
| EASY | 3색 + 빈 화분 2개 |
| NORMAL | 4색 + 빈 화분 2개 |
| HARD | 5색 + 빈 화분 2개, 더 깊은 혼합 |
| VERY_HARD | 6색 + 빈 화분 2개, 긴 선행 정리 필요 |

### 반복 변형

해답이 검증된 배치 세트를 난이도별로 여러 개 사용하고 꽃빛 색·식물 장식만 가볍게 바꿉니다.

## 8. 기숙사 공용 공간 — 요정의 거래

`요정의 거래`는 미니게임이 아니라 **주간 육성 전략을 조정하는 특수 활동**입니다.

### 일정 규칙

- `SPECIAL` 일정으로 등록합니다.
- 평일 일정 슬롯 1칸을 소비합니다.
- 한 주에 최대 **1회**만 등록할 수 있습니다.
- 체력 소비는 `0`입니다.
- 미니게임 플레이/클리어 횟수나 수업 횟수에는 포함하지 않습니다.

### 거래 규칙

- 대상은 `지식 / 표현력 / 솜씨 / 탐험 / 마법` 5개 성장 스탯만 사용합니다.
- 체력과 보이지 않는 스탯은 거래할 수 없습니다.
- 출발 스탯 1개와 도착 스탯 1개를 서로 다르게 선택합니다.
- 한 번의 방문에서 `1~5` 포인트를 **1:1**로 이전합니다.
- 실제 선택 가능 최대량은 `min(5, 출발 스탯 현재값, 500 - 도착 스탯 현재값)`입니다.
- 거래로 전체 성장 스탯 합계는 증가하지 않습니다.
- 현재 회차 `run.stats`만 바꾸며 영구 보너스·캐릭터 보정·펫 보정을 이동하지 않습니다.

예:

```text
지식 180 / 탐험 145
→ 지식 5를 요정에게 건넴
→ 지식 175 / 탐험 150
```

실행 시 `거래하지 않기`를 선택할 수 있지만 이미 시작된 일정 슬롯은 사용한 것으로 처리합니다. 거래 결과는 `TRANSFERRED` 또는 `SKIPPED`로 기록하며 `FAIL/SUCCESS/GREAT` 판정을 사용하지 않습니다.

## 9. 대서고 — 봉인 서가

### 역할

`Unblock Me / Rush Hour` 계열의 이동 퍼즐입니다. 서가와 책 묶음을 밀어 **봉인된 고서가 출구까지 빠져나갈 길**을 만듭니다.

### 조작·한 세션

- 가로 책 묶음은 좌우, 세로 책 묶음은 상하로만 이동합니다.
- 다른 책 묶음을 통과할 수 없습니다.
- 목표 고서를 출구까지 이동하면 스테이지를 해결합니다.
- `Undo`와 현재 스테이지 `Reset`은 최종 결과가 나오기 전까지 허용합니다. 이는 세션 전체 재도전이 아닙니다.
- 한 세션은 검증된 퍼즐 최대 3개, 약 `60~120초`입니다.

### 결과

- `GREAT`: 3개 모두 해결하고 각 스테이지가 설정한 `greatMoveLimit` 합계 이내.
- `SUCCESS`: 3개 중 2개 이상 해결.
- `FAIL`: 2개 미만 해결, 제한시간 종료, 또는 포기.

### 난이도

| 난이도 | 규칙 변화 |
|---|---|
| EASY | 적은 장애 서가, 짧은 최소 해법 |
| NORMAL | 장애 서가 증가 |
| HARD | 긴 우회 이동과 선행 공간 확보 필요 |
| VERY_HARD | 여러 책 묶음을 되돌려야 하는 긴 최소 해법 |

### 반복 변형

난이도별 hand-authored 퍼즐 풀을 순환·seed 선택합니다. 무작위 생성보다 해법과 이동 수가 검증된 퍼즐을 우선합니다.

## 10. 마도 공방 — 룬 회로

### 역할

파이프 연결 퍼즐을 룬 공학으로 변환합니다. 회로 타일을 회전시켜 마력 발생점에서 목표 마법진까지 유효한 흐름을 만듭니다.

### 조작·한 세션

- 회로 타일을 클릭/터치하면 90도 회전합니다.
- 연결된 마력 구간은 즉시 시각적으로 표시합니다.
- 한 세션은 스테이지 3개, 최대 약 `120초`입니다.

### 결과

- `GREAT`: 3개 모두 해결 + 전체 제한시간 `20초 이상` 남음.
- `SUCCESS`: 3개 중 2개 이상 해결.
- `FAIL`: 2개 미만 해결, 제한시간 종료, 또는 포기.

### 난이도

| 난이도 | 규칙 변화 |
|---|---|
| EASY | `4×4`, 단일 목표, 적은 불필요 타일 |
| NORMAL | `5×5`, 불필요 타일 증가 |
| HARD | 고정 타일 + 반드시 통과해야 하는 룬 |
| VERY_HARD | 분기 회로 + 복수 목표 마법진 |

### 반복 변형

해답 검증된 stage pool에서 seed로 선택합니다. 타일 테마와 목표 룬을 바꾸되 난이도별 최소 해법 범위를 유지합니다.

## 11. 수련장 — 룬 핀 훈련

### 역할

`Knife Hit` 계열의 타이밍 게임을 어린이·학원 세계관에 맞게 **훈련용 룬 핀과 회전 표적**으로 변환합니다. 무기 타격보다 집중·타이밍 훈련으로 표현합니다.

### 조작·한 세션

- 중앙의 훈련 룬 원판이 회전합니다.
- 클릭/터치하면 룬 핀 하나가 원판에 꽂힙니다.
- 이미 꽂힌 핀 또는 보호 영역과 충돌하면 실수 1회입니다.
- 3라운드, 최대 약 `90초`를 사용합니다.

### 결과

- `GREAT`: 3라운드 모두 완료 + 전체 실수 `0~1회`.
- `SUCCESS`: 3라운드 중 2개 이상 완료.
- `FAIL`: 2개 미만 완료, 실수 한도 초과, 제한시간 종료, 또는 포기.

### 난이도

| 난이도 | 규칙 변화 |
|---|---|
| EASY | 느린 일정 회전, 라운드당 적은 핀 |
| NORMAL | 회전 속도 증가 + 라운드당 핀 증가 |
| HARD | 방향 전환과 속도 변화 |
| VERY_HARD | 짧은 정지·재가속 + 보호 영역 일부 등장 |

실수 한도는 세션 전체 `3회`를 기본으로 하고 실제 플레이테스트에서 조정할 수 있습니다.

### 반복 변형

회전 속도 패턴, 시작 방향, 핀 개수, 보호 영역 위치를 난이도별 패턴 풀에서 선택합니다.

## 12. 활동 시작·자동저장·비정상 종료 복구

### 새 회차 최초 저장

`새로 시작하기`는 빈 슬롯이 있을 때만 사용할 수 있습니다. 캐릭터 선택을 확정하면 **첫 번째 빈 슬롯에 회차 문서를 먼저 생성하고 초기 자동저장이 성공한 뒤** MS01과 실제 플레이를 시작합니다.

```text
새로 시작하기
→ 첫 빈 슬롯 확인
→ 캐릭터 선택
→ 슬롯/activeRun 생성·자동저장
→ 저장 성공
→ MS01 / 플레이 시작
```

초기 저장이 실패하면 본편 플레이로 진입하지 않습니다. 슬롯 5개가 모두 사용 중이면 기존 정책대로 `새로 시작하기` 자체가 새 회차를 생성하지 않습니다.

### 활동 체크포인트

미니게임·모험·특수 활동을 시작할 때 다음 순서로 처리합니다.

```text
일정 항목 status = IN_PROGRESS
→ 필요한 체력 선차감
→ 활동 시작 체크포인트 자동저장
→ 저장 성공 후 콘텐츠 실행
```

미니게임 결과가 확정되면 성장량·실패 연속 횟수·통계를 반영하고 해당 일정 항목을 `COMPLETED`로 만든 뒤 다시 자동 저장합니다.

### 비정상 종료

브라우저 강제 종료·프로세스 종료·네트워크 단절 등으로 `IN_PROGRESS` 체크포인트만 남은 경우 재접속 시 다음처럼 복구합니다.

```text
최근 자동저장 로드
→ IN_PROGRESS 일정 발견
→ 해당 활동 resolution = INTERRUPTED
→ 이미 저장된 체력 소비는 유지
→ 성장량 0
→ 미니게임 FAIL/연속 실패 횟수에는 미반영
→ 해당 평일 일정 COMPLETED 처리 후 복구 저장
→ 마이룸 이동
→ 저장 phase 판단
→ 다음 예정 평일 활동 또는 새 주 일정 작성으로 진행
```

미니게임의 프레임·보드·타이머를 저장해 중간부터 다시 시작하지 않습니다. 비정상 종료는 플레이어가 선택한 `포기하기`와 구분합니다. 이 마이룸 복귀는 **재접속/이어 하기 복구 경로**이며 정상 활동 완료 뒤에는 최신 주간 연속 진행 계약대로 다음 예정 활동으로 바로 이동합니다.

## 13. WBS 2.4 기획 완료 기준

다음 계약은 이 문서에서 확정합니다.

- 7개 공간별 콘텐츠 1개 연결
- 6개 미니게임 + 요정의 거래 구분
- 각 게임의 핵심 조작과 1회 흐름
- `FAIL / SUCCESS / GREAT` 조건
- `EASY / NORMAL / HARD / VERY_HARD` 플레이 변화
- 반복 플레이 변형 방식
- 즉시 재도전 없음과 `포기=FAIL`
- 2회 연속 실패부터 난이도 보조
- 보상 난이도와 플레이 난이도 분리
- 공통 결과 객체
- Location Story와 공간 콘텐츠 실행 순서
- 새 회차 최초 저장, 활동 시작 체크포인트, 비정상 종료 복구

따라서 WBS 2.4의 **기획 계약은 작업완료 판단이 가능**합니다. 실제 Phaser 구현·그래픽·사운드·조작감·실측 플레이 시간·난이도 수치 튜닝은 후속 구현/퀄리티 검수 단계로 분리합니다.
