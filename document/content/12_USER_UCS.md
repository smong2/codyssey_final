# 사용자 UCS — 완결된 상호작용 순서

이 문서는 **WBS 4.2 사용자 UCS**의 최종 기획 계약입니다. 기능이 존재한다는 설명이 아니라, 사용자가 실제로 무엇을 누르고 시스템이 어떤 저장·오류·복귀 상태를 거쳐 어디에서 끝나는지를 하나의 순서로 정의합니다.

대상 WBS:

- `4.2.1` 가입·로그인 UCS
- `4.2.2` 새 게임·이어 하기 UCS
- `4.2.3` 한 주 진행 UCS
- `4.2.4` 장소 게임·이야기 UCS
- `4.2.5` 가방·배경 퍼즐 UCS
- `4.2.6` 엔딩·다음 회차 UCS
- `4.2.7` 내 계정 관리 UCS

화면의 상세 디자인은 `09_TITLE_ACCOUNT_UI.md`, `10_COMMON_ENGINE_FRAME.md`, `11_FEATURE_FRAME.md`를 따르고, 이 문서는 **사용자 행동 순서와 종료 상태**를 기준으로 삼습니다.

## 1. 공통 UCS 원칙

### 1.1 정상 진행과 재접속 진행을 구분

정상적으로 한 주를 플레이하고 있을 때는 한 활동 결과 저장이 성공하면 마이룸을 거치지 않고 다음 예정 활동으로 자동 진행합니다.

반면 **로그인 후 `이어 하기`, 브라우저 재접속, 비정상 종료 후 복구**는 기본적으로 마이룸을 복귀 허브로 사용합니다.

```text
이어 하기
→ 세이브 로드/검증
→ 복구가 필요하면 복구 상태 먼저 확정·저장
→ 마이룸
→ 현재 회차 phase 판단
→ 필요한 다음 화면으로 자연스럽게 이동
```

마이룸에서 판단하는 대표 상태:

| 저장 상태 | 마이룸 이후 동작 |
|---|---|
| 새 주 시작, 주간 요약 미확인 | 지난주 주간 요약 → 스케줄 작성 |
| 이번 주 일정 미확정 | 스케줄 작성 화면 |
| 이번 주 일정 확정, 다음 활동 존재 | 다음 예정 활동으로 진행 |
| 다음 활동이 휴식 | 마이룸에서 휴식 선택 UI 표시 |
| `IN_PROGRESS` 활동이 비정상 종료됨 | `INTERRUPTED` 복구 저장 후 마이룸 → 다음 예정 활동 |
| 엔딩 표시가 아직 완료되지 않음 | 마이룸 일반 복귀보다 **엔딩 다시 보기 우선** |

마이룸은 재접속 시 안전하게 현재 진행을 판별하는 **복귀 허브**이지, 정상 월~금 활동 사이에 매번 거치는 중간 화면이 아닙니다.

### 1.2 대화·이야기 장면은 중간 저장하지 않음

메인·NPC·Location Story 대화는 **대사 한 줄, 선택지 노출, 선택 직후 같은 중간 지점에 세이브 체크포인트를 만들지 않습니다.**

- 장면 시작 전 마지막 안정 체크포인트를 사용합니다.
- 장면을 정상 완료하면 선택 결과·스토리 진행·스탯/플래그를 반영하고 저장합니다.
- 중간 종료 후 특정 대사 위치로 복귀하는 기능은 WBS 4.2 범위에 두지 않습니다.
- 따라서 `이어 하기`의 상태별 복귀표에 `대화 7번째 문장` 같은 중간 상태를 만들지 않습니다.

### 1.3 저장 실패

사용자 행동 결과를 확정해야 하는 위치에서 저장이 실패하면 다음 화면으로 넘어가지 않습니다.

```text
결과 확정
→ SAVING
→ 실패
→ 현재 결과/원본 상태 보존
→ 오류 + [다시 시도]
→ 저장 성공
→ 다음 단계
```

# 2. WBS 4.2.1 — 가입·로그인 UCS

## UCS-A01 기존 인증 계정 로그인

```text
로그인 화면
→ 이메일 입력
→ 비밀번호 입력
→ [로그인]
→ Firebase 인증
→ email_verified 확인
→ 인증 완료 계정
→ 인트로
→ 타이틀
```

- 계정 없음/비밀번호 오류 → 로그인 화면 유지
- 이메일 미인증 → 인증 대기 화면
- 네트워크 오류 → 일반 오류 + 재시도

## UCS-A02 회원가입·이메일 인증

```text
로그인 화면
→ [회원가입]
→ 이메일 / 비밀번호 / 비밀번호 확인
→ 개인정보 필수 동의
→ [회원가입]
→ Firebase 계정 생성
→ 인증 메일 발송
→ 인증 대기 화면
→ 이메일에서 인증
→ 게임의 [인증 완료 확인]
→ 현재 Firebase 세션 갱신
→ 인트로
→ 타이틀
```

- 인증 완료 전 본편 세이브/메타를 만들지 않습니다.
- 인증 메일이 오지 않으면 `인증 메일 다시 보내기`를 사용합니다.
- 인증 확인 성공 뒤 이메일·비밀번호를 다시 입력시키지 않습니다.

## UCS-A03 비밀번호 분실

현재 비밀번호를 모르는 **복구 상황만** 외부 이메일 링크를 사용합니다.

```text
비밀번호를 잊으셨나요?
→ 등록 이메일 확인
→ 재설정 메일 발송
→ 이메일 보안 링크
→ 사용자가 새 비밀번호 직접 설정
→ 로그인 화면
→ 새 비밀번호로 로그인
```

# 3. WBS 4.2.2 — 새 게임·이어 하기 UCS

## UCS-S01 새 게임

```text
타이틀
→ [시작하기] 또는 [새로 시작하기]
→ 첫 번째 빈 슬롯 자동 예약
→ 캐릭터 선택
→ [시작하기]
→ 슬롯 + Active Run 생성
→ 초기 자동 저장
→ 저장 성공
→ MS01 입학·온보딩
→ 첫 주 진행
```

- 캐릭터 확정 전 뒤로가면 슬롯을 소비하지 않습니다.
- 초기 저장 실패 시 MS01에 진입하지 않습니다.
- 새 게임이어도 Global Meta는 유지합니다.
- 5개 슬롯이 모두 사용 중이면 `새로 시작하기`를 비활성화합니다.

## UCS-S02 PLAYING 슬롯 이어 하기

```text
타이틀
→ [이어서 하기]
→ 슬롯 카드
→ [이어서 하기]
→ 세이브 로드/검증
→ 기본적으로 마이룸
→ 저장 phase 판단
```

마이룸 이후:

```text
새 주/스케줄 작성 필요
→ 필요 시 지난주 요약
→ 스케줄 작성

주간 일정 진행 중
→ 다음 예정 활동

다음 일정 = 휴식
→ 마이룸 휴식 UI
```

### `IN_PROGRESS`가 남은 경우

```text
이어 하기
→ IN_PROGRESS 감지
→ 해당 활동 = INTERRUPTED
→ 이미 저장된 체력 소비 유지
→ 활동 성장/보상 없음
→ 복구 저장
→ 마이룸
→ 다음 예정 일정 판단
```

## UCS-S03 미완료 엔딩이 남은 슬롯

엔딩 표시 도중 종료되어 **엔딩 최종 확인이 끝나지 않은 상태**가 남아 있으면 일반 마이룸 복귀보다 엔딩 표시를 우선합니다.

이때 슬롯은 아직 `RUN_COMPLETE`가 아니라 `PLAYING`이며 회차 phase가 엔딩 표시 단계에 머뭅니다.

```text
타이틀
→ [이어서 하기]
→ 해당 슬롯
→ 엔딩 표시 미완료 확인
→ 저장된 직업/편지 로드
→ `무엇을 지켰니?`부터 엔딩 다시 표시
```

- 엔딩 중간 화면 번호는 저장하지 않습니다.
- 이미 준비한 편지를 사용하고 Gemini를 다시 호출하지 않습니다.
- 최종 확인 전에는 `N+1회차 시작`을 제공하지 않습니다.

## UCS-S04 슬롯 로드 오류

```text
슬롯 로드 실패
→ `저장 기록을 확인할 수 없습니다.`
→ [다시 시도] / [삭제]
```

- 재시도 성공 → 실제 슬롯 상태 표시
- 삭제 → 확인 후 슬롯만 삭제, Global Meta 유지
- 실패 슬롯을 `EMPTY`로 추정하지 않음

# 4. WBS 4.2.3 — 한 주 진행 UCS

## UCS-W01 주간 일정 작성

```text
월요일 마이룸
→ 지난주 요약이 있으면 확인
→ 스케줄
→ 월~금 5칸 작성
→ 모험은 장소까지 선택
→ 5칸 완성
→ [일정 시작]
→ 일정 확정 자동 저장
→ 월요일 활동
```

시작 전에는 삭제·재배치할 수 있고 시작 후에는 일반 일정을 수정하지 않습니다.

## UCS-W02 월~금 연속 진행

```text
활동 시작
→ IN_PROGRESS + 필요한 체력 선차감 저장
→ 콘텐츠 실행
→ 결과 확정
→ 활동 완료 저장
→ 저장 성공
→ 다음 평일 활동 자동 진입
```

- 정상 진행에서 활동마다 마이룸에 돌아가지 않습니다.
- 휴식만 마이룸 자체가 활동 화면입니다.
- 수업 `포기하기`는 `FAIL`입니다.
- 모험은 `MISSION_COMPLETE / TIMEOUT`, 비정상 종료는 `INTERRUPTED`입니다.

## UCS-W03 금요일 종료·다음 주

```text
금요일 활동 완료 저장
→ 토·일 자동 처리
→ 가능한 주말 이벤트
→ 주간 결과 저장
→ 다음 월요일
→ 지난주 주간 요약
→ 마이룸
→ 새 주 스케줄 작성
```

52주차 뒤에는 새 주 스케줄 대신 엔딩 UCS로 이동합니다.

# 5. WBS 4.2.4 — 장소 게임·이야기 UCS

## UCS-L01 수업·모험·특수 활동

```text
예정 활동 진입
→ IN_PROGRESS 체크포인트 저장
→ 콘텐츠 실행
→ 결과 확정
→ 성장/통계 반영
→ 활동 완료 저장
→ Location/NPC Story 판정
```

활동별 결과는 기존 계약을 사용합니다.

- 수업: `FAIL / SUCCESS / GREAT`
- 모험: `MISSION_COMPLETE / TIMEOUT`
- 요정의 거래: `TRANSFERRED / SKIPPED`

## UCS-L02 활동 후 이야기

```text
활동 완료 자동 저장
→ Location/NPC Story 후보 판정

이야기 없음
→ 다음 일정

이야기 있음
→ 장면 시작
→ 대화
→ 선택이 있으면 선택
→ 선택별 짧은 반응
→ 중립 공통 대화
→ 장면 종료
→ 스탯/hidden stat/eventFlag/storyProgress 반영
→ 이야기 결과 저장
→ 다음 일정
```

- 이야기 중간 대사/선택 지점에는 저장하지 않습니다.
- 이야기 결과 저장 실패 시 다음 일정으로 넘어가지 않고 재시도합니다.
- 선택과 모순되는 공통 대사를 만들지 않습니다.

# 6. WBS 4.2.5 — 가방·배경 퍼즐 UCS

## UCS-B01 가방 확인

```text
마이룸
→ [가방]
→ 아이템 기본 탭
→ 배지 / 캐릭터 / 펫 / 마이룸 탭 이동
→ [X]
→ 마이룸
```

가방 확인만으로 날짜·일정은 진행하지 않습니다.

## UCS-B02 퍼즐 조각·배경 완성 알림

일반 조각 획득:

```text
보상 조건 달성
→ 미획득 조각 1개 지급
→ 짧은 조각 획득 알림
→ 현재 게임 계속
```

배경 `12 / 12` 완성:

```text
마지막 조각 획득
→ 배경 영구 해금
→ `새로운 마이룸 배경을 완성했어요!`
→ `가방 > 마이룸에서 확인해보세요.`
→ 현재 게임 계속
```

- 자동으로 가방을 열지 않습니다.
- 자동으로 새 배경을 적용하지 않습니다.
- 가방 `마이룸` 탭에 새 항목 표시를 남길 수 있습니다.

## UCS-B03 배경 적용

```text
마이룸
→ 가방
→ 마이룸 탭
→ 해금된 배경 선택
→ [이 배경 사용하기]
→ activeRoomBackgroundId 저장
→ 저장 성공
→ 가방/마이룸 탭 유지
→ 선택 배경 = `사용 중`
→ [X]
→ 마이룸
→ 선택한 새 배경 표시
```

배경 적용 성공만으로 가방을 자동으로 닫지 않습니다.

저장 실패:

```text
→ 기존 activeRoomBackgroundId 유지
→ `배경을 변경하지 못했습니다.`
→ [다시 시도]
```

# 7. WBS 4.2.6 — 엔딩·다음 회차 UCS

## UCS-E01 엔딩 준비

```text
52주차 완료
→ 12월 31일 마지막 주간 요약
→ 엔딩 직업 판정
→ 개인화 편지 생성/검증 또는 fallback 준비
→ 재접속 가능한 엔딩 결과 안전 저장
→ 슬롯은 PLAYING / 엔딩 표시 phase 유지
→ 엔딩 표시 미완료 상태
→ 엔딩 화면 시작
```

이 준비 저장만으로 해당 엔딩을 이미 `본 엔딩`으로 카운트하지 않습니다.

## UCS-E02 엔딩 표시

```text
무엇을 지켰니?
→ [계속]
→ 미래 직업 공개
→ [편지 보기]
→ 개인화 편지 + 아르카디아에서의 기록
```

신규 해금 요약이 없으면 편지의 마지막 버튼은 `[타이틀로]`입니다.

신규 해금 요약이 있으면:

```text
편지
→ [다음]
→ 이번 여행으로 새롭게 열린 것
→ 신규 해금 요약
→ [타이틀로]
```

즉 **엔딩 전체의 최종 확인 버튼은 항상 `타이틀로`** 입니다.

## UCS-E03 `타이틀로` — 엔딩 열람 확정

```text
[타이틀로]
→ 엔딩 열람 완료 커밋
→ seenEndingIds 반영(정규 엔딩)
→ endingViewCounts +1
→ 엔딩 열람/회차 종료에 의존하는 해금·메타 결과 확정
→ 엔딩 표시 미완료 상태 해제
→ 저장 성공
→ 타이틀
```

- 재시도되어도 엔딩 횟수·해금이 중복 반영되지 않아야 합니다.
- 최종 저장 실패 시 타이틀로 보내지 않고 `다시 시도`합니다.
- 최종 확인 전에는 다음 회차 시작을 허용하지 않습니다.

## UCS-E04 엔딩 표시 중 종료·재접속

```text
엔딩 표시 중 종료/오류
→ 다음 접속
→ 타이틀
→ [이어서 하기]
→ 엔딩 표시 미완료 확인
→ 저장된 직업/편지 사용
→ `무엇을 지켰니?`부터 다시 표시
```

- 중간 페이지 위치는 저장하지 않습니다.
- AI를 재호출하지 않습니다.
- 최종 `타이틀로` 성공 전까지 `N+1회차 시작`을 잠급니다.

`endingPresentationPending`은 논리 상태를 설명하기 위한 이름이며 실제 Firestore 필드명·트랜잭션 구조는 저장/API 구현 WBS에서 확정할 수 있습니다.

## UCS-E05 다음 회차

```text
엔딩 열람 완료
→ 타이틀
→ [이어서 하기]
→ RUN_COMPLETE 슬롯
→ [N+1회차 시작]
→ 캐릭터 선택
→ 새 Active Run 생성/저장
→ 새 회차 시작
```

- 현재 비밀번호 분실 → 이메일 복구 흐름


- 전체 완료를 확인하지 못한 오류에서는 `탈퇴 완료`라고 표시하지 않고 재시도를 제공

# 9. WBS 4.2 완료 판단

### 4.2.1 가입·로그인 UCS
- 로그인 정상/오류/미인증 분기
- 회원가입 → 인증 → 게임 진입
- 비밀번호 분실 복구

### 4.2.2 새 게임·이어 하기 UCS
- 첫 빈 슬롯 자동 배정 → 캐릭터 → 초기 저장 → MS01
- PLAYING 이어 하기의 마이룸 복귀 허브
- 스케줄 작성/다음 활동/휴식 라우팅
- IN_PROGRESS 복구
- 미완료 엔딩 우선 재표시
- 슬롯 로드 오류

### 4.2.3 한 주 진행 UCS
- 주간 일정 5칸 작성·확정
- 월~금 연속 실행
- 금요일 → 주말 → 주간 저장 → 월요일 요약 → 새 일정

### 4.2.4 장소 게임·이야기 UCS
- 수업/모험/특수 활동 진입·결과·저장 순서
- 활동 완료 후 Location/NPC Story 판정
- 선택 → 결과 반영 → 이야기 완료 저장
- 대화 중간 저장 없음

### 4.2.5 가방·배경 퍼즐 UCS
- 가방 진입·복귀
- 조각 획득과 배경 완성 안내
- 완성 시 가방 강제 이동 없음
- 배경 적용 성공 후 가방 유지, 닫을 때 새 배경 표시
- 설정 저장 실패 재시도

### 4.2.6 엔딩·다음 회차 UCS
- 엔딩 준비 저장과 실제 열람 완료 분리
- 표시 도중 종료 시 이어 하기에서 처음부터 재표시
- 최종 `타이틀로`에서 본 엔딩/관련 메타를 한 번만 확정
- 열람 완료 전 다음 회차 시작 금지
- 완료 후 RUN_COMPLETE 슬롯에서 다음 회차 시작

### 4.2.7 내 계정 관리 UCS
- 비밀번호 변경 성공/취소/오류
- 다른 기기 로그아웃 성공/오류
- 현재 기기 로그아웃
- 탈퇴 확인/취소/재인증/성공/오류

위 7개 UCS는 각 기능의 **시작 상태 → 사용자 행동 → 시스템 반응 → 저장 경계 → 오류/취소 → 종료 상태**를 정의하므로 **WBS 4.2 기획 범위는 작업완료 판단 가능**합니다. 실제 Firebase·Firestore·엔진 상태 라우터·엔딩 재개 데이터·API의 구현과 통합 테스트는 개발 WBS에서 별도로 수행합니다.
