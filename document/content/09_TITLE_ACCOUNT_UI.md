# 첫 화면·이어 하기·계정 화면 계약

이 문서는 **WBS 4.4 첫 화면·계정 화면**의 최종 기획 계약입니다. 계정 정책은 [계정·인증·탈퇴 정책](08_ACCOUNT_POLICY.md), 슬롯과 회차 데이터 정책은 [저장과 회차 계승](04_SAVE_META_PROGRESSION.md)을 원본으로 사용하고, 이 문서는 이를 실제 화면·입력·오류 상태로 연결합니다.

## 1. WBS 4.4 범위

WBS 4.4는 다음 세 화면군을 정의합니다.

1. 첫 접속부터 이메일 인증 완료까지의 계정 진입 화면
2. 타이틀의 `시작하기 / 새로 시작하기 / 이어서 하기`와 5개 슬롯 화면
3. 로그인 후 게임 메뉴에서 접근하는 계정 관리 화면

Firebase·FastAPI·Firestore의 실제 운영 연결과 통합 테스트는 개발 WBS에서 수행합니다. 이 문서의 완료는 **화면 계약과 상태 전이가 확정되었다는 의미**이며 서버 연동 완료를 의미하지 않습니다.

## 2. 최초 접속과 로그인 상태 분기

```text
웹 접속
→ Firebase 로컬 인증 상태 확인
   ├─ 로그인 세션 없음
   │   → 로그인 화면
   ├─ 로그인 세션 있음 + email_verified = false
   │   → 이메일 인증 대기 화면
   └─ 로그인 세션 있음 + email_verified = true
       → 인트로
       → 타이틀
```

- 현재 브라우저는 명시적으로 로그아웃할 때까지 Firebase 로그인 상태를 유지합니다.
- `로그인 유지` 체크박스는 사용하지 않습니다.
- 인증 완료 전에는 인트로·타이틀·세이브 슬롯·본편 데이터에 진입하지 않습니다.

## 3. 로그인 화면

로그인 화면은 다음 항목만 사용합니다.

```text
이메일
[                         ]

비밀번호
[                         ]

[ 로그인 ]

비밀번호를 잊으셨나요?
회원가입
```

로그인·회원가입 화면에는 `52주 플레이 기록을 바탕으로 AI가 개인화 엔딩 편지를 만들어요. 생성이 어려우면 미리 작성된 편지를 보여 줍니다.`라는 안내를 표시합니다.

### 로그인 결과

| 상황 | 처리 |
|---|---|
| 인증된 계정 로그인 성공 | 인트로 → 타이틀 |
| 이메일 미인증 | 인증 대기 화면으로 이동 |
| 계정 없음/비밀번호 불일치 | `이메일 또는 비밀번호를 확인해주세요.` |
| 이메일 형식 오류 | `이메일 형식을 확인해주세요.` |
| 네트워크/서버 오류 | `잠시 후 다시 시도해주세요.` |

## 4. 회원가입과 이메일 인증

회원가입 입력:

```text
이메일
비밀번호
비밀번호 확인
☐ [필수] 개인정보 수집·이용 동의

[ 회원가입 ]
```

가입 성공 후:

```text
등록한 이메일로 인증 메일을 보냈습니다.
이메일에서 인증을 완료해주세요.

[ 인증 완료 확인 ]
[ 인증 메일 다시 보내기 ]

다른 계정으로 로그인
```

`인증 완료 확인`이 성공하면 같은 Firebase 세션을 갱신하여 **이메일과 비밀번호를 다시 입력시키지 않고** 인트로 → 타이틀로 이동합니다.

## 5. 비밀번호 분실

로그인할 수 없거나 현재 비밀번호를 잊은 경우에만 이메일 기반 복구를 사용합니다.

```text
비밀번호를 잊으셨나요?
→ 이메일 입력/확인
→ Firebase 재설정 메일 발송
→ 이메일의 보안 링크에서 새 비밀번호 직접 설정
```

어린이 사용자가 일반 계정 관리 중 외부 화면으로 이동하는 것은 피하고, **본인 인증 수단을 잃은 복구 상황에서만 이메일 외부 흐름을 허용**합니다.

## 6. 타이틀 화면

슬롯 상태에 따라 타이틀의 주 버튼을 바꿉니다.

### 모든 슬롯이 비어 있음

```text
[ 시작하기 ]
```

### 하나 이상의 사용 중 슬롯 존재

```text
[ 새로 시작하기 ]
[ 이어서 하기 ]
```

### 슬롯 5개가 모두 사용 중

`새로 시작하기`는 일반 상태의 색상·불투명도와 클릭 가능 상태를 유지합니다. 누르면 캐릭터 선택이나 새 회차 생성으로 넘어가지 않고, 버튼들 아래에 프레임이 있는 짧은 안내를 약 3초 표시한 뒤 숨깁니다. 연속 클릭하면 표시 시간을 갱신합니다. 상시 안내나 별도 모달 오류 팝업은 사용하지 않습니다.

```text
[ 새로 시작하기 ]  ← 정상 모습·클릭 가능
[ 이어서 하기 ]

새로 시작하기를 누른 뒤 아래 프레임에 잠시 표시:
5개 슬롯이 모두 사용 중입니다. 슬롯을 삭제하면 새로 시작할 수 있습니다.
```

기존 저장을 자동 삭제하거나 덮어쓰지 않습니다. 슬롯 삭제는 사용자가 `이어서 하기`에서 대상 슬롯을 고르고 기존 삭제 확인 절차를 거쳐야 합니다. 저장 실패·데이터 읽기 오류로 인한 진행 차단은 슬롯 가득 참 안내와 구분합니다.

## 7. 이어서 하기 — 5개 슬롯

`이어서 하기`는 타이틀 배경 위 프레임으로 열며 **항상 슬롯 1~5를 모두 표시**합니다. 마지막으로 저장에 성공한 슬롯이 있으면 같은 슬롯을 맨 위에 `최근 저장` 바로가기로 한 번 더 보여 줍니다.

### EMPTY

```text
슬롯 3
저장 기록 없음
```

빈 슬롯 카드는 이어서 하기 대상으로 사용하지 않습니다.

### PLAYING

```text
슬롯 1
아이리스
2회차 · 18주차
마지막 저장 2026.10.15 09:30

[ 이어서 하기 ]    [ 삭제 ]
```

`PLAYING` 슬롯의 `이어서 하기`는 세이브를 로드한 뒤 **기본적으로 마이룸을 복귀 허브로 사용**합니다. 마이룸에서 저장된 회차 `phase`를 확인해 새 주의 스케줄 작성이 필요하면 스케줄로, 이미 이번 주 일정이 진행 중이면 다음 예정 활동으로 자연스럽게 연결합니다. `IN_PROGRESS`가 남아 있으면 기존 복구 규칙으로 `INTERRUPTED`를 먼저 확정·저장한 뒤 마이룸에서 다음 예정 활동을 판단합니다.

정상 월~금 플레이 중 활동 하나를 마칠 때마다 마이룸으로 돌아간다는 뜻은 아닙니다. 이 규칙은 **재접속·이어 하기의 복귀 위치**에 대한 계약입니다.

엔딩 표시를 시작했지만 마지막 `타이틀로`까지 확인하지 못한 회차도 아직 `PLAYING`으로 두고 엔딩 표시 phase를 유지합니다. 이 상태에서 `이어 하기`를 누르면 마이룸 일반 복귀보다 저장된 엔딩 재표시를 우선하며 `무엇을 지켰니?`부터 다시 보여 줍니다. 마지막 `타이틀로`의 열람 완료 저장이 성공한 뒤에만 슬롯을 `RUN_COMPLETE`로 전환합니다.

### RUN_COMPLETE

```text
슬롯 2
카엘
1회차 완료
엔딩: 아르카디아 탐험가

[ 2회차 시작 ]    [ 삭제 ]
```

카드에는 선택에 필요한 최소 정보만 표시하고 전체 스탯·NPC 진행·엔딩 조건 등은 넣지 않습니다.

## 8. 슬롯 로드 오류 표시

`LOAD_ERROR`는 Firestore에 저장하는 슬롯 상태가 아닙니다. 서버/네트워크/데이터 검증 문제 때문에 특정 슬롯을 정상 표시하지 못했을 때 사용하는 **클라이언트 표시 상태**입니다.

```text
슬롯 2
저장 기록을 확인할 수 없습니다.

[ 다시 시도 ]    [ 삭제 ]
```

규칙:

- 읽기 실패를 `EMPTY`로 간주하지 않습니다.
- 읽기 실패만으로 기존 데이터를 자동 초기화·덮어쓰기하지 않습니다.
- `다시 시도`가 성공하면 원래 `EMPTY / PLAYING / RUN_COMPLETE` 카드로 돌아갑니다.
- 삭제 버튼은 표시하지만 반드시 확인 절차를 거칩니다.
- 삭제 요청은 슬롯 내용을 정상 해석할 수 없더라도 인증된 사용자의 해당 `slotId`를 서버가 삭제할 수 있는 별도 파괴적 동작으로 취급합니다.

오류 슬롯 삭제 확인:

```text
이 저장 기록을 삭제할까요?

현재 이 슬롯의 저장 기록을 정상적으로 확인할 수 없습니다.
삭제한 슬롯 기록은 복구할 수 없습니다.

배지·캐릭터·펫·엔딩 등 계정 전체 진행은 유지됩니다.

[ 취소 ]    [ 삭제 ]
```

## 9. 정상 슬롯 삭제

정상 슬롯도 기존 정책대로 확인 후 삭제합니다.

```text
이 저장 기록을 삭제할까요?
이 슬롯의 현재 진행과 슬롯 회차 요약이 삭제됩니다.
삭제한 슬롯 기록은 복구할 수 없습니다.

배지·캐릭터·펫·엔딩 등 계정 전체 진행은 유지됩니다.

[ 취소 ]    [ 삭제 ]
```

슬롯 삭제는 Global Meta를 삭제하지 않습니다.

## 10. 게임 내 계정 진입점

현재 Final Project에서는 계정 외에 독립적인 환경설정 카테고리가 없으므로 **`환경설정 → 계정` 2단계를 만들지 않습니다.**

```text
게임 메뉴
├─ 계속하기
├─ 관계
├─ 계정
└─ 타이틀로 돌아가기
```

게임 메뉴 전체 구성과 개발용 항목 제거 기준은 [공통 엔진 프레임·마이룸·모험 흐름](10_COMMON_ENGINE_FRAME.md)을 따릅니다. `오늘을 마무리하기`와 개발 검증용 `전체 흐름 보기`는 최종 메뉴에서 제외하고, 방 변경·퍼즐은 가방의 마이룸 영역에서 관리합니다.

향후 BGM·효과음·접근성·텍스트 속도 등 여러 설정이 실제로 추가되면 `환경설정` 상위 메뉴를 만들고 계정을 그 아래로 옮길 수 있습니다. 현재는 불필요한 한 단계만 늘어나므로 만들지 않습니다.

## 11. 계정 화면

```text
계정

연결된 이메일
player@example.com

최초 가입일
2026.10.15

[ 비밀번호 변경 ]
[ 다른 기기에서 모두 로그아웃 ]

[ 이 기기에서 로그아웃 ]
[ 계정 탈퇴 ]
```

### 읽기 전용 정보

- `연결된 이메일`: Firebase Authentication의 현재 사용자 이메일
- `최초 가입일`: 서버 사용자 루트 `createdAt`을 날짜 단위로 표시
- 이메일 수정 기능은 제공하지 않음

## 12. 게임 내부 비밀번호 변경

현재 비밀번호를 알고 있는 사용자는 게임 밖으로 이동하지 않습니다.

```text
비밀번호 변경

현재 비밀번호
[                         ]

새 비밀번호
[                         ]

새 비밀번호 확인
[                         ]

현재 비밀번호를 잊으셨나요?

[ 취소 ]    [ 변경 ]
```

처리:

```text
현재 비밀번호 확인/재인증
→ 새 비밀번호 형식·확인 값 검사
→ Firebase 비밀번호 변경
→ 성공 안내
→ 계정 화면 복귀
```

현재 비밀번호를 잊은 경우에는 이메일 재설정 메일을 요청하고 외부 이메일 보안 링크에서 복구합니다. 이 경우만 게임 외 인증 흐름을 허용합니다.

## 13. 다른 기기에서 모두 로그아웃

버튼은 계정 화면에 직접 둡니다. 체크박스나 지속 설정으로 만들지 않습니다.

```text
다른 기기에서 모두 로그아웃
→ 현재 비밀번호 입력
→ 현재 계정 재인증
→ 서버가 기존 로그인 세션 폐기
→ 현재 기기는 새 인증 상태로 갱신
→ 현재 기기 로그인 유지
```

사용자 안내 예:

```text
다른 기기의 로그인 상태를 해제할까요?
이 기기에서는 계속 게임을 이용할 수 있습니다.

현재 비밀번호
[                         ]

[ 취소 ]    [ 다른 기기 로그아웃 ]
```

실제 구현에서는 Firebase의 사용자 refresh token 폐기 후 현재 기기를 재인증해 새 세션으로 유지합니다. 서버 보호 API는 폐기된 세션을 거부할 수 있도록 세션 폐기 여부를 검사합니다.

## 14. 이 기기에서 로그아웃

```text
[ 이 기기에서 로그아웃 ]
→ 현재 브라우저 Firebase 세션 종료
→ 로그인 화면
```

세이브 슬롯·Global Meta·엔딩 기록은 삭제하지 않습니다.

## 15. 계정 탈퇴

계정 탈퇴는 슬롯 삭제와 다르게 모든 계정 데이터를 삭제하므로 강한 확인을 사용합니다.

```text
계정을 탈퇴하면 모든 게임 기록과 엔딩 편지가 영구 삭제됩니다.
삭제한 데이터는 복구할 수 없습니다.

[ 취소 ]    [ 계정 탈퇴 ]
```

Firebase가 최근 인증을 요구하면 게임 내부에서 현재 비밀번호를 입력받아 재인증한 뒤 탈퇴를 수행합니다. 현재 비밀번호를 잊어 재인증할 수 없다면 먼저 이메일 계정 복구 절차가 필요합니다.

## 16. WBS 4.4 완료 판단

### 4.4.1 첫 화면·새로 하기 프레임

- 인트로·타이틀·시작/새로 시작하기 연결 기준 존재
- 빈 슬롯 자동 배정 규칙 확정
- 슬롯 5개 가득 참 안내 문구 확정

### 4.4.2 이어 하기·5개 슬롯 프레임

- `EMPTY / PLAYING / RUN_COMPLETE` 카드 표시 확정
- 최근 저장 바로가기 확정
- 이어하기·다음 회차·삭제 동작 확정
- 슬롯별 `LOAD_ERROR` 표시와 `다시 시도 / 삭제` 처리 확정

### 4.4.3 가입·로그인·계정 관리 프레임

- 로그인 페이지가 이메일 인증 완료까지 담당하는 흐름 확정
- 로그인 세션 로컬 유지와 자동 복원 확정
- 회원가입·인증 대기·인증 재발송·인증 완료 확인 확정
- 비밀번호를 아는 경우 게임 내부 변경 확정
- 비밀번호 분실 시에만 이메일 외부 복구 확정
- 게임 메뉴의 1뎁스 `계정` 진입점 확정
- 이메일·최초 가입일 읽기 전용 표시 확정
- 다른 기기 모두 로그아웃 정책 확정
- 현재 기기 로그아웃·계정 탈퇴 확정
