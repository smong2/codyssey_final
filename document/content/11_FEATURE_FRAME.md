# 기능 프레임 — 가방·배경 퍼즐·대화·엔딩

이 문서는 **WBS 4.3 기능 프레임**의 최종 기획 계약입니다.

- `4.3.1` 가방·배경 퍼즐 기능 프레임
- `4.3.2` 대화 프레임 설계·구현 인수
- `4.3.3` 엔딩 화면 프레임

실제 서버 API, 해금 판정 코드, AI 생성, 최종 디자인·애니메이션 구현은 각 개발 WBS에서 별도로 검증합니다. 여기서 `작업완료`는 **화면의 상태·진입·복귀·해금 표시와 엔딩 진행 계약이 확정되었다는 의미**입니다.

---

## 1. 가방 공통 프레임

마이룸의 `가방` 버튼으로 가방 프레임을 엽니다. 가방은 다이어리와 별개의 카드형 수집/관리 화면이며 책 페이지 넘김 연출을 사용하지 않습니다.

기본 탭 구조는 다음과 같습니다.

```text
배지 | 펫 | 캐릭터 | 마이룸
```

- 마이룸의 일반 `가방` 버튼으로 들어오면 `배지` 탭을 기본으로 엽니다.
- 마이룸에 표시된 현재 펫을 누르면 짧은 말풍선 대화가 나오고, `가방 → 펫`에서 교체할 수 있음을 안내합니다. 펫과 주인공 위치는 드래그해 계정에 저장합니다.
- 탭을 바꿔도 가방 프레임 안에서 전환합니다.
- 우측 상단 `X` 또는 공통 닫기 동작으로 **원래 마이룸으로 복귀**합니다.
- 가방을 열거나 탭을 보는 것만으로 날짜·일정·세이브 슬롯 진행 상태를 변경하지 않습니다.

### 확정된 탭·카드 표현

- 상단 `가방` 제목은 표시하지 않습니다. 4개 탭은 양피지 질감의 고전 서적 책갈피 형태로 프레임 바깥 왼쪽 상단에 붙이고, 전체 탭 가로길이는 프레임의 약 1/3로 둡니다. 캡슐 바나 이미지 버튼으로 되돌리지 않습니다.
- 기본 탭은 아이보리 바탕·브라운 글씨, 선택 탭은 그린 바탕·아이보리 글씨로 표시하고 선택 탭을 조금 더 높입니다. 폰트는 고운바탕을 사용하며 글자가 잘리거나 겹치지 않게 반응형으로 조정합니다.
- 가방 내부 이미지 버튼은 기본 `BT04_blank_pale_ivory_short.png`, 선택 상태 `BT04_blank_pale_green_short.png`를 사용하고 원본 비율을 유지합니다. 프레임은 양피지 바탕과 얇은 빈티지 금색 베벨 테두리를 사용합니다.
- 펫·캐릭터 카드는 같은 크기의 둥근 정사각형으로 통일하고 카드 이름은 표시하지 않습니다. 미해금은 프레임과 어울리는 저채도 브라운 실루엣으로 표현하며 머리 윗부분이 잘리지 않게 배치합니다. 전신 원본을 사용하되 카드 안에 전신 전체를 억지로 넣을 필요는 없습니다.
- 해금 카드를 누르면 정보 팝업을, 미해금 카드를 누르면 해금 조건 안내를 엽니다. 캐릭터의 조건 달성과 실제 해금 시점은 기존 규칙대로 구분합니다.

### 아이템 탭 제외와 원본 보존

`asset/item/`의 아이템 이미지는 **디자인 자원**이며 소유·획득 규칙이 확정된 인벤토리 마스터가 아닙니다. 현재 DB에도 일반 아이템 보유 ID 목록을 저장하는 계약이 없습니다.

따라서 WBS 4.3에서는 다음을 원칙으로 합니다.

- 실제 보유 데이터가 정의되지 않은 아이템을 보유한 것처럼 표시하지 않습니다.
- 자원 확인용 시안은 실제 보유 목록과 명확히 구분합니다.
- 모험의 숨은 목표 아이템을 자동으로 가방 아이템으로 변환하지 않습니다.
- 현재 가방에서는 `아이템` 탭을 제거하며 빈 탭이나 등록 예정 탭도 표시하지 않습니다. 이야기 물건·도구·재료의 인벤토리는 별도 계약 없이 추가하지 않습니다.
- `asset/item/` 원본은 보존합니다. 탭 제거를 이미지 파일 삭제나 기존 플레이 기록 삭제로 해석하지 않습니다.

## 2. 모험 목표 아이템과 가방의 경계

직접 모험에서 찾는 `1~5개`의 숨은 목표 아이템은 **현재 모험판의 성공 조건을 구성하는 임시 미션 오브젝트**입니다.

```text
모험 진입
→ 숨은 목표 아이템 배치
→ 조사·발견
→ 전부 발견하면 MISSION_COMPLETE
→ 모험 결과/성장/플레이 기록 반영
→ 목표 아이템의 개별 보유 상태는 남기지 않음
```

### 확정 원칙

- `MISSION_COMPLETE`여도 목표 아이템 ID를 가방 인벤토리에 저장하지 않습니다.
- `TIMEOUT / INTERRUPTED`에서는 기존 모험 규칙대로 목표 아이템 획득이 없습니다.
- 같은 미션을 다시 플레이하면 새 모험판의 목표로 다시 등장할 수 있습니다.
- 목표 아이템은 **배지처럼 영구 수집 목록을 채우는 컬렉션 항목이 아닙니다.**

다만 기존 시스템에서 이미 사용하는 `특별 아이템·발견물 횟수`, `장소 발견 횟수` 같은 값은 **아이템 보유 목록이 아니라 플레이 기록 카운터**입니다. 콘텐츠 마스터가 해당 발견을 통계 대상으로 지정했다면 성공 결과에서 카운터만 증가시킬 수 있습니다. 이 카운터가 배지·엔딩 조건에 사용되더라도 개별 모험 아이템을 영구 소지하거나 가방에 표시한다는 뜻은 아닙니다.

## 3. 배지 화면

배지는 총 `200개 = 5개 대분류 × 5개 소분류 × 8개` 구조를 그대로 사용합니다.

### 3.1 대분류 화면

```text
배지

[탐험과 발견]
[배움과 성장]
[활동과 성취]
[관계와 공감]
[각성과 선택]
```

대분류를 선택하면 소분류 5개와 각 진행도를 표시합니다.

```text
탐험과 발견

오늘도 탐험!        3 / 8
보물 찾았다!        2 / 8
여기 뭐가 있지?     1 / 8
궁금한 건 못 참아   0 / 8
펫과 함께           4 / 8
```

### 3.2 소분류 상세

소분류를 선택하면 8개 배지를 카드/격자로 표시합니다.

- 획득 배지: 실제 조합 배지 디자인 표시
- 미획득 배지: 공통 잠금 아이콘 표시
- `8 / 8`: 소분류 골드 완성 강조

미획득 배지는 최종 디자인을 미리 노출하지 않지만 **획득 조건과 현재 진행도는 보여 줍니다.**

예:

```text
다음 배지
모험을 10번 떠나기
현재 7 / 10
```

보이지 않는 스탯과 연결된 배지는 내부 수치를 공개하지 않고 기존 행동 태그 카운터를 사용자 친화적인 조건으로 표시합니다.

```text
호기심이 담긴 행동을 10번 해보기
현재 6 / 10
```

### 3.3 단계 보상

소분류의 `2 / 8`, `5 / 8`, `8 / 8` 보상은 **수령 버튼 없이 자동 지급**합니다.

```text
소분류 보상

✓ 2 / 8   탐험 +1
○ 5 / 8   탐험 +1
○ 8 / 8   탐험 +1

※ 영구 보너스는 다음 회차부터 적용됩니다.
```

이미 지급한 단계 보상을 다시 누르거나 재수령하는 UI는 만들지 않습니다.

## 4. 마이룸 배경 퍼즐 화면

가방의 `마이룸` 탭에서 기본 배경과 추가 배경 3종의 상태를 함께 확인합니다.

```text
마이룸

[기본 기숙사방]
사용 가능
[사용하기]

[기숙사방 1]
퍼즐 7 / 12
[퍼즐 보기]

[기숙사방 2]
퍼즐 4 / 12
[퍼즐 보기]

[기숙사방 3]
퍼즐 2 / 12
[퍼즐 보기]
```

현재 사용 중인 배경에는 `사용 중` 상태를 표시하고 선택 버튼을 비활성화하거나 현재 선택임을 명확히 표현합니다.

### 4.1 퍼즐 상세

추가 배경마다 실제 위치가 고정된 `12개` 퍼즐 조각을 사용합니다.

- 획득한 조각: 해당 위치의 실제 배경 이미지 조각을 보여 줍니다.
- 미획득 조각: 해당 위치를 `? / 잠금 / 가림` 상태로 표시합니다.
- 획득 조각을 조립해 갈수록 완성 배경을 점진적으로 확인할 수 있게 합니다.
- 조각은 이동·회전해 맞추는 별도 퍼즐 게임이 아니라 **수집 현황 시각화**입니다.

```text
기숙사방 1

[조각][ ? ][조각][ ? ]
[ ? ][조각][ ? ][조각]
[조각][ ? ][ ? ][조각]

7 / 12
```

### 4.2 완성과 배경 적용

한 배경이 `12 / 12`가 되면 즉시 계정 전역으로 해금합니다.

```text
기숙사방 1 완성!
[이 배경 사용하기]
```

중요:

- **완성했다고 자동으로 현재 마이룸 배경을 바꾸지 않습니다.**
- 사용자가 `사용하기`를 눌렀을 때만 현재 배경을 변경합니다.
- 한 번 해금된 배경은 이후 **마이룸에서 가방을 열 수 있는 정상 상태라면 언제든 자유롭게 변경**할 수 있습니다.
- 배경 선택은 세이브 슬롯별이 아니라 계정 전역 설정 `activeRoomBackgroundId`로 공유합니다.
- 배경을 바꿔도 현재 회차 스탯·일정·날짜를 변경하지 않습니다.
- 잠긴 배경에는 `사용하기`를 제공하지 않습니다.
- `사용하기`를 누르면 `activeRoomBackgroundId` 저장 성공 후에도 **가방을 자동으로 닫지 않습니다.** 현재 마이룸 탭에서 선택 배경을 `사용 중`으로 갱신하고, 사용자가 `X`로 가방을 닫았을 때 새 배경의 마이룸을 보여 줍니다.
- 배경 설정 저장에 실패하면 기존 선택을 유지하고 `배경을 변경하지 못했습니다 / 다시 시도` 상태를 제공합니다.

### 4.3 퍼즐 조각 획득 알림

퍼즐 조각 획득 때문에 진행 중인 주간 활동을 강제로 가방 화면으로 이동시키지 않습니다.

```text
퍼즐 조각을 발견했어요!
기숙사방 2 · 8 / 12
```

처럼 짧게 알리고 가방의 `마이룸` 탭에 새 항목 표시를 남길 수 있습니다. 배경을 `12 / 12`로 완성한 경우에는 `새로운 마이룸 배경을 완성했어요! 가방 > 마이룸에서 확인해보세요.`라고 안내하고 끝냅니다. **자동으로 가방/배경 화면으로 이동시키지 않습니다.** 플레이어는 이후 원하는 시점에 직접 확인합니다.

## 5. 대화 프레임 인수 기준

WBS 4.3.2는 현재 main 엔진 시안의 대화 프레임을 인수합니다.

- 상단 왼쪽 `대화기록`
- 상단 오른쪽 `건너뛰기`가 허용된 장면의 건너뛰기
- 대화 상대의 전신 이미지 한 명을 기본 중앙에 배치하고 플레이어 이미지는 표시하지 않음. 선택지가 있으면 전신 인물을 왼쪽으로 옮기고 얼굴·상체 오른쪽에 선택지를 배치
- `*_1_base.png`를 포함한 상반신·표정 이미지는 사용하지 않음. 기존 표정 파일명 입력은 전신 표시 호환으로 처리하며 새 원고·데이터는 전신 파일을 참조
- 하단 대화창
- 임시 원고와 정식 시나리오 데이터 구분

현재 대화 프레임의 구현·main 통합·자동 검증은 완료 근거로 사용합니다. 실제 시나리오 원고·분기 데이터 연결은 후속 콘텐츠/엔진 WBS이며 4.3.2의 기획 프레임 완료를 막지 않습니다.

## 6. 엔딩 화면 전체 흐름

정상 52주 완료의 엔딩 화면은 다음 **3단계 + 선택적 해금 요약**을 사용합니다.

```text
12월 31일 마지막 주간 요약
→ 1. `무엇을 지켰니?`
→ 2. 미래 직업 공개
→ 3. 개인화 편지 + 아르카디아에서의 기록
→ 신규 해금이 있으면 해금 요약
→ 타이틀
```

엔딩 화면에서 직접 다음 회차를 시작하지 않습니다.

---

## 7. 엔딩 1단계 — `무엇을 지켰니?`

전체 화면 또는 엔딩 전용 프레임에 작가의 고정 문구를 중심으로 보여 줍니다.

```text
무엇을 지켰니?

[계속]
```

- 입력란·정답 선택지를 두지 않습니다.
- AI가 답을 대신 제시하지 않습니다.
- 자동으로 바로 넘기기보다 플레이어가 `계속`을 눌러 다음 단계로 이동합니다.

---

## 8. 엔딩 2단계 — 미래 직업 공개

직업은 AI 편지 안에 묻히지 않도록 **독립된 보상 화면**으로 먼저 공개합니다.

```text
너의 미래는

아르카디아 탐험가

《아직 가보지 않은 길》

[편지 보기]
```

- 직업은 규칙 엔진이 이미 확정한 값입니다.
- AI는 직업을 바꾸지 않습니다.
- fallback `별길 개척자`도 실패나 조건 미달 표현 없이 같은 수준의 엔딩 결과로 표시합니다.

---

## 9. 엔딩 3단계 — 편지와 플레이 기록

편지 화면에는 최소 다음을 함께 표시합니다.

```text
[캐릭터 이름]에게

[개인화 엔딩 편지]

----------------
아르카디아에서의 기록

수업          74회
모험          41회
NPC 만남      86회
장소 발견      12회
----------------

[타이틀로 또는 다음]
```

- 플레이 기록은 백엔드가 선별한 실제 횟수형 기록 `4~6개`를 UI가 직접 렌더링합니다.
- 기록의 숫자·라벨을 AI가 새로 만들어 내지 않습니다.
- 로그인·회원가입 화면에서 AI 개인화 엔딩 편지와 생성 실패 시 사전 작성 편지 사용 가능성을 안내합니다. 엔딩 편지에는 작성 주체를 별도로 표시하지 않습니다.
- 편지는 해당 회차의 `Ending Record`에 저장하고 같은 직업을 다시 보더라도 **회차별 편지를 각각 보존**합니다.
- 정상 엔딩에서는 개발 미리보기용 `X → 마이룸` 동작을 사용하지 않습니다.
- 정상 엔딩 전체의 최종 종료 행동은 항상 `타이틀로`입니다. 신규 해금 요약이 없다면 편지 화면에서 바로 `타이틀로`, 신규 해금 요약이 있다면 편지에서는 `다음`으로 해금 요약에 진입하고 그 화면의 마지막 버튼을 `타이틀로`로 사용합니다.

### AI 편지 준비 중

직업 판정은 AI 생성보다 먼저 확정하므로 `무엇을 지켰니? → 직업 공개`는 AI 응답을 기다리지 않고 진행할 수 있습니다.

편지 화면 진입 시 아직 준비 중이라면:

```text
아르카디아에서 온 편지를 준비하고 있어요...
```

를 표시합니다.

AI 생성/검증 실패는 내부 재시도와 안전한 fallback 편지로 처리하며, 어린이에게 Gemini나 모델 오류명을 직접 노출하지 않습니다.

서버/네트워크 문제로 최종 결과 자체를 읽을 수 없을 때만:

```text
편지를 불러오지 못했습니다.
[다시 시도]
```

같은 일반 오류를 사용합니다.

AI 최종 실패 후 fallback이 준비되면 정상 편지처럼 표시하고 엔딩·해금·회차 완료를 막지 않습니다.

## 10. 엔딩 후 신규 해금 요약

회차 완료로 신규 캐릭터·펫·배지 등 계정 전역 해금이 발생했다면 편지 뒤에 **한 번의 간단한 해금 요약**을 보여 줍니다.

```text
이번 여행으로 새롭게 열린 것

새로운 캐릭터 2명
새로운 펫 1마리
배지 3개

[타이틀로]
```

- 실제 새 해금이 하나도 없다면 이 화면은 생략합니다.
- 동일한 해금 알림을 여러 개의 연속 팝업으로 쪼개지 않습니다.
- 해금 데이터는 엔딩 저장/메타 반영 결과를 그대로 표시하며 UI가 임의로 생성하지 않습니다.
- 최종 `타이틀로`가 엔딩 전체의 열람 완료 확인 동작입니다.

### 엔딩 열람 완료와 재접속

직업 판정과 최종 편지는 엔딩 표시 도중 종료되어도 같은 내용을 다시 보여 줄 수 있도록 먼저 안전하게 저장합니다. 그러나 이 준비 저장만으로 엔딩을 `본 엔딩`으로 계산하지 않습니다.

```text
엔딩 준비 저장
→ 표시 미완료 상태
→ 엔딩 화면

중간 종료
→ 이어 하기
→ 저장된 결과로 `무엇을 지켰니?`부터 다시 표시
```

중간 페이지 위치는 저장하지 않고 엔딩을 처음부터 다시 보여 줍니다. 이미 저장한 편지를 사용하므로 Gemini를 다시 호출하지 않습니다.

최종 `타이틀로`를 눌렀을 때 `seenEndingIds / endingViewCounts`와 엔딩 열람에 의존하는 메타·해금을 한 번만 확정하고 표시 미완료 상태를 해제합니다. 해당 저장이 실패하면 타이틀로 이동하지 않고 재시도합니다. 최종 확인 전에는 다음 회차 시작을 허용하지 않습니다.

---

## 11. 다음 회차 행동

엔딩 화면에는 `N+1회차 시작` 버튼을 두지 않습니다.

```text
엔딩 최종 `타이틀로` 저장 완료
→ 슬롯 = RUN_COMPLETE
→ 타이틀
→ 이어서 하기
→ 해당 슬롯의 [N+1회차 시작]
→ 캐릭터 선택
```

따라서 엔딩 감상과 새 회차 시작을 분리하고, 저장 슬롯 계약은 `04_SAVE_META_PROGRESSION.md`를 그대로 사용합니다.

## 12. WBS 4.3 완료 판단

### 4.3.1 가방·배경 퍼즐 기능 프레임

- 가방 4탭(`배지 → 펫 → 캐릭터 → 마이룸`, 기본 배지) 진입·복귀 규칙 확정
- 모험 목표 아이템을 일반 인벤토리로 저장하지 않는 경계 확정
- 배지 5대분류 → 소분류 → 8개 배지 화면 구조 확정
- 잠긴 배지의 조건·현재 진행도 표시 확정
- 배지 단계 보상 자동 지급 표시 확정
- 마이룸 3개 추가 배경의 12조각 시각화 확정
- 배경 완성 시 자동 적용하지 않고 사용자가 직접 선택하는 규칙 확정
- 해금 배경을 언제든 변경하고 계정 전역 설정으로 공유하는 규칙 확정
- 퍼즐 조각 획득 알림이 주간 진행을 강제로 중단하지 않는 규칙 확정

### 4.3.2 대화 프레임 설계·구현 인수

- 대화기록·건너뛰기·초상/대화창 프레임 main 통합 확인
- 임시 대사와 정식 시나리오 데이터의 구현 경계 확인
- 기존 자동 검증 근거를 인수

### 4.3.3 엔딩 화면 프레임

- `무엇을 지켰니? → 직업 공개 → 편지+기록` 3단계 확정
- AI 준비/실패/fallback/네트워크 재시도 표시 상태 확정
- 회차별 엔딩 편지 영구 저장·재조회 원칙 확정
- 신규 해금이 있을 때만 1회 요약 화면 표시 확정
- 실제 엔딩의 종료는 `타이틀로`, 다음 회차 시작은 RUN_COMPLETE 슬롯에서 처리하는 원칙 확정
- 개발 미리보기용 `X → 마이룸`과 실제 52주 엔딩 동작을 구분

위 계약을 기준으로 **WBS 4.3 기획 범위는 작업완료 판단 가능**합니다. 실제 수집/해금 API, 퍼즐 조각 UI 구현, 계정 전역 배경 선택 저장 연결, 정식 엔딩 API·Gemini·Ending Record 저장과 통합 테스트는 개발 WBS에서 별도로 수행합니다.
