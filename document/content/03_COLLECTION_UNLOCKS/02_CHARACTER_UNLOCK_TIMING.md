# 플레이 가능 캐릭터 해금 시점

## 1. 기본 원칙

- 최종 플레이 가능 캐릭터는 남학생 16명, 여학생 16명, 총 **32명**을 목표로 합니다.
- 최초 게임 시작 시에는 남학생 **3명**, 여학생 **3명**, 총 **6명**을 기본 선택 가능 캐릭터로 제공합니다.
- 기본 오픈 캐릭터는 `카엘(CH01) / 로빈(CH15) / 니코(CH31) / 세라(CH02) / 아이리스(CH08) / 티아(CH16)`입니다.
- 추가 캐릭터의 해금 조건은 **52주 플레이 도중 언제든 달성**할 수 있습니다.
- 조건을 달성한 순간에는 해금 알림을 표시하지만, 현재 진행 중인 주인공을 교체하지는 않습니다.
- 실제 캐릭터 해금은 **현재 52주 회차 종료가 최종 확정되는 시점**, 즉 엔딩의 마지막 `타이틀로` 저장이 성공할 때 확정합니다.
- 새로 해금된 캐릭터는 **다음 회차의 주인공 선택 화면부터 사용 가능**합니다.

핵심 규칙은 다음과 같습니다.

`플레이 중 해금 조건 달성 → 달성 알림 → 현재 52주 플레이 계속 → 엔딩 마지막 타이틀로 저장 성공 → 회차 종료·캐릭터 해금 확정 → 다음 회차부터 선택 가능`

## 2. 해금 시점

| 시점 | 캐릭터 해금 처리 | 비고 |
|---|---|---|
| 게임 최초 시작 | 기본 캐릭터 6명 사용 가능 | 남 3명 + 여 3명 |
| 52주 플레이 중 | 추가 캐릭터 해금 조건 달성 가능 | 조건 달성 상태를 기록 |
| 조건 달성 순간 | 해금 조건 달성 알림 표시 | 현재 캐릭터는 그대로 플레이 |
| 1회차 종료 시 | 엔딩 최종 `타이틀로` 저장 성공과 함께 조건을 만족한 신규 캐릭터 실제 해금 | 다음 회차부터 선택 가능 |
| 2회차 종료 시 | 추가 캐릭터 해금 가능 | 엔딩·수집·누적 조건 반영 |
| 3~4회차 종료 시 | 중기 캐릭터 해금 구간 | 선택 가능한 캐릭터 폭 확대 |
| 5~8회차 종료 시 | 다수의 추가 캐릭터 해금 구간 | 반복 플레이 보상 구간 |
| 9~12회차 이후 | 희귀·장기 조건 캐릭터 해금 구간 | 장기 수집 목표 |
| 장기 플레이 완료 | 총 32명 전체 해금 가능 | 최종 메타 진행 목표 |

위 회차 구간은 **해금 속도의 기획 기준**이며, 어떤 캐릭터를 어느 회차에 배치할지는 각 캐릭터의 실제 해금 조건을 설계할 때 확정합니다.

## 3. 조건 유형별 처리 시점

| 조건 종류 | 조건 달성 시점 | 실제 사용 가능 시점 |
|---|---|---|
| 첫 52주 완주 | 회차 종료 | 다음 회차 |
| 특정 엔딩 확인 | 회차 종료 | 다음 회차 |
| 서로 다른 엔딩 N개 확인 | 회차 종료 | 다음 회차 |
| 특정 배지 카테고리 완성 | 플레이 중 언제든 | 다음 회차 |
| 특정 NPC 스토리 완료 | 플레이 중 | 다음 회차 |
| 특정 이벤트 완료 | 플레이 중 | 다음 회차 |
| 누적 모험·수업·미니게임 조건 달성 | 플레이 중 | 다음 회차 |
| 누적 플레이 회차 달성 | 회차 종료 | 다음 회차 |

## 4. UX 처리

플레이 중 조건을 달성했을 때는 즉시 보상감을 주되 회차 흐름은 유지합니다.

예시:

`27주차 캐릭터 해금 조건 달성 → "새로운 캐릭터를 만날 수 있게 되었습니다" 알림 → 52주까지 현재 캐릭터로 계속 진행 → 엔딩 최종 타이틀로 저장 성공 → 신규 캐릭터 해금 → 다음 회차 캐릭터 선택 화면에 추가`

현재 회차 도중에는 새 캐릭터로 교체하지 않습니다.

## 5. 추가 캐릭터 26명 해금 조건

캐릭터 해금은 새 전용 시스템을 만들지 않고 [배지 분류·보상](01_BADGE_COLLECTION_DESIGN.md)의 진행도와 이미 저장하는 엔딩·회차 기록을 재사용합니다.

기본 규칙은 다음과 같습니다.

- 아래 `5/8` 조건은 해당 소분류의 **두 번째 단계 보상까지 획득한 상태**, 즉 배지 5개를 모은 상태를 뜻합니다.
- `펫과 함께`, `새로운 얼굴!`은 각각 펫/캐릭터 해금 수에 의존하므로 캐릭터 해금 조건으로 다시 사용하지 않습니다. 순환 의존을 피하기 위한 결정입니다.
- 한 회차에서 여러 조건을 만족하면 **조건을 만족한 캐릭터를 모두 pending 상태로 기록하고 엔딩 최종 `타이틀로` 저장 성공 시 한꺼번에 해금**합니다. 회차당 해금 인원 제한은 두지 않습니다.
- 이미 해금된 캐릭터의 조건을 다시 만족해도 중복 보상은 없습니다.

## 6. 해금 처리 순서

회차 중에는 조건을 만족할 때 `pendingCharacterUnlockIds`에 추가하고 간단한 달성 알림만 표시합니다.

```text
배지/엔딩/회차 조건 만족
→ pendingCharacterUnlockIds 추가
→ 현재 주인공으로 계속 진행
→ 엔딩 화면 표시
→ 최종 [타이틀로]
→ 열람/회차 종료 저장 성공
→ pending 캐릭터를 unlockedCharacterIds에 일괄 반영
→ pending 비우기
→ 다음 회차 캐릭터 선택부터 사용 가능
```

`CH13`의 첫 회차 완료, `CH14/CH32`의 엔딩 수 조건은 최종 `타이틀로`의 엔딩 열람·회차 종료 확정 처리 중 검사합니다. 같은 엔딩 정산에서 여러 조건이 동시에 만족되면 모두 해금합니다.
`별길 개척자` fallback은 `CH14/CH32`의 서로 다른 직업 엔딩 수에 포함하지 않습니다.

## 7. 구현·테스트 단계 확인 항목

- 첫 1~2회차에서 실제로 몇 명이 해금되는지 확인하고 지나치게 많은 경우 **배지 조건의 수치만** 조정합니다.
- `CH32`는 서로 다른 엔딩 10개를 요구하므로 직업 엔딩 최종 수가 10개 이상인지 엔딩 마스터와 함께 검증합니다.
- 캐릭터별 조건 ID는 마스터 데이터에서 관리하고 사용자 저장에는 `pending/unlocked characterId`만 저장합니다.
- 해금 조건을 나중에 밸런스 조정해도 이미 해금된 캐릭터를 다시 잠그지 않습니다.
