# 펫 시스템

## 1. 역할과 기본 구조

LUMIA 본편의 펫은 플레이어가 수집하고 선택하여 사용하는 **계정 전역 수집 요소이자 작은 스탯 보정 장치**입니다.

- 펫은 총 **10마리**입니다.
- `PET01`은 게임 시작 시 기본 해금합니다.
- `PET02~PET10`은 [펫 해금 시점](03_PET_UNLOCK_TIMING.md)의 조건에 따라 해금합니다.
- 본편에는 데모 버전의 단일 펫 캐릭터 **베른이 등장하지 않습니다.** `asset/pet/PT01~PT10` 이미지 10종을 본편의 독립된 펫 자원으로 사용합니다.
- 본편의 10마리 펫은 서로 다른 개체이며, 각자 고유 이름·외형·설명을 갖습니다.
- `PET01~PET10`의 외형 자원, 이름, 게임 화면 설명은 아래 마스터 표를 본편 기본값으로 사용합니다.

## 2. 가방에서의 선택

펫 선택은 마이룸의 **가방 → 펫 탭**에서 관리합니다. 별도의 환경설정 펫 화면은 두지 않습니다.

- 해금된 펫만 선택할 수 있습니다.
- 해금되지 않은 펫은 목록에서 잠금 상태로 표시하며 선택할 수 없습니다.
- 해금된 펫끼리는 플레이 중 언제든 활성 펫을 변경할 수 있습니다.
- 활성 펫은 한 번에 **1마리**만 적용합니다.
- 펫을 변경하면 이전 펫의 보정 효과는 즉시 해제되고 새 펫의 효과만 적용합니다.
- 기본 펫 `PET01`이 처음부터 해금되어 있으므로 별도의 `펫 없음` 상태는 기본 범위에 두지 않습니다.

펫 해금 여부는 계정의 `Global Meta Progress`에 저장하고, 현재 선택한 펫은 계정 설정의 `activePetId`로 관리합니다. 모든 세이브 슬롯은 같은 해금 목록과 활성 펫 설정을 공유합니다.

마이룸에서 펫을 누르면 캐릭터별로 작성한 짧은 대사 20개 중 하나를 무작위 말풍선으로 보여 줍니다. 대사는 SQLite 콘텐츠 마스터에 보관하고, 같은 대사가 연속해서 나오지 않도록 합니다. 말풍선에는 펫 교체 경로인 `가방 → 펫`을 함께 안내합니다. 펫과 주인공은 마이룸 안에서 드래그할 수 있으며 위치는 계정 설정에 저장합니다.

## 3. 스탯 보정 원칙

펫 보정은 캐릭터의 성장 스탯 저장값 자체를 영구 변경하지 않는 **임시 보정값**으로 처리합니다.

```text
실제 저장 성장 스탯(run.stats)
+ 현재 활성 펫 보정(petModifier)
= 화면·게임 판정에 사용하는 유효 성장 스탯(effectiveStats)
```

따라서 펫을 변경할 때 과거에 더했던 값을 다시 빼는 방식으로 저장 데이터를 수정하지 않습니다. 활성 펫 ID를 바꾸고 유효 스탯을 다시 계산합니다.

### 보정 대상

- 펫은 `지식 / 표현력 / 솜씨 / 탐험 / 마법` 5개 성장 스탯만 보정합니다.
- `체력`은 펫 보정 대상에서 제외합니다. 최대 체력·현재 체력 변경 시 발생하는 별도 회복/클램프 규칙을 만들지 않기 위함입니다.
- 보이지 않는 스탯은 성격 평가처럼 보이지 않도록 펫이 직접 보정하지 않습니다.

### 보정량

펫은 해금 난이도에 따라 **일반 보정 펫**과 **후반 강화 펫**으로 나눕니다.

- `PET01~PET07`: 주 보정 `+5`, 부 보정 `+3` — 총 `+8`
- `PET08~PET10`: 두 보정 모두 `+5` — 총 `+10`
- 패널티 스탯: 없음

후반에 해금되는 `PET08~PET10`은 수집 성취를 체감할 수 있도록 조금 더 높은 총 보정량을 제공합니다. 다만 한 펫이 모든 상황에서 정답이 되지 않도록 두 개의 특정 성장 스탯만 강화합니다.

## 5. 해금과 적용 시점

- `PET01`은 최초 계정 생성 시 해금 상태입니다.
- 다른 펫은 조건을 만족하는 즉시 계정 전역 해금 목록에 추가할 수 있습니다.
- 새로 해금된 펫은 해금 직후 가방의 펫 탭에서 선택할 수 있습니다.
- 캐릭터 해금처럼 회차 종료까지 기다리지 않습니다.
- 펫을 새로 선택하면 다음 안정 상태부터 해당 펫의 유효 스탯 계산을 사용합니다. 이미 확정된 과거 행동 결과를 다시 계산하지 않습니다.

구체적인 `PET02~PET10` 해금 조건은 [펫 해금 시점](03_PET_UNLOCK_TIMING.md)에서 관리합니다.

## 6. 저장 데이터

최소 저장 데이터는 다음과 같습니다.

### Global Meta Progress

```text
unlockedPetIds: [PET01, ...]
```

### Account Settings

```text
activePetId: PET01
```

펫 스탯 보정값은 사용자 저장 데이터에 복사하지 않고 펫 마스터 데이터에서 조회합니다. 이렇게 하면 밸런스 수치를 수정해도 계정별 저장 데이터 마이그레이션 부담을 줄일 수 있습니다.

## 7. UI 표시 기준

가방의 펫 탭에서는 최소 다음 정보를 보여 줍니다.

- 펫 이미지
- 펫 이름
- 한 줄 설명
- 주/부 스탯 보정 효과
- 해금/잠금 상태
- 현재 선택 상태

잠긴 펫의 최종 디자인을 어느 정도까지 미리 보여 줄지는 디자인 단계에서 결정합니다. 단, 잠긴 상태에서는 선택 버튼을 비활성화합니다.

## 8. `asset/pet/` 자원 처리

데모 버전에서는 베른이라는 하나의 펫 캐릭터를 사용했지만 **본편에서는 베른이라는 단일 캐릭터를 사용하지 않습니다.**

`asset/pet/`의 `PT01~PT10` 이미지는 번호 순서대로 게임 데이터 ID `PET01~PET10`과 1:1 대응합니다. `PT`는 이미지 파일 접두어이고 `PET`은 게임의 펫 ID입니다.

## 9. 구현 시 확인할 항목

- `activePetId`가 반드시 `unlockedPetIds`에 포함되어 있는지 서버에서 검증
- 잘못된/삭제된 펫 ID가 저장되어 있으면 기본 `PET01`로 복구
- 펫 변경 시 `run.stats` 원본을 수정하지 않고 `effectiveStats`만 다시 계산
- 활성 펫 변경 직전 이미 확정된 행동·보상 결과는 소급 재계산하지 않음
- 실제 화면에서 일반 펫 `+5/+3`, 후반 강화 펫 `+5/+5`의 차이가 지나치게 크거나 작으면 사용자 테스트에서 수치만 조정
