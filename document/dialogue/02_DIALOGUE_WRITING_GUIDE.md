# LUMIA 대화 집필 가이드

이 문서는 Main Story, NPC Story, Location Story의 실제 대사를 작성·검수할 때 사용하는 **작법 기준**이다.

기술 DTO와 엔진 처리 방식은 [Dialogue API · Engine 계약](01_ENGINE_API_CONTRACT.md), DB 식별자·저장 규칙은 [이벤트 대화 시퀀스 계약](../content/13_DIALOGUE_SEQUENCE.md)을 따른다. 사건·배역·장면 수·이미지 사용·선택 의미는 각 `story/*_PRODUCTION.md`가 우선한다.

## 1. 집필 목표

LUMIA의 주요 플레이어는 약 9~11세 어린이다. 대화는 교육 문구를 읽는 경험이 아니라 **판타지 학교에서 사람과 사건을 만나 스스로 관찰하고 선택하는 경험**이어야 한다.

프로젝트의 기본 경험은 다음 흐름을 따른다.

```text
사건 발견
→ 관찰·경청·탐색
→ 서로 다른 접근 중 선택
→ 인물·환경의 반응
→ 해결 또는 새로운 정보
→ 안도·회복·돌아보기
```

사회성, 자기주도, 절제, 공감, 책임, 호기심, 용기, 협력, 독립성, 신중함, 솔직함 같은 의미는 **대사로 가르치지 않고 플레이 과정에 녹인다.**

## 2. 필수 집필 원칙 19개

### 1. 9~11세가 편하게 읽는 따뜻하고 명확한 표현을 사용한다

- 욕설, 모욕, 조롱, 위협, 과도한 공포 표현을 피한다.
- 문제의 책임을 특정 인물이나 플레이어에게 거칠게 돌리지 않는다.
- 긴 판타지 용어 설명을 한 말풍선에 몰아넣지 않는다.
- 한 말풍선에는 가급적 한 가지 정보·감정·행동만 담는다.

긴장되는 사건은 가능하지만 어린이가 **해결할 수 있는 문제**로 느껴져야 한다.

### 2. 교육 메시지를 직접 설명하거나 평가하지 않는다

다음과 같은 문장은 피한다.

```text
친구의 마음을 먼저 이해하는 게 중요해.
협력하는 사람이 더 좋은 사람이야.
이번 선택은 책임감 있는 선택이었어.
```

대신 상황과 NPC 반응을 통해 플레이어가 직접 의미를 느끼게 한다.

### 3. 교육적 의미는 상황과 행동 선택 속에 숨긴다

예:

```text
A. 안쪽 친구에게 먼저 말을 걸어 본다.      # 공감 계열
B. 덩굴이 어디서 자라는지 먼저 살펴본다.   # 신중함/관찰 계열
```

플레이어에게 내부 태그나 스탯 이름을 표시하지 않는다.

### 4. 선택지는 모두 현실적으로 그럴듯한 접근이어야 한다

선택은 `좋은 행동 / 나쁜 행동`이 아니라 **서로 다른 해결 방식**이어야 한다.

좋은 예:

```text
A. 친구에게 무슨 일이 있었는지 먼저 물어본다.
B. 주변에서 달라진 점부터 찾아본다.
```

피해야 할 예:

```text
A. 차분히 살펴본다.
B. 생각 없이 마법을 마구 쏜다.
```

### 5. 선택지 사이에 도덕적·지적 우열을 만들지 않는다

- 한 선택만 유난히 친절하거나 현명하게 쓰지 않는다.
- 한 선택을 무시, 비겁함, 어리석음처럼 보이게 만들지 않는다.
- 선택지의 보상 효율 때문에 특정 답이 사실상 정답이 되지 않게 한다.

### 6. 선택별 짧은 반응 후 어느 선택에서도 자연스러운 공통 흐름으로 합류한다

```text
선택 A → A 반응 1~2문장 ─┐
                          ├→ 공통 다음 대화
선택 B → B 반응 1~2문장 ─┘
```

공통 합류 문장은 앞선 선택의 태도를 단정하지 않는다.

### 7. NPC가 플레이어보다 먼저 원인과 해법을 모두 알려주지 않는다

안내자는 답을 말하는 사람이 아니라 관찰 방향이나 질문을 열어 주는 역할을 한다.

특히 발렌티누스는 플레이어가 발견해야 할 원인과 해법을 먼저 밝히지 않는다.

### 8. 실패나 예상 밖 결과를 비난이 아니라 새로운 정보와 다음 시도로 연결한다

피해야 할 예:

```text
네가 그렇게 해서 더 심해졌잖아!
```

권장 예:

```text
어? 생각했던 것과 다르게 반응해.
그럼 우리가 아직 못 본 게 있는 것 같아.
```

### 9. 캐릭터의 성격은 설명하지 않고 말투·관심·행동 방식으로 보여 준다

`나는 감정 표현에 서툰 편이야`처럼 설정을 자기소개시키지 않는다.

같은 정보를 발견해도 캐릭터마다 표현이 달라야 한다.

```text
카엘: "잠깐. 아까하고 빛나는 간격이 달라."
아이리스: "어? 방금 또 변했어! 한 번 더 보면 규칙이 보일지도 몰라."
티아: "앗, 빛이 잠깐 졸았나 봐. 그래도 아까랑 조금 다른데?"
```

### 10. MBTI를 직접적인 대사 공식으로 사용하지 않는다

MBTI는 제작 참고일 뿐이다. `INTJ=항상 냉정`, `ENFP=항상 시끄러움`처럼 단순화하지 않는다.

대사는 다음 요소를 함께 본다.

- 핵심 설정과 관심 분야
- 문장 길이와 말의 속도
- 감정 표현 정도
- 먼저 행동하는지, 먼저 관찰하는지
- 사람과 현상 중 어디에 먼저 관심을 두는지
- 유머의 사용 여부와 방식

### 11. 플레이어 캐릭터도 사건의 실제 참여자여야 한다

NPC가 문제·원인·해법을 전부 말하고 플레이어가 듣기만 하는 흐름을 피한다.

플레이어 발화는 최소한 다음 중 하나를 수행해야 한다.

- 질문
- 관찰
- 의견
- 접근 방법 제안
- 타인에게 말 걸기
- 최종 선택

### 12. 캐릭터의 약점을 놀림거리나 고쳐야 할 결함으로 쓰지 않는다

신중함과 용기, 협력과 독립성처럼 서로 다른 태도는 상황에 따라 다른 강점이 될 수 있다.

캐릭터의 성향을 선악 또는 우열로 분류하지 않는다.

### 13. 긴장 뒤에는 작은 안도·유머·회복을 둔다

메인 사건은 가능하면 다음 리듬을 가진다.

```text
일상
→ 이상함
→ 긴장
→ 문제 확대
→ 발견
→ 해결
→ 웃음/안도/따뜻한 마무리
```

### 14. 모든 말풍선은 목적을 가져야 한다

한 줄은 최소 하나를 수행한다.

- 캐릭터를 보여 줌
- 사건 정보를 전달함
- 감정을 보여 줌
- 선택을 준비함
- 선택에 반응함
- 다음 단계로 이동함
- 해결 후 여운을 줌

아무 역할도 없는 반복 설명은 줄인다.

### 15. 선택지 문장 길이·긍정성·정보량을 비슷하게 맞춘다

한 보기만 훨씬 길거나 구체적이면 정답처럼 보일 수 있다.

```text
나쁜 예
A. 살펴본다.
B. 친구들과 충분히 이야기하고 가장 안전한 방법을 차분하게 찾아본다.
```

선택지를 읽는 순간 개발자가 원하는 답이 드러나지 않게 한다.

### 16. 선택 결과는 숫자보다 인물과 세계의 반응으로 먼저 느끼게 한다

`공감 +8`, `좋은 선택!` 같은 도덕적 보상 문구를 대화 안에서 사용하지 않는다.

선택 결과는 우선 다음으로 보여 준다.

- NPC의 한두 문장 반응
- 표정/화자 이미지 변화가 가능한 경우 해당 이미지
- 룬·빛·식물·배경 상태 변화
- 다음 행동의 자연스러운 변화

### 17. 대화 외에도 장면 설명·관찰·주인공 속마음·이미 알려진 배경 사실을 사용할 수 있다

기술적으로는 모두 `LINE`이며 `lineMode`로 의미를 구분한다.

| `lineMode` | 의미 | 예 |
|---|---|---|
| `DIALOGUE` | 실제 인물의 발화 | `"잠깐, 저쪽을 봐."` |
| `NARRATION` | 현재 장면에서 관찰 가능한 상황 설명 | `광장 한쪽에서 희미한 빛이 흔들린다.` |
| `THOUGHT` | 현재 플레이 캐릭터의 속마음 | `조금 더 살펴보는 게 좋겠다.` |
| `CONTEXT` | 이미 알려진 과거·배경 사실 | `이 물체는 어제부터 이곳에 있었다.` |

### 18. 설명자는 플레이어가 직접 알아내야 할 감정·원인·해법을 먼저 확정하지 않는다

`NARRATION`은 가능하면 **관찰 가능한 사실**을 보여 준다.

피해야 할 예:

```text
상대는 불안하고 다급하다.
```

권장 예:

```text
상대는 몇 번이나 뒤를 돌아본다.
손에는 접힌 종이를 꼭 쥐고 있다.
```

플레이어가 그 모습을 보고 감정을 해석할 여지를 남긴다.

`CONTEXT`도 이미 알려진 사실만 제공하고 사건의 답을 대신 말하지 않는다.

```text
가능: 이 물체는 어제부터 이곳에 있었다. 몇몇 학생이 살펴봤지만 정체는 아직 모른다.
금지: 이 물체는 봉인 룬이며 마력을 천천히 흘려야 열린다.
```

### 19. 중요한 선택이라는 사실을 시스템 문구로 직접 강조하지 않는다

다음 표현을 피한다.

```text
이번 선택은 중요한 결과를 만들 것 같다.
신중하게 선택해야 한다.
```

대신 NPC의 행동, 주변 분위기, 주인공의 자연스러운 생각으로 중요성을 느끼게 한다.

```text
NARRATION: 상대는 말을 꺼냈다가 잠시 멈춘다.
THOUGHT: 평소보다 말을 고르는 것 같다.
```

## 3. `lineMode` 작성 규칙

### `DIALOGUE`

- 사람, NPC, 그림자 등 실제 장면 안에서 말하는 존재의 발화다.
- `speaker`가 필요하다.
- 캐릭터성이 가장 강하게 드러나는 영역이다.

### `NARRATION`

- 현재 화면에서 보이거나 들리는 장면, 행동, 분위기를 짧게 서술한다.
- 기본적으로 특정 캐릭터의 내면을 단정하지 않는다.
- 장면 시작, 화자 사이의 짧은 행동, 이미지 변화 전후에 사용할 수 있다.

### `THOUGHT`

- 현재 플레이 캐릭터의 속마음이다.
- `speaker=PLAYER`를 사용한다.
- 플레이어 초상은 표시하지 않는다.
- 32명 캐릭터별 Voice Guide를 적용해 말투가 달라질 수 있다.
- 플레이어에게 정답을 암시하지 않는다.

### `CONTEXT`

- 플레이어가 이미 알고 있는 과거 사실이나 장면 이해에 필요한 배경 정보를 제공한다.
- 현재 사건의 원인·정답·해법을 새로 폭로하는 수단으로 사용하지 않는다.
- 지나친 설정 설명을 피하고 실제 장면 이해에 필요한 만큼만 사용한다.

## 4. 32인 Voice Guide 기준

실제 32인 대사를 대량 제작하기 전에 각 캐릭터에 대해 최소 다음 항목을 짧게 정의한다.

```text
문장 길이/리듬
주 관심 대상
감정 표현 정도
관찰 우선 / 행동 우선
사람 우선 / 현상 우선
유머 방식
자주 쓰는 표현 특성
피해야 할 표현
```

예:

```text
카엘
- 문장: 짧고 정돈됨
- 관심: 원인, 순서, 패턴
- 감정 표현: 직접적이지 않음
- 행동: 관찰 후 제안
- 유머: 드물고 건조함
- 피함: 과장된 감탄, 지나치게 들뜬 표현

티아
- 문장: 밝고 가벼움
- 관심: 사람, 분위기, 신기한 현상
- 감정 표현: 풍부함
- 행동: 먼저 말 걸고 함께하자고 제안
- 유머: 가벼운 비유와 장난
- 피함: 길고 딱딱한 분석 설명
```

MBTI는 이 Voice Guide를 만드는 참고 자료 중 하나일 뿐, 대사를 자동 결정하지 않는다.

## 5. 선택지 검수 체크리스트

실제 대사 제작 전과 제작 후 각 선택 노드를 다음 기준으로 검수한다.

1. 보기 모두 어린이가 실제로 고를 법한가?
2. 한 보기가 명백한 정답처럼 보이지 않는가?
3. 한 보기가 무례·무책임·어리석음으로 만들어지지 않았는가?
4. 문장 길이와 정보량이 비슷한가?
5. 서로 다른 태도나 접근법을 자연스럽게 보여 주는가?
6. 어느 보기를 골라도 사건이 자연스럽게 계속되는가?
7. 각 보기 뒤 1~2문장의 차별 반응이 있는가?
8. 공통 합류 문장이 앞선 선택을 잘못 단정하지 않는가?
9. 선택의 내부 스탯 의미가 화면 문구에서 노골적으로 드러나지 않는가?
10. Production 문서가 정한 사건·결말·선택 수를 훼손하지 않는가?

## 6. 설명 요소가 포함된 예시

아래는 작법 구조만 보여 주는 비정식 예시다.

```text
[NARRATION]
해가 진 뒤의 시계탑 광장은 낮보다 훨씬 조용하다.

[NARRATION]
광장 한쪽에 처음 보는 작은 상자가 놓여 있다.

[CONTEXT]
이 상자는 어제부터 이곳에 있었다.
몇몇 학생이 살펴봤지만 무엇인지는 아직 밝혀지지 않았다.

[티아 / DIALOGUE]
"너도 이거 보러 왔어?"

[PLAYER / DIALOGUE]
"응. 조금 신경 쓰여서."

[NARRATION]
티아는 상자를 바라보다가 주위를 한번 둘러본다.

[THOUGHT]
평소보다 말을 고르는 것 같다.

[티아 / DIALOGUE]
"난 주변을 더 봐도 좋을 것 같고, 먼저 본 사람을 찾아봐도 좋을 것 같아."

[CHOICE]
A. "주변부터 조금 더 살펴보자."
B. "누가 이걸 봤는지 먼저 물어보자."

A reaction
[티아]
```
