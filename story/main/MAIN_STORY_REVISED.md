## 1. 달력 기준

기존 52주 게임 달력과 자동 노출 일정을 변경하지 않는다.

- **1월 1일은 월요일**이다.
- 일반적인 **비윤년 달력**을 기준으로 한다.
- 한 주는 `월요일 ~ 일요일`이다.
- 52주 플레이는 `1월 1일 ~ 12월 30일`이다.
- `12월 31일`은 52주 플레이가 모두 끝난 뒤 별도 엔딩 시나리오로 진입하는 날로 사용한다.
- 3월·6월·9월·12월 메인 스토리는 각 월의 **첫 월요일, 해당 주 일반 일정 시작 전**에 자동 노출한다.
- 메인 스토리는 Location Story·NPC Story와 달리 방문 여부나 랜덤 판정에 의존하지 않는다. 메인 진행에 필요한 단서는 **해당 메인 스토리 안에서** 제공한다.

## 2. 메인 스토리 구조

| **MS01** | **1월 1일 / 1주차 시작 전** | 각자의 이유로 아카데미에 | 기존 `인트로` 유지 + 도입 연출 일부 조정 제안 | 선택한 캐릭터가 자신의 이유로 아르카디아에 입학한다. 시계탑 광장 등 주요 공간을 소개받는 중, **수호 룬의 빛이 잠깐 흐려졌다 돌아오는 현상**을 본다. 교직원은 당장 위험하지 않다고 안내한다. 사소한 이상을 암시하되 학교생활의 기대감을 해치지 않는다. | NPC와 짧게 대화하며 `수업 / 모험 / 휴식`, 주간 일정·체력·마이룸을 안내받는다. 캐릭터별 입학 동기는 짧은 변형 문구로 처리한다. | 학교생활을 시작한다. 수호 룬에 대한 설명은 핵심 정보를 숨기는 미스터리가 아니라 세계관의 작은 복선으로 남는다. → 1주차 일반 육성 |

### 공통 게임화 원칙

- **메인 4편은 각자 완결:** `MS02`·`MS03`·`MS04`·`MS05` 끝에서 당면한 문제와 인물의 갈등이 해결되고, 최소 한 장면의 안정된 이후를 보여 준다.
- **주인공이 행동하는 순간이 해결의 원인:** NPC는 문제·힌트·감정 변화를 짧게 전달하고, 플레이어가 마지막 오브젝트 선택·배치·약속·작동 중 하나를 실행해야 장면이 해결된다.
- **극적 실패는 필수 진행 연출:** 첫 방법의 실패를 '오답 페널티'로 취급하지 않는다. 선택지별 반응은 달라도 진행 불능·반복 노가다·별도 호감도 하락은 만들지 않는다.
- **분기 범위 최소화:** 정규 사건과 해결 결과는 같게 유지하고, NPC 반응·선택한 소품의 모양·짧은 후속 대사만 국소적으로 달라지게 한다. 에피소드당 필수 대화는 주로 1~3명의 NPC로 해결한다.
- **제작 자산 재사용:** 온실·시계탑 광장·수련장과 기존 NPC 대화 UI를 활용한다. 동적 식물 성장·시간 루프·실시간 추격·복잡한 음악 엔진·대규모 신규 컷신을 요구하지 않는다. 덩굴·음표·실루엣·별·조명 변화는 정적 레이어·짧은 효과음·화면 전환 위주로 제안한다.
- **동일 캐릭터 충돌 방지:** 메인 장면의 제보·도움 NPC에 플레이어블 캐릭터를 배정한다면, 해당 캐릭터 선택 시 **기존 학생 중 대체자 1명**에게 동일 역할을 맡긴다. 현재 문서에서는 배역을 확정하지 않는다.
- **랜덤 콘텐츠와 독립:** Location Story와 NPC Story의 발생 유무·완료 여부를 메인 에피소드의 필수 진행 조건으로 쓰지 않는다. 별도 콘텐츠는 메인 사건의 필수 단서와 배경 소품을 공유하지 않고, 시간 순서에 무관하게 자연스럽게 읽히도록 유지한다.

## 4. DB 적용을 위한 기본 구분

기존 메인 스토리의 저장·조회 구분을 보존한다. 아래 필드는 개념 예시이며, 실제 DB 스키마는 구현 시 확정한다.

| 필드 개념 | 예시 | 용도 |
|---|---|---|
| `story_id` | `MS02` | 메인 스토리 고유 ID (동일한 날짜에 완결) |
| `trigger_month` | `3` | 노출 월 |
| `trigger_day` | `5` | 노출 일 |
| `trigger_week` | `10` | 게임 주차 |
| `trigger_timing` | `BEFORE_WEEK_START` | 해당 주 일반 일정 전 자동 실행 |
| `title` | `온실을 삼킨 마법 덩굴` | 스토리 표시 제목 |
| `source_type` | `WRITER_MODIFIED` / `PROPOSED` | 원본 소재 변형/신규 기획 구분. MS03·MS04는 신규 사건 중심 |
| `story_state` | `REVIEW_REQUIRED` | 이번 개편안의 내용 및 MS05·MS06 분리 변경은 확정 전 |
| `scene_step` | `S1`~`S5` | 같은 메인 스토리 안에서의 국소 단계 구분(구현 방식 미정) |
| `choice_result` | 별도 정의 | 짧은 반응·소품·후속 대사 등 로컬 선택 결과 |
| `dialogue_set_id` | 별도 정의 | NPC 대화·플레이어 선택 대사 데이터 연결 |
| `reward_id` | 필요 시 별도 정의 | 작은 기념품의 지급 여부와 중복 지급 방지(보상 미확정) |

### 대화 데이터 원칙

- 본 문서에는 **실제 대사를 넣지 않는다.** 대사 구성은 NPC 화자·상황·정보량·분기 목적만 명시한다.
- 각 메인 스토리에는 추후 `dialogue_set_id` 또는 이에 준하는 연결 키를 둔다.
- 일반 대화, 플레이어 선택 대사, 선택 후 NPC 반응은 별도 대화 데이터에서 관리한다.
- **반복 대화·장시간 설명이 필요한 기믹을 피한다.** 등장 NPC가 짧은 힌트를 주고, 정적 오브젝트의 시각적 변화와 플레이어 클릭으로 사건을 전달한다.
- 메인 4편의 해결에는 필수 랜덤 조우, 특정 친밀도, 이전 장소·NPC 연속 스토리 완료를 요구하지 않는다.
- 선택에 따른 분위기와 보상 표현은 달라도 **같은 결말·다음 주 진행**을 보장한다.

## 5. 기존 구조 대비 변경 사항 및 작가 검토

1. 기존 `인트로`는 **MS01 / 1월 1일**에 유지하며 게임 온보딩과 시계탑의 가벼운 복선을 결합한다.
2. **MS02~MS05는 네 편의 개별 완결 에피소드**로 개편한다. 기존의 `희귀 식물 관리`·`상충하는 기록`·`안전 결계 부품 점검`처럼 현실적인 해결 중심의 갈등은, 구출·판타지 미스터리·그림자 화해·별빛 축제라는 다른 게임 경험으로 전환한다.
3. **빌런을 추가하지 않는다.** 적대 인물이 아니라 마법 사고·뜻밖의 오해·축제의 위기가 갈등을 만든다. 매 편의 70~80% 부근에서 실패 또는 상황 악화가 발생하지만 최종 해결은 플레이어의 명확한 행동으로 완성한다.
4. **가장 큰 구조 변경:** 기존 문서의 `MS05(12월 3일) 위기 제시 → MS06(12월 24일) EP4 해결` 구성을, **`MS05 안에서 EP4 완결 → MS06은 행복한 후일담`** 으로 바꾼다. 따라서 **기존 'EP4 분할 확정' 규칙과 충돌**하며, 작가·기획·개발 측 변경 승인 및 관련 문서 동기화가 필요하다.
5. MS05에서 시계탑 수호 룬도 안정되도록 해 **MS06에 다시 위기를 재발시키지 않는다.** MS06 후 마지막 자유 플레이 주간(`MS07`)은 그대로 보장한다.
6. 기존 `엔딩 — 무엇을 지켰니?`는 삭제하지 않고 **12월 31일 고정 문구**로 사용한다. 직업 엔딩은 메인 사건 성공/실패에 따라 갈라지지 않고 52주 플레이의 스탯·행동·선택을 별도 시스템이 종합해 결정한다.
7. 다른 업로드 문서의 **Location Story 및 NPC Story 진행 규칙은 변경하지 않는다.** 두 시스템의 랜덤 발생이 메인 진행을 방해하지 않도록 필수 단서를 서로 분리한다. 신규 NPC 2명(`TBD1`, `TBD2`)의 교류 스토리는 메인 시나리오가 아닌 별도 검토 과제로 유지한다.
8. 작가 확인 필요: **(a)** 네 에피소드의 제목·상징 소품·마법 규칙의 자연스러움, **(b)** 메인 장면의 NPC 실제 캐스팅 및 주인공 선택 시 대체자, **(c)** 소품/화면 전환/퍼즐 구현 가능 범위, **(d)** 소형 기념 보상 및 마지막 축제 표식 사용 여부, **(e)** 후일담의 2~3개 대화와 이전 선택 반영 범위, **(f)** 기존 `MS05`·`MS06` 분할 규칙 변경 승인.
9. **기존 원본 `story/main/09_MAIN_STORY_SCENARIO.md`는 이 대화에 첨부되지 않았다.** 이 문서는 전달된 구조화 문서 및 이번 대화에서 합의·검토한 소재를 바탕으로 작성한 **개편 초안**이며, 작가 원문과의 문장 단위 대비·인물별 설정 검증은 별도 확인이 필요하다.
10. 실제 상호작용 대사는 이 구조 문서와 분리한다. 직업명·고정 직업 소개 `careerAnchor`·엔딩 중복 제외 규칙·AI 편지는 엔딩 마스터가 담당한다. `별길 개척자` fallback을 포함한 최종 판정 명세는 엔딩 시스템의 정식 버전과 일치시키도록 재확인한다.
