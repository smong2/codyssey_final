# 메인 스토리 구조화 — 52주 배치 확정

> **문서 상태:** 52주 구조·엔딩 연결 확정  
> **원본 기준:** `story/main/09_MAIN_STORY_SCENARIO.md`  
> **목적:** 작가가 작성한 메인 시나리오를 52주 육성 구조와 DB 저장·조회에 사용할 수 있는 메인 스토리 단위로 재배치한다.  
> **대화:** 이 문서에서는 실제 대사를 작성하지 않는다. 각 메인 스토리의 상호작용 대화와 선택 대사는 별도 데이터/문서로 정의한다.  
> **엔딩:** 직업 엔딩 판정·AI 편지는 별도 엔딩 시스템에서 처리한다. 작가 원문의 `무엇을 지켰니?`는 12월 31일 엔딩 진입의 고정 문구로 보존한다.

## 1. 달력 기준

메인 스토리 노출 시점을 명확하게 고정하기 위해 게임 내 1년은 다음 기준을 사용한다.

- **1월 1일은 월요일**이다.
- 일반적인 **비윤년 달력**을 기준으로 한다.
- 한 주는 `월요일 ~ 일요일`이다.
- 52주 플레이는 `1월 1일 ~ 12월 30일`이다.
- `12월 31일`은 52주 플레이가 모두 끝난 뒤 별도 엔딩 시나리오로 진입하는 날로 사용한다.
- 3월·6월·9월·12월 메인 스토리는 각 월의 **첫 월요일, 해당 주 일반 일정 시작 전**에 노출한다.

## 2. 메인 스토리 구조

아래 표는 작가 원문의 내용을 새 플레이 구조에 맞춰 배치한 최종 구조다. 작가 원문을 그대로 사용하는 구간과 52주 플레이 구조를 위해 원문을 분리·연결한 구간은 `출처` 열에서 구분한다.

| ID | 노출 시점 | 스토리명 | 출처 | 시나리오 내용 | 주요 선택·상호작용 | 종료 상태 / 다음 흐름 |
|---|---|---|---|---|---|---|
| **MS01** | **1월 1일 / 1주차 시작 전** | 각자의 이유로 아카데미에 | 작가 시나리오 `인트로` | 선택한 캐릭터가 자신의 배경과 연결된 이유를 품고 아르카디아에 입학한다. 입학 과정에서 시계탑 광장과 아카데미의 주요 생활 공간을 접한다. 시계탑의 수호 룬이 평소보다 어두워져 있음을 처음 목격한다. 교직원도 이상을 확인하고 있지만 원인은 아직 모른다. 이후 아카데미 생활이 시작된다. | 이 구간에는 게임 온보딩을 결합한다. 상호작용 대화를 통해 `수업 / 모험 / 휴식`, 주간 일정, 체력, 마이룸 등 기본 게임 흐름을 안내한다. 캐릭터별 입학 동기는 짧은 개별 맥락으로 반영한다. **실제 대사와 선택 대사는 별도 정의한다.** | 플레이어가 게임의 기본 목적과 생활 방식을 이해한다. 수호 룬의 이상을 최초 인지한다. → 1주차 일반 육성 시작 |
| **MS02** | **3월 5일 / 10주차 시작 전** | 온실의 마지막 화분 | 작가 시나리오 `EP1` | 유리 온실의 희귀 식물이 시들기 시작한다. 식물을 돌보는 두 학생은 `현재 식물을 계속 살릴 것인가 / 건강한 씨앗과 새순을 먼저 보존할 것인가`를 두고 의견이 갈린다. 조사 결과 누군가의 실수가 아니라 계절 변화와 관리 방식이 맞지 않아 식물이 약해진 상태임을 알게 된다. | 식물·흙·빛·주변 환경 조사와 NPC 상호작용을 거친다. 핵심 선택은 **① 현재 식물을 살리는 데 집중 ② 씨앗과 새순을 우선 보존**이다. 어느 쪽도 정답/오답으로 처리하지 않는다. **실제 대사와 선택 대사는 별도 정의한다.** | 온실 사건은 해결된다. 선택에 따라 남는 식물과 이후 관리 방식이 달라진다. 온실의 그림자는 옅어지지만 시계탑 수호 룬에는 여전히 그림자가 남아 있음을 확인한다. → 10주차 일반 육성 진행 |
| **MS03** | **6월 4일 / 23주차 시작 전** | 서로 다른 두 기록 | 작가 시나리오 `EP2` | 대서고에서 오래된 학원 행사에 관한 서로 다른 두 기록이 발견된다. 하나는 행사가 취소되었다고 하고 다른 하나는 열렸다고 기록한다. 두 학생이 각자의 기록이 더 정확하다고 주장한다. 조사 결과 두 기록은 거짓 기록이 아니라 행사의 서로 다른 시점과 부분을 기록한 것임을 알게 된다. | 기록의 작성 시기·장소·맥락을 조사한다. 핵심 선택은 **① 현재 확인된 사실을 정리하고 불확실한 부분을 표시해 공유 ② 두 기록을 함께 보존하고 추가 자료가 나올 때까지 결론을 미룸**이다. **실제 대사와 선택 대사는 별도 정의한다.** | 갈등이 정리된다. 대서고의 다른 기록에서 과거에도 수호 룬에 그림자가 드리운 적이 있었다는 사실을 발견한다. 온실의 그림자 현상과 시계탑 문제가 연결될 가능성이 생긴다. → 23주차 일반 육성 진행 |
| **MS04** | **9월 3일 / 36주차 시작 전** | 멈춘 수련 결계 | 작가 시나리오 `EP3` | 수련장 안전 결계가 훈련 도중 멈춘다. 다친 학생은 없지만 훈련이 중단된다. 일부는 완전히 점검한 뒤 재개하자고 하고, 다른 일부는 안전한 범위에서 훈련을 계속하길 원한다. 점검 결과 특정 학생의 실수가 아니라 오래된 부품이 헐거워진 것이 원인이다. | 결계와 장치를 조사하고 공방·수련장 인물과 상호작용한다. 핵심 선택은 **① 훈련을 완전히 중단하고 전체 점검 ② 안전 구역에서 낮은 강도의 활동을 이어가며 병행 점검**이다. **실제 대사와 선택 대사는 별도 정의한다.** | 결계 문제는 해결된다. 동시에 시계탑 수호 룬의 보호 마법 자체도 약해지고 있음이 분명해진다. 발렌티누스는 학생들을 걱정시키지 않으려고 정보를 충분히 공개하지 않았고 그 사이 추측과 불안이 커졌음을 인정한다. → 36주차 일반 육성 진행 |
| **MS05** | **12월 3일 / 49주차 시작 전** | 시계탑을 지키는 방법 | 작가 시나리오 `EP4`의 사건·갈등·주요 선택 부분을 사용하고, 원문의 최종 해결은 MS06으로 이동 | 시계탑 수호 룬의 그림자가 크게 짙어지고 아카데미 보호 마법이 약해진다. 학생 사이에 여러 소문과 불안이 퍼진다. 앞선 사건의 학생들과 교직원이 다시 등장하고 지금까지 확인한 사실을 공유한다. 발렌티누스는 수호 룬을 한 번의 마법으로 즉시 고칠 수 없으며, 현재 상황을 이해하고 각자가 할 일을 나눠야 한다고 설명한다. | 작가 원문의 핵심 선택을 유지한다. **① 확인된 사실과 아직 모르는 점을 전체에 먼저 공개 ② 기숙사·수업 단위의 작은 대화부터 열고 내용을 정리해 전체에 공유.** 선택에 따라 대응 과정과 NPC 반응을 다르게 할 수 있다. **실제 대사와 선택 대사는 별도 정의한다.** | 여기서는 수호 룬이 완전히 회복되지 않는다. 아카데미 구성원들이 대응 방법과 역할을 정하고 실제 행동을 시작하는 상태에서 종료한다. → 49~51주차 일반 육성 진행 |
| **MS06** | **12월 24일 / 52주차 시작 직전** | **우리가 지켜낸 것** | 작가 `EP4 룬 문제 해결` 부분을 전·후반으로 분리해 후반부로 확정 | MS05 이후 학생과 교직원이 각자의 역할을 수행해 왔고, 마지막 주를 앞두고 수호 룬의 상태가 다시 크게 흔들리며 실제 위기 상황이 온다. 플레이어가 시계탑으로 향하면 앞선 사건에서 만난 인물들이 각자의 방식으로 대응하고 있는 모습을 본다. 온실에서는 필요한 약초와 자원을 준비하고, 대서고에서는 확인된 정보를 정리하며, 공방과 수련장에서는 보호 장치를 점검한다. 플레이어 혼자 문제를 해결하는 것이 아니라 한 해 동안 함께한 사람들이 각자의 역할을 나누어 최종 위기를 극복한다. | 별도 대형 신규 퍼즐을 필수로 두지 않고 기존 상호작용과 대화를 중심으로 구성한다. 필요하다면 마지막 역할 선택 정도의 로컬 분기를 둘 수 있으며 MS05에서 선택한 정보 공유 방식에 따라 일부 진행 순서·NPC 반응을 다르게 할 수 있다. **실제 대사와 선택 대사는 별도 정의한다.** | 수호 룬의 그림자가 걷히고 보호 마법이 안정된다. 미래 직업이나 최종 엔딩은 아직 보여주지 않는다. 위기를 극복한 뒤 플레이어에게 마지막 한 주를 스스로 보낼 기회를 돌려준다. → 52주차 자유 플레이 |
| **MS07** | **12월 24일~30일 / 52주차** | **마지막 한 주** | 52주 플레이 구조를 위해 추가한 확정 연결 구간 | 새로운 메인 위기는 발생하지 않는다. 큰 위기를 극복한 뒤 아르카디아가 다시 일상으로 돌아온 상태에서 플레이어가 마지막 한 주를 직접 보낸다. 기존 주간 일정 시스템을 그대로 사용한다. 이전 메인 사건을 경험한 NPC와 장소에는 사건 이후의 짧은 반응을 연결할 수 있다. | 플레이어는 평소처럼 **수업 / 모험 / 휴식**을 선택한다. 새로운 메인 선택지는 필수로 두지 않는다. NPC·장소 후속 대화는 별도 대화 데이터에서 정의한다. | 12월 30일 주말 처리까지 완료하면 52주 회차가 끝난다. 마지막 주의 행동도 현재 회차 플레이 기록과 엔딩 판정에 반영한다. → 12월 31일 엔딩 진입 |
| **END** | **12월 31일 / 52주 완료 후** | 무엇을 지켰니? → 직업 엔딩 | 작가 고정 문구 + 별도 엔딩 시스템 | 마지막 주간 요약 뒤 작가 원문의 질문 **`무엇을 지켰니?`** 를 고정 문구로 보여 준다. 이어서 보이는 스탯, 보이지 않는 스탯, 이벤트, NPC 만남·스토리 진행, 실제 플레이 행동과 선택을 종합해 직업 엔딩 하나를 결정하고 개인화 편지를 보여 준다. | `무엇을 지켰니?`의 답을 AI나 게임 규칙이 대신 판정하지 않는다. 별도의 `올해의 기억` 화면을 만들지 않고 대표 사건·선택은 엔딩 편지의 회고 문장에 흡수한다. 실제 횟수 기록 4~6개는 `아르카디아에서의 기록`으로 유지할 수 있다. | 엔딩 완료 → 회차 완료 처리 → Global Meta 반영 → 슬롯 `RUN_COMPLETE` → 다음 회차 시작 가능 |

## 4. DB 적용을 위한 기본 구분

실제 DB 스키마는 구현 단계에서 별도로 확정하되, 메인 스토리는 최소한 다음 단위가 구분되어야 한다.

| 필드 개념 | 예시 | 용도 |
|---|---|---|
| `story_id` | `MS02` | 메인 스토리 고유 ID |
| `trigger_month` | `3` | 노출 월 |
| `trigger_day` | `5` | 노출 일 |
| `trigger_week` | `10` | 게임 주차 |
| `trigger_timing` | `BEFORE_WEEK_START` | 일반 주간 일정 전 실행 여부 |
| `title` | `온실의 마지막 화분` | 표시 제목 |
| `source_type` | `WRITER` / `PROPOSED` / `WRITER_MODIFIED` | 작가 원문/제안/원문 변형 구분 |
| `story_state` | `CONFIRMED` | 52주 배치·EP4 분리·엔딩 연결 확정 상태 |
| `choice_result` | 별도 정의 | 주요 선택 결과 저장 |
| `dialogue_set_id` | 별도 정의 | 실제 상호작용 대화 데이터 연결 |

### 대화 데이터 원칙

- 본 문서에는 실제 대사를 넣지 않는다.
- 각 메인 스토리에는 추후 `dialogue_set_id` 또는 이에 준하는 연결 키를 둔다.
- 일반 대화, 플레이어 선택 대사, 선택 후 NPC 반응은 별도 대화 데이터로 관리한다.
- 시나리오 구조와 대화 원고를 분리하여 작가 수정이 메인 스토리 발생 조건·주차 구조를 불필요하게 변경하지 않도록 한다.

## 5. 최종 확정된 구조 변경

1. 기존 `인트로`를 **MS01 / 1월 1일** 메인 스토리로 사용하며 게임 온보딩 역할을 함께 부여한다.
2. 기존 EP1~EP3은 각각 **3월 5일 / 6월 4일 / 9월 3일**에 배치한다.
3. 기존 EP4는 한 번에 해결하지 않고 두 단계로 분리한다.
   - **12월 3일 MS05:** 위기 심화, 사실 공유, 대응 방식과 역할 결정
   - **12월 24일 MS06:** 실제 공동 대응과 수호 룬 최종 안정
4. 기존 문서의 `엔딩 — 무엇을 지켰니?`는 삭제하지 않고 **12월 31일 엔딩 진입의 고정 작가 문구**로 사용한다. AI나 게임 규칙이 `무엇을 지켰는지` 정답을 대신 판정하지 않는다.
5. **12월 24~30일 52주차는 마지막 자유 플레이 주간**으로 남긴다.
6. **12월 31일**에는 `마지막 주간 요약 → 무엇을 지켰니? → 직업 엔딩 → 개인화 엔딩 편지` 순서로 진행한다.
7. 별도 `올해의 기억` 섹션은 만들지 않는다. 대표 사건·선택은 엔딩 편지의 회고 문장에 포함하고, 실제 횟수형 플레이 기록은 `아르카디아에서의 기록`으로 유지한다.
8. 실제 상호작용 대화와 직업별 편지 원고는 이 구조 문서와 분리해 별도로 작성한다.
