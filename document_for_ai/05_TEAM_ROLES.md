# 팀 역할·협업 경계

현재 팀의 R&R은 다음과 같이 확정되어 있다. 이름과 담당 영역은 임의로 바꾸지 않는다.

| 담당자 | 역할 | 주 영역 | 참고 브랜치·관리 |
|---|---|---|---|
| 이대선 | 엔진 · 게임 UI | `engine/` | `dev-ds` |
| 최현서 | 스토리 | `story/` | `dev-hs` |
| 최주원 | 디자인 | `asset/` | `dev-jw` |
| 박순몽 | 백엔드 · 콘텐츠 기획 · PM | `backend/`, `document/`, 공통 기획 | 별도 담당 브랜치 미기재 |

게임 UI의 코드·상태 전환·입력·화면 연결은 이대선의 구현 영역이고, UI에 들어가는 그래픽 자원과 시각 디자인은 최주원의 디자인 영역이다. 시나리오 내용은 최현서가 담당하며, 스토리의 발생 규칙·일정·해금·보상·저장처럼 시스템화되는 콘텐츠 기획은 박순몽이 담당한다. 박순몽은 PM으로 일정·이슈·영역 간 통합 조율도 맡는다.

`prototype/`은 보존 영역이고 `lumia/`는 최종 통합 영역이다. 브랜치는 참고 정보일 뿐 AI가 임의로 전환하지 않는다. 각 전문 영역의 산출물은 해당 담당자가 검수하고, 영역 간 연결은 PM이 조율한다. 기획 결정이 바뀌면 관련 팀 문서를 먼저 확인하고 이 폴더의 요약을 동기화한다. 이미지 교체 시에는 파일, 사용 상태, 문서 링크를 함께 확인한다. 사람에게 의사결정이 필요한 항목을 AI가 임의로 확정하지 않는다.

실제 협업은 [GitHub Project 애자일 보드](https://github.com/users/smong2/projects/2)의 WBS 이슈로 담당자·목표 일정·진행 현황과 처리 내용을 공유하는 방식으로 운영했다. 팀은 약 3주간 기획하고 매일 늦은 시간까지 회의하며 사용자 문제·52주 경험·영역 간 연결을 논의했다. 세부 우선순위는 조정해도 관계와 선택을 중심으로 한 핵심 방향은 유지했다. `story/`·`asset/`·`engine/`·`backend/`를 역할별 작업 공간으로 나누어 충돌을 줄이고, 공통 문서·콘텐츠 ID·API/데이터 계약으로 인계했다. 상세 내용은 [팀 역할](../document/05_TEAM_ROLES.md)과 [기획서](../document/11_PROJECT_PLAN.md)를 확인한다.

`engine/minigame-demo/`는 엔진 작업 영역의 **독립 실행형 7종 미니게임 데모**이며 통합 게임이 아니다. 엔진 담당자가 이식할 때는 해당 폴더의 README와 통합 프롬프트를 확인하고, Scene의 결과를 수업·성장 시스템에 연결한다. 데모의 수업 제안명과 점수는 최종 확정값이 아니다.

상세 자료가 있을 때: [팀 역할](../document/05_TEAM_ROLES.md), [협업 규칙](06_WORKSPACE_RULES.md).

`engine/`에는 Phaser 3 실행형 UI 시안이 있다. 7종 미니게임의 일정 연결, 슬롯·주말 로컬 저장·재개, 달력·주별 다이어리, 모험 SD 이동·흑백 충돌 마스크와 입학 장면 프레임을 확인할 수 있다. 본편 펫 10종의 선택·임시 스탯 보정은 로컬 시안에 연결됐지만 자동 해금·서버 검증은 미연결이다. 실제 스토리 원고·AI 편지·계정/서버 저장·최종 통합은 후속 대상이다. 엔딩은 로컬 직업 판정과 표시 프레임이 있으나 AI 편지·서버 저장은 미연결이다. 구현 범위는 [엔진 README](../engine/README.md)를 기준으로 확인하며 최신 역할·본편 기획을 변경하지 않는다.
