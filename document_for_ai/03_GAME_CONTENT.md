# 게임 콘텐츠의 기본 구조

2026-10-18 Phase 12 최신 검증: Python 회귀 152개, 엔진·미니게임 회귀 339개와 Firebase Emulator 통합 테스트 1개가 통과했다. 로컬 Emulator 브라우저에서 가입·인증·bootstrap·MS01 로드·재접속을 확인했고, Vercel 프론트 로그인 화면은 운영 URL에서 열렸다. Render API, 실제 Gemini 호출, 52주 엔딩과 관리자·탈퇴 운영 E2E는 아직 검증 전이다. 아래 단계별 구현 설명의 과거 검증 대기 문구보다 이 상태를 우선한다.

AI 엔딩 구현 상태: 엔진의 최종 이벤트·엔딩 프레임은 직업/편지 준비·실패·3개 섹션 표시와 조회 adapter 연결 지점을 제공한다. FastAPI Phase 8의 정규 10종 + fallback **규칙 기반 직업 판정과 수집·해금 로컬 회귀 테스트는 사용자가 통과를 확인**했다. Phase 9에는 `ENDING_DECIDED → Long-term Play Memory 4~6개 기록 + 중요 선택 최대 2개 선별 → Gemini 생성/검증 또는 fallback → ENDING_READY 안전 저장 → 마지막 타이틀로에서 Ending Record·열람 기록·회차 완료·해금 일괄 확정` 코드와 오프라인 회귀 테스트가 추가됐고 해당 백엔드 회귀 검증도 사용자가 통과를 확인했다. 재접속은 저장된 편지를 재사용하고 Gemini를 다시 호출하지 않으며, raw Hidden 점수는 AI 요청에만 일시적으로 사용할 수 있고 완료 기록에는 dominant ID만 남긴다. Phase 11 엔진은 `ENDING_PENDING → decision → prepare → 저장 편지 표시 → finish`를 운영 provider에 연결하고, `ENDING_READY` 재접속은 저장된 편지를 조회한 뒤 **질문부터 같은 엔딩을 다시 표시하되 Gemini를 재호출하지 않는다**. `prepare`는 일반 API보다 긴 timeout을 사용하지만 자동 중복 재전송하지 않고 동일 requestId 명시적 재시도로 복구한다. 현재 Phase 11-3 엔딩 UI·계정 설정·활성 펫 모험 시간 보정 코드는 **구현 및 테스트 작성 완료 / 사용자의 로컬 재검증 전**이며 실제 Gemini 서비스 호출, Firebase Emulator/실제 프로젝트, Render/Vercel 브라우저 E2E는 후속이다. 현재 엔진 개발 시안의 `전체 흐름 보기`에서는 짧은 사용자 승인 예시를 볼 수 있지만, WBS 4.1 최종 메뉴 계약에서는 이 개발용 진입점을 제거한다. 제출판의 AI 기술 요소는 **자동화 워크플로우 + Long-term Memory**이며 별도 AI Agent는 사용하지 않는다. Long-term Memory는 일반 세이브가 아니라 현재 회차에서 여러 주차·세션에 걸쳐 누적한 활동 결과·중요 선택을 계정에 보존하고, **52주 종료 시 다시 로드해 대표 기록 4~6개와 중요 선택 최대 2개를 AI Memory Context로 구성한 뒤 실제 Gemini 입력에 사용하는 Long-term Play Memory**다. AI 입력은 `System Prompt / Task Context / Task Prompt / Output Contract` 책임을 분리하며, 현재 회차 Firestore 기록을 백엔드가 직접 조회·선별한다. 별도 RAG·벡터 검색·외부 웹 검색은 사용하지 않는다. 최종 화면 계약은 `무엇을 지켰니? → 미래 직업 공개 → 개인화 편지+아르카디아 기록 → 신규 해금이 있을 때만 1회 요약 → 타이틀`이다. 직업/편지는 재접속용으로 먼저 안전 저장하되 **실제 본 엔딩 카운트와 엔딩 열람 의존 메타는 마지막 `타이틀로` 저장 성공 시 한 번만 확정**한다. 표시 도중 종료되면 이어 하기에서 같은 결과로 엔딩을 처음부터 다시 보여 주고 AI를 재호출하지 않는다. 최종 편지와 사용한 대표 기억은 회차별 Ending Record에 보존하며 다음 회차의 편지에는 이전 회차 기억을 자동으로 섞지 않는다. > **2026-10-18 운영 검수 반영:** 아래 기존 설명 중 `Location/NPC Story를 모두 활동 결과 저장 뒤 판정`하는 표현은 최신 계약으로 대체한다. Story 선택은 Main `Visible +2 / Primary Hidden +8 / 일부 Secondary +3`, NPC·Location `Visible +1 / Primary Hidden +5 / 일부 Secondary +2`를 사용하고 감점하지 않는다. Story 선택 보상은 저체력 성장량 감소와 관리자 반복 성장 배율을 적용하지 않는다. 선택 순간에는 보상 수치를 숨기고 END 저장 성공 후 clamp까지 반영한 실제 Visible 증가량의 이벤트 합계만 보여 주며 Hidden 증가량은 노출하지 않는다. 세 Story 유형은 총 77 canonical choice / 205 `story_choice_effects`를 사용한다. 보이지 않는 스탯은 도덕적 선악 점수가 아니라 이벤트·대화·엔딩 조건에 사용하는 플레이 스타일 기록이다.

본편 7개 공간 콘텐츠는 **6개 미니게임 + 기숙사 특수 활동 1개**로 확정한다. `OBS 별빛 천문대 → 거울 마법 → 탐험`, `CLK 시계탑 야외무대 → 별빛 무대 → 표현력`, `GH 유리 온실 → 정령 화분 정리 → 지식`, `DRM 기숙사 공용 공간 → 요정의 거래 → 성장 스탯 최대 5포인트 1:1 이전`, `LIB 대서고 → 봉인 서가 → 지식`, `WRK 마도 공방 → 룬 회로 → 마법`, `TRN 수련장 → 룬 핀 훈련 → 솜씨`를 사용한다. 거울 마법과 룬 회로만 기존 독립 데모의 핵심 조작을 본편에 재채택하고 나머지 데모 게임은 본편 기준으로 사용하지 않는다. 교육 문제를 직접 출제하기보다 게임 행위 자체에서 기억·분류·추론·선택적 주의·표현을 사용하게 하는 것을 원칙으로 한다.

6개 본편 미니게임은 `FAIL / SUCCESS / GREAT`를 반환하고 결과 화면에서 즉시 다시 하기를 제공하지 않는다. 사용자가 `포기하기`를 누르면 `FAIL`로 확정한다. 같은 게임 2회 연속 실패 시 다음 플레이 난이도를 1단계, 4회 이상이면 최대 2단계 낮추지만 성장 보상은 원래 `run.stats`로 정한 `rewardDifficulty`를 유지한다. 성공/대성공 시 해당 게임 연속 실패 횟수를 0으로 초기화한다. 비정상 종료 `INTERRUPTED`는 FAIL에 포함하지 않는다. `engine/minigame-demo/`는 독립 참고 구현이며 본편 세부 규칙은 `document/content/06_01_LOCATION_ACTIVITIES.md`를 우선한다.

본편 NPC Story는 `GUIDE / WORK / LULU` 3개 체인만 사용하고 각 4단계로 총 12장면을 구성한다. `TBD1 / TBD2` 추가 체인은 스펙 아웃한다. GUIDE는 `4/15/29/41주차`, WORK는 `8/20/32/44주차`, LULU는 `12/25/35/48주차`부터 각 단계가 순차적으로 후보가 된다. GUIDE의 티아가 주인공이면 로빈, WORK의 렌이 주인공이면 다나가 동일 체인을 대신 수행하며 별도 체인으로 세지 않는다. 로빈은 빠른 친화력과 자유로운 행동성을 살린 짧고 가벼운 말투, 다나는 규격·구조·작동 상태를 관찰하는 짧고 명확한 엔지니어 말투를 사용하되 사건·선택·결과 구조는 원래 체인과 동일하게 유지한다. 실제 공통 Dialogue 원고는 `document/dialogue/npc/`에 작성되어 있으며 GUIDE/WORK/LULU 각 4편, 총 **12장면 / 선택 화면 12개 / canonical choice 24개**다. `document/dialogue/npc/character_sets/`에는 CH01~CH32의 실제 PLAYER Voice, 24개 선택 문구, 각 선택 직후 상대 reaction이 작성되어 있으며 **32명 × 12 choiceNode = 384개 캐릭터별 선택 화면 / 32명 × 24 canonical choiceId = 768개 실제 선택 문구**를 검산했다. GUIDE는 `안내지 정리 → 안내지 배치 → 리본 선택 → 마지막 준비`, WORK는 `부품 분류 → 비슷한 부품 비교 → 도구 정돈 → 익숙한 작업대`, LULU는 `단추 발견 → 보관 → 보물상자 공유 → 새 발견 공유`로 4단계 관계 변화를 보여 주며 친밀도 수치는 사용하지 않는다. `WORK_02`는 정답 퀴즈가 아니라 `홈 두 개 쪽이 더 맞아 보임 / 둘을 다시 나란히 비교`의 두 합리적 관찰 방식으로 유지한다. 루루는 `asset/pet/`에 실제 NPC 이미지 세트가 있으나 이 원고에서는 최종 의상/표정 채택을 확정하지 않는다. 현재 상태는 **NPC 공통 대화 + CH01~CH32 Character Set 검수 승인 / SQLite v4 NPC seed 구현 완료 / 실제 DB 실행 검증 전**이다. `backend/database/sqlite/seed_npc_story.py`는 3 Story / 12 Event / 16 event condition / 24 canonical choice / **64 choice effect** / 384 dialogue sequence / 768 dialogue option을 같은 `gameDataVersion`에 생성하도록 구현했으며 GUIDE/WORK actor ROLE과 루루 화자도 함께 적재한다. 상세는 `backend/database/NPC_STORY_DB_SPEC.md`를 따른다. 각 체인의 4단계가 해당 NPC와의 마지막 만남이며 완료 뒤 체인 전용 일반 조우·후속 대사는 제작하지 않는다. 이전 행동을 기억하는 반응은 다음 단계 안에서만 사용한다. 1단계 이전의 공통 선행 일반 조우 규칙은 유지한다. 수업 미니게임과 직접 모험 플레이 내부에는 NPC를 배치하거나 NPC 대화·NPC/Location Story를 실행하지 않는다. NPC Story 후보는 활동 결과 저장 뒤 판정하고, 선정 시 활동 화면과 분리된 이야기 장면으로 실행한다. 후보 선정은 균등 랜덤보다 `기본 100 + 장소 일치 50 + 진행 중 스토리 80 + 메인 연관 40 + 최근 미등장 주당 10(최대 60)`의 가중치를 사용한다. 숫자형 친밀도·호감도는 사용하지 않고 `encounterCount / lastEncounterWeek / storyProgress / eventFlags`로 조우와 이야기를 관리한다. NPC·공간 스토리 이벤트는 합쳐 주당 최대 2회, 하루 최대 1회이며 동일 NPC 스토리는 주당 1단계만 진행한다. 향후 대사에 필요한 선택만 플래그로, 엔딩 편지에 의미 있는 중요 선택만 대표 선택으로 저장한다. 엔딩은 작가 `story/ending/ENDING_STORY.md`의 **룬 연구자 / 아르카디아 탐험가 / 마도 장인 / 약초 정원사 / 아카데미 수호 기사 / 아카데미 교사 / 아카이브 기록관 / 마법 공연가 / 마법 생물 돌봄이 / 아카데미 행사 기획자**를 정규 직업 10종으로 채택하고, fallback `별길 개척자` 1종을 별도로 둔다. 작가 원문의 직업명·부제·직업 의미·미래 첫걸음 방향은 고정 원고로 보존하되, 판정 조건은 현재 시스템의 단순 규칙에 맞춰 대표 성장 스탯 `300 이상`을 필수 조건으로 하고 보조 스탯·보이지 않는 스탯·관련 활동의 선택 조건 3개 중 충족 개수를 적합도로 사용한다. 여러 정규 후보가 있으면 미노출 우선 → 적합도 → 직업별 대표 기록 → 대표 성장 스탯 → 랜덤 순으로 판정하고, 만족한 후보가 모두 이미 본 엔딩이면 정규 후보 전체에서 랜덤으로 결정한다. 정규 필수 조건을 하나도 만족하지 못하면 준비된 직업을 억지 배정하지 않고 `ENDING_STARPATH_PIONEER / 별길 개척자`를 확정하며, 이 횟수는 `endingViewCounts`에 누적하되 정규 엔딩 해금 수에는 포함하지 않는다. **직업 엔딩 판정은 게임 규칙이 수행하고 생성형 AI는 판정 결과를 바꾸지 않는다.** 12월 31일에는 마지막 주간 요약 뒤 작가의 고정 질문 `무엇을 지켰니?`를 먼저 보여 준다. 이 질문의 답을 AI가 대신 정하지 않는다. 대표 사건 목록은 AI 입력에서 제외하고 백엔드가 선별한 실제 횟수형 플레이 기록 4~6개와 중요 선택 최대 2개만 개인화 입력에 사용한다. `아르카디아에서의 기록` 라벨·숫자는 UI가 직접 표시하고 AI는 작가 원문의 직업 의미와 미래 장면 범위 안에서 성장 회고와 응원 문장만 생성한다. 편지는 어린이의 실제 성격·심리·진로를 진단하는 표현을 사용하지 않는다. 상세 기준은 [AI 핵심 기능](../document/09_AI_ENDING_LETTER.md)을 확인한다.

현재 Production 원고의 스토리 선택 보상은 **Main: Visible +2 / Primary Hidden +8 / 일부 Secondary +3**, **NPC·Location: Visible +1 / Primary Hidden +5 / 일부 Secondary +2**다. 같은 choiceNode에서는 Hidden 총량을 동일하게 유지하고 Primary/Secondary는 서로 다른 Hidden을 사용한다. 선택별 대상 스탯은 각 Production 문서의 안정적인 `choiceId` 표에서 확정한다. 선택 순간에는 수치를 표시하지 않고 END 저장 성공 후 실제 적용된 Visible 합계만 표시하며 Hidden 결과는 공개하지 않는다. 일회성 Story 보상이므로 관리자 반복 성장 배율과 저체력 성장량 감소는 적용하지 않는다. 상세는 `document/content/02_STATS_EVENTS_ENDINGS/04_STORY_CHOICE_REWARDS.md`를 따른다.

본편 Location Story 제작 범위는 `OBS` 천문대 4회 + `GH` 온실 1회 + `LIB` 대서고 1회, 총 **6장면**이다. `GH02/LIB02/WRK/TRN/CLK/DRM`의 과거 생활 이벤트는 본편 발생 후보에서 제외한다. 모든 6장면은 최소 1회의 플레이어 대사 선택을 가지며 오브젝트 직접 조작 없이 대화와 정적 이미지 전환으로 진행한다. `LOC_GH_01`의 온실 학생은 `LOC_GREENHOUSE_STUDENT` 역할로 회차 시작 때 확정하며 주인공 및 메인 `MAIN_GREENHOUSE_STUDENT`와 달라야 하고, 다른 Main 핵심 역할과도 가능하면 겹치지 않게 한다. `LOC_LIB_01`의 학생 사서 **세린**은 이 1회 이벤트만 담당하는 텍스트 화자이며 전용 캐릭터 이미지 없이 화자명·대화창만으로 등장한다. 공통 대화는 `document/dialogue/location/`, CH01~CH32 실제 PLAYER/THOUGHT·선택 문구·reaction은 `document/dialogue/location/character_sets/`에 작성되어 있다. 검산값은 **32명 / 192 choiceNode / 416 실제 선택 문구 / signature override 192개**다. `LOC_GREENHOUSE_STUDENT`는 CH12 리네·CH19 요한 protagonist에서 하젤(CH20), 나머지 30명에서 요한(CH19)이며 fallback은 없다. `LOC_OBS_01~04`는 같은 `ART-L01` 일기 이미지를 재사용하고, `LOC_GH_01`은 `ART-L02 → ART-L03`, `LOC_LIB_01`은 `ART-L04 → FOCUS HIDE`로 상태 변화를 표현한다. 총 기본 대화량은 **20왕복**, 선택 화면 6개, canonical choice 13개다. 직접 모험은 `유리 온실·약초원 / 대서고 / 별빛 천문대` 3곳을 사용한다. 맵별 고유 목표 아이템 5종 중 난이도별 `1/2/3~4/5개`를 중복 없이 무작위 선택해 시작점에서 실제로 도달 가능한 충돌 영역 안에 배치한다. 배치는 맵 중심에 너무 가깝거나 중심 기준 6시인 후보를 가능한 한 피하고 방향을 분산한다. 시작 전 모든 아이템의 **맵 중심 기준 24방향(30분 간격)** 시계 단서를 공개하고 하나를 추적할 수 있으며, 추적하지 않은 아이템을 우연히 정확히 조사해도 발견으로 인정한다. 단서 화면의 아이템 이미지는 후속 제작 대상으로, 없어도 텍스트 단서는 사용 가능하다. 조사 횟수는 제한하지 않는다. 제한시간은 탐험 50 이하 120초, 50~500에서 120~240초 선형 증가, 500 이상 240초이며 활성 펫 탐험 보정을 포함하고 저체력 감소로 시간까지 줄이지 않는다. 단서 읽기·1~2초 조사 연출·로딩 중에는 타이머를 멈춘다. 모험 맵에는 NPC를 배치하지 않으며 NPC 대화·NPC/Location Story는 모험 플레이 내부에서 실행하지 않는다. 관련 이야기 후보는 모험 결과 저장 뒤 판정하고 별도 이야기 장면에서 실행한다. 전부 찾으면 `MISSION_COMPLETE`, 시간 초과면 `TIMEOUT`이다. 숨은 목표 아이템은 **현재 모험판의 임시 성공 조건**이며 성공해도 개별 item ID를 가방·계정 영구 수집 목록에 저장하지 않고 모험 종료 뒤 개별 획득물 확인이나 가방 NEW 표시도 만들지 않는다. 기존 배지/엔딩에서 쓰는 특별 발견·장소 발견 값은 소지품이 아니라 플레이 기록 카운터로만 유지할 수 있다. 반대로 배지·캐릭터·펫·마이룸 퍼즐/배경처럼 계정에 영구적으로 남는 획득·해금은 짧은 알림, 엔딩 해금 요약 또는 가방 NEW 표시로 사용자가 결과를 확인할 수 있게 한다. TIMEOUT에서는 발견 아이템을 결과로 남기지 않고, 한 개 이상 찾았다면 발견 비율에 따라 성공보다 작은 탐험 성장 일부만 남긴다. 비정상 종료 `INTERRUPTED`는 목표 아이템과 부분 성장을 남기지 않는다. 세부 계약은 `document/content/10_COMMON_ENGINE_FRAME.md`, `document/content/11_FEATURE_FRAME.md`, 사용자 흐름은 `document/content/12_USER_UCS.md`를 따른다.

수집 배지는 `5개 대분류 × 5개 소분류 × 소분류당 8개 = 총 200개`로 확정한다. 대분류는 `탐험과 발견 / 배움과 성장 / 활동과 성취 / 관계와 공감 / 각성과 선택`이며 기존 5개 프레임과 25개 심볼을 그대로 사용한다. 소분류별 8개 조건은 모험·수업·NPC·발견·행동 태그·퍼즐·캐릭터·펫·엔딩 같은 계정 누적 기록의 단계값으로 정의한다. FastAPI Phase 8 규칙 엔진은 이 25개 트랙과 `2/5/8` 자동 영구 보상, 23개 배지 연동 캐릭터 pending, 펫 즉시 해금, 36개 퍼즐 비중복 지급·3개 배경 완성 판정을 같은 계정 progression 경계에 구현한다. 수업·모험·Story 결과 transaction에서 관련 전역 통계를 갱신한 직후 progression을 함께 평가하고, 마이룸 방문은 같은 `runId + week`당 한 번만 `myRoomActiveWeekCount`를 증가시킨다. 특별 아이템·발견물 카운터는 콘텐츠 마스터의 명시적 통계 지정이 아직 없어 임의 증가하지 않는다. 가방 배지 UI는 대분류→소분류→8개 배지로 들어가며 **잠긴 배지는 공통 잠금 디자인을 유지하되 획득 조건과 현재 진행도는 표시**한다. `2/8 → 5/8 → 8/8` 보상은 수령 버튼 없이 자동 지급하고 다음 회차부터 적용됨을 표시한다. 각 단계는 해당 대분류 성장 스탯을 영구 `+1`씩 지급해 한 소분류 최대 `+3`, 한 성장 스탯의 배지 영구 보너스 상한은 `+15`다. 체력 영구 보너스는 사용하지 않는다. 대분류 40/40 완성은 추가 수치 없이 골드 강조와 완료 알림만 제공한다. 디자인은 `대분류 프레임 5종 + 소분류 심볼 25종 + 공용 장식 8종 + 상태 표현 3종`의 조립형 구조를 사용한다. 최초 캐릭터는 남 3명 `카엘 / 로빈 / 니코`, 여 3명 `세라 / 아이리스 / 티아`의 총 6명이며 성장 스탯 보정 없이 시작한다. 추가 26명은 각자 `+10/-10` 초기 보정을 가지며, 23명은 지정 배지 소분류 `5/8`, `CH13`은 첫 52주 완료, `CH14`는 서로 다른 엔딩 3개, `CH32`는 서로 다른 엔딩 10개로 해금한다. 조건은 플레이 중 달성할 수 있지만 실제 캐릭터 해금은 **엔딩의 마지막 `타이틀로` 저장 성공으로 회차 종료가 확정될 때** 일괄 반영한다. `PET02`의 첫 엔딩 조건도 같은 최종 열람 완료 시점에 확정한다. 본편 펫은 `PET01~PET10`의 서로 다른 10마리이며 `PET01`을 기본 해금하고 나머지 9마리를 순차 해금한다. 해금된 펫은 가방 → 펫 탭에서 언제든 활성 펫 1마리를 선택할 수 있다. 마이룸 배경은 기본 기숙사방 외에 추가 3종, 각 12조각 총 36개를 사용한다. 가방 → 마이룸에서 획득 조각 위치만 실제 그림으로 공개하고 미획득 위치는 가린다. `12/12`이면 영구 해금하지만 **자동 적용하지 않으며 사용자가 직접 선택**한다. 해금 배경은 언제든 다시 변경할 수 있고 계정 전역 `activeRoomBackgroundId`로 슬롯 전체가 공유한다. 퍼즐 획득은 주간 진행을 강제로 열지 않고 짧은 알림/새 항목 표시만 남긴다.

저장은 계정 단위 Global Meta Progress + 5개 세이브 슬롯 구조를 사용한다. `이어서 하기`에서는 항상 5개 카드를 보여 주며 빈 슬롯은 `저장 기록 없음`으로 표시한다. 특정 슬롯 로드 실패는 저장 상태가 아닌 UI `LOAD_ERROR`로 취급해 `다시 시도 / 삭제`를 제공하고 EMPTY로 추정하거나 자동 덮어쓰지 않는다. 5개 슬롯이 모두 사용 중이어도 `새로 시작하기`는 정상 색상·불투명도와 클릭 가능 상태를 유지한다. 클릭하면 새 회차를 만들지 않고 버튼들 아래 프레임에 슬롯 삭제 안내를 약 3초 표시한 뒤 숨기며 연속 클릭은 표시 시간을 갱신한다. 상시 안내·모달 오류 팝업·기존 기록 자동 덮어쓰기는 사용하지 않는다. `새로 시작하기`는 빈 슬롯이 있을 때만 가능하고, 캐릭터 확정 후 첫 빈 슬롯에 초기 회차 저장이 성공해야 MS01과 실제 플레이를 시작한다. 자동 저장은 `새 회차 생성 / 주간 일정 확정 / 각 활동 시작 체크포인트 / 각 활동 결과 확정 / 주간 종료 / 엔딩 확정`을 안정 경계로 사용한다. 활동 시작 때 `IN_PROGRESS`와 체력 선차감 상태를 저장한 뒤 콘텐츠를 실행한다. 정상 활동 결과 저장 성공 뒤에는 Location/NPC Story 후보를 판정하고, 선택적 별도 이야기 장면의 완료 결과 저장까지 끝낸 뒤 다음 일정으로 자동 진행한다. 활동 또는 이야기 결과 저장 실패 시 전환을 멈추고 재시도한다. 비정상 종료 후 `IN_PROGRESS`가 남으면 해당 활동을 `INTERRUPTED`로 소비하고 성장량·연속 실패 카운트는 바꾸지 않은 채 복구 저장 후 **마이룸 복귀 허브에서 다음 phase를 판단**한다. NPC/Location Story 대사 중간은 저장하지 않고 장면 완료 결과만 저장한다. 미니게임 보드와 모험의 숨은 좌표·남은 시간·임시 발견 목록 같은 활동 중간 상태도 저장하지 않는다. 캐릭터·펫·배지·배경·엔딩·영구 보너스와 장기 누적 기록은 Global Meta로 유지된다. 엔딩 편지는 회차별 Ending Record에 영구 저장하며 같은 직업 엔딩이 반복되어도 과거 편지를 덮어쓰지 않는다. 엔딩 표시가 미완료면 이어 하기에서 처음부터 재표시하고 마지막 `타이틀로` 성공 전까지 다음 회차 시작을 허용하지 않는다.

계정 UI는 Email/Password + 이메일 인증을 사용하며 **로그인 페이지 영역이 회원가입과 이메일 인증 완료 확인까지 담당**한다. 인증된 현재 브라우저 세션은 명시적 로그아웃 전까지 유지한다. 현재 게임에는 계정 외 별도 설정 카테고리가 없으므로 `환경설정` 상위 뎁스를 만들지 않고 마이룸 게임 메뉴에 `계정`을 직접 둔다. 계정 화면은 연결 이메일·최초 가입일을 읽기 전용으로 보여 주고 `비밀번호 변경 / 다른 기기에서 모두 로그아웃 / 이 기기에서 로그아웃 / 계정 탈퇴`를 제공한다. 현재 비밀번호를 아는 경우 재인증 후 게임 내부에서 새 비밀번호를 직접 설정하며, 현재 비밀번호를 잊은 복구 상황에서만 이메일의 외부 재설정 링크를 사용한다. `다른 기기에서 모두 로그아웃`은 기존 원격 인증 세션을 폐기한 뒤 현재 기기를 새 세션으로 재인증해 유지하는 일회성 보안 동작이다.

최신 타이틀 UI 결정: 저장된 슬롯이 없으면 `시작하기`만, 하나 이상 있으면 `새로 시작하기 / 이어서 하기`를 표시한다. 두 시작 버튼은 첫 빈 슬롯 자동 배정 → 캐릭터 선택이며 별도 빈 슬롯 선택 화면을 표시하지 않는다. 빈 슬롯이 없으면 안내하고 덮어쓰지 않는다. `이어서 하기`는 타이틀 위 한 열 슬롯 프레임으로 열리며 실제 최근 저장 슬롯의 바로가기를 맨 위에 추가한다. 캐릭터 선택 확정 전에는 회차를 생성하지 않고 새 게임 뒤로가기는 타이틀, 다음 회차 뒤로가기는 슬롯 프레임으로 돌아간다.

최신 사용자 결정: 펫 선택 진입점은 별도 환경설정이 아니라 마이룸의 **가방 → 펫 탭**이다. 해금·`activePetId`·임시 보정·슬롯 공유 규칙은 기존 펫 기획을 그대로 유지한다. 같은 문서의 이전 `환경설정` 표기는 이 결정으로 대체한다.

가방의 확정 UI는 **배지 → 펫 → 캐릭터 → 마이룸**의 4탭이며 기본 진입은 배지다. 아이템 탭과 상단 `가방` 제목은 표시하지 않고 자원 원본은 보존한다. 탭은 캡슐 바가 아닌 양피지 질감의 고전 서적 책갈피로 프레임 바깥 왼쪽 상단에 붙이며 전체 길이는 프레임의 약 1/3이다. 기본 탭은 아이보리·브라운 글씨, 선택 탭은 조금 더 높은 그린·아이보리 글씨이며 고운바탕을 사용한다. 내부 이미지 버튼은 ivory/green short BT04와 원본 비율을 유지한다. 펫·캐릭터는 이름 없는 동일 크기의 둥근 정사각형 카드로 표시하고 미해금 실루엣은 저채도 브라운으로, 머리 윗부분이 잘리지 않게 배치한다. 해금 카드는 정보 팝업, 미해금 카드는 해금 조건 안내를 연다. 캐릭터는 전신 원본만 사용하되 카드에서 전신 전체를 보일 필요는 없으며 작은 얼굴 프로필은 표시하지 않는다. 대화 상대도 전신 한 명만 기본 중앙에 표시하고 플레이어 이미지는 표시하지 않으며, 선택지가 있으면 인물을 왼쪽·선택지를 얼굴/상체 오른쪽에 둔다. 이 표시 변경은 해금·보상·저장 데이터 규칙을 바꾸지 않는다.

현재 본편 기획의 일정 UI 규칙: 계획 중에는 활동 선택 시 가장 이른 빈 평일에 순차 등록하거나 특정 날짜를 먼저 선택해 넣을 수 있고, 등록 날짜를 눌러 상세 확인·삭제 후 재등록할 수 있다. 5칸이 모두 채워져야 시작하며 시작 후에는 일반 일정 수정이 불가하다. 모험은 일정 작성 때 3개 장소 중 하나까지 정한다. `요정의 거래`는 `SPECIAL` 일정으로 주 1회만 등록할 수 있다. 엔진의 현재 구현 상태가 이 기획을 모두 충족하는지는 별도 검수 대상이다. 지난 활동 이미지는 흑백이며 원본 일별 완료 기록을 다이어리에서 주별로 묶어 표시한다. 현재 엔진의 온실 SD 이동·흑백 충돌 마스크는 모험 구현의 출발점이며, 본편 최종 계약은 숨은 아이템 배치·단서·조사·120~240초 타이머·성공/TIMEOUT·부분 성장까지 포함한다. 대서고·별빛 천문대 맵 자원과 이 탐색 로직의 실제 구현은 후속이다. 본편의 기획과 구현 완료를 구분한다.

새 에피소드에서는 경험 목표, 시작·종료 상태, 중심 갈등, 단서, 필요한 상호작용, 중요한 선택, 세계 변화와 돌아보기를 연결해 검토한다. 필요 없는 요소를 억지로 넣지 않는다. 일반 아이템/소지품의 실제 획득·보유 인벤토리, 질문 풀·서버 연결, 제작·수리 범위, 보호자 피드백 형식은 **미정**이다. 모험 목표 아이템은 이 인벤토리와 분리된 판 내부 임시 목표로 확정한다.

이벤트 대화는 Main/NPC/Location 모두 **하나의 공통 DialoguePlayer**로 재생한다. 콘텐츠 DB는 관리·검증이 쉬운 정규화 구조(`dialogue_sequences / dialogue_nodes / dialogue_options`와 선택·이벤트 효과 분리)를 사용하고, FastAPI가 현재 플레이 캐릭터와 `activeRun.storyCast`를 해석해 엔진용 순차 `sequence[]`로 변환한다. 엔진 payload의 명령은 `LINE / IMAGE / CHOICE / END` 네 종류이며 DB의 `nextNodeId` 그래프를 엔진에 그대로 노출하지 않는다. `LINE`은 `DIALOGUE / NARRATION / THOUGHT / CONTEXT` 네 표현 모드로 실제 발화, 장면·관찰 설명, 플레이 캐릭터 속마음, 이미 알려진 배경 사실을 구분한다. 설명 모드는 사건의 정답·감정·해법을 플레이어보다 먼저 단정하지 않고, 속마음도 특정 선택을 정답처럼 암시하지 않는다. 캐릭터/NPC 화자는 기본적으로 현재 말하는 한 명만 중심 이미지로 표시하고 플레이어 초상은 표시하지 않는다. 명시적 `IMAGE`는 배경 또는 단일 FOCUS 슬롯에서 인물·아이템·사건 그림을 공통 처리하며, `LINE.visualMode=KEEP`으로 직전 이미지를 설명 중 유지할 수 있다. 선택은 짧은 선택별 reaction 뒤 같은 다음 sequence로 합류하며 대화 로드 payload에는 성장량·Hidden Stat·플래그 결과를 보내지 않는다. 엔진은 선택한 `choiceNodeId + choiceId`만 수집하고 `END`에서 완료 서비스 1회를 호출한다. 서버가 효과와 스토리 진행을 검증·Firestore 저장한 뒤 **clamp 후 실제 적용된 Visible Stat delta의 이벤트 합계만 결과 표시용으로 반환**하고 Hidden delta는 UI에 노출하지 않는다. 대화 스킵 정책은 관리자 `AFTER_FIRST_ENDING / ALWAYS / NEVER` 3단계로 두고 엔진은 최종 `canSkip`만 사용한다. 운영 기본은 계정 전역 첫 엔딩 이후 스킵 가능이고 QA는 `ALWAYS`로 즉시 허용할 수 있다. `SKIP`은 Story/Event 완료로 인정하지만 해당 장면의 선택 보상은 전부 0이며 미도달 선택 노드는 서버에서 `SKIPPED`로 계산할 수 있다. 현재 엔진의 하드코딩된 Main/NPC/Location 테스트 대사와 `lines / choices / closing` DTO는 최종 계약이 아니며 API 연결 시 제거·교체 가능하다. 상세는 `document/dialogue/README.md`, `document/dialogue/01_ENGINE_API_CONTRACT.md`, `document/dialogue/02_DIALOGUE_WRITING_GUIDE.md`, `document/content/13_DIALOGUE_SEQUENCE.md`, `document/content/02_STATS_EVENTS_ENDINGS/04_STORY_CHOICE_REWARDS.md`, `document_for_ai/07_DIALOGUE_ENGINE_HANDOFF.md`를 따른다.

Main Story `MS01~MS06`의 **사람 검수용 실제 시퀀스 원고**는 `document/dialogue/main/`에 작성되어 있다. `document/dialogue/main/character_sets/`에는 **CH01~CH32 전원의 Character Set 초안이 작성 완료**되어 있고, 각 세트는 공통 마스터를 상속하면서 캐릭터별 `THOUGHT`, 선택 문구, PLAYER 발화와 상대 branch reaction을 함께 변형한다. `VOICE_GUIDES.md`는 32명 말투 기준, `CAST_MATRIX.md`는 protagonist별 실제 `storyCast`를 제공하며 기본 역할 충돌 7건의 대체 반응도 반영했다. `seed_dialogue_content.py`는 **6 Main Story × 32명 = 192 시퀀스**, canonical choice 40개와 현재 규칙 기준 **effect 102개**를 생성한다. 사용자가 과거 Primary Hidden만 사용하던 v3 규칙의 `40 choices / 80 effects`는 실제 로컬 SQLite에서 확인했지만 Secondary Hidden 반영 후 재검증은 아직 전이다. 현재 seed는 v4 마이그레이션도 지원한다. Main/NPC/Location은 같은 `dialogue_* / story_*` 물리 구조를 사용한다. `MS03_S4_MORE_MAGIC`은 명백한 오답형 표현 대신 `약한 구간에 소량의 마력을 보태며 반응을 확인`하는 합리적인 조사 접근으로 수정되어 `MS03_S4_TUNE_FLOW`와 같은 조율 해결로 합류한다.
