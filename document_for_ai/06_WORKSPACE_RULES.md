# 협업 디렉터리·변경 규칙

이 문서는 저장소에서 작업하는 AI를 위한 협업 경계입니다. 작업 시작 시 [AI 시작 문서](00_READ_FIRST.md)와 요청받은 영역의 README를 읽으세요. 실제 파일을 확인하지 않고 존재·내용·구현 상태를 추측하지 마세요.

| 영역 | 주 작업 디렉터리 | 참고 브랜치·관리 |
|---|---|---|
| 엔진 | `engine/` | `dev-ds` |
| 스토리 | `story/` | `dev-hs` |
| 디자인 | `asset/` | `dev-jw` |
| 백엔드 | `backend/` | 사용자 직접 관리; 브랜치 미기재 |

브랜치는 담당 영역을 알려 주는 참고 정보입니다. AI는 지시 없이 생성·전환하지 않습니다. `prototype/`은 완성 기준물로 취급하고 사용자의 명시적 요청 없이 내부 파일을 수정하지 않습니다. `lumia/`는 최종 통합 결과물 영역이므로 통합 요청 없이 변경하지 않습니다.

## 변경 시 함께 확인할 것

1. 평소에는 요청받은 담당 영역을 중심으로 수정합니다. 다른 영역의 변경이 필요하면 사용자나 담당자에게 먼저 알립니다. **저장소 전체 구조 정리처럼 명시적으로 여러 영역을 요청받은 작업**은 요청 범위 안에서 진행합니다.
2. 기존 데이터의 삭제·대규모 이동·이름 변경을 임의로 하지 않습니다. 공통 문서는 꼭 필요한 경우에만 수정합니다.
3. `asset/` 이미지를 추가·삭제·교체했다면 해당 카테고리 `README.md`의 **파일명·설명·미리보기**를 같이 갱신합니다. 새 이미지의 채택·검수 상태를 추정하지 않습니다.
4. `engine/` 실행 방식이 바뀌면 [공식 실행방법](../document/실행방법.md)을 같은 작업에서 갱신합니다.
5. 팀 기준인 `document/`가 바뀌면 연결된 AI 요약을 읽고 필요한 경우 함께 수정합니다. 변경 확인 도구의 감지와 의미적 동기화는 별개입니다.
6. 담당자, 기술 스택, 게임 설정, 에셋 최종 선택처럼 확정 근거가 없는 사항은 `미정`으로 두고 사용자에게 확인합니다.
