# 협업 디렉터리·변경 규칙

이 문서는 저장소에서 작업하는 AI를 위한 협업 경계입니다. 작업 시작 시 [AI 시작 문서](00_READ_FIRST.md)와 요청받은 영역의 README를 읽으세요. 실제 파일을 확인하지 않고 존재·내용·구현 상태를 추측하지 마세요.

| 영역 | 주 작업 디렉터리 | 참고 브랜치·관리 |
|---|---|---|
| 엔진 | `engine/` | `dev-ds` |
| 스토리 | `story/` | `dev-hs` |
| 디자인 | `asset/` | `dev-jw` |
| 백엔드 | `backend/` | 박순몽; 담당 브랜치 미기재 |

브랜치는 담당 영역을 알려 주는 참고 정보입니다. AI는 지시 없이 생성·전환하지 않습니다. `prototype/`은 완성 기준물로 취급하고 사용자의 명시적 요청 없이 내부 파일을 수정하지 않습니다. `lumia/`는 최종 통합 결과물 영역이므로 통합 요청 없이 변경하지 않습니다.

## 변경 시 함께 확인할 것

1. 평소에는 요청받은 담당 영역을 중심으로 수정합니다. 다른 영역의 변경이 필요하면 사용자나 담당자에게 먼저 알립니다. **저장소 전체 구조 정리처럼 명시적으로 여러 영역을 요청받은 작업**은 요청 범위 안에서 진행합니다.
2. 기존 데이터의 삭제·대규모 이동·이름 변경을 임의로 하지 않습니다. 공통 문서는 꼭 필요한 경우에만 수정합니다.
3. `asset/` 이미지를 추가·삭제·교체했다면 해당 카테고리 `README.md`의 **파일명·설명·미리보기**를 같이 갱신합니다. 새 이미지의 채택·검수 상태를 추정하지 않습니다.
4. `engine/` 실행 방식이 바뀌면 [공식 실행방법](../document/실행방법.md)을 같은 작업에서 갱신합니다.
5. 팀 기준인 `document/`가 바뀌면 연결된 AI 요약을 읽고 필요한 경우 함께 수정합니다. 변경 확인 도구의 감지와 의미적 동기화는 별개입니다.
6. 담당자, 기술 스택, 게임 설정, 에셋 최종 선택처럼 확정 근거가 없는 사항은 `미정`으로 두고 사용자에게 확인합니다.
7. 기획·콘텐츠·요구사항·프로젝트 문서를 수정한 작업은 문서 동기화가 끝난 뒤 [`github-wbs-handoff`](../skills/github-wbs-handoff/SKILL.md) 절차로 관련 GitHub WBS를 확인합니다. 상태나 comment 변경이 필요하면 저장소 파일을 건드리지 않고 GitHub 작업만 수행하는 Codex 프롬프트를 생성합니다. 변경할 것이 없으면 `Codex GitHub 작업 불필요`라고 명시합니다. 사용자가 직접 GitHub 변경을 요청하지 않은 한 문서 작업과 GitHub 변경을 한 단계에서 섞지 않습니다.

사용자 결정으로 `engine/`의 엔진은 Phaser 3를 사용합니다. 실행형 시안은 `node engine/server.mjs`로 실행하며 기본 주소는 `http://127.0.0.1:4173/`입니다. 상태·저장·서버·Scene 연결 검증은 `node --test engine/tests/*.test.mjs`입니다. 모험 SD 이동·마스크 충돌과 입학 연결 프레임이 있으며 실제 스토리·계정/AI/본편 펫/해금/엔딩 및 `lumia/` 최종 통합은 후속입니다. 확정된 운영 기술 스택을 미정으로 되돌리지 않고 구현 상태와 구분합니다. 범위와 로컬 저장 제한은 [engine README](../engine/README.md)를 확인합니다.

`engine/minigame-demo/`는 여전히 별도 7종 미니게임 검증 환경이며 기본 포트는 4174입니다. 명령은 [데모 README](../engine/minigame-demo/README.md) 및 [공식 실행방법](../document/실행방법.md)에 있습니다. 독립 데모의 동작을 최종 게임 전체 구현·검수 완료로 취급하지 않습니다.

현재 사용자의 요청에 따라 항상 작업 전에 수정 범위·진행 순서·검증 계획부터 알립니다.

## 변경 검사 규칙

저장소 전체에 접근할 수 있는 작업에서는 `node document_for_ai/check_sources.mjs`로 문서·자원 동기화 상태를 확인합니다.

- `CHANGED`: 이미 추적 중인 문서 또는 asset inventory가 기록된 기준에서 바뀌었습니다. 출력된 AI 문서를 다시 읽고 필요한 요약을 갱신합니다.
- `UNTRACKED`: `source_manifest.json`의 `discovery` 범위에서 새 관리 문서를 발견했지만 `trackedFiles`에는 아직 없습니다. `routes`의 연결 규칙을 확인하고 검토 후 manifest에 등록합니다.
- `ASSET README`: asset 카테고리의 실제 파일과 README 목록·로컬 미리보기 참조가 맞지 않습니다. README를 실제 파일 상태에 맞춘 뒤 다시 검사합니다.
- `UNAVAILABLE`: 추적 대상 원문이나 asset 경로를 찾을 수 없습니다. 없는 자료를 추측하지 않고 접근 가능 여부부터 확인합니다.
- `MANIFEST`: manifest 구조, 중복 추적 경로, SHA-256 형식, AI route 대상 등에 문제가 있습니다. 다른 변경 처리보다 manifest 오류를 먼저 해결합니다.
- `UNROUTED`: `--add-untracked`로 새 문서를 등록하려 했지만 연결할 AI 문서를 결정할 route가 없습니다. `routes`를 먼저 정의한 뒤 다시 시도합니다.

`--record`는 이미 `trackedFiles`에 등록된 파일과 `assetInventory`의 현재 해시를 승인하는 기능입니다. 새 문서를 자동 등록하거나 AI 요약의 의미적 정확성을 검증하지 않습니다. `--add-untracked`는 `discovery`에서 발견되고 `routes`로 AI 연결 대상을 결정할 수 있는 새 문서만 `trackedFiles`에 등록합니다. 두 옵션은 동시에 사용하지 않습니다. 새 관리 대상을 추가할 때는 `discovery`, `routes`, `trackedFiles`의 역할을 구분해 수정합니다.
