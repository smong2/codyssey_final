# LUMIA 게임 엔진

Phaser 3 기반 실행형 개발 시안입니다. `lumia/` 최종 통합판이나 운영 계정 저장을 대신하지 않습니다.

## 2026-10-20 마이룸·스토리·엔딩 보완

- 스케줄의 `교육` 명칭을 `수업`으로 바꿨다. 대화 END로 이동할 때 마지막 대화창을 먼저 숨기지 않아 저장 응답을 기다리는 동안 이름만 남는 화면이 나오지 않는다.
- `지난 엔딩 편지`는 계정의 완료 엔딩 목록을 조회하고 직업·최종 스탯·활동 횟수·편지 원문을 재표시한다. 상단 X로 닫는다. 이전 로컬 미리보기 기록 중 스탯·횟수가 저장되지 않았던 항목은 없는 값을 만들지 않는다.
- 마이룸의 펫과 주인공을 드래그해 놓을 수 있다. 위치는 정규화 좌표로 계정 설정에 저장해 다른 기기에서도 불러온다. 펫 대사를 미리 불러오는 동안 말풍선에 `zzz`를 표시하고 클릭 대화는 막는다. 준비되면 `안녕?`으로 바뀌며, 그때부터 펫별 SQLite 대사 20개 중 하나를 눌러 볼 수 있다. 로컬 미리보기는 같은 원고의 읽기 전용 사본을 사용한다.
- 아이리스의 MS02 구출 전 숨김은 원고 의도이므로 유지한다.

## 2026-10-18 대화·수집·엔딩 연결 보완

- 부팅 전에 정식 `loadDialogue / completeDialogue` 서비스를 주입하면 입학·Main·NPC·Location을 같은 대화 UI와 완료 경계로 실행합니다. 서버 선정 이벤트는 예전 로컬 후보표로 재판정하지 않습니다. 서비스 없는 로컬 미리보기와 기존 기록은 유지합니다.
- END/SKIP 완료는 현재 계정·슬롯·회차를 확인하고 서버의 최신 `activeRun`을 검증해 개발 저장까지 성공한 뒤 적용합니다. 같은 요청의 저장 재시도는 서버 완료를 다시 호출하지 않습니다. 서버의 `skill/caution` 스탯 이름은 엔진의 `dexterity/prudence`로 변환합니다. 결과 팝업은 수신한 실제 Visible 증가량만 표시하며 Hidden과 0 증가량은 표시하지 않습니다.

- `loadEnding` 서비스가 있으면 로컬 직업 예측을 확정하지 않고 서버 결과를 기다립니다. AI 편지 안내는 로그인·회원가입 화면에 표시하고, 실제 편지는 작성 주체 없이 보여 주며 직업별 수업 기록을 포함한 서버의 기록 선별 순서를 유지합니다. 메뉴의 `지난 엔딩 편지`는 저장된 편지를 읽기만 합니다.
- **인계 대기:** 최초 슬롯의 `serverRevision`과 엔진 호환 상태 제공, 실제 계정·슬롯 저장/설정 API, 엔딩 최종 완료 API, 정식 대사와 이미지의 서비스 제공은 백엔드 연동 이후 검증해야 합니다. HTTP 주소·Firebase·DB·Gemini 구현과 원본 자산은 수정하지 않았습니다. 현재 저장은 계속 개발용 로컬 저장이며 운영 API 통합 완료가 아닙니다.
- 검증: 전체 자동 테스트 **301개 통과**, 미리보기 진입점 문법 검사와 변경 파일 공백 검사 통과. 서버 `slot-1`과 엔진 슬롯 번호 `1`은 같은 슬롯으로 연결하되 계정·활동 토큰 일치는 계속 검증합니다. 브라우저 화면·정식 API 연동은 이번 자동 검증에 포함하지 않았습니다.

## 실행

Node.js 24.20.0에서 검증한 로컬 미리보기입니다. 별도 패키지 설치 없이 동봉 Phaser 3.90.0 배포본과 MIT 라이선스를 재사용합니다.

팀원은 저장소 전체를 내려받고 루트에서 실행합니다. `engine/`, `asset/`, `prototype/assets/`의 상대 위치를 유지해야 이미지·폰트·오디오·인트로 영상이 로드됩니다.

```powershell
node engine/server.mjs
```

브라우저 주소는 `http://127.0.0.1:4173/`입니다. 소스를 바꾼 뒤 새로고침하고, 서버 종료는 실행 터미널에서 `Ctrl+C`를 누릅니다. HTML 파일을 직접 열면 모듈과 이미지가 정상 로드되지 않습니다.

포트 충돌이 있을 때는 다음처럼 바꿉니다. 포트마다 로컬 저장 공간이 별도로 생깁니다.

```powershell
$env:LUMIA_ENGINE_PORT = "4176"
node engine/server.mjs
```

서버는 `127.0.0.1` 전용이며 외부 배포용 서버가 아닙니다. 이번 화면 수정으로 실행 방법은 바뀌지 않았습니다.

### 화면과 자원

- 인트로 `건너뛰기`는 영상과 검정 로고 단독 구간을 생략하고, 배경이 등장하는 타이틀 연출 시점부터 재생합니다. 배경·부제·이펙트는 즉시 페이드 시작, 로고는 기존 4초 모션의 2.4초 시점부터 상단 이동, 버튼은 0.3초 후 등장합니다. 일반 재생의 8~10초 전환과 `다시 보기`는 기존 타이밍을 사용합니다.
- 타이틀은 `BT04_blank_pale_green.png`, 마이룸의 다이어리·가방·메뉴는 BT01·BT02·BT03 green 이미지를 원본 비율로 사용합니다. 슬롯이 모두 차도 새로 시작하기 버튼은 정상 모습으로 유지하며, 클릭하면 버튼들 아래에 프레임 안내가 약 3초 표시됩니다.
- 마이룸 왼쪽 위 프로필은 UI21 녹색 프레임(2058:764)에 이름과 실제 체력 막대만 표시하고, 날짜는 UI22 아이보리 프레임(2058:854)에 연도·날짜·계절/주차를 표시합니다. 두 이미지는 비율을 유지하며 날짜를 누르면 스케줄로 이동합니다. 캐릭터·NPC 대화·선택지는 전신 파일을 사용하고 플레이어 이미지는 대화에서 표시하지 않습니다.
- 타이틀 음악은 캐릭터·슬롯 선택까지 이어집니다. 캐릭터 선택 후 시작하면 초대장/시계탑 장면의 1회성 입학 BGM으로, 마이룸 진입 시 마이룸 BGM으로 바뀝니다. 효과음은 BGM과 별도로 설정할 수 있습니다. 타이틀의 스피커는 BGM 전용이고 오른쪽 아래에 배치됩니다. 다시보기·건너뛰기 버튼은 각각 상단 좌우에 둡니다. 상세와 트랙 경로는 아래 [타이틀 음악 전환](#타이틀-음악-전환)을 참고하세요.
- 본편 펫 `PET01~PET10` 마스터를 연결했습니다. 마이룸의 가방 → 펫 탭에서 해금된 펫을 선택하며, 현재 펫은 모든 슬롯이 공유하는 `activePetId` 설정으로 로컬 저장됩니다. 잠긴 펫은 선택할 수 없습니다. 별도의 환경설정 펫 화면은 사용하지 않습니다.

- 프로필 화면은 저장 성장 스탯을 바꾸지 않고 활성 펫 보정을 더한 뒤 0~500으로 제한한 유효 스탯을 표시합니다. 체력 10~30에서는 그 값을 내림 70%로 표시합니다. 체력은 펫 보정 대상이 아닙니다. 자동 해금 판정·서버 검증·운영 계정 저장은 아직 연결하지 않았습니다.
- 마이룸에는 선택한 펫을 캐릭터와 함께 표시합니다. 펫과 주인공을 드래그해 배치할 수 있고, 펫을 누르면 캐릭터별 말풍선이 열립니다. 펫 선택은 가방의 펫 탭에서 합니다.
- 마이룸은 별도 하단 스케줄 버튼을 두지 않으며, 왼쪽 상단 날짜 카드를 누르면 기존 주간 스케줄 화면으로 이동합니다. 프로필·스케줄·다이어리·가방 화면은 현재 시간대의 마이룸 배경을 유지하고 UI 프레임만 전환합니다.
- 사용자 결정에 따라 `오늘 돌아보기` 기능은 제거했습니다. 메뉴와 활동 완료 후 유도 카드를 표시하지 않으며, 답변·저장·야간 전환을 위한 임시 상태도 사용하지 않습니다. 다이어리의 실제 활동 기록과 주간 요약·엔딩 편지는 유지합니다.
- 다이어리는 UI08 펼친 책의 원본 비율(1286×850)을 유지해 화면 중앙에 맞춥니다. 책 왼쪽에 UI09 천 책갈피 `이야기 / 활동기록`을 붙이고, 선택한 책갈피는 왼쪽으로 더 길게 펼쳐 어둡게 표시합니다. 왼쪽 페이지 기록 카드는 2열이며 주별 활동 카드마다 대표 이미지 1장만 표시합니다. 저장된 활동 중 대성공·성공을 우선하고 같은 결과이면 모험, 같은 우선순위이면 뒤 요일을 대표 이미지로 고릅니다. 오른쪽 페이지는 선택한 주의 완료 활동이나 이야기 상세이며, 대표 이미지 선택과 주별 묶음은 원본 일별 기록을 변경하지 않습니다. 배지 팝업은 활동 결과 저장 뒤 실제 획득 receipt와 보유 단계가 확인된 경우에만 표시하고 확인 후 다음 장면으로 이동합니다. 세부 adapter 필드는 [연결·인계 안내](DATA_HANDOFF.md#수집-알림-수신)에 기록했습니다.
- 스케줄은 가방과 같은 양피지·빈티지 금색 테두리의 단일 프레임에 제목, 달력, 활동 목록, 하단 안내와 일정 시작 버튼을 배치합니다. 활동 분류는 그린/아이보리 책갈피 탭으로 표시합니다. 활동 목록은 내부 스크롤하고, 좁은 세로 화면에서는 달력 아래에 배치하여 전체 화면 스크롤로 접근합니다. 하단 안내는 양피지 위 짙은 그린 글씨로 표시합니다.
- 스케줄의 이번 주 편집 가능한 인접 달 날짜를 누르면 해당 월로 이동하면서 날짜 선택을 유지합니다. 선택 시 기존 테두리 색과 칸 배경색을 바꾸며 초록 외곽선을 겹치지 않습니다. 하단 안내는 `화요일 선택`처럼 요일만 볼드로 강조하고 다음 줄에 `활동 카드로 변경 · 날짜를 다시 누르면 삭제`를 표시합니다. 빈 날짜에는 `활동 카드를 골라 주세요.`를 표시하며 모든 요일에 같은 형식을 씁니다.
- 모험은 MP01·MP02에 3840×2160 PNG 전체맵·투명 전경·충돌 마스크를 사용하고 MP03에는 기존 3840×2160 WebP 전체맵·전경과 1920×1080 마스크를 사용합니다. MP01·MP02의 5504×3072 원본도 별도 보존합니다. 전경은 오브젝트별 정렬 데이터가 생길 때까지 사용자 승인에 따라 항상 캐릭터 앞에 표시합니다. 카메라 기본 확대율은 0.7이며 캐릭터를 추적합니다. 화면의 충돌 보기 버튼은 제거했지만 충돌 판정은 유지합니다.
- 맵 파일은 서버가 `asset/map/`에서 직접 제공하며 MP01·MP02 썸네일은 각 3840×2160 PNG 전체맵을 재사용합니다. 경로와 검수 상태는 [`asset/map/README.md`](../asset/map/README.md)를 따르며, 이전 `engine/assets/` 경로는 사용하지 않습니다.

### 일정·성장·저장

- 본편은 최신 장소 활동 문서의 **5개 미니게임 + 요정의 거래**를 사용합니다. 거울 마법(탐험), 별빛 무대(표현력), 정령 화분 정리(솜씨), 봉인 서가(지식), 룬 회로(마법)를 엔진 전용 Scene으로 연결했습니다. 기존 7종 독립 데모와 과거 일정 ID·기록은 보존합니다. 룬 핀 훈련은 새 일정에서 제외하되 이전에 저장한 일정은 계속 실행할 수 있습니다.
- 난이도와 성장은 #72 확정 규칙을 연결합니다. 저장된 해당 성장 스탯 0~100/101~200/201~350/351~500이 난이도 1~4를 결정합니다. 실패는 난이도별 +0/+1/+2/+3, 성공은 +5/+6/+7/+8, 대성공은 +10이며, 체력 10~30은 증가량의 절반을 내림 적용하고 성장값은 500을 넘지 않습니다. 점수는 성장량으로 환산하지 않습니다. 수업 체력 10 소모를 유지합니다.
- 본편 결과 버전 2는 장소 코드·대상 스탯·보상/플레이 난이도(`EASY~VERY_HARD`)·도움 단계·`FAIL/SUCCESS/GREAT`·`COMPLETE/TIMEOUT/QUIT`를 반환합니다. 게임별 문서 기준으로 대성공을 판정합니다. 시간 종료와 포기는 `FAIL`이므로 보상 난이도별 실패 성장과 연속 실패를 반영합니다. 과거 데모의 `timeout` 결과는 기존 성장 0 규칙으로 읽습니다. 모험 시간 종료는 별도 부분 탐험 성장 계약입니다.
- 보상 입력 `rewardInputs`는 전달 슬롯일 뿐이며 수집품·배지 지급 조건을 임의로 만들지 않습니다. 새 퍼즐은 해답을 검증하고, 난이도별 패턴·타이밍·색 수와 조작을 구분합니다. 퍼즐 풀의 다양성·난이도 체감과 실제 가로 화면 조작은 플레이테스트 대상입니다.
- 주간 활동은 시작 전에 `IN_PROGRESS` 체크포인트와 수업 체력 -10/모험 체력 -15를 저장하고, 결과 저장 성공 후에만 다음 일정으로 자동 이동합니다. 서버 저장 실패 시 같은 요청 재시도, 서버 상태 확인, 게임 다시 불러오기를 제공하며 확인 전에는 다음 일정으로 넘어가지 않습니다. 재시도 중 중복 입력을 막고, 재조회 실패 시 복구 안내를 유지합니다. 중복 차감·하루 진행을 막습니다. 재접속 또는 모험 중 `중단하기` 확정 시 한 번만 `INTERRUPTED`로 기록하고 이미 소비한 체력은 유지하며 성장·보상 없이 다음 일정으로 진행합니다. 수업의 `포기하기`는 날짜를 소비하는 실패입니다.
- 주간 일정은 활동 카드만 고르면 가장 이른 빈 평일에 자동 배치하고, 날짜를 먼저 고른 뒤 카드를 선택하면 해당 요일에 배치·교체합니다. 선택 전 강제휴식일은 자동 배치 후보에서 제외합니다. 금요일 일정과 이야기 저장이 끝나면 주말을 자동 처리하고 주간 요약을 저장합니다. 요약에는 기록된 스탯 변화·수업 횟수·체력 소비/회복·시작/종료 체력·강제휴식 일수가 표시됩니다. 요약의 `창 닫기`를 누르면 마이룸으로 돌아가며 날짜 카드에서 새 일정을 엽니다. 이어 하기에서도 확인 전 상태를 복원하고, 52주차는 마지막 요약 확인 후 엔딩으로 진행합니다.
- 일정 작성 중 날짜 칸을 누르면 해당 요일을 선택하고 활동 카드 선택 안내를 표시합니다. 선택된 날짜를 다시 누르면 이미 배정된 활동이 삭제됩니다. 별도의 날짜 상세/닫기/삭제 카드 UI는 없습니다. `특별` 카드의 `요정의 거래`는 주 1회, 체력 소모 없이 서로 다른 표시 성장 스탯 사이 1~5점을 1:1 교환하거나 건너뛸 수 있습니다.
- 성장 보정 설정은 `setGrowthRewardConfig` adapter로 주입하며 5개 표시 성장 스탯별 0.5~1.0(0.1 단위)을 검증합니다. 수업·모험 결과 확정 때만 반복 성장에 반영합니다. 같은 미니게임에서 실패/시간 종료 2회 연속이면 다음 플레이 난이도를 1단계, 4회면 2단계 낮추되 보상 난이도는 저장 스탯 기준으로 유지합니다. 성공·대성공 시 연속 실패 수를 초기화합니다.
- 모험 성장의 저체력 보정은 활동 시작 전 체력을 기준으로 한 번만 적용합니다. 목표를 한 개 이상 발견한 `TIMEOUT`은 성장 보정 배율 적용 뒤에도 최소 +1을 유지하며, 탐험 스탯 500 상한은 넘지 않습니다. 발견 0개·중단에는 이 최소 성장을 지급하지 않습니다. 기존 저장 성장치는 소급 수정하지 않습니다.

### 스토리·모험·엔딩

- 메인 스토리는 `MS01` 캐릭터 선택 후 입학 흐름, 이후 1/1·3/5·6/4·9/3·12/3·12/24(1·10·23·36·49·52주차)에 주간 일정 바깥의 5단계 프레임으로 연결합니다. 입학 흐름은 공통 Dialogue UI 확인을 위해 티아와 임시 문구를 중앙에 표시하지만, 정식 캐스팅·대사·보상·관계 변경은 아닙니다. 플레이어 캐릭터 이미지는 표시하지 않습니다. 나머지 원고 미등록 단계도 `미등록 프레임`으로 표시하며 실제 대사·선택·보상을 만들지 않습니다. 기록에 실제 스토리 성장 변화가 있을 경우 주간 요약에 합산합니다.
- 52주 마지막 요약 후 `무엇을 지켰니? → 미래 직업·작가 부제 → 편지와 실제 기록 → 신규 해금이 있을 때만 요약 → 타이틀로` 순서입니다. 같은 슬롯·회차·직업의 검증된 AI/기본 편지를 받아 준비 저장해야 최종 완료할 수 있습니다. 준비된 편지는 재사용하고 재접속 시 질문부터 시작합니다. 편지/최종 저장 실패 시 진행을 막고 같은 결과로 재시도하며, 화면 이탈 후 도착한 응답은 무시합니다. 엔딩 열람 수와 로컬 회차 완료는 최종 확인 저장에서만 확정합니다. 실제 편지 API·안전 검증·해금 판정은 담당 데이터 연결 대기입니다.
- 모험 일정은 유리 온실·약초원, 대서고, 별빛 천문대 중 장소까지 선택해 날짜별로 저장합니다. 구버전 저장에 장소 정보가 없으면 온실로 읽어 호환합니다. 세 장소는 각각 MP01·MP02·MP03 맵을 사용합니다. `ADVENTURE_MAPS`의 월드·충돌 마스크·전경·썸네일·시작점·카메라 설정을 실제 로더가 읽으며, 각 장소의 `ADVENTURE_LOCATIONS.mapId`로 선택합니다. 지도 교체 방법은 [연결·인계 안내](DATA_HANDOFF.md#map-handoff)를 참고하세요.
- 모험은 목표 1~5개, 탐험 스탯 기반 제한시간, 시작 전 전체 단서, 추적 선택, 시간 정지형 조사와 방향/거리 질적 힌트, `MISSION_COMPLETE / TIMEOUT / INTERRUPTED` 흐름을 연결했습니다. 목표 좌표는 시작점에서 연결된 흰색 충돌 영역을 탐색해 벽 여유·시작 주변 제외·목표 간격을 둔 뒤 시드 기반으로 배치합니다. 맵에는 NPC·이름표·보이지 않는 조우 지점을 배치하지 않으며 이동·조사 중 NPC 대화를 실행하지 않습니다. 목표 이름·힌트·어려움 구간의 3개 목표 선택·성공 성장량 +8은 미리보기 전용 임시값입니다. 목표 아이템은 영구 소지품이나 보상으로 저장하지 않습니다.
- 목표 배치는 월드 좌표의 발 영역 여유를 적용한 충돌 영역에서 시작점 연결성을 검사하고, 시작 주변·배치 금지 영역·조사 반경 중첩을 제외합니다. 조사 중에는 `찾는 중...`을 표시하며, 단서나 대화의 일시정지가 겹쳐도 조사가 끝났다는 이유로 시간이 다시 흐르지 않습니다.
- 모험 플레이어는 `asset/sd_character/`의 기본 6명 중 선택한 학생의 8방향 보행 세트를 사용합니다. NPC용 SD·이름표·바닥 그림자는 로드하거나 표시하지 않습니다. 신규 SD는 자원 README의 모션 검수 대기 상태를 유지하며 엔진 연결을 최종 아트 승인으로 취급하지 않습니다.

### 계정 화면과 개발 저장의 경계

- 마이룸 메뉴의 `계정`에서 로그인·가입·이메일 인증·비밀번호 재설정과 계정 관리 프레임을 확인할 수 있습니다. 서비스가 없으면 연결 대기이며 실제 로그인·탈퇴 등을 성공으로 표시하지 않습니다.
- 부팅 전에 완전한 `lumiaEngineServices` 운영 provider를 제공하면 로그인/이메일 인증 확인 뒤 서버 슬롯·수집 데이터를 불러오고, Main/NPC/Location 공통 Dialogue, 일정·활동 결과, 주간 저장, 마이룸 방문, 엔딩 결정/편지/완료를 서버 authoritative 상태로 진행합니다. ID Token·HTTP URL·timeout/retry·오류 매핑은 provider 책임이며 엔진은 Hidden Stat·성장량·해금 결과를 직접 확정하지 않습니다.
- 활성 펫과 마이룸 배경은 계정 전역 `settings/account` API로 저장합니다. 서버가 해금 목록을 검증하고, 모험 제한시간은 서버 SQLite 펫 마스터의 활성 펫 탐험 보정을 사용합니다. 수업/모험 난이도 단계는 펫 보정과 무관하게 저장 `run.stats`로 정합니다.
- 서비스 없는 기존 로컬 실행은 계속 개발 미리보기로 유지하며 로컬 세이브를 운영 계정으로 자동 이전하지 않습니다. 운영 provider가 일부만 주입된 경우에는 부분 서버 모드로 진행하지 않고 로컬 미리보기 경계를 유지합니다. 로그아웃은 서버 저장을 삭제하지 않고 화면·메모리 상태만 비웁니다.
- 실제 연결 인터페이스와 수신 소유권 규칙은 [연결·인계 안내](DATA_HANDOFF.md#account-slot-boundary)를 참고하세요. 실행 명령과 포트는 바뀌지 않았습니다.

인트로와 타이틀 음악은 `asset/audio/bgm/bgm_title_intro.mp3`, `asset/audio/bgm/bgm_title_main.mp3`를 사용합니다. 입학 장면에는 1회성 트랙 `asset/audio/bgm/bgm_admission_invitation.mp3`, 마이룸에는 반복 트랙 `asset/audio/bgm/bgm_myroom.mp3`를 사용합니다. 클릭 효과음은 `asset/audio/sfx/sfx_button_press.mp3`, 다이어리 열기에는 `asset/audio/sfx/sfx_diary_open.mp3`를 사용합니다. 오디오 파일 확장자는 소문자 `.mp3`로 통일합니다. 시계탑 전용 트랙은 현재 이 흐름에서 재생하지 않습니다. 엔진·서버·배포는 title-audio.mjs의 AUDIO_TRACK_FILES에 등록된 BGM 16곡·SFX 2개를 공유합니다. MP3는 Range 요청을 지원해 재생 중 필요한 구간을 읽습니다.

인트로 음악은 영상과 함께 시작하고, 영상이 먼저 끝나도 음악 트랙을 계속 재생합니다. 실제 트랙 재생 위치가 끝나기 약 6초 전이 되면 메인 BGM을 0초부터 시작해 약 6초간 교차 페이드합니다. 트랙 종료 이벤트는 메타데이터를 읽지 못했을 때의 대체 경로입니다. `건너뛰기`는 0.65초 교차 페이드하며 메인 BGM을 항상 0초부터 시작합니다. `다시 보기`는 인트로 음악을 다시 시작하고 메인 BGM 위치도 0초로 초기화해, 인트로 트랙 종료 시 메인 BGM을 처음부터 재생합니다. 캐릭터 선택에서 `시작하기`를 누르면 초대장 전환 전에 0.9초 블랙 디졸브를 적용합니다. 입학 트랙은 초대장과 시계탑 장면의 흐름 동안 유지하고, 마이룸 진입 시 마이룸 BGM으로 교체합니다. 오른쪽 아래 스피커는 BGM만 음소거/해제하며, 마이룸 메뉴의 `소리 설정`에서 BGM과 효과음을 각각 전환할 수 있습니다. 자동 재생 차단과 사용자의 음소거 설정을 별도로 유지하며, 효과음 재생 오류는 개발자 콘솔에만 기록하고 화면 안내는 띄우지 않습니다. 다이어리 버튼은 전용 효과음을 사용하고 나머지 버튼은 공통 클릭 효과음을 사용합니다. 실제 크롬 재생/화면 검수는 사용자가 진행합니다.

검증: 엔진 전체 자동 테스트 83개 통과. MP3 MIME/Range 응답, 허용된 음악·효과음 경로와 그 외 오디오 경로 거부, 입학/마이룸 전환, 트랙 종료 전환, 건너뛰기/다시 보기 초기화, 자동 재생 차단 복구, BGM·효과음 독립 음소거 및 효과음 오류 안내를 확인했습니다. 실제 크롬 재생/화면 검수는 사용자가 진행합니다.

오디오 파일들은 `asset/` 담당 영역의 원본입니다. 이 엔진 변경에서는 해당 파일을 수정하거나 이동하지 않습니다. 다른 환경에서 엔진을 확인할 때도 위 경로에 지정된 파일들이 제공되어야 합니다.

## 현재 동작하는 범위

- 새로 시작하기는 첫 빈 슬롯을 자동 사용하고, 모두 사용 중이면 안내합니다. 이어서 하기는 최근 저장 바로가기와 슬롯 1~5를 표시하며 빈 슬롯은 `저장 기록 없음`으로 표시합니다.
- 기본 캐릭터 카엘·로빈·니코·세라·아이리스·티아와 실제 해금 목록의 추가 캐릭터를 선택합니다. 체력 100, 성장 스탯 기본 50에 캐릭터 초기 보정·영구 보너스를 더해 새 회차를 생성합니다.
- 마이룸 → 월~금 일정 등록 → 수업·모험·휴식 → 주말 자동 처리 → 주간 요약 확인 → 다음 주 일정의 실행 흐름. 일정은 카드 자동 배치 또는 날짜 우선 지정이 가능하며, 요약은 확인 전까지 저장 상태로 유지됩니다.
- 6개 본편 수업과 요정의 거래를 연결했습니다. 결과는 한 번만 반영하고 수업 포기는 실패로 하루를 소비합니다. 비정상 종료는 시작 체크포인트의 체력을 유지하고 성장 없이 하루를 진행합니다. 기존 7종 데모와 과거 일정도 보존합니다.
- 일반 휴식은 마이룸에서 집·친구·취미 중 하나를 고릅니다. 선택별 체력 범위에서 무작위 회복하고 친구·취미는 성장 스탯 1종만 각각 +1/+2 올립니다. 체력 0~9에서는 행동 가능한 평일 3일을 강제 휴식하며, 같은 주의 연속 휴식일은 한 번에 처리하고 세 번째 휴식 완료 시 체력 100으로 복귀합니다.
- 공용 메타와 슬롯·현재 회차 분리. 슬롯 삭제 확인을 거치며 공용 메타는 삭제하지 않습니다.
- 회차 생성·일정 확정·활동 시작/결과·이야기 완료·주간 요약의 안정 경계에서 로컬 자동 저장합니다. 52주 마지막 요약 후 직업 엔딩을 준비하고, 마지막 `타이틀로` 저장이 성공해야 회차 완료와 계정 메타를 반영합니다. AI 편지는 연결 대기입니다.

금요일 결과와 후속 이야기가 저장되면 주말을 자동 처리하고 주간 요약을 보여 줍니다. 요약의 `창 닫기` 버튼으로 마이룸에 돌아가며, 날짜 카드에서 다음 주 스케줄에 들어갑니다. 52주차 요약은 확인 후 엔딩 화면으로 이어집니다. 현재 이 엔진 미리보기에서는 주말 회복이나 별도 주말 일정을 만들지 않습니다.

## 구조와 확장 경계

```text
engine/
  index.html, style.css       개발 화면과 공통 스타일
  preview.css                현재 실행형 시안 스타일
  server.mjs                  허용된 코드·이미지만 제공하는 로컬 서버
  src/preview-main.mjs        현재 진입점·화면·일정·Scene 연결
  src/main.mjs                이전 골격 기록 (현재 진입점 아님)
  src/core/state.mjs          Phaser에 독립적인 슬롯·회차·행동 규칙
  src/core/storage.mjs        저장 검증·개발용 저장 adapter·경계 재시도
  src/core/post-activity-story.mjs  결과 저장 후 이야기 선정·시작 경계 복구
  src/ui/                     가방·다이어리·마이룸·스케줄 프레임
  src/scenes/                 미니게임 adapter·모험 이동·조사
  tests/                      상태·저장·서버·결과 연결 검증
  minigame-demo/              기존 7종 독립 데모 (원본 보존)
```

미니게임은 난이도·시드·제한시간으로 시작하고 `minigame:complete / minigame:quit` 이벤트를 반환합니다. 본편 6종은 버전 2 결과를 기존 성장·저장 경계로 정규화합니다. Scene은 캐릭터 상태와 저장을 직접 변경하지 않습니다. 독립 데모 7종과 과거 저장용 adapter도 보존합니다.

기존 `asset/background/`, `asset/character/`의 파일을 읽기 전용으로 사용합니다. 이미지 존재와 개발판 사용은 최종 디자인 선택·검수 완료를 의미하지 않습니다.

## 저장의 한계와 안전장치

현재 저장은 **계정 저장을 대신하는 개발용 localStorage adapter**입니다. 키는 `lumia.engine.dev.v1`입니다. 로그인·서버·DB와 연동하지 않았으며 같은 브라우저와 주소에서만 유지됩니다. 개발판은 한 탭에서 사용하세요. 여러 탭의 동시 진행·충돌 병합은 아직 지원하지 않습니다.

- 일정 초안과 미니게임/모험의 매 프레임·대화 중간은 저장하지 않습니다. 확정 일정과 활동 시작/결과는 저장합니다. 진행 중 재접속하면 저장된 시작 체크포인트를 한 번만 `INTERRUPTED`로 정리하고 다음 일정으로 복구합니다. 완료된 활동·주간 기록은 보존합니다.
- 다른 슬롯으로 이동하려면 현재 주 일정과 주말 저장을 마쳐야 합니다. 주중 결과가 다른 슬롯 저장에 섞이지 않게 하는 개발판 제한입니다.
- 저장 실패 시 다음 행동을 멈추고 재시도 버튼을 제공합니다. 재시도는 실패 당시의 경계 스냅샷만 저장합니다.
- 손상된 JSON이나 지원하지 않는 버전은 자동 초기화·덮어쓰기하지 않고 진행을 중단합니다. 자동 복구·버전 이관은 후속 작업입니다.
- 전체 메타 초기화 기능을 제공하지 않습니다.

## 개발 시험값 — 최종 기획 아님

일반 휴식의 선택별 회복량 균등 추첨, 모험 목표 이름·힌트·3개 목표 선택·성공 성장량 +8은 시안용입니다. 세 모험 장소는 각 MP01·MP02·MP03 지도를 사용하며 모험 중 임시 NPC 인사는 실행하지 않습니다. 주말에는 체력을 회복하지 않습니다. 본편 6종의 시간 종료는 `FAIL` 성장 규칙, 과거 데모 `timeout`은 기존 성장 0 규칙을 유지합니다. 새 퍼즐 풀의 반복 다양성·난이도 체감과 실제 가로 화면 조작은 플레이테스트가 필요합니다. 자동 해금·보상 지급·실제 이야기 발생 결정과 정식 원고는 담당 데이터 연결을 기다립니다.

## 검증

저장소 루트에서:

```powershell
node --test engine/tests/*.test.mjs
node --test engine/minigame-demo/tests/*.test.mjs
```

또는 `engine/`에서 `npm test`를 실행합니다. 자동 검증은 슬롯 독립성, 메타 유지, 결과 중복 방지, 중단/실패 처리, 과로, 52주 경계, 저장 오류·재시도, 서버 접근 제한, Scene 복귀를 대상으로 합니다.

2026-10-11 브라우저에서는 캐릭터 선택·마이룸·룬 회로 실행과 중단 복귀·5일 휴식·주말 저장·2주차 이어서 하기를 확인했습니다. 룬 회로 3단계 성공 전체 플레이, 신규 플레이어 재미/난이도, 실제 모바일 기기 검수는 별도로 필요합니다.

## 미구현·후속 작업

정식 이야기 원고·선택 효과·발생 결정, 루루·추가 캐릭터 SD, 최종 모험 미션/밸런스·금지 영역, 수집·해금 판정/메타 API, 개인화 엔딩 편지·계정/서버 저장·AI 기능은 후속입니다. 본편 수업·이야기·수집·엔딩의 엔진 수신 프레임은 마련했지만 실제 전달 데이터와 아트·플레이 검수까지 완료된 것은 아닙니다. 자세한 인계 목록은 [연결·인계 안내](DATA_HANDOFF.md)를 참고하세요.

후속 작업은 정식 스토리 원고/캐스팅·선택 효과, 관리자 설정 전달 경로, 전용 지도·미션 마스터, 백엔드 계정/엔딩 편지 API 연결입니다. 확정되지 않은 보상·밸런스·스토리 선택 효과는 엔진에서 임의로 만들지 않습니다.

참고 브랜치는 `dev-ds`이며 AI가 임의로 전환하지 않습니다. `prototype/`·`lumia/`는 수정하지 않습니다. 실행 방식 변경 시 [공식 실행방법](../document/실행방법.md)도 갱신합니다. 기존 독립 데모는 [데모 README](minigame-demo/README.md)와 [통합 프롬프트](minigame-demo/ENGINE_INTEGRATION_PROMPT.md)를 참고하세요.
