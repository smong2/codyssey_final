## 실행

Node.js 24.20.0에서 검증한 로컬 미리보기입니다. 별도 패키지 설치 없이 동봉 Phaser 3.90.0 배포본과 MIT 라이선스를 재사용합니다.

팀원은 저장소 전체를 내려받고 루트에서 실행합니다. `engine/`, `asset/`, `prototype/assets/`의 상대 위치를 유지해야 이미지·폰트·오디오·인트로 영상이 로드됩니다.

```powershell
node engine/server.mjs
```

브라우저 주소는 `http://127.0.0.1:4173/`입니다. 소스를 바꾼 뒤 새로고침하고, 서버 종료는 실행 터미널에서 `Ctrl+C`를 누릅니다. HTML 파일을 직접 열면 모듈과 이미지가 정상 로드되지 않습니다.

포트 충돌이 있을 때는 다음처럼 바꿉니다. 포트마다 로컬 저장 공간이 별도로 생깁니다.

```powershell
$env:LUMIA_ENGINE_PORT = "4176"
node engine/server.mjs
```

서버는 `127.0.0.1` 전용이며 외부 배포용 서버가 아닙니다. 이번 화면 수정으로 실행 방법은 바뀌지 않았습니다.

## 현재 엔진 상태 — 2026-10-18 최신 반영

이 절은 현재 구현 기준입니다. 과거 결정과 당시 검증 결과는 [작업 기록](UPDATE_PLAN.md#readme-history)에 보존했습니다.

이번 보완은 `engine/` 구현과 사용자가 수정한 BT04 버튼 이미지, 기존 오디오 2개의 소문자 파일명 정리를 포함합니다. 우선순위별 결과는 [작업 기록](UPDATE_PLAN.md), 백엔드·콘텐츠 담당자가 전달할 데이터는 [연결·인계 안내](DATA_HANDOFF.md)를 참고하세요. 기준 기획·백엔드·미니게임 원본은 유지합니다.

`origin/main`의 `7e1d4b9`까지 반영했습니다. 배경·펫·온실 맵의 기존 파일명은 `asset-paths.mjs`의 URL 호환을 사용하며 원본을 복제하지 않습니다. 독립 데모 서버도 같은 호환표를 사용합니다. 대서고·별빛 천문대 전용 지도, 이미지 버튼, 추가 방 3종과 퍼즐 조각은 연결했습니다. 루루의 화면 적용과 최종 디자인 검수는 후속입니다.

### 화면과 자원

- 인트로 `건너뛰기`는 영상과 검정 로고 단독 구간을 생략하고, 배경이 등장하는 타이틀 연출 시점부터 재생합니다. 배경·부제·이펙트는 즉시 페이드 시작, 로고는 기존 4초 모션의 2.4초 시점부터 상단 이동, 버튼은 0.3초 후 등장합니다. 일반 재생의 8~10초 전환과 `다시 보기`는 기존 타이밍을 사용합니다.
- 타이틀은 `BT04_blank_pale_green.png`, 마이룸의 다이어리·가방·메뉴는 BT01·BT02·BT03 green 이미지를 원본 비율로 사용합니다. 슬롯이 모두 차도 새로 시작하기 버튼은 정상 모습으로 유지하며, 클릭하면 버튼들 아래에 프레임 안내가 약 3초 표시됩니다.
- 마이룸 왼쪽 상단의 작은 프로필 카드는 `UI14_date_frame_variant_01.png`를 직전 크기의 2배로 키우고 원본 비율을 유지합니다. 중앙 금색 장식선을 가리지 않도록 이름은 위, 체력 막대는 아래에 배치하며 라벨·수치는 감춥니다. 막대에는 실제 체력을 반영하고, 카드를 누르면 기존 프로필 화면으로 이동합니다. 캐릭터 데이터·NPC 대화·선택지 화면은 전신 파일을 사용하며, 예전 상반신 경로를 가진 대화와 저장 기록도 전신 표시로 호환합니다. 캐릭터 원본 파일은 삭제하지 않았습니다.
- 타이틀 음악은 캐릭터·슬롯 선택까지 이어집니다. 캐릭터 선택 후 시작하면 초대장/시계탑 장면의 1회성 입학 BGM으로, 마이룸 진입 시 마이룸 BGM으로 바뀝니다. 효과음은 BGM과 별도로 설정할 수 있습니다. 타이틀의 스피커는 BGM 전용이고 오른쪽 아래에 배치됩니다. 다시보기·건너뛰기 버튼은 각각 상단 좌우에 둡니다. 상세와 트랙 경로는 아래 [타이틀 음악 전환](#타이틀-음악-전환)을 참고하세요.
- 본편 펫 `PET01~PET10` 마스터를 연결했습니다. 마이룸의 가방 → 펫 탭에서 해금된 펫을 선택하며, 현재 펫은 모든 슬롯이 공유하는 `activePetId` 설정으로 로컬 저장됩니다. 잠긴 펫은 선택할 수 없습니다. 별도의 환경설정 펫 화면은 사용하지 않습니다.
- 가방은 `배지 → 펫 → 캐릭터 → 마이룸` 순서이며 처음 열 때 배지를 표시합니다. 상단 `가방` 제목은 없고, 4개 카테고리는 이미지 없이 만든 그린 탭 바 안에서 선택 항목만 아이보리 캡슐로 표시합니다. 나머지 탭은 아이보리 글씨, 선택 탭은 그린 글씨입니다. 배지 왼쪽 대분류·함께하기·배경 사용/재시도 같은 내부 버튼은 기본 `BT04_blank_pale_ivory_short.png`, 선택 상태 `BT04_blank_pale_green_short.png`와 1362:311 원본 비율을 유지합니다. 아이템 탭 UI는 제거했지만 `asset/item/` 원본은 보존합니다.
- 상단 바는 프레임 내부 폭의 70%로 중앙 배치하고, 과한 캡슐 모서리 대신 완만한 9px/6px 라운드를 사용합니다. 탭 글씨는 고운바탕이며 이전 크기의 80%입니다. 가방 전체 프레임은 2.1px 금색 테두리와 밝고 어두운 겹선으로 빈티지 베벨을 표현하며 초기 베벨 두께의 70%로 줄였습니다. 양피지·버튼 원본은 변경하지 않습니다.
- 배지의 활동·태그 진행 수치는 전달받은 `collectionView.badges[].current`만 표시합니다. 수신값이 없으면 진행 기록 확인 대기로 두며, 오래된 로컬 `meta.counters`를 배지 판정 진행도로 대입하지 않습니다. 보유 펫·캐릭터·퍼즐 수처럼 실제 목록에서 직접 확인되는 수집 수는 별도로 표시합니다. 원본 누적 저장값과 실제 보상 지급 여부는 UI가 수정하지 않습니다.
- 배지는 왼쪽에 이미지 없는 대분류 버튼 5개와 얇은 세로 구분선을 고정하고, 오른쪽에 소분류 5개와 진행도를 표시합니다. 한 소분류만 펼쳐 배지 8개·다음 목표·자동 보상 상태를 확인하며 개별 배지를 누르면 해당 조건과 진행도를 표시합니다. 넓은 화면은 배지 8열, 작은 가로 화면은 4열이며 오른쪽 내용만 세로 스크롤됩니다. 가방 밖으로 이동하거나 획득 기록을 바꾸지 않습니다.
- 캐릭터·펫은 같은 둥근 정사각형 카드에 이름 없이 표시합니다. 이미지 상단을 맞춰 머리가 잘리지 않게 하며 상체 중심으로 크롭합니다. 해금된 카드는 원본 컬러, 미해금 카드는 프레임과 어울리는 저채도 브라운 단색 실루엣과 잠금 표시를 사용합니다.
- 해금된 카드를 누르면 캐릭터/펫 정보를 표시하고, 펫 상세의 `함께하기`에서 기존 `activePetId` 저장 흐름을 사용합니다. 미해금 카드는 기준 문서의 실제 해금 조건을 안내하며, 자동 해금 판정·보상은 아직 연결하지 않았습니다.
- 프로필 화면은 저장 성장 스탯을 바꾸지 않고 활성 펫 보정을 더한 뒤 0~500으로 제한한 유효 스탯을 표시합니다. 체력 10~30에서는 그 값을 내림 70%로 표시합니다. 체력은 펫 보정 대상이 아닙니다. 자동 해금 판정·서버 검증·운영 계정 저장은 아직 연결하지 않았습니다.
- 마이룸에는 선택한 펫을 캐릭터 뒤 레이어에 표시합니다. 세라는 넓은 의상에 가려지지 않도록 펫을 더 왼쪽에 배치합니다. 펫을 누르면 가방의 펫 탭을 엽니다.
- 마이룸은 별도 하단 스케줄 버튼을 두지 않으며, 왼쪽 상단 날짜 카드를 누르면 기존 주간 스케줄 화면으로 이동합니다. 프로필·스케줄·다이어리·가방 화면은 현재 시간대의 마이룸 배경을 유지하고 UI 프레임만 전환합니다.
- 다이어리는 UI08 펼친 책의 원본 비율(1286×850)을 유지해 화면 중앙에 맞춥니다. 책 왼쪽에 UI09 천 책갈피 `이야기 / 활동기록`을 붙이고, 선택한 책갈피는 왼쪽으로 더 길게 펼쳐 어둡게 표시합니다. 왼쪽 페이지 기록 카드는 2열이며 주별 활동 카드마다 대표 이미지 1장만 표시합니다. 저장된 활동 중 대성공·성공을 우선하고 같은 결과이면 모험, 같은 우선순위이면 뒤 요일을 대표 이미지로 고릅니다. 오른쪽 페이지는 선택한 주의 완료 활동이나 이야기 상세이며, 대표 이미지 선택과 주별 묶음은 원본 일별 기록을 변경하지 않습니다. 배지 팝업은 활동 결과 저장 뒤 실제 획득 receipt와 보유 단계가 확인된 경우에만 표시하고 확인 후 다음 장면으로 이동합니다. 세부 adapter 필드는 [연결·인계 안내](DATA_HANDOFF.md#수집-알림-수신)에 기록했습니다.
- 스케줄의 이번 주 편집 가능한 인접 달 날짜를 누르면 해당 월로 이동하면서 날짜 선택을 유지합니다. 선택 시 기존 테두리 색과 칸 배경색을 바꾸며 초록 외곽선을 겹치지 않습니다. 오른쪽 활동 프레임 하단 안내는 기본/선택 상태 모두 코랄 배경·흰 글씨이며 그림자는 없습니다. `화요일 선택`처럼 요일만 볼드로 강조하고 다음 줄에 `활동 카드로 변경 · 날짜를 다시 누르면 삭제`를 표시합니다. 빈 날짜에는 `활동 카드를 골라 주세요.`를 표시하며 모든 요일에 같은 형식을 씁니다.
- 모험은 `asset/map/`의 장소별 3840×2160 WebP 배경·투명 전경과 1920×1080 흑백 충돌 마스크를 사용합니다. 대서고와 별빛 천문대는 추가된 MP02·MP03 맵으로 연결했고, 배경·전경 원본 PNG는 보존합니다. 전경은 오브젝트별 정렬 데이터가 생길 때까지 사용자 승인에 따라 항상 캐릭터 앞에 표시합니다. 카메라 기본 확대율은 0.7이며 캐릭터를 추적합니다. 화면의 충돌 보기 버튼은 제거했지만 충돌 판정은 유지합니다.
- 배경·전경 원본 PNG는 보존하고 런타임 파생 파일만 별도로 사용합니다. 맵 자원과 내보내기 기준은 [`asset/map/README.md`](../asset/map/README.md)를 따르며, 이전 `engine/assets/` 경로는 사용하지 않습니다.

### 일정·성장·저장

- 본편은 최신 장소 활동 문서의 **6개 미니게임 + 요정의 거래**를 사용합니다. 거울 마법(탐험), 별빛 무대(표현력), 정령 화분 정리·봉인 서가(지식), 룬 회로(마법), 룬 핀 훈련(솜씨)을 엔진 전용 Scene으로 연결했습니다. 기존 7종 독립 데모와 과거 일정 ID·스탯 의미는 보존합니다.
- 난이도와 성장은 #72 확정 규칙을 연결합니다. 저장된 해당 성장 스탯 0~100/101~200/201~350/351~500이 난이도 1~4를 결정합니다. 실패는 난이도별 +0/+1/+2/+3, 성공은 +5/+6/+7/+8, 대성공은 +10이며, 체력 10~30은 증가량의 절반을 내림 적용하고 성장값은 500을 넘지 않습니다. 점수는 성장량으로 환산하지 않습니다. 수업 체력 10 소모를 유지합니다.
- 본편 결과 버전 2는 장소 코드·대상 스탯·보상/플레이 난이도(`EASY~VERY_HARD`)·도움 단계·`FAIL/SUCCESS/GREAT`·`COMPLETE/TIMEOUT/QUIT`를 반환합니다. 게임별 문서 기준으로 대성공을 판정합니다. 시간 종료와 포기는 `FAIL`이므로 보상 난이도별 실패 성장과 연속 실패를 반영합니다. 과거 데모의 `timeout` 결과는 기존 성장 0 규칙으로 읽습니다. 모험 시간 종료는 별도 부분 탐험 성장 계약입니다.
- 보상 입력 `rewardInputs`는 전달 슬롯일 뿐이며 수집품·배지 지급 조건을 임의로 만들지 않습니다. 새 퍼즐은 해답을 검증하고, 난이도별 패턴·타이밍·색 수와 조작을 구분합니다. 퍼즐 풀의 다양성·난이도 체감과 실제 가로 화면 조작은 플레이테스트 대상입니다.

- 모험 성장의 저체력 보정은 활동 시작 전 체력을 기준으로 한 번만 적용합니다. 목표를 한 개 이상 발견한 `TIMEOUT`은 성장 보정 배율 적용 뒤에도 최소 +1을 유지하며, 탐험 스탯 500 상한은 넘지 않습니다. 발견 0개·중단에는 이 최소 성장을 지급하지 않습니다. 기존 저장 성장치는 소급 수정하지 않습니다.

### 수집·새 회차

- 배지는 5대분류 → 25소분류 → 각각 8개 조건과 `2/5/8` 보상 프레임을 사용합니다. 횟수와 수령 상태는 전달 데이터를 표시하며, 횟수가 높다는 이유만으로 획득 사실이나 보너스를 추정하지 않습니다. 숨은 스탯을 배지 태그 횟수로 해석하지 않습니다.
- 배지는 5대분류 → 5소분류 → 8단계로 탐색합니다. 미획득 배지는 공통 잠금 이미지, 획득 배지는 프레임·심볼·장식 조합을 표시합니다. 다음 획득 조건과 실제 누적 진행도, 2/5/8 단계의 지급 완료·다음 보상·다음 회차 적용 안내를 표시하며 직접 수령 버튼은 없습니다. 태그 행동 횟수는 보여 주지만 숨은 스탯 수치는 읽지 않습니다.
- 기본 방 + 추가 3개 방을 같은 둥근 정사각형 카드로 표시합니다. 목록의 `사용 중/퍼즐 보기` 버튼은 없고 현재 배경은 체크·테두리로 표시합니다. 카드를 누르면 상세 팝업이 열립니다. 미해금 카드는 방 이미지의 명암을 살린 저채도 브라운 모노톤에 공통 배지 자물쇠를 표시합니다. `room-1/2/3`은 우주방·공주방·식물방이며 실제 12조각 PNG를 연결했습니다. 팝업의 4×3 퍼즐에는 소유한 위치만 원본 조각으로 표시하고, 미획득 위치는 아이콘·물음표 없는 가림 칸으로 둡니다. 기본 방은 전체 미리보기를 표시합니다. 해금된 배경에만 팝업 안의 `이 배경 사용하기`를 제공하고 현재 배경에는 버튼 대신 상태를 표시합니다. 전달받은 해금 여부를 따르며 `12/12`만으로 임의 해금·자동 적용하지 않습니다. 저장 성공 후 팝업·가방을 유지하고 목록의 현재 배경 표시를 갱신하며, 가방을 닫을 때 새 배경이 보입니다. 저장 실패 시 기존 선택을 유지하고 같은 팝업에서 재시도합니다. 계정 설정만 저장하며 미저장 회차를 섞지 않습니다.
- 기본 6명 외에도 전달된 해금 목록에 있는 캐릭터는 새 회차에 선택할 수 있습니다. 캐릭터 초기 ±10 보정과 스탯별 영구 보너스(최대 +15)는 새 회차 생성 때만 더합니다. 기존 회차를 다시 계산하지 않습니다. 현재 모험용 SD는 기본 6명만 제공되어 있으며 추가 캐릭터는 전용 SD 인계 전까지 모험 자산 대기 오류를 명시합니다.
- 슬롯 5개가 모두 사용 중이면 새 게임 버튼을 비활성화하고 슬롯 삭제 경로를 안내합니다. 읽기 실패는 `LOAD_ERROR` 카드로 표시하고 재시도와 영구 삭제 확인을 제공합니다. 손상된 슬롯을 빈 슬롯으로 자동 덮어쓰지 않습니다. 현재 로컬판은 5개 슬롯이 하나의 저장 묶음이므로, 일부 슬롯만 손상돼도 다른 슬롯은 정보 확인만 가능하며 오류 복구/확인 삭제 후 이어할 수 있습니다. JSON·공용 메타 전체가 손상됐거나 저장소 접근이 차단되면 삭제하지 않고 재시도만 제공합니다.
- 실제 수신된 퍼즐 획득·배경 완성 정보를 결과 저장 성공 후 안내합니다. 같은 수신 ID를 중복 안내하지 않고, 가방의 마이룸 탭과 해당 방에 `NEW`를 표시합니다. 방 상세를 확인한 뒤 확인 상태도 저장하며, 실패하면 표시를 보존하고 재시도합니다. 배경을 자동 적용하거나 가방으로 강제 이동하지 않습니다. 기본 실행에는 실제 지급 서비스가 없어 임의 알림을 만들지 않습니다.

### 계정 화면과 개발 저장의 경계

- 마이룸 메뉴의 `계정`에서 로그인·가입·이메일 인증·비밀번호 재설정과 계정 관리 프레임을 확인할 수 있습니다. 서비스가 없으면 연결 대기이며 실제 로그인·탈퇴 등을 성공으로 표시하지 않습니다.
- 부팅 전에 `lumiaEngineServices.account`를 제공하면 로그인/이메일 인증 확인을 마친 뒤에만 인트로와 게임으로 진입합니다. 이메일·최초 가입일은 읽기 전용이며 비밀번호 변경, 다른 기기 로그아웃, 현재 기기 로그아웃, 영구 삭제 확인은 해당 provider 함수에만 위임합니다. 비밀번호는 저장하지 않으며 원문 서비스 오류를 화면에 노출하지 않습니다.
- 인증된 개발 저장은 uid별 별도 키를 사용합니다. 기존 기본 로컬 세이브를 특정 계정에 자동 이전하지 않습니다. 로그아웃은 저장을 삭제하지 않고 화면·메모리만 비웁니다. 이는 운영 서버 저장이나 실제 계정 서비스 구현 완료가 아닙니다. 서비스 없는 기존 로컬 실행은 개발 미리보기이며 운영용 게스트 모드가 아닙니다.
- 실제 연결 인터페이스와 수신 소유권 규칙은 [연결·인계 안내](DATA_HANDOFF.md#account-slot-boundary)를 참고하세요. 실행 명령과 포트는 바뀌지 않았습니다.

인트로와 타이틀 음악은 `asset/audio/bgm/bgm_title_intro.mp3`, `asset/audio/bgm/bgm_title_main.mp3`를 사용합니다. 입학 장면에는 1회성 트랙 `asset/audio/bgm/bgm_admission_invitation.mp3`, 마이룸에는 반복 트랙 `asset/audio/bgm/bgm_myroom.mp3`를 사용합니다. 클릭 효과음은 `asset/audio/sfx/sfx_button_click.mp3`, 다이어리 열기에는 `asset/audio/sfx/sfx_diary_open.mp3`를 사용합니다. 오디오 파일 확장자는 소문자 `.mp3`로 통일합니다. 시계탑 전용 트랙은 현재 이 흐름에서 재생하지 않습니다. 엔진 서버는 위 파일만 오디오 경로로 허용하며, 다른 오디오 파일은 공개하지 않습니다. 금요일 결과와 후속 이야기가 저장되면 주말을 자동 처리하고 주간 요약을 보여 줍니다. 요약의 `새 일정 작성` 버튼으로 다음 주 스케줄에 들어가며, 52주차 요약은 확인 후 엔딩 화면으로 이어집니다. 현재 이 엔진 미리보기에서는 주말 회복이나 별도 주말 일정을 만들지 않습니다.

## 저장의 한계와 안전장치

현재 저장은 **계정 저장을 대신하는 개발용 localStorage adapter**입니다. 키는 `lumia.engine.dev.v1`입니다. 로그인·서버·DB와 연동하지 않았으며 같은 브라우저와 주소에서만 유지됩니다. 개발판은 한 탭에서 사용하세요. 여러 탭의 동시 진행·충돌 병합은 아직 지원하지 않습니다.

- 일정 초안과 미니게임/모험의 매 프레임·대화 중간은 저장하지 않습니다. 확정 일정과 활동 시작/결과는 저장합니다. 진행 중 재접속하면 저장된 시작 체크포인트를 한 번만 `INTERRUPTED`로 정리하고 다음 일정으로 복구합니다. 완료된 활동·주간 기록은 보존합니다.
- 다른 슬롯으로 이동하려면 현재 주 일정과 주말 저장을 마쳐야 합니다. 주중 결과가 다른 슬롯 저장에 섞이지 않게 하는 개발판 제한입니다.
- 저장 실패 시 다음 행동을 멈추고 재시도 버튼을 제공합니다. 재시도는 실패 당시의 경계 스냅샷만 저장합니다.
- 손상된 JSON이나 지원하지 않는 버전은 자동 초기화·덮어쓰기하지 않고 진행을 중단합니다. 자동 복구·버전 이관은 후속 작업입니다.
- 전체 메타 초기화 기능을 제공하지 않습니다.

## 개발 시험값 — 최종 기획 아님

일반 휴식 +40/+50/+70의 균등 추첨, 모험 목표 이름·힌트·3개 목표 선택·성공 성장량 +8은 시안용입니다. 세 모험 장소는 각 MP01·MP02·MP03 지도를 사용하며 모험 중 임시 NPC 인사는 실행하지 않습니다. 주말에는 체력을 회복하지 않습니다. 본편 6종의 시간 종료는 `FAIL` 성장 규칙, 과거 데모 `timeout`은 기존 성장 0 규칙을 유지합니다. 새 퍼즐 풀의 반복 다양성·이동 상한 체감·BPM·핀 회전 패턴은 실제 플레이 검수가 필요합니다. 자동 해금·보상 지급·실제 이야기 발생 결정과 정식 원고는 담당 데이터 연결을 기다립니다.

```powershell
node --test engine/tests/*.test.mjs

```

또는 `engine/`에서 `npm test`를 실행합니다. 자동 검증은 슬롯 독립성, 메타 유지, 결과 중복 방지, 중단/실패 처리, 과로, 52주 경계, 저장 오류·재시도, 서버 접근 제한, Scene 복귀를 대상으로 합니다.

2026-10-11 브라우저에서는 캐릭터 선택·마이룸·룬 회로 실행과 중단 복귀·5일 휴식·주말 저장·2주차 이어서 하기를 확인했습니다. 룬 회로 3단계 성공 전체 플레이, 신규 플레이어 재미/난이도, 실제 모바일 기기 검수는 별도로 필요합니다.

## 미구현·후속 작업

정식 이야기 원고·선택 효과·발생 결정, 루루·추가 캐릭터 SD, 최종 모험 미션/밸런스·금지 영역, 수집·해금 판정/메타 API, 개인화 엔딩 편지·계정/서버 저장·AI 기능은 후속입니다. 본편 수업·이야기·수집·엔딩의 엔진 수신 프레임은 마련했지만 실제 전달 데이터와 아트·플레이 검수까지 완료된 것은 아닙니다. 자세한 인계 목록은 [연결·인계 안내](DATA_HANDOFF.md)를 참고하세요.

후속 작업은 정식 스토리 원고/캐스팅·선택 효과, 관리자 설정 전달 경로, 전용 지도·미션 마스터, 백엔드 계정/엔딩 편지 API 연결입니다. 확정되지 않은 보상·밸런스·스토리 선택 효과는 엔진에서 임의로 만들지 않습니다.

참고 브랜치는 `dev-ds`이며 AI가 임의로 전환하지 않습니다. `prototype/`·`lumia/`는 수정하지 않습니다. 실행 방식 변경 시 [공식 실행방법](../document/실행방법.md)도 갱신합니다. 기존 독립 데모는 [데모 README](minigame-demo/README.md)와 [통합 프롬프트](minigame-demo/ENGINE_INTEGRATION_PROMPT.md)를 참고하세요.
